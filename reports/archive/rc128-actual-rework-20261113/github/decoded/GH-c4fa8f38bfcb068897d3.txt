[Feature] Add 910C matmul-allreduce-rmsnorm fusion op for Qwen3 down-projection
### What this PR does / why we need it?

This PR adds a **fused matmul + allreduce + add + rmsnorm operator targeting Ascend 910C**, specialized for the **Qwen3 down-projection** path, and wires it through the vllm-ascend compilation graph-fusion layer.

**Background — different swim-lanes, converged onto this release.**
This fusion work was developed on a separate internal development branch (different "swim-lane" from the mainline v0.22.1rc work). It is contributed here on top of the current `releases/v0.22.1rc` baseline so the three-operator fusion (matmul → allreduce → rmsnorm) lands as a single coherent change on this release rather than as scattered commits. The four original development commits (which included WIP staging) have been squashed into this one clean commit for review.

**Why fusion helps.**
The Qwen3 down-projection normally issues a matmul, then an allreduce, then a residual add and an rmsnorm as separate kernels. Each is a separate kernel launch plus, for the collective, a host-device round trip. Fusing the four stages into one 910C op removes those launches and round trips, reducing the down-projection latency.

**What this PR adds:**

- `csrc/mc2/matmul_allreduce_add_rmsnorm_910c/`: the aclnn host adapter (def/proto/tiling/workspace), the aclnn torch entry, the AIC and AIV kernels, tiling, utils, and shared `moe_distribute` base/comm-context helpers.
- `csrc/` wiring: `CMakeLists` entries, `func.cmake` registration, `torch_binding.cpp` / `torch_binding_meta.cpp` bindings, and `build.sh` / `build_aclnn.sh` entries.
- `vllm_ascend/compilation/passes/allreduce_rmsnorm_fusion_pass.py`: the graph fusion pass that matches the down-proj → allreduce → add → rmsnorm pattern and routes it to the new fused op on 910C.
- `vllm_ascend/ascend_config.py`, `compiler_interface.py`, `graph_fusion_pass_manager.py`, `passes/base_pattern.py`: config and base-pattern plumbing so the pass is registered and gated behind the Ascend compilation config.
- `tests/ut/compilation/test_compiler_interface.py`: unit tests for the fusion pass registration/matching.

**Implementation notes:**

- AIC/AIV scheduling uses a 1:1 ratio for the fused decode op; the matmul and the collective epilogue are pipelined to overlap compute and communication.
- The op is gated behind the 910C Ascend compilation config path; other hardware and non-Qwen3 paths are unaffected.

### Does this PR introduce _any_ user-facing change?

Yes, opt-in. The fused op is registered behind the Ascend compilation config for 910C and is exercised via the allreduce_rmsnorm fusion pass. It activates for the Qwen3 down-projection path when the 910C compilation config enables it; existing paths and other hardware are unchanged. No public Python API name changes.
