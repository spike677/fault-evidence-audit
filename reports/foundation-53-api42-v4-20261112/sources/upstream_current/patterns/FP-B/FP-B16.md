# FP-B16 出参 stride 未参与寻址（非连续 view 被按连续布局回写，前 numel 个正确其后全旧值）

> [← 库索引](../../README.md) ｜ [变更记录](../../CHANGELOG.md) ｜ 类别：功能/兼容 ｜ 风险：高（S3×O3=9） ｜ 状态：活跃

- **元数据**：类别 功能/兼容 ｜ 风险 高（S3×O3=9）｜ 状态 活跃 ｜ 来源 `cann/ops-nn` 2026-11-12 定向实测（19 issue / 25 接口，A2-910B3 CANN 9.2.0 与 A3 CANN 9.3.0 双版本逐位一致 + 物理内存 dump 实证）；v6.64 建条
- **适用**：仓 ops-nn ｜ 侧别 Host ｜ 载体 aclnn源码,Host源码 ｜ 触发 AutoContiguous ｜ 默认启用 true
- **子型**：① **该算对却没算对**（资料非连续列标 `√` / 填 `x` 即「跟随某输入」/ 填 `-` 未标注，实现既不算对也不拒绝）；② **该拒绝却未拒绝**（资料非连续列标 `×`，测试首段应返回 `161002` 却返回 0）；③ **声明了 `AutoContiguous` 却不生效**（`op_host/*_def.cpp` 的出参 `Output().AutoContiguous()` 未落到框架回写路径）。
- **故障机理**：aclnn 出参张量的 **stride 从未参与寻址**。kernel 按自己的 tiling 假设出参是行主序连续布局，把**完全正确的 `view.numel()` 个结果**依次写到 `storage` 基址起的连续位置；调用方传进来的 `aclCreateTensor(..., strides, storageShape)` 里的 `strides` 与 `storageShape` 在**整个回写链路上被丢弃**（既没有 `IsContiguous()` 拦一道，也没有 ViewCopy 回写视图）。因此 `view` 与 `storage` 之间存在**任何空洞**时（`stride[i] != 连续 stride`），按 stride 读回就有一半偏移落在未写区，读到调用方预填的旧值/哨兵。**它不越界**——严格满足 `max_offset < numel(storage)`，因此 memcheck/越界检测全绿、无 aic error、无 coredump，返回码为 0；**结果也不"差一点"**——已写部分与连续基线**逐位相同**。这是「**值算对了，位置写错了**」，只能靠「出参预填哨兵 + 按 stride 读回对拍」暴露，任何只断言返回码或只比对连续出参的用例都会判 PASS。注意与「没算全」的区别：本条**算出的结果数量是对的**（等于 `view.numel()`），缺的是**落位**。
- **触发条件**：出参以带空洞 stride 的 view 传入（典型：末维切片 `stride = {H*2, 2}` 而 `storage = [B, H*2]`，或中间维空洞 `stride = {64,8,2}`）；且该算子的 `ACLNNTYPE` 为 `aclnn`（**op_api 由 op def 自动生成、`op_host/op_api/` 目录不存在**），出参回写路径由框架 autogen 完成而非手写。反过来说：`ACLNNTYPE aclnn_exclude` 的算子走另一条通路，本轮抽样 15 个**全部正常**。**连续出参永远测不出来**——必须构造 `view.numel() < numel(storage)` 的合法视图。
- **典型表现**：① **恰好一半（或 `1/stride比` 的比例）出参元素为预填值**——`y1Out` 16/32、`out` 12/24、`yOut` 64/128、`logProbOut` 20/40；② **物理 dump 显示"前 numel 个正确、其后全旧值"**——这是本条的**决定性判据**（如 `[8,8,4]` 出参 `stride={64,8,2}`、`storage=[8,8,8]`：物理 `[0..255]` 是 256 个完整正确结果、`[256..511]` 全是哨兵 `-777000`）；③ **返回码 `0/0`、无任何告警**，跨版本跨硬件**逐位一致**；④ **对照失效**：同一接口的 in-out 出参（如 `InplaceAddRmsNorm` 的 `x1Ref`）非连续时**完全正确 128/128**，只有常规出参（`rstd`）失效——说明缺陷局限在出参回写这一路，不是整个算子不支持非连续。
- **源码审查映射点**：① 先确认 `op_host/` 下**是否存在 `op_api/` 目录**——不存在即意味着出参回写完全交给 autogen，是本条的高危前提（`ACLNNTYPE aclnn` 算子大多如此）；② 查 `op_host/*_def.cpp` 的 `Output(...)` 链尾是否声明 `.AutoContiguous()`：**声明了却不生效**是本条最强的"实现声称支持"证据（`add_rms_norm_cast` 4/4、`inplace_add_rms_norm` 6/6、`foreach_*` 1/1、`scatter_list` 2/2 均有声明；但 `GroupNormSwish` 的 `y`/`mean` **无声明也照样失效**，故"有声明"是加分项而非必要条件）；③ 查是否有任何 `GetStrides` / `GetStorageShape` / `IsContiguous()` 出现在**出参**相关路径上——**只在入参出现、出参从不出现**即命中（实测 `cross_entropy_loss` 6 处 `AutoContiguous` 全在 `input`/`target`/`weight`）；④ 核对资料 `docs/aclnn*.md` 参数表里每个出参的**非连续Tensor 列**取值，据此判子型（`√`/张量名/`-` → 子型①；`×` → 子型②）；⑤ 同算子同族的其他出参是否复制了同一模式（`DeepNormGrad` 4 个出参、`GroupNormSwishGrad` 3 个出参**全部同时失效**）。
- **检测签名**：**无判别性指纹**。2026-11-12 用 `scripts/sig_yield.py` 在真实 `ops-nn`（12363 文件）实测：候选正则 `\.Output\([^;]{0,200}\.AutoContiguous\(\)` **命中 0 次**——因为真实代码里 `Output("x")` 与其 `.AutoContiguous()` **跨行书写**（如 `norm/add_rms_norm_cast/op_host/add_rms_norm_cast_def.cpp:95-98`），单行正则无法表达属主关系；而放宽到单行 `AutoContiguous\(\)` 则全仓 **2085 次**，属超量。故本条**不设签名**，全部降级为审查关键词与人工核查命令（与 FP-A22 的处理一致）。
- **审查关键词**：`出参 stride|output stride|ViewCopy|AutoContiguous`；`非连续|non-contiguous|storageShape`；`哨兵预填|canary|未写残留`；`aclCreateTensor.*strides`。
- **测试拦截建议**：① **出参一律传带空洞 stride 的合法 view**（`stride = {H*2, 2}`、`storage = [B, H*2]`、`view = [B, H]`），并**先自检合法性**：断言 `max_offset = Σ(shape[i]-1)*stride[i] < numel(storage)`——不满足则是构造错误，不是缺陷；② **出参 buffer 预填哨兵**（FLOAT 用 `-777000`，FP16 用 `0xFBFF`，INT8 用 `-128`），跑后统计残留数量与**位置分布**：残留为连续区间（如 `[16..31]`）即"整块未写"，比只报总数更有诊断力；③ **必须同时跑连续基线并断言基线哨兵为 0**——基线不干净时（`quantMode="static"` 下 `scaleOut` 不输出、`CrossEntropyLoss` 的 `zloss`/`lseForZloss` 资料明示"暂不支持"）不得据此判缺陷；④ **物理内存 dump 定根因**：直接读 `storage` 前 `numel(view)` 个元素，与连续基线的 `numel(view)` 个逻辑值逐元素比对，**全部相同即坐实"值对位置错"**——这一步是从"一半没写"升级到"stride 未参与寻址"的关键，仅凭残留计数无法区分"没算"与"写错位置"；⑤ **in-out 出参做内部对照**（同一次调用里测一个 in-out 出参），能排除"整个算子不支持非连续"。
- **控制变量（v6.30）**：**必须固定**——shape / dtype / 属性 / 数值全部不变，仅出参的 stride 与 storageShape 变化 ｜ **允许变动**——单个出参的 stride（一次只测一个出参，多出参同时改则无法定位是哪一路失效）｜ **多变量同变的典型误判**——把"出参非连续"和"入参非连续"同时改，会把入参侧的 `AutoContiguous` 生效误当成出参也生效；实测 `cross_entropy_loss` / `deep_norm_grad` 的 `AutoContiguous` **全部只作用在入参**，出参一路完全没有。
- **实证案例**：`cann/ops-nn` 19 个 issue / 25 个接口（全部 open，A2/9.2.0 与 A3/9.3.0 逐位一致）：**#8663**（7 接口同族：`RmsNorm`/`GemmaRmsNorm`/`RmsNormGrad`/`AddLayerNormGrad`/`MaskedSoftmaxWithRelPosBias`/`ExpandIntoJaggedPermute`/`TopKTopPSample`，错位倍率恰等于 stride）；**#8674** `AddRmsNormCast`（4 出参 `y1`/`y2`/`rstd`/`x` 全错，16/32；4/4 声明 `AutoContiguous` 却不生效）；**#8675** `InplaceAddRmsNorm`（`rstd` 4/8，**同调用 `x1Ref` 128/128 正确**）；**#8677/#8679/#8680/#8681** `Foreach{Minimum,Add,Sub,Pow}ScalarList`（各 12/24）；**#8682** `GroupNormSwish`（3 出参全错，`y` 12/24，物理前 24 与基线 **24/24 相同**）；**#8686/#8687** `SwiGlu`/`SwiGluGrad`（16/32、32/64）；**#8688/#8689** `SituGlu`/`SituGluGrad`（16/32、32/64）；**#8693** `DequantBias`（`y` 5120/10240）；**#8698** `DynamicBlockQuant`（`y` 64/128 + `scale` 8/16）；**#8699** `SwiGluQuant`（`out` 24/48 + `scaleOut` 1/3）；**#8701** `DequantSwigluQuant`（`yOut` 64/128 + `scaleOut` 4/8，资料 9 参数非连续列全填 `x`）；**#8702** `CrossEntropyLoss`（`logProbOut` 20/40，资料 4 出参该列全为 `-` 未标注）；**#8704** `DeepNormGrad`（**4 出参全错**，物理前 32 与基线 32/32）；**#8706** `GroupNormSwishGrad`（**3 出参全错**，`dx` 128/256、物理 256/256）。**同批相邻形态单列**：**#8691** `ClippedSwiglu` 为**基线缺陷**（出参全连续、官方示例原样即复现 `out[1]` 整行未写 16/32），指向 kernel 第 0 维偏移未参与寻址，**不属 stride 问题**，勿混入本条。**阴性对照**：`ScatterList`（list 出参 2/2 声明 `AutoContiguous`，实测 60/60 完全正确）——证明"有声明"不等于"必失效"，落候选后仍须实测。**规模口径**：2026-11-12 实测 `ACLNNTYPE aclnn` 族 69 个接口，本条命中 25 个（36%）；`aclnn_exclude` 族抽样 15 个**全部正常**。
- **关联**：[FP-B12](FP-B12.md)（B12-2 是"返回 SUCCESS 但输出未写全"的**结果面**；本条给出其中一类**确定的根因**——出参 stride 未参与寻址。若 dump 出"前 numel 个正确其后全旧值"则归本条，勿在 B12 重复定级）、[FP-A22](../FP-A/FP-A22.md)（A22 子型③"分派后输出覆盖不全"是 **dtype 派发表错**，换个 dtype 即变；本条**与 dtype 无关**，只随出参 stride 变化）、[FP-B07](FP-B07.md)（B07 是**偏移算式算错致越界**，有 aic error / memcheck 告警；本条 `max_offset < numel(storage)`，**从不越界**，两者靠"memcheck 是否干净 + 是否有报错"即可一刀分开）、[FP-B05](FP-B05.md)（B05 只管**入参**校验且限定 `op_api/*.cpp`；本条的 19 个算子**全都没有 `op_api` 目录**）、[FP-B11](FP-B11.md)（子型②"该拒未拒"与 B11 的契约校验缺失同面，但 B11 的对象是 shape/rank/attr **取值**，本条的对象是 **stride 布局**）、[FP-B04](FP-B04.md)（B04 收录的 `CheckDisContinuousStride` 是**该检查自身缺 `return`**，方向相反：本条是**根本没有这道检查**）、[FP-E01](../FP-E/FP-E01.md)（只断言返回码 / 只测连续出参的 UT 会把本条长期判 PASS）、[FP-A05](../FP-A/FP-A05.md)（出参残留旧值在端到端表现为"精度异常/脏数据"，须防止被误归因为数值精度问题）。
