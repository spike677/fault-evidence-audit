What this PR does / why we need it?
Related issue:
https://gitcode.com/Ascend/MindSpeed-LLM/issues/1934
Packed SFT with
--mtp-num-layers 1 --reset-attention-mask
encounters two consecutive errors:
DecoderPackedMTFDataset.__getitem__()
converts
actual_seq_len
to a list when constructing MTP boundaries, then passes that list to
F.pad
, causing
TypeError: pad(): argument input must be Tensor, not list
. Only pad the non-MTP result; the MTP path already constructs its own tensor.
With micro batch size 1,
SFTTrainer.get_batch()
flattens the per-layer boundaries, causing
TypeError: int object is not subscriptable
in the DeepSeek4 forward path. Use
squeeze(0)
to remove only the batch dimension and retain
[mtp_num_layers + 1, num_boundaries]
in both intermediate and first/last pipeline stage branches.
Does this PR introduce any user-facing change?
No new arguments or data format changes. This fixes the existing MTP packed-SFT data path. Existing non-MTP and micro batch size > 1 processing is retained.
How was this patch tested?
Local: Python AST syntax checks for both modified files and
git diff --check
passed. No local PyTorch/NPU training environment is available.
Reported remote run: DeepSeek-V4-Flash packed SFT, 4 nodes / 64 NPUs, TP1 / PP4 / EP16 / CP4,
kvallgather_cp_algo
, BF16, MTP1, micro batch size 1, global batch size 32, reset attention/position IDs. At sequence length 8192, three consecutive training steps completed with finite LM/MTP losses, zero skipped updates and zero NaN iterations.
A sequence-length-20480 run also completed one training step after these fixes; subsequent runs had separate device/HCCL memory failures. This PR does not claim to resolve the 20k OOM or the device-kernel error.
Multi-layer MTP, micro batch size > 1, other CP algorithms and checkpoint save/restore are not covered by the remote validation.
