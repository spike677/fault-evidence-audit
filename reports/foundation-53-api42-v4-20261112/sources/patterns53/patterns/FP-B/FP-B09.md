# FP-B09 动态 shape 标签未参与校验决策（`-2`/`-1` 被当真实维度）

> [← 库索引](../../README.md) ｜ [变更记录](../../CHANGELOG.md) ｜ 类别：功能/兼容 ｜ 风险：高（S2×O3=6） ｜ 状态：活跃

- **元数据**：类别 功能/兼容 ｜ 风险 高（S2×O3=6）｜ 状态 活跃 ｜ 来源 gitcode canndev 仓 issue 检索（2026-09-16）+ ops-cv/ops-nn 仓同机理实证（v6.1 扩仓）
- **适用**：仓 All ｜ 侧别 Host ｜ 载体 IR与图配置 ｜ 触发 UNKNOWN_RANK|UNKNOWN_SHAPE|GetShapeRange|GetDims ｜ 默认启用 true
- **故障机理**：GE 的动态 shape 用**哨兵值**表达未知程度——`-1` = `UNKNOWN_SHAPE`（维数已知、某维长度未知）、`-2` = `UNKNOWN_RANK`（连维数都未知）。**校验/推导代码（infershape、verifier、tiling 入口）把这些哨兵值当成普通维度值直接参与运算**，于是「正确的动态 input」被判为非法。三种独立成因：① **哨兵当实数用**——`-2`/`-1` 参与「维度必须为 N」「各维必须相等」「维度数必须为 N」等判断必然为假，**infershape 直接返回失败**；② **短向量按下标访存**——`GetDims()` 对 `{-2}`（UNKNOWN_RANK）返回 **size=1** 的向量，而代码按静态假设访问 `inputShape[1]`、`inputShape[2]`，**越界读致崩溃**；③ **取 shape range 前未 `MakeUpRange`**——`GetShapeRange()` 返回的是「补全后」的上下界，未先 `MakeUpRange` 即取值会拿到不完整/错误区间，后续校验基于错误前提。**共同的修复范式**：**校验前先判动态标签，命中则跳过维数/取值/一致性校验并让输出相应置 `-1`**（#1786、#1787 的修复方案即为此），而非在原有静态校验上打补丁。
- **触发条件**：**任一动态 shape 输入**——① 输入 tensor 带 `-2`（UNKNOWN_RANK）或 `-1`（UNKNOWN_SHAPE）标签；② 该输入的校验/推导路径**未在入口前置动态标签判断**；③ 算子为**新上库**或**刚同步配置**（#1673「新增 AdaptiveAvgPool2dGrad，同步修改 cann 仓原有配置」即此类：新算子易照抄静态校验骨架）。**静态 shape 输入不触发**，故常规静态用例全绿也测不出；**动态编译能过而静态编译失败**（或反向）是典型旁证。
- **典型表现**：**infershape / verifier 阶段直接报错、编译期中断**，而非运行期结果错——报错信息多形如「维度不为 1」「维数不为 2」「shape 不合法」，**与真实原因（输入本就是合法动态 shape）完全不符**，最易把排查引向输入数据；`{-2}` 场景下可能**崩溃**而非有序报错（越界读）；同一算子**动态编译通路能跑、GEIR 通路报错**（#1786）；**精度无从谈起**（根本没跑起来），与「跑起来但精度不对」的 FP-A 族有本质区别。**关键识别特征：错误发生在图编译/推导阶段，且报错指向的「非法输入」实际合法。**
- **源码审查映射点**：① 每个 shape 校验分支前**是否先判动态标签**——检查 `GetShapeSize()`/`GetDimNum()`/`GetDims()` 结果参与判断前，有没有 `IsUnknownShape()` / `IsUnknownRank()` / 直接比对 `-1`/`-2` 的前置门；② **`GetDims()` 返回值是否先查 size 再按下标访存**——`GetDims()[i]`、`inputShape[i]` 等下标访问是否先校验 `size > i`（`{-2}` 只返回 size=1，`[1]` 即越界，这是**崩溃**而非报错的直接成因）；③ **`GetShapeRange()` 调用前是否 `MakeUpRange`**——取连续区间/对齐推导是否基于补全后的 range（#1766 明确点名此缺陷，并给出「参考 YUV4442YUV422」的可对照实现）；④ **输出 shape 是否随之置 `-1`**——动态分支下输出若仍按静态推导会给下游埋错（#1786 修复要求「输出 shape 相应设为 -1」）；⑤ **新上库算子的校验骨架是否为静态版复制**——新增算子/新增配置项的 review 需专门确认动态分支；⑥ **infershape 1.0 与 2.0 双套实现的一致性**——是否存在「1.0 有缺陷而 2.0 正常」或反之（#1804 直接**屏蔽 infershape1.0 改用子仓 infershape2.0** 规避，#1673 亦点名 「infershape1.0」），两套需**同输入同断言**对照。
- **检测签名**：`GetShapeSize\(\)|GetDimNum\(\)` 与 `-1|-2|UNKNOWN_SHAPE|UNKNOWN_RANK` 比较前无 `IsUnknown` 前置判断；`GetDims\(\)\s*\[` （`GetDims()` 结果直接下标访问，高危）；`inputShape\s*\[\s*[1-9]`（假定维数 ≥2 的硬下标）；`(GetDim\w*|GetShape\w*|GetStorageDim\w*)\s*\([^)]*\)\s*(==|!=)\s*-(1|2)\b`（维度语境哨兵值直连比较——`GetDims()`/`GetShapeSize()` 等维度查询接口返回值直接与 `-1`/`-2` 比较，需人判是动态标签前置门还是哨兵当实数误用）；`GetShapeRange\(\)` 调用点前 200 行内无 `MakeUpRange`（`MakeUpRange` 为修复态特征、不作存在型签名，索引侧以缺失型规则 absence 承载：infershape 文件含 `GetShapeRange` 调用而无 `MakeUpRange` 即候选，文件级粗筛）；同一算子目录内 `_infershape_2\.0|InferShape2|infershape1\.0` 双实现并存。
- **测试拦截建议**：① **每个算子必配动态 shape 最小集**——`{-2}`（UNKNOWN_RANK）、`{-1}`、`{-1,-1,-1}`、`{-1,-1,-1,-1}` 四组，**断言不报错而非只断言精度**（此类缺陷是「跑不起来」，只比精度的用例根本走不到比较步）；② **动态用例进泛化矩阵与门禁**——新算子/新配置项合入时，动态用例与静态用例**同等必过**，不可标记为可选；③ **动静一致性对拍**——同语义输入分别走静态编译与动态编译，**两者都应成功且结果一致**（#1786 即「期望与动态编译一致」的思路）；④ 对 `GetDims()` 下标访问写法加**静态门禁**（要求前置 size 校验）；⑤ **专项覆盖「新上库算子」**——按 #1673 的模式，新增算子因照抄静态骨架而高发，review checklist 需含动态分支项。
- **实证案例**：canndev 仓 6 条**同机理独立实证**（3 条 closed / 3 条 open，2026-05-30 ~ 2026-08-10，覆盖 6 个不同算子）：**#1673**（closed，AdaptiveAvgPool2dGrad）「当输入的动态 shape 为 `-2` 时，**infershape1.0 会把 `-2` 当成真实的维度值参与校验导致报错**」，复现「复跑带动态标签为 `-2` 的用例即可」，环境 Ascend950 / CANN9.1.0，期望「无校验报错，且精度为 100%」——**形态① 哨兵当实数用的教科书案例**；**#1770**（open，SparseSegmentSumGrad）「动态 shape 下第二、三个输入如果为 `-2` 会**判断维度不为 1，从而导致 infershape 失败**」——形态①，且体现「维度必须为 1」这类硬校验的高发；**#1766**（closed，RGB2YUV422）「inferShape 对 UnknownRank 情况没有考虑，同时 **`GetShapeRange` 前没有 `MakeUpRange`**，应该参考 YUV4442YUV422」，复现「跑 `(-2)` 和 `(-1,-1,-1)` 场景必现」，环境 Ascend950 / CANN9.1.0——**形态③ 的唯一实证，且附可对照的正确实现（YUV4442YUV422）**；**#1786**（open，ProdVirialSeA）「ProdVirialSeA 的 GEIR 通路在运行动态 shape 用例（`-2` UNKNOWN_RANK / `-1` UNKNOWN_SHAPE）时报错。`ProdVirialSeAVerify` 和 `ProdVirialSeAInferShape` **硬校验输入维度必须为 2**，动态 shape 下 `GetDims()` 返回 `{-2}` 或 `{-1}`，**size 不为 2，直接报错**」，并给出修复范式「**对每个输入的 shape 校验前先判断是否为动态 shape（UNKNOWN_RANK / UNKNOWN_SHAPE）**：动态 shape 时跳过维度和值校验，nframes 设为 -1，输出 shape 相应设为 -1；静态 shape 时保持原有校验逻辑不变」——**形态① 的完整闭环，含官方修复范式**；**#1787**（open，Yolo）「修复 Yolo 算子的 `YoloVerify` 函数在动态 shape 场景下校验失败的问题：**完全未知动态 shape `(-2,)`：`GetDims()` 返回 size=1，`inputShape[1]` 越界导致崩溃**；部分未知动态 shape `(-1,-1,-1,-1)`：channelNum=-1，channel 一致性校验失败」，修复「size==1 时跳过维度校验，channelNum 设为 -1；channelNum==-1 时跳过 channel 一致性校验」——**形态② 越界崩溃的唯一实证，同时是形态① 的叠加**；**#1804**（open，SparseApplyAdagradV2）「**屏蔽 infershape1.0，使用子仓的 infershape2.0**」，UT 参数明确以 `{-2}` / `{-1,-1}` 组合构造（`var({-2},{-2})` / `accum({-1,-1},{-1,-1})` / `lr({-2},{-2})`），期望输出 `{{-2},{-2}}`——**揭示「infershape 1.0 与 2.0 双套实现」这一结构性诱因，其"屏蔽旧版"的做法本身即是回避缺陷的旁证**。 **v6.1 扩仓补充（ops-* 三仓同机理独立实证，本条是 `applicability.repos` 由 `canndev` 放宽为 `All` 的直接依据）**：**ops-cv#926**（open，Yuv444ToYuv422）「InferShape 拒绝动态未知 shape / `(-1,-1,-1)` 输入」——动态 shape 恰是该接口文档允许的合法形态，属形态①哨兵当实数用；**ops-nn#6842**（open，SoftplusGrad）「动态 Rank
