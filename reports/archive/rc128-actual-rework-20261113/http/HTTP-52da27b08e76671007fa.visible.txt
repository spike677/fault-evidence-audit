Describe the current behavior / 问题描述 (Mandatory / 必填)
attention/kv_compress_epilog/tests/st/arch35/ttk_kernel_kv_compress_epilog_st.csv
中 20 条 ST 用例（quant_mode 0/1/2）在 Ascend950DT 真机上执行时， 14 条与 golden 逐字节比对失败，且结果非确定 ：同一份输入数据（runner 输入种子为固定值）连续运行 3 次，同一用例的差异字节数逐次不同。
关键证据 ：
非确定性 ：固定输入种子（
np.random.default_rng(20261104)
）下连跑 3 次，同一用例差异字节数逐次变化，例如
wb_mode1_default_d128
：179 → 359 → 352 字节；
wb_mode2_g32_d192
：36 → 129 → 261 字节。详见"日志"一节。
决定性对照 ：保持 shape/属性不变，仅将 slot_mapping 改为唯一映射（
np.arange(bs)
）后，mode 0/1/2 全部逐字节等于 golden（diff=0），多次运行稳定。
失败分布与并发写冲突强相关 ：6 条稳定 PASS 的用例（
eps_tiny
/
allzero
×2/
bs1
/
tight_head
/
wide
）均为全零输入、bs=1 或 slot 恰好无实际冲突的场景；14 条 FAIL 用例的 slot 抽样均存在大量重复值（如 16 token 中 slot=0 出现 7 次、slot=1 出现 7 次）。
该问题在 master（dd0c5026b）原始代码上即可复现，与近期任何功能修改无关。
根因分析 ：20 条用例的
input_data_ranges
第 3 项（slot_mapping）均给定为
(-1, 1)
，即 bs=16/32/64 个 token 的 slot 值只能在 {-1, 0, 1} 三个值中随机取值。该算子是 scatter 语义（按 slot_mapping 将各 token 的量化结果写入 kvCache 对应行），slot 空间仅 3 个值必然导致 大量 token 映射到同一 kvCache 行 ；kernel 多核并行写入同一行无顺序保证，而 golden（numpy 实现）按 token 顺序依次覆盖的确定性语义计算期望值，二者在"重复 slot"场景下必然不一致，且 kernel 多次执行结果互不相同。
Environment Information / 环境信息 (Mandatory / 必填)
昇腾硬件型号：Ascend950DT（V120，device 2 实测）
CANN 版本：9.2.0（Ascend-cann-toolkit_9.2.0_linux-aarch64 + Ascend-cann-950-ops_9.2.0_linux-aarch64）
Python 版本：3.11.6
操作系统：openEuler 24.03 aarch64
代码版本：ops-transformer master dd0c5026b
算子包：build.sh --pkg --soc=ascend950 --ops=kv_compress_epilog 构建安装

Describe the expected behavior / 预期结果 (Mandatory / 必填)
ST 用例应当稳定通过，至少结果应当确定。具体修复建议（二选一或组合）：
修用例（推荐） ：将 20 条用例
input_data_ranges
中 slot_mapping 的范围从
(-1, 1)
放宽到与 bs 匹配的唯一区间（如 bs=16 取
(0, 15)
，bs=32/64 相应扩大且不超过 cache 行数），保证任意随机抽样下 slot 无重复；
明确契约 ：若"重复 slot_mapping"本身是合法输入，则需在算子接口文档中明确"多 token 映射同一 kvCache 行时写入顺序未定义"，并将 golden 调整为对应的容忍比对方式（如按行集合比对而非逐字节）。

感谢详细反馈。您提供的唯一映射对照结果表明，重复 slot 写入冲突可能是用例结果不稳定的原因；重复 slot 是否属于合法输入及其写入语义仍需确认。
对需要确定性比对的用例，可以考虑在有效 cache 行范围内生成不重复的
slot_mapping
，例如在行数足够时使用
np.arange(bs)
。仅扩大随机取值范围不能保证不重复。
对重复 slot 场景，需要先确认接口契约，再评估文档和 golden 的处理方式；若允许并发写入，还需确认实际写入粒度，不能直接假定结果一定是某个 token 的完整行。
我们会继续确认重复 slot 的接口语义及用例生成方式。
