# INVARIANTS.md —— 四条全局不变量（跨模式的判定底座）

> 52 张卡各自描述「一种机理」。但**大量真实缺陷不是某张卡命中的，而是某个量「没有被人问过」**。
>
> 这份文档只做一件事：给出**四个必须能回答的问题**。任何一处可疑代码、任何一个候选，只要能把这四问答全，就不需要再靠「感觉像不像」来判有没有问题；任何**答不出来的**，都不能关闭。
>
> **定位**：不替代模式卡（`patterns/`），也不是第 53 条模式。它是**判定前置工序**——用在「拿不准这算不算缺陷」「两个模式都能套，到底归哪个」「候选想撤销但找不到反证依据」这三种时刻。

## 0. 为什么需要（本库原先的缺口）

库里的 53 条模式是按**机理**组织的：越界、空指针、同步缺失、确定性…… 但缺陷的实际形态是**变量用错了对象 / 单位 / 生命周期 / 消费者**。同一行代码可能同时踩中三条模式，也可能一条都不沾却依然错。

历史现网修复的共性（25 个案例归纳）：

| 错法 | 同一行代码看起来没问题，因为 | 真相 |
|---|---|---|
| `GetSizeByDataType(outDataType)` | 类型名没错、编译通过 | 用的是**输出存储 dtype**，该处需要**计算 dtype** |
| `pbAL1` 算 weight 容量 | 系数存在、公式成形 | A/B 是**两个 buffer**，weight 属 B 侧 |
| `ndNum = 2` 固定搬运 | 主块完全正确 | **尾块只剩 1 个单元**时越界 |
| `isTndLayout` 只在 TND 分支置 true | 单次 TND 调用正确 | **跨调用**继承旧值 |
| `if (Times > 0) { ... Wait ... }` | 循环内同步配平 | **零迭代分支**绕过后置条件 |
| dw 路径读 `gradInput` 的 shape | 全输出场景正确 | dx 可为 `nullptr`，**所有权越界** |

**这六种错误，没有一种能被「关键词扫描」抓到，全部能被四问抓到。**

## 1. 四个问题

对**每一个参与计算、校验、寻址、搬运、资源分配的量**（不是每一个变量——只对真正驱动行为的量），依次回答：

### Q1 对象 — 这个量属于谁？

- 属于哪个 **tensor**（input / weight / bias / scale / offset / mask / indices / 单个 output / 某个中间结果）？
- 属于哪个 **buffer**（A 侧 / B 侧 / UB / L1 / workspace / 分片私有 / 共享）？
- 属于哪个 **坐标系**（全局 / 分核 / 局部 tile / CP 后的局部 S1、S2 / batch 内第几块）？
- 属于哪个 **dtype 位**（输入存储 / 计算 / 累加 / 输出存储）？

**答不出来 ⇒ 该量可能是「借来的」**——从别的对象取了 shape、stride、长度，这正是 FP-B04 子型②（可选输出反向依赖）和 26-06（对齐长度当真实长度）的共同根因。

### Q2 单位 — 这个数的量纲是什么？

七种单位，**混用即缺陷**：

| 单位 | 判据 |
|---|---|
| 元素个数 | 与 `GetShapeSize()` 同域 |
| 字节数 | = 元素数 × `GetSizeByDataType()` |
| 32B block 数 | 对齐后 / 32，`CeilDiv(x, 32)` |
| ND 单元数 | 与 `ndNum` / `blockCount` 同域 |
| repeat 次数 | 与 `repeatTimes` 同域（受 255 上限约束） |
| 物理对齐单元 | NZ 分形块，与逻辑 shape **不同域** |
| 时间 / 事件数 | Set/Wait 次数，与 buffer 数不必然相等 |

**答不出来 ⇒ 检查该量的两类消费者是否混用同一变量**：容量估算（要字节/对齐）与循环上界（要元素/真实长度）**必须分别持有变量**。26-06 的 `realK/realN` vs 对齐后长度、25-08 的 ceil 整批 vs floor 实际次数，都是这一个问题没答清。

### Q3 生命周期 — 谁创建、谁初始化、谁可写、何时复位？

四个子问，缺一不可：

1. **谁创建**：类成员 / 文件作用域（TU 级）/ 函数局部 / 每核 / 每 task？
2. **谁初始化**：**首次读取前**是否在**所有路径**都赋了确定值？（`if (A) flag = true;` 而 `else` 不置 false ⇒ 缺陷）
3. **谁可写**：单写者还是多写者？并行 worker 是否**单调写**（只把 true 改成 false，不反向）？
4. **何时复位**：per-call 状态是否在**每次进入**时重置？对象复用（executor 复用、tiling 对象复用）时呢？

**答不出来 ⇒ 按「跨调用污染」（FP-A21）或「共享结果竞争」（FP-A05）立观察项**。26-09 的 `isTndLayout`、25-10 的 `isNumColAlign`、25-04 的 `*output = true` 都在这里。

### Q4 消费者 — 这个量最终喂给谁？

四种消费者，判据完全不同：

| 消费者 | 该量必须是 | 若用错 |
|---|---|---|
| shape / 契约校验 | 逻辑 shape | 用对齐后 → 误拒或误接（FP-B01/B11） |
| 容量 / 资源估算 | 字节、对齐后 | 用元素数 → 申请不足或浪费（FP-D01） |
| 地址 / 偏移计算 | **64 位计算域** | 32 位回绕（FP-B07 成因⑥） |
| 指令参数（MM/DataCopy） | 物理布局、对齐单元 | 逻辑尺寸喂指令 → 越界或 NaN |

**答不出来 ⇒ 不能判「对齐是错的」也不能判「对齐是对的」**。库里最容易误判的一条：见到 `CeilAlign(...)` 就报「不该对齐」——但若消费者是 MM 指令，对齐是**必须**的；若消费者是循环上界，对齐就**必须**还原成真实长度。**先定消费者，再判对错。**

## 2. 用法：三个时刻

### 时刻一：候选定性（拿不准算不算缺陷）

对候选涉及的量逐个过 Q1~Q4，写成一页表：

| 量 | Q1 对象 | Q2 单位 | Q3 生命周期 | Q4 消费者 | 结论 |
|---|---|---|---|---|---|
| `outTypeSize` | `lin_space` 输出 tensor | 字节 | tiling 内局部 | tiling 容量估算 | **Q1 错**：应为计算 dtype → 命中 |
| `pbAL1`（weight 容量） | **A 侧**系数 | 字节 | tiling 局部 | L1 容量估算 | **Q1 错**：weight 属 B 侧 → 命中 |
| `ndNum = 2` | BMM2 搬运单元 | ND 单元 | kernel 局部 | `blockCount` / `cacheSize` | **Q2 错**：尾块实为 1 → 命中 |
| `isTndLayout` | tiling 对象成员 | bool | **类成员，跨调用** | tiling 分支选择 | **Q3 错**：非 TND 路径未复位 → 命中 |

**四问全答且自洽 ⇒ 才可撤销候选**（同时须给 `[文件]:[行号]` 负向证据，见各 skill 第 7 节）。

### 时刻二：模式归属（两个卡都能套，归哪个）

**按「哪一问答错了」归**，不按「代码长什么样」归：

| 答错的问题 | 归属 |
|---|---|
| Q1（对象） | 反向依赖 → FP-B04 ②；跨角色 shape → FP-B07（**必须先确认算式本身对，只错在操作数取错时**）；角度/坐标 → FP-A07 |
| Q2（单位） | 尾块/对齐/取整 → FP-B07；容量系数 → FP-A07 / FP-D01 |
| Q3（生命周期） | 跨调用 → FP-A21；未初始化 → FP-A05；并行共享 → FP-A05 |
| Q4（消费者） | 契约校验错位 → FP-B01 / FP-B11；同步后置条件 → FP-G02 |

> **2026-11-09 Q1 补充**：旧文案把 Q1 错一律指向 FP-B07，会在特定形态下归错卡。
> FP-B07 的 7 个成因（B07-1~B07-7）全是**偏移算式算错** —— 窄化溢出、符号翻转、
> `>=`/`>`、32B 对齐、次序、32 位回绕、负索引。但 Q1 错可以**完全不产生算式错误**。
>
> 实证 `ops-nn/index/repeat_interleave_grad`：
> `op_host/repeat_interleave_grad_tiling.cpp:79-85` 里
> `repeats_i_grad_dim_num = input_grad_shape.GetDim(axis_attr)`(=4)、
> `repeats_o_grad_dim_num = repeats_shape.GetDim(0)`(=2)，两个赋值各自都对；
> 错在 `op_kernel/repeat_interleave_grad.h:140` 把后者当**批步长**用 ——
> 遍历 4 次、每次跳 2 行，算到第 8 行而 `out` 只有 2 行，
> memcheck 报 9 条 `illegal read of size 12`（`size = data_dim_num(3) × 4B`，
> 正好是 out 一行）。
>
> **B07 的源码审查映射点扫不到这种错**：它扫 `int32_t`/`idxOffset`/`CeilDiv`/
> `DataCopy` blockLen，本案这些全都正确。
> 归卡时先问一句：**操作数取对了吗？** 取错 → 不是 B07。
> 判据是「同一函数内 ≥2 个名字相似、语义不同的维度变量，回溯赋值来源，
> 再核对 tiling 赋值处与 kernel 消费处的角色是否一致」；
> 重点查 `if (x == 1) {…} else {…}` 双分支给同一变量赋了**不同量纲**的值
> （本案 `==1` 分支给的是 `input/output` 商，else 分支给的是 raw dim）。

**若四问答错的方式在 52 张卡里都找不到位置** → 这是库的真实缺口，登记到对应 skill 的「模式库缺口」，或走 `patterns/` + `subtypes` 新增子型。

### 时刻三：审查起点（还没找到可疑点）

不要从关键词开始扫。先按**代码中的量**建表：把某函数内所有参与寻址、容量、循环上界、分支条件的量列出来，逐个过 Q1~Q4。**答不出的那一行就是可疑点**——这比「先扫签名再看命中」的假阳性低得多。

## 3. 与现有模式卡的映射（不重复造卡）

四问是**判定底座**，不是新模式。下表说明每问主要服务哪些卡——审查时仍以卡片自身的机理描述和检视清单为准：

| 问题 | 主要服务的模式 | 典型命中形态 |
|---|---|---|
| Q1 对象 | FP-B04（②可选输出反向依赖）、FP-B07、FP-A07、FP-A22 | 读了别的输出的 shape；A/B buffer 系数串用；dtype 分派错位 |
| Q2 单位 | FP-B07（①③④⑥）、FP-A07、FP-D01、FP-A19 | 元素/字节/block 混用；`>=` vs `>`；对齐长度当真实长度 |
| Q3 生命周期 | FP-A21、FP-A05、FP-A06、FP-A20 | 跨调用残留；未初始化；worker 内重复初始化；确定性上下文未传播 |
| Q4 消费者 | FP-B01、FP-B11、FP-B06、FP-B12、FP-G02 | 支持面过宽/过窄；早退跳过校验；同步后置条件不覆盖零迭代 |

## 4. 纪律

1. **只对驱动力矩量做四问**，不要给每个局部变量都建表——那是形式主义，会淹没真正的可疑点。
2. **四个问题必须**全部作答**，答「不确定」也要写明为什么不确定**——「答不出」本身就是产出（= 观察项），不是失败。
3. **Q4 未定，不得判 Q2 的对错**：对齐、取整、单位提升是否错误，**取决于消费者**。先定消费者再判。
4. **四问自洽 ≠ 无缺陷**：它排除的是「对象/单位/生命周期/消费者」这一族；数值稳定性、算法本身、精度口径仍需各自模式覆盖。
5. **不许用四问替代复现**：四问产出的是「候选 / 观察项 / 反证」，**立卡仍须按各 skill 第 7 节走正向 + 负向证据**。
6. **术语一致**：本库统一用「对象 / 单位 / 生命周期 / 消费者」，不引入同义词（如「归属/量纲/作用域/用途」），避免检索断链。
