# migration-audit：跨仓迁移 / 重构 / 分支合并专项

> 用于**代码从 A 仓搬到 B 仓、目录重构、大分支合并**后的风险体检：这类变更的典型失效不是「写错」，而是「**搬丢了**」——
> 防御分支、校验、属性透传、交付注册在搬运过程中静默消失，测试还全绿。

## 输入

- 迁移提交区间或 diff（必填，`git log --oneline A..B` 或 MR diff）；
- 源仓 / 目标仓（同仓目录重构则给两路径）；
- 是否含 proto / 接口签名变更（有则加跑交付面）。

## 阶段

### Stage 0 — 圈定变更面

1. 按目录归类 diff：`op_host` / `op_kernel` / `op_api` / `op_proto` / `tests` / `docs` / 构建文件；
2. 标出**被删除的行**（`-` 行）——迁移缺陷八成藏在这里；
3. 记录源/目标 HEAD，报告里写清「以哪一侧为基线」。

### Stage 1 — 三条主模式（必跑）

| 模式 | skill | 看点 |
|---|---|---|
| FP-B03 迁移丢失防御 / 拦截逻辑 | [fpb03-migration-review](../skills/FP-B/fpb03-migration-review/SKILL.md) | 被删的校验分支、`skipCheck` 类开关、无条件放行 |
| FP-B08 节点级配置未参与派发决策 | [fpb08-fallback-review](../skills/FP-B/fpb08-fallback-review/SKILL.md) | fallback 回调 / 前端插件 / fusion pass 三载体的属性透传 |
| FP-F04 接口交付面缺失 | [fpf04-delivery-review](../skills/FP-F/fpf04-delivery-review/SKILL.md) | 符号导出 / 原型注册 / 派发表 / 商分清单 / 开源同步 |

### Stage 2 — 前后拦截点比对表（本 workflow 的核心产出）

对 diff 中每一个被删 / 被改的校验点，填一行：

| # | 文件:行号 | 迁移前行为 | 迁移后行为 | 判定 | 证据 |
|---|---|---|---|---|---|
| 1 | `x.cpp:120` | 拦截非法 shape 返回 161002 | 分支被删，直接进 tiling | **丢失** | `diff -120` + 目标侧缺失 |

判定只有三种：**丢失**（应拦未拦）/ **保留**（迁移后仍有等价校验，写防护面证据）/ **有意删除**（须有提交说明或设计文档依据，否则按丢失处理）。

### Stage 3 — 回归建议

1. 对每个「丢失」项补一条负向用例（迁移前的拦截输入），断言返回码或早退行为；
2. 动态 shape / 空 tensor / 非法 rank 三类输入单独建组（迁移最常丢这三类拦截）；
3. 建议把「拦截点清单」纳入迁移 MR 的检查项，而不是一次性人工比对。

### Stage 4 — 报告

```markdown
# {迁移批次} 迁移风险报告（YYYY-MM-DD）
## 一、范围与口径（源/目标 HEAD、diff 区间、目录分布、删除行数）
## 二、三条主模式结论（B03 / B08 / F04，逐条命中或反证）
## 三、前后拦截点比对表（丢失 / 保留 / 有意删除）
## 四、回归建议（负向用例清单 + 纳入 MR 检查项）
## 五、残余风险（未覆盖目录、无法取证的宏/模板展开）
```

## 停止条件与边界

- 只审 diff 触及的文件 + 其直接调用方，不做全仓体检（要全量请用 [operator-admission](operator-admission.md)）；
- 宏展开、模板实例化、跨文件调用链无法完全还原时，在报告标「能力边界」，不得据此断言「无丢失」；
- 「测试全绿」不是反证：迁移丢的往往正是**没有用例覆盖的拦截分支**。
