# FP-A18 aclnn 接口检视（fpa18-int32float-review）

对用户指定的 aclnn 接口做 FP-A18 专项源码检视：先定位算子实现，再按清单逐项核查，每个结论给出**文件 + 行号 + 推导链**证据，命中即出 Bug 卡，输出检视报告。**本模式特殊纪律：① 缺陷表征是「边界值用例失败 / 分支选错」而非常规数值整体偏差——必须做**边界取值代入验算**（INT32_MAX/MIN、2^24 两侧）才能立卡；② 卡片触发为关键词（`numeric_limits<int32_t>|INT32_MAX|INT32_MIN`）——命中只作定位提示，真正的判据是**转换后用于比较且舍入改变走向**；③ 同一 `#5562` 在 FP-A18 与 FP-A15 两卡分别记录（tiling 极值转换比较 / kernel isnan 分支），检视该算子时两卡须同时核；④ **golden 曾按错误实现编写**（#5562 的 golden.py 随修复同步修改）——检视必须同步核测试资产，否则修了实现反而用例失败。**

## 0. 与相邻模式的边界

| 相邻模式 | 分工 |
|---|---|
| FP-A12（大整数转 fp32 计算精度损失） | **最易混淆项（卡片关联直指）**：同源不同焦点——A18 管**比较语义**（转换后用于比较 / 索引 / 阈值判断，分支走错），A12 管**数值计算损失**（转换后参与乘加 / 求和，结果整体偏差）。同一转换点两面并存时两卡连打，并在 Bug 卡内标注用途对表 |
| FP-A15（inf/nan 特殊值行为差异） | 卡片关联项：同为比较语义面——A18 是**有限大整数**舍入致阈值比较失真，A15 是**非有限值**（nan / inf）致比较分支走向错。实证 #5562 同时含两面，须连打 |
| FP-A11（AiCore 不支持 double 类型） | A11 是 double 类型在 AiCore 不可用（编译 / 功能面）；A18 是 int32→float 的舍入语义（精度面）——想用 double 规避舍入时须先确认 A11 可用性 |
| FP-A03（竞品高精度中间计算，NPU 直接低精度） | A03 是中间计算整体精度档位低于竞品；A18 是**单点转换**的舍入语义——阈值常量本身的档位设计问题归 A03 |
| FP-B07（索引 / 偏移计算错误致越界） | 同属 int32 主题：B07 管整型承载与符号语义（溢出 / 回绕 / 方向），A18 管转 float 后的舍入比较语义——#1928 类交叠按主导机理归属 |
| FP-E01（golden/UT 期望值失配或按错误实现编写） | **#5562 的 golden.py 随修复同步修改**——UT 期望值曾按错误实现编写；检视时须同步核测试资产，E01 连打 |

**症状反查定位**：边界值用例（INT32_MAX/MIN、2^24±1）精度失败而常规用例全过 → 首查该算子整型极值转 float 的比较点（#5562）；`constexpr float xxxMaxAsFloat` 类常量与标杆阈值不一致 → 极值转换舍入偏差；**分支选择错误**（走错阈值分支）而非数值整体偏差 → 比较语义面（本型）；数值整体偏差 → 移交 FP-A12；golden 与实现曾同步修改 → UT 期望值可能按错误实现编写（E01 连打）；大 shape 下索引比较失效 → 同步核 FP-B07。

## 1. FP-A18 模式卡摘要（检视依据，源自本库 `patterns/FP-A/FP-A18.md`，v3.1）

- **编号 / 名称**：FP-A18 int32 边界值转 float 舍入致比较语义偏差 ｜ **类别**：精度 ｜ **风险**：高（S3×O2=6）｜ **状态**：活跃 ｜ **来源**：ops-nn #5562 + 缺陷检视记录（2026-09-05）
- **适用声明头**（照抄卡片）：仓 All ｜ 侧别 All ｜ 载体 Tiling源码,Kernel源码 ｜ 触发 numeric_limits<int32_t>|INT32_MAX|INT32_MIN ｜ 默认启用 true
- **skill 核查面**：侧别 All——skill 落地为 `op_host` 的 tiling / infershape（极值常量定义与阈值比较，实证即在 tiling）、`op_kernel` 的比较 / 索引 / 掩码分支（隐式提升与混合表达式）、`tests/` 的 golden 与边界值用例（期望值口径与覆盖）
- **故障机理**：`int32` 大整数（> 2^24）转 `float` 时尾数位不足，**舍入后比较 / 索引语义偏差**。
- **触发条件**：int32 输入接近或超过 2^24；参与比较、索引、阈值判断。
- **典型表现**：边界值用例精度失败或分支选择错误。
- **源码审查映射点**：int32→float 的隐式转换点；比较 / 索引前的类型提升；`static_cast<float>/<double>(std::numeric_limits<int32_t/int64_t>::min()/max())` 等整型极值转换点；整型值与浮点阈值直接比较；混合 int/float 表达式的隐式提升；**标杆参考是否在整数域比较**。
- **检测签名**：`static_cast<(float|double)>\(\s*std::numeric_limits<(int32_t|int64_t)>::(min|max)`；`constexpr\s+(float|double)\s+\w*(Min|Max)\w*As(Float|Double)`。
- **测试拦截建议**：int32 边界值用例集（**2^24 两侧、INT32_MAX/MIN**）。
- **实证案例**：ops-nn **#5562**（int32 边界舍入致比较语义偏差），另 **58 处**静态扫描命中。ops-nn **#5562 / PR !9773** `threshold_grad_v2_d` 比较语义与标杆不一致——`threshold_grad_v2_d_tiling_arch35.cpp:92-93` 的 `constexpr float int32MinAsFloat/int32MaxAsFloat = static_cast<float>(std::numeric_limits<int32_t>::min()/max())`；**golden.py 随修复同步修改，证明 UT 期望值曾按错误实现编写**；2026-09-05 跨仓追溯命中 58 处同型风险点（ops-nn 37 / ops-transformer 14 / ops-math 7，P1）。同号 issue 另在 FP-A15 记录 kernel isnan 分支面——两卡连打。
- **关联**：FP-A12、FP-A15。

## 2. 检视输入与算子定位

**输入**：aclnn 接口名（必填）；可选 ref（默认 master）、指定仓（默认自动定位）；可选现象描述（失败的是哪类边界取值 / 是否表现为分支选错——用于症状反查）；可选复现输入（边界值取值、参与比较的另一侧阈值）；可选标杆来源（golden.py / 参考实现——整数域比较口径核对用）。

**接口名 → 算子目录换算**：去 `aclnn` 前缀 + 驼峰转下划线小写：
`aclnnThresholdGradV2D → threshold_grad_v2_d`（接口名以 `docs/aclnn*.md` 为准）、`aclnnReduceSum → reduce_sum`、`aclnnIndexFill → index_fill`。

**仓定位顺序**（GitCode `cann` 组织，逐仓用目录列表确认）：`ops-nn`（activation / norm / index 类——实证集中地）→ `ops-math` → `ops-transformer` → `ops-cv`。**类目名不总与直觉一致**，以目录列表为准。FP-A18 高发面：含阈值 / 掩码 / 分段判断的算子、tiling 中定义整型极值常量的算子、index / scatter 类（int32 索引与阈值比较）、含 `numeric_limits<int32_t>` 或 `constexpr float ...AsFloat` 的 tiling / kernel。

**算子目录结构约定**（已验证示例 `cann/ops-nn` → `activation/threshold_grad_v2_d/` 类目录，类目以目录列表确认）：

## 4. 比较语义检视清单（每点：查什么 → 何处 → 命中判据）

对 `op_host`（tiling / infershape）、`op_kernel`、`tests`（golden + 用例）逐点核查，**每点先查命中面、再做反证排除**，正确的整数域比较 / 显式提升写法也要记录为防护面证据。

### ① 整型极值转 float 的常量定义点
- 查什么：`static_cast<float>/<double>(std::numeric_limits<int32_t/int64_t>::min()/max())` 与 `constexpr float ...AsFloat/AsDouble` 类常量——转换后的值与数学真值差多少 ULP（如 INT32_MAX=2147483647 转 float 后为 2147483648.0f，差 1）；该常量**用于比较**还是用于计算。
- 何处：`op_host` tiling（`*_tiling*.cpp`，实证 `threshold_grad_v2_d_tiling_arch35.cpp:92-93`）、`op_kernel` 的阈值常量定义。
- 命中判据：极值转 float 后参与比较且差值可达 ULP 级（可给出「边界值 x → 转换值 → 比较结果与整数域真值不符」推导）⇒ 命中候选；仅用于计算 ⇒ 移交 FP-A12 口径，在本报告标注「已移交」。

### ② 比较 / 索引前的类型提升
- 查什么：整型值与浮点阈值**直接比较**处（`intVal > floatThr` 触发隐式提升）；是否应先提升到整型域或 double 再比较；混合 int/float 表达式的隐式提升方向（`int + float` 整体提升为 float）。
- 何处：`op_kernel` 比较分支、tiling 阈值判断、index / 掩码条件。
- 命中判据：比较双方一侧为 int32 大值、另一侧为 float ⇒ 命中候选（须给出边界取值下的走向差异）；双方同域（整型比整型 / 浮点比浮点）⇒ 反证排除。

### ③ 标杆是否在整数域比较
- 查什么：golden / 标杆参考实现是否在**整数域**比较（整数域精确），而 NPU 实现转 float 比较——口径不一致即偏差来源；golden 是否曾随实现同步修改（#5562 的 golden.py 同步改动即信号，连打 FP-E01）。
- 何处：`tests/assets/golden.py`、参考实现、`docs/` 语义说明。
- 命中判据：标杆整数域比较 + 实现浮点域比较 ⇒ 命中候选（并连打 E01 核测试资产）；两者同域 ⇒ 反证排除。

### ④ 与 A12 的分工判定
- 查什么：同一转换点是否**同时**用于计算与比较——分别归 A12 / A18，避免重复立卡或漏判。
- 何处：转换点的全部使用位置。
- 命中判据：给出「转换点 → 用途（计算 / 比较）→ 归属」对表，两用则两卡连打。

### 横切面：边界值用例覆盖
- 查什么：卡片拦截建议的边界值用例集（**2^24 两侧、INT32_MAX/MIN**）是否存在于用例集；纯常规取值用例天然漏检本型。
- 何处：`tests/` 用例与输入生成脚本。
- 命中判据：无边界值用例 + 存在静态命中的比较点 ⇒ 记观察项（测试建设缺口）；用例齐备 ⇒ 记录为防护面。

## 5. 检视流程

1. **定界**：换算 op 目录、确认所在仓与 ref；按用户现象（边界值失败 / 分支选错）反查优先清单点；收集边界取值与参与比较的另一侧阈值。
2. **枚举**：目录列表列出 `op_host`（tiling / infershape / op_api）、`op_kernel`（含架构子目录）、`tests`（含 golden）全部相关文件，产出文件清单。
3. **触发词扫描**：按 `numeric_limits<int32_t>|numeric_limits<int64_t>|INT32_MAX|INT32_MIN`、`constexpr\s+(float|double)\s+\w*(Min|Max)\w*As(Float|Double)`、`static_cast<(float|double)>` 与整型同现定位风险面（本地仓用 grep；API 模式逐文件拉取后检查）。**签名零命中时清单仍须逐项核查**（隐式转换、混合表达式同样命中面）。
4. **逐点核查**：每点记录命中面与防护面证据（文件:行号）；对每个比较点写出「左值类型 / 右值类型 → 是否隐式提升 → 边界取值代入（INT32_MAX、INT32_MIN、2^24±1）→ 比较结果 vs 整数域真值」五项对表。
5. **反证排除**：双方同域比较、显式提升到整型 / double、极值常量仅用于计算、标杆与实现同域 → 明确写出反证理由。
6. **判定**：按第 7 节标准给出 命中 / 观察项 / 反证排除。
7. **GitCode 查重**（仅命中项）：issues API 按接口名 + `边界|int32|精度|比较` 检索，逐条比对是否同机理；无同机理才立卡。
8. **业务可达性核查**（仅命中项）：判 B 等级、定业务影响类型、给处置建议；默认保守（无法证明不可达即记 B3），降档须附证据；B 不改 S×O 档位。
9. **出报告**：按第 8 节模板落盘；所有数值后果标注「静态推演，需 NPU 实测确认」，并附边界值用例与 golden 口径核对方案。

## 6. 风险定级（S×O）与业务影响评估（B 轴）

- **S**：S3（比较语义偏差致结果错 / 分支选择错误——结果错但可运行）；S2（仅在极端边界值才显、影响范围有限）；S1（仅测试覆盖缺口、比较语义正确）。
- **O**：O3 = ≥2 条独立实证；O2 = 1 条独立实证；O1 = 仅静态扫描命中或团队笔记（实证 = 确认对应的 issue / PR，或经跨仓、跨分支核验确认的缺陷记录，同权计入）。静态推演命中且无实证默认 **O1**；升档须在报告中给出实证依据。
- **风险 = S×O**：≥6 高；3/4 中；1/2 低。FP-A18 基准：模式卡整体 **S3×O2=6（高）**；纯静态命中 S3×O1=3（中，暂定），实测后复评。

### B 轴：业务影响评估（与 S×O 正交；报告层新增，不改卡片定级）

S×O 回答"多严重、多常见"，**不回答"真实业务能不能碰到"**。B 轴补这一问，只决定**修复优先级建议**，**不参与 S/O 取值、不改 S×O 档位与卡片元数据**。

**业务可达性（B）**——触发条件在真实负载中的可达程度：

| 等级 | 判据 | 证据要求 |
|---|---|---|
| B3 现实可达 | 主流框架/公开模型默认路径即可命中（如 PTA/torch_npu、vLLM、MindIE 常规调用） | 调用方或公开负载来源 |
| B2 条件可达 | 需特定 attr/dtype/shape 组合，业务中存在但非默认 | 该组合的业务来源 |
| B1 边界/不可达 | 需极端、超规格或非法参数（超出接口合理上限的 shape、退化/非法输入） | "为何不可达"的说明 |

- **默认保守**：无法证明不可达 → 记 **B3**；降为 B1/B2 必须附证据，**不得仅凭"业务应该不会这么用"**。
- 超规格参数是否算 B1 取决于**接口契约**：契约允许但业务不用 → B1；契约不允许（本应报错）→ 属校验缺失（FP-B04/B05 类），另行归属。

**业务影响类型**（命中后对用户可见结果的后果，用业务语言表述）：静默精度损失（模型效果下降 / loss 不收敛 / 偶发 NaN）｜ 任务失败中断（报错 / 崩溃 / 挂死）｜ 性能退化 ｜ 仅可观测性（日志 / 错误码 / 文档，不影响结果）。

**处置建议**（由两轴推导的报告结论，非新档位）：

| S×O \ B | B3 现实可达 | B2 条件可达 | B1 边界/不可达 |
|---|---|---|---|
| 高（≥6） | 尽快修 | 尽快修 | 排期修 |
| 中（3/4） | 尽快修 | 排期修 | 记录（业务难以触达） |
| 低（1/2） | 排期修 | 记录 | 记录 |

## 7. 判定标准与反误报原则

- **签名 / 触发词命中 ≠ 成立**：`numeric_limits<int32_t>` 命中只说明存在极值转换——必须过「转换值 ULP 差 + 用途为比较 + 边界取值走向差异」三关；用于计算的移交 A12。
- **三种判定**：
  - **命中**（可静态证缺陷路径）：极值 / 大值转 float 参与比较 + 边界取值代入后走向与整数域真值不符（或与标杆口径不符）的推导链完整 ⇒ 立 Bug 卡；
  - **观察项**：走向差异需运行时实测确认、或标杆口径待确认（E01 未决）⇒ 记录并附边界值用例方案，按 S3×O1 暂定；
  - **反证排除**：双方同域比较、显式整型 / double 提升、极值常量仅用于计算 → 写出防护面证据与反证理由。
- **必须同步核测试资产**：#5562 的 golden.py 随修复同步修改——期望值可能按错误实现编写；只修实现不改 golden 会使用例失败，反之只改 golden 会掩盖缺陷。判定时给出「实现 + golden 双侧」结论（E01 连打）。
- **「常规用例全绿」不是反证**：本型识别特征正是「常规取值全过、边界取值才失败」——用例覆盖面须按边界取值核。
- **与 A12 / A15 连打纪律**：同一转换点两用 → A12 连打；同一比较点涉及非有限值 → A15 连打；报告中须写明归属与移交。
- **不臆造行号**：每条证据必须是实际读到的 文件:行号；引用 #5562 时注明 issue 时点行号与本地 HEAD 的漂移。
- **静态推演声明**：无 NPU 环境时，所有运行时行为结论必须标注「静态推演，需 NPU 实测确认」。

### 判定纪律补充（v3.6）：非对称增减、证据等级与误判记录

**增减不对称**：允许追加候选（有据即可，错了可由用户排除）；**撤销或否决候选必须附 `[文件]:[行号] [代码行]` 负向证据**。无证据的「看起来没问题」一律记为「未核查」，不得计入反证排除，也不得据此下调等级——否决造成的漏报用户不可见、不可恢复。

- **证据等级**（Bug 卡必填）：`静态可证` = 推导链完整且触发输入可静态构造；`需实测确认` = 依赖运行时输入规模、设备行为或环境差异。标 `需实测确认` 的条目**不得以「命中」名义出卡**，按观察项记录并附实测用例。
- **Agent 误判记录**（Bug 卡必填）：本次被推翻的假设、推翻它的证据（`[文件]:[行号] [代码行]` 或实测输出）、判定标准是否随之修订；无推翻写「无」。
- **误判回流**：同类误判在 3 次检视中重复出现，登记至 `cases/misjudgments.jsonl`（字段见 `cases/README.md`），并在本模式判定标准中新增对应防线；守门 C19d 校验台账字段合法。

## 10. 能力边界与自检（v3.8）

### 能力边界

- **静态可证**：清单里能在源码内给出「`文件:行号` + 推导链」的部分，按第 7 节判据出卡。
- **需实测确认**：依赖运行时输入规模、设备行为或环境差异的结论，只能记观察项并附实测用例（证据等级见第 7 节）。
- **不覆盖**：本模式以外的机理（边界见第 0 节）与仓外框架侧行为；`TRIAGE.md` 只负责收敛候选，不构成判定依据。
- **找不到 ≠ 没有**：按清单未命中只说明「本轮未发现」，不得表述为「该算子无此缺陷」；抽样核查须在报告写明抽样口径。
