变更摘要
该 PR 修复了
NsaCompressAttention
中 TopK 操作临时缓冲区大小硬编码导致的内存检测问题。原先使用固定值
20 * S2sizeAlign32
估算临时 UB 空间，不同配置下可能分配不足或浪费。本次改动引入 AscendC 运行时 API
GetTopKMaxMinTmpSize
动态计算实际所需的临时内存大小，并通过新增的 tiling 字段
tmpUbSize
传递给 kernel 层使用，确保内存分配与实际需求一致。
主要改动
新增 tiling 字段
tmpUbSize
：在
nsa_compress_attention_tiling.h
的 TILING_DATA 中新增
tmpUbSize
字段，用于记录 TopK 操作所需的临时 UB 缓冲区大小。
TopKTiling()
中动态计算临时缓冲区大小
：在
nsa_compress_attention_tiling_general.cpp
的
TopKTiling()
函数中，调用
AscendC::GetTopKMaxMinTmpSize
获取
maxsize
，并通过
importanceScoreParams.set_tmpUbSize()
写入 tiling 数据。
Kernel 层使用动态
tmpUbSize
替代硬编码值
：在
nsa_compress_attention_s1s2_bn2gs1_sab.h
中，
maxTopkBase
的计算由
190 * 1024 - 20 * S2sizeAlign32
改为
190 * 1024 - tmpUbSize
，
topKTmpLocal
的偏移量由
20 * S2sizeTopK
改为
tmpUbSize
，消除硬编码假定的缓冲区大小。
