# FP-E02 精度判据与标杆设施检视（fpe02-benchmark-review）

对用户指定的精度判据 / 标杆设施（cann-bench，如涉及 MERE/MARE 近零相消的判据）做 FP-E02 专项检视：先定位精度比对基础设施（判据实现、阈值表、标杆生成与装载、用例配置），再按五成因清单逐项核查，每个结论给出**文件 + 行号 + 推导链**证据，命中即出 Bug 卡，输出检视报告。**本模式特殊纪律：① 检视对象是**判据/标杆本身**，不是被测算子的实现质量——「失败与 NPU 实现无关（换任何合法实现都 FAIL）」是本型的核心指纹；② 卡片适用声明为「触发：无代码触发特征」——不依赖签名命中，对被检判据设施无条件执行五成因清单；③ 失败/误报是否发生需批量跑与数值实验确认，静态检视只能立「判据口径缺陷路径 + 数值反例」，不可直接表述为「必然误报」。**

## 0. 与相邻模式的边界

| 相邻模式 | 分工 |
|---|---|
| FP-E01（golden/UT 期望值失配） | **最易混淆项**：E01 是 **golden 期望值本身错**（数据/约定错，用例永远绿）；E02 是 **判据/标杆口径设计错**（容差、比对方式、标杆选择、分母退化）。**换一套判据口径能救的归 E02**，期望值数据本身错的归 E01；二者常叠加放大，命中时双向互查 |
| FP-A02（累加顺序差） | 累加顺序差是**本型误报的物理来源**——A02 管实现侧归约顺序（真实精度行为），E02 管判据是否把合法的顺序差放大成 FAIL |
| FP-A20（确定性等级描述不足） | 同属「口径未声明」家族：A20 是确定性面未分级标注，E02 成因⑤ 是中间计算精度口径未声明 |
| FP-B01（校验过严/声明与实现不符） | 声明面与实现面不符在精度口径上的呈现（实证 #5675：文档声明 A2 HF32、实际 fp16 分支因前置 cast 不可达）——B01 管校验拦截面，E02 管精度判据面 |
| FP-E01（golden 本身错） | 见上，二者叠加 |

**症状反查定位**：同 shape 同 dtype **换 cubeMathType 即大面积翻转** PASS/FAIL → 成因①；失败误差**恒为 1 ulp 量级且无放大** → 成因②；**rmse 比值远大于 mare/mere 比值**（分母塌陷指纹）→ 成因④；**近零/相消输出点**失败、`golden==native` 时容差为 0 → 成因③；**bf16 超阈而 fp16/fp32 同机制漏报** → 成因⑤；同族通过/失败的分界是**基准误差是否为 0** 而非 NPU 误差幅度 → 成因④。

## 1. FP-E02 模式卡摘要（检视依据，源自本库 `patterns/FP-E/FP-E02.md`，v3.1）

- **编号 / 名称**：FP-E02 精度测试判据与标杆口径设计缺陷 ｜ **类别**：测试有效性 ｜ **风险**：高（S3×O3=9）｜ **状态**：活跃
- **适用声明头**（照抄卡片）：仓 cann-bench ｜ 侧别 All ｜ 载体 UT与golden资产 ｜ 触发 无代码触发特征 ｜ 默认启用 true
- **skill 核查面**：载体为 UT 与 golden 资产——skill 落地为 cann-bench 的**精度比对基础设施**：判据实现（阈值与比对公式）、阈值配置表、标杆（golden）生成与装载、用例配置（含 cubeMathType 等属性）、平台别名/基线映射表；被测算子仓（ops-nn / ops-math / ops-cv / ops-transformer）作为**触发场景来源**（提供近零相消、极端值域、窄类型多步累加、降精度属性等用例），仅在判定「判据是否与实现口径同侧」时读取
- **故障机理**：精度比对基础设施的**判据/标杆选择设计缺陷**导致结构性误报（假阳性泛滥、用例被误关停）或漏报（真缺陷被口径吞掉）。五种独立成因：① **降精度模式误比全精度标杆**——cubeMathType=1/2/3（HF32/FP16 降精度）按文档语义降精度计算，却被与不降精度的 GPU 标杆比较，失败率 100% 属口径分歧；② **阈值紧贴 1 ulp 理论下界**——single_bm 阈值（fp16 1.125×2⁻¹¹、bf16 1.015625×2⁻⁸）落在 1 ulp 相对误差带内，任何孤立 1 ulp 舍入翻转几乎必然判 FAIL；③ **相对误差判据缺绝对误差地板**——近零/相消输出点上累加顺序差被放大 60 倍以上，`golden==native` 时容差为 0，任何 NPU 实现结构性不可通过；④ **双标杆比例分母退化**——基准侧误差恰为 0 时比例分母取固定下限 2⁻¹⁴，RMS 判据退化为与数值量纲无关的绝对误差要求，极端值域下必然失败；⑤ **中间计算精度口径未声明**——文档公式不规定乘加中间精度，「fp32 中间累加+出口单次舍入」与「逐步落回窄类型」两条合法路径的系统性 1 ULP 分歧无裁定依据，同机制在 fp16/fp32 上低于阈值而漏报、仅在 bf16 上超阈而误报。
- **触发条件**：ATK/TTK 批量精度测试；含 cubeMathType 降精度属性、近零相消输出、极端值域（±1e30）、窄类型（bf16）多步累加的算子；阈值按「1 ulp × 1.125」类口径设定。
- **典型表现**：同 shape 同 dtype 换 cubeMathType 即大面积翻转 PASS/FAIL；失败误差恒为 1 ulp 量级且无放大；rmse 比值远大于 mare/mere 比值（分母塌陷指纹）；失败与 NPU 实现质量无关（换任何合法实现都 FAIL）。
- **源码审查映射点**：判据分母（native/golden 误差为 0 时的退化路径）与绝对误差地板；阈值与 1 ulp 带的相对位置；降精度模式与标杆精度是否同侧；文档是否声明中间计算精度口径。
- **测试拦截建议**：判据增加与量纲无关性解耦的绝对误差地板（近零兜底不得复用 golden 自身误差为分母）；降精度模式用同精度标杆或按口径豁免；阈值设定对 1 ulp 翻转留裕度（≥1 ulp 上界而非带内）；文档显式声明中间精度口径后再定判据；建立「rmse/mare 比值失衡 = 判据缺陷指纹」的自动识别。
- **实证案例**：cann-bench **#59**（closed）MERE/MARE 近零相消结构性不可通过——golden（CPU fp32）与候选（NPU fp32）对 fp64 真值误差同量级（3.99e-5 vs 5.14e-5），仅因 golden 近零点相对误差放大 60 倍判 FAIL，且 `golden==native` 时容差为 0 无地板；ops-nn **#5657** AdaptiveAvgPool3d fp32 ±1e30 用例基准侧误差为 0 时比例分母退化至 2⁻¹⁴，1 ulp（7.56e22）必然超阈，同族通过/失败的分界是基准误差是否为 0 而非 NPU 误差幅度；ops-nn **#5692** AvgPool2d 阈值恰落 1 ulp 带内（fp16 约 78%、bf16 约 97% 取值位置必然超阈），65/88 例失败均为 1 ulp 翻转；ops-nn **#5694** Baddbmm 降精度模式与全精度标杆误比 257/1000（cmt=2 100% FAIL；同 shape bf16 对照 cmt=0 与标杆逐位一致而 cmt=1/2 23/28 超阈）；ops-nn **#5675** AvgPool2dBackward 文档声明 A2 HF32 实际 fp16 分支因前置 cast 不可达（实现与声明不符同框暴露）；ops-transformer **#5071** MoeTokenUnpermuteWithEp「fp32 累加+单次舍入」vs 参考逐步落 bf16 系统性 1 ULP，bf16 用例 72.6% FAIL 而 fp16/fp32 同机制漏报（1 ULP 低于阈值）；ops-transformer **#5045** MoeFinalizeRouting bf16 中间精度口径文档未声明，299/331（90.3%）FAIL 且 K=1 无累加项也失败。**共性特征：失败与 NPU 实现质量无关，判据/标杆口径单侧即可决定 PASS/FAIL。**
- **关联**：FP-E01（golden 本身错 vs 判据设计错，常叠加）、FP-A20（口径未声明家族）、FP-A02（累加顺序差是本型误报的物理来源）、FP-B01（声明面与实现面不符在精度口径上的呈现）。

## 2. 检视输入与检视对象定位

**输入**：判据/标杆设施标识（必填，如「MERE/MARE 判据」「single_bm 阈值表」「cann-bench 精度比对框架」；也可给被测算子名 + 失败用例清单反查）；可选 ref（默认 master）；可选**被测仓暴露 issue**（如 ops-nn #5657 / ops-transformer #5071——提供触发场景与失败统计，是判据缺陷的主要证据来源）；可选**失败用例清单 / PASS-FAIL 翻转统计**（用于定位判据分支与阈值行）。

**被测算子名 → 触发场景换算**：去 `aclnn` 前缀 + 驼峰转下划线小写，用于反查该场景在 cann-bench 走哪条判据分支：
`aclnnAdaptiveAvgPool3d → adaptive_avg_pool3d`、`aclnnBaddbmm → baddbmm`、`aclnnMoeFinalizeRouting → moe_finalize_routing`。

**仓定位顺序**：
1. **判据设施所在仓**：`cann-bench`（GitCode `cann` 组织）——判据实现、阈值表、标杆生成/装载、用例配置、平台别名/基线映射均在此仓；
2. **触发场景来源仓**（仅提供用例场景与失败统计）：`ops-nn` → `ops-math` → `ops-cv` → `ops-transformer`；
3. **被测算子实现**（仅在判「判据是否与实现口径同侧」时读）：对应算子仓的 op_host / op_kernel / docs。

**判据设施面结构约定**（以 cann-bench 目录列表为准；下列为需逐一定位的设施面，不含未经核实的固定文件名）：

```text
cann-bench/
├── {比对实现}        # 判据核心：误差公式（relative/absolute/RMS/MERE/MARE）、容差判定分支
├── {阈值配置}        # single_bm 类阈值表：fp16/bf16/fp32 各自的容差取值（1 ulp 带位置核对点）
├── {标杆生成/装载}   # golden（CPU fp32 / GPU / 三方）生成与载入——标杆精度是否与降精度模式同侧
├── {用例配置}        # 用例属性：cubeMathType、dtype、shape、极端值域（±1e30）、近零相消场景
├── {平台别名/基线}   # 平台别名表与基线映射（评测平台选型面）
└── {文档/口径声明}   # 中间计算精度口径、降精度模式语义的文档依据
```

**设施面 → 成因映射**：判据核心 → 成因③④；阈值配置 → 成因②；标杆生成/装载与用例属性 → 成因①⑤；文档口径声明 → 成因⑤。

## 4. 五成因检视清单（每点：查什么 → 何处 → 命中判据）

对判据设施的全部设施面逐点核查，**每点先查命中面、再做反证排除**；判据设计正确的部分也要记录（作为反证依据）。

### 成因① 降精度模式误比全精度标杆
- 查什么：判据/用例在 `cubeMathType=1/2/3`（HF32/FP16 降精度）下，**标杆（golden/参考）是否与降精度模式同侧**——按文档语义降精度计算的输出，若被与**不降精度**的 GPU/全精度标杆比较，失败率 100% 属口径分歧而非实现缺陷。
- 何处：判据的标杆选择分支、用例配置中的 `cubeMathType` 属性处理、标杆生成/装载逻辑。
- 命中判据：能写出「降精度模式 → 选用了全精度标杆 → 差异来自降精度语义本身」的静态推导（实证 #5694：cmt=2 100% FAIL，而同 shape bf16 的 cmt=0 与标杆逐位一致）。

### 成因② 阈值紧贴 1 ulp 理论下界
- 查什么：阈值（如 single_bm 的 fp16 1.125×2⁻¹¹、bf16 1.015625×2⁻⁸）与 **1 ulp 相对误差带**的相对位置——阈值落在带内时，任何孤立 1 ulp 舍入翻转几乎必然判 FAIL；核对各 dtype 阈值是否有对 1 ulp 翻转的裕度（≥1 ulp 上界）。
- 何处：阈值配置表（按 dtype 取值）、判据的比较分支。
- 命中判据：阈值与 1 ulp 带位置可静态比对，且能构造「某取值位置必然超阈」的反例（实证 #5692：fp16 约 78%、bf16 约 97% 取值位置必然超阈，65/88 例失败均为 1 ulp 翻转）。

### 成因③ 相对误差判据缺绝对误差地板（近零/相消）
- 查什么：判据分母在 **native/golden 误差为 0** 时的退化路径，以及是否设**与量纲无关的绝对误差地板**——近零/相消输出点上累加顺序差被放大 60 倍以上，`golden==native` 时容差为 0，任何 NPU 实现结构性不可通过；近零兜底**不得复用 golden 自身误差为分母**。
- 何处：判据的 relative/absolute 误差公式、分母计算段与兜底分支。
- 命中判据：能构造**近零相消反例**（golden 与候选对 fp64 真值误差同量级，仅因相对误差放大判 FAIL——实证 cann-bench #59：3.99e-5 vs 5.14e-5、放大 60 倍、容差为 0）。

### 成因④ 双标杆比例分母退化
- 查什么：双标杆（比例判据）在**基准侧误差恰为 0** 时，比例分母是否取固定下限（如 2⁻¹⁴）——分母退化使 RMS 判据**退化为与数值量纲无关的绝对误差要求**，极端值域（±1e30）下 1 ulp 必然超阈；同族通过/失败的分界是**基准误差是否为 0** 而非 NPU 误差幅度。
- 何处：双标杆比例公式的分母计算段、下限兜底常量、RMS 判据实现。
- 命中判据：能构造「基准误差=0 → 分母退化到下限 → 1 ulp 超阈」的静态推导（实证 #5657：1 ulp = 7.56e22 必然超阈）。

### 成因⑤ 中间计算精度口径未声明
- 查什么：文档公式是否规定**乘加中间精度**——「fp32 中间累加 + 出口单次舍入」与「逐步落回窄类型」两条合法路径的系统性 1 ULP 分歧无裁定依据时，同机制在 fp16/fp32 上低于阈值而漏报、仅在 bf16 上超阈而误报；核对口径声明与判据阈值是否配套。
- 何处：判据文档/口径声明、判据的中间精度假设、用例 dtype 矩阵。
- 命中判据：口径缺失 + 能构造「同一实现两条合法路径 → bf16 超阈、fp16/fp32 通过」的反例（实证 #5071：bf16 72.6% FAIL 而 fp16/fp32 漏报；#5045：bf16 299/331 FAIL 且 K=1 无累加项也失败）。

### 横切面：判据缺陷指纹的自动识别
- 查什么：是否建立「**rmse/mare 比值失衡 = 判据缺陷指纹**」的自动识别——`rmse 比值远大于 mare/mere 比值` 即分母塌陷信号；失败误差**恒为 1 ulp 量级且无放大**即阈值带内信号；**失败与 NPU 实现质量无关**（换任何合法实现都 FAIL）是本型最根本指纹。
- 何处：判据报告的统计输出、CI 的失败聚类逻辑。
- 命中判据：指纹可静态/统计识别且与某一成因对应 ⇒ 提升该成因的判定置信度。

### 防护面与反证（记录用）
- 查什么：已有的绝对误差地板、降精度同侧标杆、阈值 1 ulp 裕度、分母下限的**量纲一致性处理**、口径声明——逐条记录（文件:行号）作为反证依据。

## 5. 检视流程

1. **定界**：确定判据/标杆设施标识，确认 cann-bench 仓与 ref；若给的是被测算子名 + 失败统计，先换算场景并反查走哪条判据分支；确认触发场景来源 issue 是否提供。
2. **枚举**：目录列表定位判据设施面全部文件（判据核心 / 阈值配置 / 标杆生成装载 / 用例配置 / 平台别名 / 文档口径），产出文件清单与「设施面 → 成因」映射。
3. **触发词扫描**：按 `cubeMathType|cube_math_type|single_bm|1.125|1.015625|rmse|mare|mere|RMS|2\^-14|1e-14|tolerance|rtol|atol|benchmark|PLATFORM_ALIAS` 定位风险面（本地仓用 grep；API 模式逐文件拉取后检查）。**卡片触发为「无代码触发特征」：签名零命中时五成因清单仍须逐项核查完毕。**
4. **五成因逐项核查**：每点记录命中面与防护面证据（文件:行号）；对阈值做 1 ulp 带位置比对，对分母做退化路径推导，对标杆做同侧判定，对口径做声明核对。
5. **反证排除**：判据确有绝对误差地板、降精度模式用同精度标杆、阈值对 1 ulp 有裕度、分母下限做了量纲一致性处理、口径已声明 → 明确写出反证理由。
6. **判定**：按第 7 节标准给出 命中 / 观察项 / 反证排除。
7. **GitCode 查重**（仅命中项）：issues API 在 cann-bench 与触发场景仓按 `精度|判据|阈值|MERE|MARE|rmse|FAIL` 检索，逐条比对是否同机理；无同机理才立卡。
8. **业务可达性核查**（仅命中项）：判 B 等级、定业务影响类型、给处置建议；默认保守（无法证明不可达即记 B3），降档须附证据；B 不改 S×O 档位。
9. **出报告**：按第 8 节模板落盘；静态结论一律附数值实验/批量跑方案（近零相消输入、±1e30 极端值域、cubeMathType 矩阵、bf16 多步累加）。

## 6. 风险定级（S×O）与业务影响评估（B 轴）

- **S**：S3（验证体系失效——假阳性泛滥致用例被误关停、真缺陷被口径吞掉漏报）；S2（单一 dtype/单一成因的局部判据缺陷——降级）。
- **O**：O3 = ≥2 条独立实证；O2 = 1 条独立实证；O1 = 仅静态扫描命中或团队笔记（实证 = 确认对应的 issue / PR，或经跨仓、跨分支核验确认的缺陷记录，同权计入）。静态推演命中且无实证默认 **O1**；升档须在报告中给出实证依据。
- **风险 = S×O**：≥6 高；3/4 中；1/2 低。FP-E02 基准：模式卡整体 S3×O3=9（高，7 条实证）；纯静态命中 S3×O1=3（中，暂定）。

### B 轴：业务影响评估（与 S×O 正交；报告层新增，不改卡片定级）

S×O 回答"多严重、多常见"，**不回答"真实业务能不能碰到"**。B 轴补这一问，只决定**修复优先级建议**，**不参与 S/O 取值、不改 S×O 档位与卡片元数据**。

**业务可达性（B）**——触发条件在真实负载中的可达程度：

| 等级 | 判据 | 证据要求 |
|---|---|---|
| B3 现实可达 | 主流框架/公开模型默认路径即可命中（如 PTA/torch_npu、vLLM、MindIE 常规调用） | 调用方或公开负载来源 |
| B2 条件可达 | 需特定 attr/dtype/shape 组合，业务中存在但非默认 | 该组合的业务来源 |
| B1 边界/不可达 | 需极端、超规格或非法参数（超出接口合理上限的 shape、退化/非法输入） | "为何不可达"的说明 |

- **默认保守**：无法证明不可达 → 记 **B3**；降为 B1/B2 必须附证据，**不得仅凭"业务应该不会这么用"**。
- 超规格参数是否算 B1 取决于**接口契约**：契约允许但业务不用 → B1；契约不允许（本应报错）→ 属校验缺失（FP-B04/B05 类），另行归属。

**业务影响类型**（命中后对用户可见结果的后果，用业务语言表述）：静默精度损失（模型效果下降 / loss 不收敛 / 偶发 NaN）｜ 任务失败中断（报错 / 崩溃 / 挂死）｜ 性能退化 ｜ 仅可观测性（日志 / 错误码 / 文档，不影响结果）。

**处置建议**（由两轴推导的报告结论，非新档位）：

| S×O \ B | B3 现实可达 | B2 条件可达 | B1 边界/不可达 |
|---|---|---|---|
| 高（≥6） | 尽快修 | 尽快修 | 排期修 |
| 中（3/4） | 尽快修 | 排期修 | 记录（业务难以触达） |
| 低（1/2） | 排期修 | 记录 | 记录 |

## 7. 判定标准与反误报原则

- **「失败与实现无关」优先于「失败率高」**：本型的第一后果是**结构性误报/漏报**——一个阈值宽松但口径正确的判据不构成命中；一个失败率高、但换任何合法实现都 FAIL 的判据是高危命中。
- **三种判定**：
  - **命中**（可静态证缺陷路径）：「降精度误比全精度标杆」「阈值落 1 ulp 带内」「缺绝对误差地板致近零不可通过」「分母退化到固定下限」「中间精度口径未声明」任一推导链完整 + 数值反例可静态构造 + 反证排除失败 → 立 Bug 卡；
  - **观察项**：需数值实验/批量跑才能量化翻转率、或口径分歧取决于文档裁定 → 记录并附验证方案，按 S3×O1 暂定；
  - **反证排除**：判据有绝对误差地板、降精度用同精度标杆、阈值有 1 ulp 裕度、分母做了量纲一致性处理、口径已声明 → 明确写出反证理由（防护面证据）。
- **换口径能救 = E02，期望值本身错 = E01**：判定前先确认失败是否可**仅通过改判据/标杆口径**消除——能则归 E02，不能（golden 数据本身错）归 E01，二者常叠加需双向互查。
- **可达性分析要给出可复现反例**：具体 dtype（bf16/fp16/fp32）、cubeMathType 取值、值域（±1e30）、输入形态（近零相消 / K=1 无累加项）写具体值，不写「某些用例」泛称。
- **不臆造行号与阈值**：每条证据必须是实际读到的 文件:行号 / 阈值常量；引用实证样板时同样给出路径与行号，issue 时点行号与本仓 HEAD 漂移时注明。
- **静态推演声明**：无批量跑环境时，所有翻转率/误报率结论必须标注「静态推演，需批量精度测试确认」，并附数值实验方案。

### 判定纪律补充（v3.6）：非对称增减、证据等级与误判记录

**增减不对称**：允许追加候选（有据即可，错了可由用户排除）；**撤销或否决候选必须附 `[文件]:[行号] [代码行]` 负向证据**。无证据的「看起来没问题」一律记为「未核查」，不得计入反证排除，也不得据此下调等级——否决造成的漏报用户不可见、不可恢复。

- **证据等级**（Bug 卡必填）：`静态可证` = 推导链完整且触发输入可静态构造；`需实测确认` = 依赖运行时输入规模、设备行为或环境差异。标 `需实测确认` 的条目**不得以「命中」名义出卡**，按观察项记录并附实测用例。
- **Agent 误判记录**（Bug 卡必填）：本次被推翻的假设、推翻它的证据（`[文件]:[行号] [代码行]` 或实测输出）、判定标准是否随之修订；无推翻写「无」。
- **误判回流**：同类误判在 3 次检视中重复出现，登记至 `cases/misjudgments.jsonl`（字段见 `cases/README.md`），并在本模式判定标准中新增对应防线；守门 C19d 校验台账字段合法。

## 9. 示例速览：cann-bench 精度判据（MERE/MARE 与 single_bm）

- **定位**：判据设施在 `cann-bench`（GitCode `cann` 组织）——判据核心（MERE/MARE/RMS 误差公式与容差分支）、阈值配置（single_bm：fp16 1.125×2⁻¹¹、bf16 1.015625×2⁻⁸）、标杆生成/装载、用例配置（cubeMathType、dtype、值域）、平台别名表；触发场景来源为 `cann/ops-nn` 与 `cann/ops-transformer` 的相关算子用例。
- **检视面提示**（引导，不预设结论，仍须逐点核查；行号以本地 HEAD 为准）：
  - 成因③（近零相消）：判据 relative 误差公式的分母与兜底分支——核对 `golden==native` 时容差是否为 0、近零兜底是否复用 golden 自身误差为分母（实证 cann-bench #59：3.99e-5 vs 5.14e-5、放大 60 倍）；
  - 成因④（分母退化）：双标杆比例公式的分母下限常量（2⁻¹⁴）——核对基准误差为 0 时 RMS 判据是否退化为绝对误差（实证 ops-nn #5657：±1e30、1 ulp=7.56e22 必然超阈）；
  - 成因②（阈值带内）：single_bm 阈值表 fp16/bf16 取值与 1 ulp 带位置（实证 ops-nn #5692：65/88 例失败均为 1 ulp 翻转）；
  - 成因①（降精度误比）：标杆选择分支 × 用例 `cubeMathType`（实证 ops-nn #5694：cmt=2 100% FAIL）；
  - 成因⑤（口径未声明）：判据文档中间精度口径 × bf16 用例（实证 ops-transformer #5071 bf16 72.6% FAIL、#5045 bf16 299/331 FAIL 且 K=1 也失败）；
  - 旁证：ops-nn #5675 AvgPool2dBackward 声明 A2 HF32 而实际 fp16 分支不可达（声明面与实现面同框暴露，归 FP-B01 交叉核）。
- 任何一点的最终判定以第 4/5/7 节口径为准，禁止凭对象类型直接下结论。

## 10. 能力边界与自检（v3.8）

### 能力边界

- **静态可证**：清单里能在源码内给出「`文件:行号` + 推导链」的部分，按第 7 节判据出卡。
- **需实测确认**：依赖运行时输入规模、设备行为或环境差异的结论，只能记观察项并附实测用例（证据等级见第 7 节）。
- **不覆盖**：本模式以外的机理（边界见第 0 节）与仓外框架侧行为；`TRIAGE.md` 只负责收敛候选，不构成判定依据。
- **找不到 ≠ 没有**：按清单未命中只说明「本轮未发现」，不得表述为「该算子无此缺陷」；抽样核查须在报告写明抽样口径。
