# FP-A03 aclnn 接口检视（fpa03-kernel-review）

对用户指定的 aclnn 接口（如 aclnnMoeTokenUnpermute）做 FP-A03 专项源码检视：先定位算子实现，再按清单逐项核查，每个结论给出**文件 + 行号 + 推导链**证据，命中即出 Bug 卡，输出检视报告。**本模式特殊纪律：① 缺陷不是「算错」而是「中间位宽低于标杆」——单算子功能正确，偏差随中间结果动态范围与层数逐层累积，bf16/fp16 下呈**大面积**超阈值（非个别离群点）；② 触发签名 `half|bfloat16_t|bf16` 在低精度算子中普遍存在，命中只表示「值得人工核」——必须给出「该中间量在标杆中为 fp32 累加、本实现为 fp16/bf16」的位宽对比推导链；③ 与 A01（指令精度）、A02（归约顺序）同属精度族，须按「位宽 vs 指令 vs 顺序」三分归因，不重复立卡。**

## 0. 与相邻模式的边界

| 相邻模式 | 分工 |
|---|---|
| FP-A01（硬件指令精度不足） | **位宽 vs 指令**二分：A03 是**中间变量位宽**不足（该 fp32 累加却用 fp16/bf16）；A01 是**指令本身**的精度规格不足（近似超越函数）。位宽归 A03，指令选型归 A01 |
| FP-A02（归约/累加实现顺序与竞品不一致） | **位宽 vs 顺序**二分：A02 是累加**位宽相同、拓扑不同**；A03 是**位宽本身不足**——位宽不足归 A03，顺序不同归 A02 |
| FP-A13（输入尾数截断才能通过精度标准） | A13 是**输入预处理阶段**的截断；A03 是**中间计算阶段**的位宽不足——按「入口截断 vs 中间位宽」分 |
| FP-A08（切块粒度差异致离群点精度问题） | A08 是**离群点/极端 shape** 下的局部偏差（尾块、padding）；A03 是**大面积**超阈值（与数据分布无关的位宽损失）——按「局部 vs 大面积」分 |
| FP-A18（int32 边界值转 float 舍入） | A18 是整型转浮点的舍入语义；A03 是浮点中间位宽不足——整数语义面归 A18 |
| FP-A10 / FP-A11（double 相关） | A10/A11 管**高精度值在低精度链路上被静默降级**（double attr / double dtype）；A03 管**fp16/bf16 中间量**位宽不足——按「double 降级 vs fp16/bf16 中间量」分 |

**症状反查定位**：bf16/fp16 dtype 下**大面积**（非个别点）超阈值而 fp32 全过 → 中间位宽面（清单①）；中间结果动态范围大（softmax 指数、norm 平方和、量化反量化）时偏差显著 → 高精度缓冲缺失面（清单②）；误差随算子链层数递增 → 逐层累积面（清单③）；输入含离群值/大动态范围时精度崩溃 → 数据分布面（清单④）。

## 1. FP-A03 模式卡摘要（检视依据，源自本库 `patterns/FP-A/FP-A03.md`，v3.1）

- **编号 / 名称**：FP-A03 竞品高精度中间计算，NPU 直接低精度 ｜ **类别**：精度 ｜ **风险**：高（S3×O3=9）｜ **状态**：活跃
- **适用声明头**（照抄卡片）：仓 All ｜ 侧别 Kernel ｜ 载体 Kernel源码 ｜ 触发 half|bfloat16_t|bf16 ｜ 默认启用 true
- **skill 核查面**：侧别 Kernel——skill 落地为 `op_kernel/` 中低精度数据类型声明与中间计算实现（含 arch35 / regbase / SIMT 等架构变体）；延伸至 `op_host` 侧与 dtype 相关的类型推导/分派（dtype 组合决定 kernel 走低精度路径的入口）
- **故障机理**：标杆（GPU/框架参考实现）在 fp32 中间缓冲累加，NPU 实现直接用 fp16/bf16 中间变量，误差逐层累积。
- **触发条件**：中间结果动态范围大的算子（softmax、norm 类、量化/反量化路径）。
- **典型表现**：精度差异、bf16/fp16 大面积超阈值。
- **源码审查映射点**：中间变量精度（该用 fp32 累加却用 fp16/bf16）；高精度中间缓冲缺失。
- **检测签名**（命中即候选缺陷点位）：`half|bfloat16_t|bf16`（低精度数据类型声明与运算定位点）。
- **测试拦截建议**：bf16/fp16 全 dtype 矩阵精度用例；含离群值的输入分布。
- **实证案例**：ops-transformer **#4624 / #4636** MoeTokenUnpermute bf16/fp16 低精度大面积超阈值（2026-09-03 修复跟踪中）。
- **关联**：FP-A13。

## 2. 检视输入与算子定位

**输入**：aclnn 接口名（必填，如 `aclnnMoeTokenUnpermute`）；可选 ref（默认 master）、指定仓（默认自动定位）；可选现象描述（失败 dtype / 超阈面积 / 失败输入分布——用于直接定位中间位宽面）；可选标杆实现（如 PyTorch / GPU 参考）。

**接口名 → 算子目录换算**：去 `aclnn` 前缀 + 驼峰转下划线小写：
`aclnnMoeTokenUnpermute → moe_token_unpermute`、`aclnnSoftmaxV2 → softmax_v2`、`aclnnLayerNorm → layer_norm`。

**仓定位顺序**（GitCode `cann` 组织，逐仓用目录列表确认）：`ops-transformer`（attention/moe 类——实证集中地）→ `ops-nn`（norm/loss/activation 类）→ `ops-math`（math/quant 类）→ `ops-cv`。**类目名不总与直觉一致**，以目录列表为准。FP-A03 高发面：含 softmax/norm 归一化的算子、moe 类重排/聚合算子、量化与反量化路径、bf16/fp16 为主 dtype 的算子、中间结果动态范围大的归约类。

**算子目录结构约定**（以实证算子为例，具体布局以目录列表为准）：

```text
{类别}/{op_name}/
├── op_kernel/                # kernel 头文件——主检视面（中间变量声明与计算）
│   └── arch35/ regbase/ ...  # 架构变体
├── op_host/                  # def / infershape / tiling——dtype 推导与分派面
│   └── op_api/               # aclnn_*.cpp（若存在）
├── op_graph/  tests/  docs/  examples/   # 视算子而定
```

## 4. 检视清单（每点：查什么 → 何处 → 命中判据）

对算子的 `op_kernel/`（含架构变体）全部相关文件逐点核查，`op_host` dtype 推导/分派同步核对，**每点先查命中面、再做反证排除**；已用 fp32 中间缓冲的实现要记录为防护面证据。

### ① 中间变量的精度（位宽）
- 查什么：中间累加器与中间结果变量的**声明类型**——该 fp32 累加却用 `half` / `bfloat16_t` / `bf16`；归约（sum/平方和）、归一化（softmax 分母、norm 的 rstd）、反量化累加等中间量的位宽是否与标杆一致（标杆在 fp32 中间缓冲累加）。
- 何处：kernel 中中间变量声明、累加器定义、`Reg::`/`Vec::` 计算段。
- 命中判据：能写出「某中间量在标杆中为 fp32、本实现为 fp16/bf16 → 该量动态范围下精度损失 → 逐层放大」的推导链 ⇒ 命中候选（须附实测方案）。

### ② 高精度中间缓冲缺失
- 查什么：是否缺少 fp32 中间缓冲（UB/寄存器）来承载高动态范围的中间结果；低精度输入是否在计算前先 `Cast` 到 fp32、计算后再降回；softmax/norm 的归一化分母是否以低精度参与除法。
- 何处：kernel 的 Cast / 缓冲分配 / 归一化计算段。
- 命中判据：存在「低精度直接参与大动态范围中间计算且无 fp32 缓冲」的路径 ⇒ 命中候选。

### ③ 逐层累积放大
- 查什么：误差是否随算子链层数递增——多阶段（如 moe 的 unpermute→聚合、norm 的多段归约）中每段的低精度截断叠加；阶段间中间结果的 dtype 是否逐段降精度。
- 何处：kernel 的多阶段计算流、阶段间缓冲 dtype。
- 命中判据：能给出「N 段低精度截断 → 误差累积量级 ≈ N × 单段截断误差」的推导 ⇒ 命中候选。

### ④ 输入分布与离群值敏感度
- 查什么：算子对输入动态范围的敏感度——含离群值/大动态范围输入时低精度中间量是否溢出/饱和；是否有针对大动态范围的 fp32 保护路径。
- 何处：kernel 输入处理段、归一化/指数计算段。
- 命中判据：存在「离群值输入下低精度中间量精度崩溃且无保护」的路径 ⇒ 命中候选（与 A08 交界，按主导因素归属）。

### ⑤ dtype 覆盖与标杆对齐基线
- 查什么：`tests/` 是否覆盖 bf16/fp16 **全 dtype 矩阵**、是否含离群值输入分布用例；`docs/` 是否标注各 dtype 的精度预期；与标杆（GPU/框架参考）的 utol 阈值是否按 dtype 分档。
- 何处：`tests/` 的精度用例与 dtype 覆盖矩阵、`docs/`。
- 命中判据：dtype 矩阵缺档 / 无离群值用例 ⇒ 记观察项（测试面缺口）。

## 5. 检视流程

1. **定界**：换算 op 目录、确认所在仓与 ref；确认架构变体布局；记录用户现象（失败 dtype / 超阈面积 / 输入分布）。
2. **枚举**：目录列表列出 `op_kernel/`（含架构子目录）与 `op_host` 相关文件、`tests/`、`docs/`，产出文件清单。
3. **触发词扫描**：按 `half|bfloat16_t|bf16`、`Cast\(|ToFloat|Reg::|Vec::`、中间缓冲声明定位风险面（本地仓用 grep；API 模式逐文件拉取后检查）。**触发为关键词：签名零命中时清单仍须逐项核查完毕**。
4. **逐点核查**：按第 4 节 ①~⑤ 记录命中面与防护面证据（文件:行号）；对每个中间量给出「标杆位宽 vs 本实现位宽」的对比表。
5. **反证排除**：中间量已为 fp32、有 fp32 中间缓冲且计算前后正确 Cast、多阶段未逐段降精度、有离群值保护 → 明确写出反证理由。
6. **判定**：按第 7 节标准给出 命中 / 观察项 / 反证排除。
7. **GitCode 查重**（仅命中项）：issues API 按接口名 + `精度|bf16|fp16|超阈|dtype` 检索，逐条比对是否同机理；无同机理才立卡。
8. **业务可达性核查**（仅命中项）：判 B 等级、定业务影响类型、给处置建议；默认保守（无法证明不可达即记 B3），降档须附证据；B 不改 S×O 档位。
9. **出报告**：按第 8 节模板落盘；所有精度结论标注「静态推演，需 bf16/fp16 全 dtype 矩阵实测确认」并附实测方案。

## 6. 风险定级（S×O）与业务影响评估（B 轴）

- **S**：S3（精度差异 / bf16/fp16 大面积超阈值——结果错但可运行）；S2（仅特定输入分布下超阈）；S1（偏差远低于阈值）。
- **O**：O3 = ≥2 条独立实证；O2 = 1 条独立实证；O1 = 仅静态扫描命中或团队笔记（实证 = 确认对应的 issue / PR，或经跨仓、跨分支核验确认的缺陷记录，同权计入）。静态推演命中且无实证默认 **O1**；升档须在报告中给出实证依据。
- **风险 = S×O**：≥6 高；3/4 中；1/2 低。FP-A03 基准：模式卡整体 S3×O3=9（高）；纯静态命中 S3×O1=3（中，暂定，实测后复评）。

### B 轴：业务影响评估（与 S×O 正交；报告层新增，不改卡片定级）

S×O 回答"多严重、多常见"，**不回答"真实业务能不能碰到"**。B 轴补这一问，只决定**修复优先级建议**，**不参与 S/O 取值、不改 S×O 档位与卡片元数据**。

**业务可达性（B）**——触发条件在真实负载中的可达程度：

| 等级 | 判据 | 证据要求 |
|---|---|---|
| B3 现实可达 | 主流框架/公开模型默认路径即可命中（如 PTA/torch_npu、vLLM、MindIE 常规调用） | 调用方或公开负载来源 |
| B2 条件可达 | 需特定 attr/dtype/shape 组合，业务中存在但非默认 | 该组合的业务来源 |
| B1 边界/不可达 | 需极端、超规格或非法参数（超出接口合理上限的 shape、退化/非法输入） | "为何不可达"的说明 |

- **默认保守**：无法证明不可达 → 记 **B3**；降为 B1/B2 必须附证据，**不得仅凭"业务应该不会这么用"**。
- 超规格参数是否算 B1 取决于**接口契约**：契约允许但业务不用 → B1；契约不允许（本应报错）→ 属校验缺失（FP-B04/B05 类），另行归属。

**业务影响类型**（命中后对用户可见结果的后果，用业务语言表述）：静默精度损失（模型效果下降 / loss 不收敛 / 偶发 NaN）｜ 任务失败中断（报错 / 崩溃 / 挂死）｜ 性能退化 ｜ 仅可观测性（日志 / 错误码 / 文档，不影响结果）。

**处置建议**（由两轴推导的报告结论，非新档位）：

| S×O \ B | B3 现实可达 | B2 条件可达 | B1 边界/不可达 |
|---|---|---|---|
| 高（≥6） | 尽快修 | 尽快修 | 排期修 |
| 中（3/4） | 尽快修 | 排期修 | 记录（业务难以触达） |
| 低（1/2） | 排期修 | 记录 | 记录 |

## 7. 判定标准与反误报原则

- **签名 / 触发词命中 ≠ 成立**：`half`/`bf16` 在低精度算子中普遍存在且多数正确（低精度输入本就用低精度存储）——命中只是定位提示，必须定位到**中间计算量**并给出「标杆为 fp32、本实现为低精度」的对比推导链。
- **三种判定**：
  - **命中**（可静态证缺陷路径）：「中间量位宽低于标杆 → 动态范围下精度损失 → 逐层放大」的推导链完整 + 失败 dtype/输入分布可构造 → 立 Bug 卡（档级按实测证据定）；
  - **观察项**：位宽存疑但超阈与否依赖实测、或仅测试面覆盖缺口 → 记录并附实测方案，按 S3×O1 暂定；
  - **反证排除**：中间量为 fp32 / 有 fp32 中间缓冲且 Cast 正确 / 无逐层降精度 → 明确写出反证理由（防护面证据）。
- **「大面积超阈值」是本型关键特征**：个别点偏差先查 A08（尾块/离群点），大面积超阈才归本型。
- **精度劣化不静态断言「必然不过」**：静态只能立「候选点位 + 实测方案」，实测前不升级为「已确认」。
- **不臆造行号**：每条证据必须是实际读到的 文件:行号；引用实证样板时同样给出路径与行号，issue 时点行号与本仓 HEAD 漂移时注明。

### 判定纪律补充（v3.6）：非对称增减、证据等级与误判记录

**增减不对称**：允许追加候选（有据即可，错了可由用户排除）；**撤销或否决候选必须附 `[文件]:[行号] [代码行]` 负向证据**。无证据的「看起来没问题」一律记为「未核查」，不得计入反证排除，也不得据此下调等级——否决造成的漏报用户不可见、不可恢复。

- **证据等级**（Bug 卡必填）：`静态可证` = 推导链完整且触发输入可静态构造；`需实测确认` = 依赖运行时输入规模、设备行为或环境差异。标 `需实测确认` 的条目**不得以「命中」名义出卡**，按观察项记录并附实测用例。
- **Agent 误判记录**（Bug 卡必填）：本次被推翻的假设、推翻它的证据（`[文件]:[行号] [代码行]` 或实测输出）、判定标准是否随之修订；无推翻写「无」。
- **误判回流**：同类误判在 3 次检视中重复出现，登记至 `cases/misjudgments.jsonl`（字段见 `cases/README.md`），并在本模式判定标准中新增对应防线；守门 C19d 校验台账字段合法。

## 10. 能力边界与自检（v3.8）

### 能力边界

- **静态可证**：清单里能在源码内给出「`文件:行号` + 推导链」的部分，按第 7 节判据出卡。
- **需实测确认**：依赖运行时输入规模、设备行为或环境差异的结论，只能记观察项并附实测用例（证据等级见第 7 节）。
- **不覆盖**：本模式以外的机理（边界见第 0 节）与仓外框架侧行为；`TRIAGE.md` 只负责收敛候选，不构成判定依据。
- **找不到 ≠ 没有**：按清单未命中只说明「本轮未发现」，不得表述为「该算子无此缺陷」；抽样核查须在报告写明抽样口径。
