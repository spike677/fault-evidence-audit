变更摘要

本次变更针对 addmm 与 baddbmm 算子在 beta=0、cubeMathType=4 分支下的精度问题：此前走 GemmV3 AlphaBeta 分支时未将 16in32out（FP16 输入、FP32 输出）标记传入接口，导致输出精度不符合预期。修复方式是在 aclnn_addmm.cpp 与 aclnn_baddbmm.cpp 中，于进入 ExecGemmV3WithAlphaBetaOp 前先调用 NeedEnableFp32Output 计算 enableGemm16In32Out，并将该标记作为新增参数传入 ExecGemmV3WithAlphaBetaOp。

主要改动

  • aclnn_addmm 传入 16in32out 标记: 在 CheckGemmV3WithAlphaBeta 且架构为 NpuArch::DAV_2201 的分支中，新增 NeedEnableFp32Output(matA->GetDataType(), matB->GetDataType(), output->GetDataType(), cubeMathType) 计算 enableGemm16In32Out，并作为新参数传给 ExecGemmV3WithAlphaBetaOp。
  • aclnn_baddbmm 传入 16in32out 标记: 在相同条件下新增 enableGemm16In32Out 的计算，并将其作为新参数传入 ExecGemmV3WithAlphaBetaOp，使 batch 场景下的 GemmV3 AlphaBeta 分支同样支持 FP32 输出标记。
  • 修正 beta=0、cubeMathType=4 分支的精度行为: 通过补全接口参数传递，使 16 位输入在需要时按 FP32 输出路径执行，解决该分支下输出精度错误的问题。
