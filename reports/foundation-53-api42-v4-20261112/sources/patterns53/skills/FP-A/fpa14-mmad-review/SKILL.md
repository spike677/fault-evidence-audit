# FP-A14 aclnn 接口检视（fpa14-mmad-review）

对用户指定的 aclnn 接口做 FP-A14 专项源码检视：先定位算子实现，再按清单逐项核查，每个结论给出**文件 + 行号 + 推导链**证据，命中即出 Bug 卡，输出检视报告。**本模式特殊纪律：① 缺陷几乎都落在 **Cube（MMAD）侧**的搬运 / 指令配置 / 对齐环节，而非 Vector 侧——检视重心是 `op_kernel` 的 block mmad / prologue 头文件与 Cube 指令配置，Vector 路径主要作为对照面；② 卡片触发为关键词（`Mmad|MMAD|SetMMAD`）——签名命中是定位提示，须逐项核指令配置与步长语义，不可按命中数下结论；③ 双路径差异的最终判据是**运行时数值**——静态只能立「指令配置 / 步长 / 补零与 shape·layout 组合不匹配」，最大相对误差量级需实测；④ 实证虽为 3 issue / 2 仓，但均为 Cube 侧配置错误这一**呈现形式**，判定时按「Cube 侧缺陷」口径从严。**

## 0. 与相邻模式的边界

| 相邻模式 | 分工 |
|---|---|
| FP-A01（硬件指令精度不足，未与竞品对齐） | 卡片关联项：A01 是**指令本身精度规格**不足（与竞品口径差，代际 / 硬件固有）；A14 是**同一算子内两条硬件路径语义差**（Vector FFMA vs Cube MMAD）——两条路径都低于竞品时先归 A01，路径间差归 A14 |
| FP-A16（aclop 与 aclnn 编译阶段精度差异） | 同为「同输入两路径结果不同」家族，**路径轴不同**——A16 差在 host / 图侧调用路径的编译期决策（常量折叠、pad 预处理），A14 差在设备侧指令路径（FFMA vs MMAD）——两轴可并存连打 |
| FP-A08（切块粒度差异致离群点精度问题） | **#1246 的 K 对齐补零缺失与尾块 / 对齐问题同源**（卡片关联直指）：对齐 / 补零缺失本身归 A08，其在 MMAD 侧表现为路径差异归 A14 |
| FP-A15（inf/nan 特殊值行为差异） | MMAD 累加器精度不足导致上溢 / 饱和的极端表现可能与特殊值传播混淆——先按 A15 核特殊值语义，再按 A14 核累加器精度 |
| FP-A02（归约 / 累加实现顺序与竞品不一致） | 累加器精度差异与归约顺序差异都表现为数值偏差：**顺序轴**归 A02，**指令 / 累加器轴**归 A14 |
| FP-B02（tiling 未适配多种芯片核数） | 代际 / 核数适配缺失可能改变路径选择：核数适配归 B02，路径内指令配置归 A14 |

**症状反查定位**：fp16 / mxfp8 矩阵乘精度比对**最大相对误差接近 100%** → 首查 Cube 侧 mmad 指令配置（#3503，c04 + innerbatch + 1x1 卷积 + NCHW）；同一算子切换 Vector / Cube 实现开关后结果变化 → 双路径语义差；A 转置 / B 不转置 + ND layout 组合下精度异常 → K 对齐补零缺失（#1246）；`stepKb` 与 `stepKa` 语义混用 → 搬运步长初始化错误（#1577）；golden 在 CPU / GPU 正常而 NPU Cube 路径偏差 → 指令路径差异；偏差呈「部分分块错位」而非整体偏移 → 搬运步长 / 补零问题。

## 1. FP-A14 模式卡摘要（检视依据，源自本库 `patterns/FP-A/FP-A14.md`，v3.1）

- **编号 / 名称**：FP-A14 FFMA 与 MMAD 硬件指令差异 ｜ **类别**：精度 ｜ **风险**：高（S3×O3=9）｜ **状态**：活跃 ｜ **来源**：团队笔记
- **适用声明头**（照抄卡片）：仓 All ｜ 侧别 Kernel ｜ 载体 Kernel源码 ｜ 触发 Mmad|MMAD|SetMMAD ｜ 默认启用 true
- **skill 核查面**：侧别 Kernel——skill 落地为 `op_kernel` 的 Cube 侧 block mmad / prologue 搬入实现（指令配置、`stepKa/stepKb` 步长、K 维补零）、`op_host` tiling 的路径分流与 dtype / layout 决策（界定两条路径如何被选中）、`tests/` 的双路径对照用例
- **故障机理**：Vector(FFMA) 与 Cube(MMAD) 的浮点语义（累加器精度、舍入模式）不同，同一数学在两条路径结果有差。
- **触发条件**：同一算子存在 Vector / Cube 两条实现路径且可切换。
- **典型表现**：精度结果与 GPU 不一致；路径切换前后结果差异。
- **源码审查映射点 / 检测签名**：映射点 = Vector(FFMA) 与 Cube(MMAD) 路径的精度语义差异点；卡片未给独立 grep 签名，触发词为 `Mmad|MMAD|SetMMAD`（关键词定位提示），实际核查面为 `block_mmad_*` / `block_prologue_*` 头文件与 mmad 指令配置段。
- **测试拦截建议**：强制走两条路径的开关级用例对比。
- **实证案例**：ops-nn **#3503** conv2d（c04 + innerbatch + 1x1 卷积 + NCHW）**mmad 指令配置错误**致精度问题（950PR，fp16，通路经 pytorch 执行，精度比对最大相对误差 **100%**）；ops-nn **#1577** `block_mmad_mx_weight_from_ub.h` / `block_prologue_b_cast_scsc_nn.h` 两处 `stepKb` 从 `stepKa` **错误初始化**；ops-transformer **#1246** mxfp8 blockmmad 在 A 转置 / B 不转置且 ND 场景下的泛化精度问题（值域拼接处的 **K 对齐补零缺失**）。**共性特征：缺陷位于 Cube（MMAD）侧的搬运 / 指令配置 / 对齐环节，而非 Vector 侧；A14 关注的「同一数学在 FFMA 与 MMAD 两路径结果有差」在四仓 issue 中体现为 Cube 侧配置错误导致的精度失败，属本型的一种呈现形式。**
- **关联**：FP-A01、FP-A16、FP-A08（#1246 的 K 对齐补零缺失与尾块 / 对齐问题同源）。注：FFMA 为 Vector 融合乘加指令、MMAD 为 Cube 矩阵乘指令。

## 2. 检视输入与算子定位

**输入**：aclnn 接口名（必填，如 `aclnnConv2d`）；可选 ref（默认 master）、指定仓（默认自动定位）；可选现象描述（最大相对误差 / 失败 shape 与 layout / 是否仅某 dtype 失败——用于直接定位 Cube 侧配置组合）；可选复现条件（dtype、layout、转置组合、量化模式）。

**接口名 → 算子目录换算**：去 `aclnn` 前缀 + 驼峰转下划线小写：
`aclnnConv2d → conv2d`、`aclnnMatMul → mat_mul`、`aclnnFlashAttentionScore → flash_attention_score`。

**仓定位顺序**（GitCode `cann` 组织，逐仓用目录列表确认）：`ops-nn`（matmul / conv 类——Cube 高发）→ `ops-transformer`（attention / moe 大模板，mxfp8 类量化 mmad）→ `ops-math` → `ops-cv`。**类目名不总与直觉一致**（如 conv 类可能落在 `conv/` 或 `convolution/`），以目录列表为准。FP-A14 高发面：含 `block_mmad_*` / `block_prologue_*` 头文件的算子、带量化（mx / mxfp8 / c04）与转置组合分支的 Cube 实现、存在 Vector / Cube 双实现或 `cubeMathType` 类开关的算子。

**算子目录结构约定**（已验证示例 `cann/ops-nn` → matmul / conv 类算子目录）：

```text
{类别}/{op_name}/
├── op_host/           # *_def.cpp、*_tiling*.cpp——路径分流 / dtype / layout 决策（界定两条路径如何被选中）
│   └── config/<soc>/  # *_binary.json——分核与模板配置
├── op_kernel/         # 主检视面：block_mmad_* / block_prologue_* 头文件、mmad 指令配置、stepK 搬运步长、K 维补零
│   └── arch22/ arch35/   # 平台 / 代际变体
├── tests/             # 双路径开关级对照用例
└── docs/ examples/
```

## 4. Cube 侧检视清单（每点：查什么 → 何处 → 命中判据）

对 `op_kernel`（含 arch22 / arch35 变体）Cube 侧实现、`op_host` 路径分流、`tests/` 逐点核查，**每点先查命中面、再做反证排除**，正确的指令配置与补零实现也要记录为防护面证据。

### ① MMAD 指令配置与 shape / layout / dtype 组合
- 查什么：Cube 侧 mmad 调用（`Mmad` / `SetMMAD` 类）的指令配置——模板参数（dtype、分形、转置位）、量化模式（c04 / mx / mxfp8）、innerbatch、1x1 卷积等组合下配置是否与实际 shape / layout / dtype 匹配（#3503 即 mmad 指令配置错误，fp16 + 950PR，最大相对误差 100%）。
- 何处：`op_kernel` 的 Cube 侧 block 实现（`*_mmad*.h` / `block_mmad_*` 类命名）与指令配置段。
- 命中判据：能给出「实际 shape / layout / dtype 组合 → 指令配置与预期不符 → 结果错误」的推导 ⇒ 命中候选；配置随组合正确切换 ⇒ 反证排除。

### ② stepK 类搬运步长初始化
- 查什么：`stepKa` / `stepKb`（及 M / N 方向同类步长）变量的初始化来源与语义——是否存在**从另一变量错误初始化**（#1577 `stepKb` 从 `stepKa` 初始化）；A / B 矩阵步长方向是否对称正确；步长与分形尺寸、dtype 字节数的换算链。
- 何处：`block_mmad_*` / `block_prologue_*` 头文件的搬运初始化段。
- 命中判据：步长变量赋值右侧与语义不符（K 方向步长取了另一侧 / 取了 M·N 方向步长）⇒ 命中候选；A / B 步长各自来源正确 ⇒ 反证排除。

### ③ K 对齐补零与值域拼接
- 查什么：转置组合（A 转置 / B 不转置等）× layout（ND / NZ）× 量化模式下 K 维对齐补零是否完整——值域拼接处是否缺失补零（#1246 mxfp8 blockmmad）；补零值是否满足 MMAD 语义（零元素对矩阵乘中性）；同步核 FP-A08（尾块 / 对齐）。
- 何处：Cube 侧 K 维切分与 pad 处理、prologue 搬入段、值域拼接逻辑。
- 命中判据：某转置 / layout 组合下 K 尾块未补零或补零值不满足 MMAD 中性语义 ⇒ 命中候选；全组合补零完整 ⇒ 反证排除（并记录防护面）。

### ④ 双路径开关与对照面
- 查什么：算子是否存在 Vector(FFMA) 与 Cube(MMAD) 两条可切换实现（`cubeMathType` 类开关 / tiling 分流 / 模板特化）；两条路径对**同一输出**的累加器精度与舍入模式是否一致；是否有开关级对照用例（卡片拦截建议）。
- 何处：`op_host` tiling 的路径分流与模板注册、`op_kernel` 双实现文件、`tests/` 用例。
- 命中判据：双路径存在而无数值一致性对照用例（或两路径差异无文档说明）⇒ 命中候选 / 观察项；仅单路径 ⇒ 反证排除并记录结论。

### ⑤ 累加器精度与舍入模式
- 查什么：MMAD 累加器位宽（fp16 输入是否 fp32 累加）、舍入模式与 golden 口径是否一致；与 FFMA 路径的差异是否有量化结论（文档 / 注释）。
- 何处：Cube 指令配置、kernel 累加变量类型、docs 精度说明。
- 命中判据：累加器位宽低于 golden 口径且无补偿 ⇒ 命中候选（与 A01 分界：指令规格固有不足归 A01）。

## 5. 检视流程

1. **定界**：换算 op 目录、确认所在仓与 ref；按用户现象（最大相对误差 / 失败 layout 组合 / dtype）反查优先清单点；记录复现条件（dtype、layout、转置组合、量化模式）。
2. **枚举**：目录列表列出 `op_kernel`（含架构子目录）Cube 侧实现、`op_host` tiling、`tests` 全部相关文件，产出文件清单；对 #1577 类实证文件名先按文件名 grep 定位所属算子。
3. **触发词扫描**：按 `Mmad|MMAD|SetMMAD`、`stepKa|stepKb|stepK`、`block_mmad|block_prologue`、`Pad|pad|duplicate|Duplicate`（补零）、`cubeMathType` 定位风险面（本地仓用 grep；API 模式逐文件拉取后检查）。**签名零命中时清单仍须逐项核查**（双路径存在但命名不同者）。
4. **逐点核查**：每点记录命中面与防护面证据（文件:行号）；对每处指令配置 / 步长写出「变量 → 语义 → 赋值来源 → 与 shape·layout·dtype 组合的匹配性」四项对表。
5. **反证排除**：指令配置随组合正确切换、A / B 步长来源各自正确、全组合补零完整、单路径算子、累加器位宽与 golden 一致 → 明确写出反证理由。
6. **判定**：按第 7 节标准给出 命中 / 观察项 / 反证排除。
7. **GitCode 查重**（仅命中项）：issues API 按接口名 + `mmad|精度|转置|对齐|fp16` 检索，逐条比对是否同机理；无同机理才立卡。
8. **业务可达性核查**（仅命中项）：判 B 等级、定业务影响类型、给处置建议；默认保守（无法证明不可达即记 B3），降档须附证据；B 不改 S×O 档位。
9. **出报告**：按第 8 节模板落盘；所有数值后果标注「静态推演，需 NPU 实测确认」，并附双路径开关级对照用例方案。

## 6. 风险定级（S×O）与业务影响评估（B 轴）

- **S**：S3（精度失败——结果错但可运行，实证 #3503 最大相对误差 100%）；S2（路径切换前后差异小、在容差内）；S1（仅配置可读性问题、无结果影响）。
- **O**：O3 = ≥2 条独立实证；O2 = 1 条独立实证；O1 = 仅静态扫描命中或团队笔记（实证 = 确认对应的 issue / PR，或经跨仓、跨分支核验确认的缺陷记录，同权计入）。静态推演命中且无实证默认 **O1**；升档须在报告中给出实证依据。
- **风险 = S×O**：≥6 高；3/4 中；1/2 低。FP-A14 基准：模式卡整体 **S3×O3=9（高）**；纯静态命中 S3×O1=3（中，暂定），实测偏差后复评。

### B 轴：业务影响评估（与 S×O 正交；报告层新增，不改卡片定级）

S×O 回答"多严重、多常见"，**不回答"真实业务能不能碰到"**。B 轴补这一问，只决定**修复优先级建议**，**不参与 S/O 取值、不改 S×O 档位与卡片元数据**。

**业务可达性（B）**——触发条件在真实负载中的可达程度：

| 等级 | 判据 | 证据要求 |
|---|---|---|
| B3 现实可达 | 主流框架/公开模型默认路径即可命中（如 PTA/torch_npu、vLLM、MindIE 常规调用） | 调用方或公开负载来源 |
| B2 条件可达 | 需特定 attr/dtype/shape 组合，业务中存在但非默认 | 该组合的业务来源 |
| B1 边界/不可达 | 需极端、超规格或非法参数（超出接口合理上限的 shape、退化/非法输入） | "为何不可达"的说明 |

- **默认保守**：无法证明不可达 → 记 **B3**；降为 B1/B2 必须附证据，**不得仅凭"业务应该不会这么用"**。
- 超规格参数是否算 B1 取决于**接口契约**：契约允许但业务不用 → B1；契约不允许（本应报错）→ 属校验缺失（FP-B04/B05 类），另行归属。

**业务影响类型**（命中后对用户可见结果的后果，用业务语言表述）：静默精度损失（模型效果下降 / loss 不收敛 / 偶发 NaN）｜ 任务失败中断（报错 / 崩溃 / 挂死）｜ 性能退化 ｜ 仅可观测性（日志 / 错误码 / 文档，不影响结果）。

**处置建议**（由两轴推导的报告结论，非新档位）：

| S×O \ B | B3 现实可达 | B2 条件可达 | B1 边界/不可达 |
|---|---|---|---|
| 高（≥6） | 尽快修 | 尽快修 | 排期修 |
| 中（3/4） | 尽快修 | 排期修 | 记录（业务难以触达） |
| 低（1/2） | 排期修 | 记录 | 记录 |

## 7. 判定标准与反误报原则

- **签名 / 触发词命中 ≠ 成立**：`Mmad` / `SetMMAD` 在 Cube 算子中普遍存在且多数正确——必须过「指令配置与组合匹配性 + 步长语义 + 补零完整性」三关；命中数大只说明核查工作量大。
- **三种判定**：
  - **命中**（可静态证缺陷路径）：指令配置 / 步长 / 补零与具体 shape·layout·dtype 组合不匹配的推导链完整 ⇒ 立 Bug 卡；
  - **观察项**：双路径存在但差异需实测量化、或累加器位宽差异属指令固有规格（与 A01 边界）⇒ 记录并附双路径对照方案，按 S3×O1 暂定；
  - **反证排除**：配置随组合正确切换、步长来源正确、补零完整、单路径算子 → 写出防护面证据与反证理由。
- **Cube 侧优先、Vector 侧作对照**：实证共性为缺陷在 Cube 侧搬运 / 配置 / 对齐环节——检视精力按此分配，但不得据此跳过双路径语义核对。
- **与 A01 / A08 的分界要写明**：指令固有精度规格归 A01，尾块 / 对齐机理归 A08，本卡只收「Cube 侧配置 / 步长 / 补零与组合不匹配」；跨模式时在报告标注并连打。
- **不臆造行号与算子归属**：每条证据必须是实际读到的 文件:行号；#1577 类通用头文件须先 grep 定位所属算子再引用，不得据文件名臆测。
- **静态推演声明**：无 NPU 环境时，所有运行时行为结论必须标注「静态推演，需 NPU 实测确认」。

### 判定纪律补充（v3.6）：非对称增减、证据等级与误判记录

**增减不对称**：允许追加候选（有据即可，错了可由用户排除）；**撤销或否决候选必须附 `[文件]:[行号] [代码行]` 负向证据**。无证据的「看起来没问题」一律记为「未核查」，不得计入反证排除，也不得据此下调等级——否决造成的漏报用户不可见、不可恢复。

- **证据等级**（Bug 卡必填）：`静态可证` = 推导链完整且触发输入可静态构造；`需实测确认` = 依赖运行时输入规模、设备行为或环境差异。标 `需实测确认` 的条目**不得以「命中」名义出卡**，按观察项记录并附实测用例。
- **Agent 误判记录**（Bug 卡必填）：本次被推翻的假设、推翻它的证据（`[文件]:[行号] [代码行]` 或实测输出）、判定标准是否随之修订；无推翻写「无」。
- **误判回流**：同类误判在 3 次检视中重复出现，登记至 `cases/misjudgments.jsonl`（字段见 `cases/README.md`），并在本模式判定标准中新增对应防线；守门 C19d 校验台账字段合法。

### 案例 1｜mmad 指令配置与算子形态不匹配 —— #3503（conv2d）

- **触发条件**：conv2d 组合 **c04 + innerbatch + 1x1 卷积 + NCHW**，**950PR**、**fp16**、通路经 pytorch 执行。
- **根因（具体路径）**：Cube 侧 **mmad 指令配置错误**（分形 / 转置位 / dtype 参数与实际形态不匹配）→ 精度比对**最大相对误差 100%**。
- **修复范式（✅，示意）**：按实际 shape·layout·dtype·量化模式修正 mmad 指令配置（分形与转置位逐组合核对）。
- **针对性发现（可执行）**：① grep `Mmad|SetMMAD`；② 逐组合核指令模板参数（dtype / 分形 / 转置位 / 量化模式）；③ 配置应随组合正确切换（有则记防护面）。
- **最小复现锚**：构造 c04+innerbatch+1x1+NCHW 的 fp16 conv2d，与 golden 比对最大相对误差。
- **实证**：ops-nn **#3503**。

### 案例 2｜stepKb 从 stepKa 错误初始化 —— #1577（block_mmad_mx_weight_from_ub.h / block_prologue_b_cast_scsc_nn.h）

- **触发条件**：使用 `block_mmad_mx_weight_from_ub.h` / `block_prologue_b_cast_scsc_nn.h` 通用 block 实现的 Cube 算子。
- **根因（具体路径）**：两处 **`stepKb` 从 `stepKa` 错误初始化** → B 矩阵步长取了 A 侧语义 → 搬进步长错误。
- **修复范式（✅，示意）**：

```cpp
// ❌ B 侧步长误取 A 侧
// stepKb = stepKa;
// ✅ 各侧步长取各自来源
// stepKa = ...;  stepKb = ...;   // 语义 / 来源独立
```

- **针对性发现（可执行）**：① 先**按文件名 grep 定位所属算子**（严禁据文件名臆测归属）；② grep `stepKa|stepKb|stepK`；③ 逐处核赋值右侧语义与 A / B 对称性。
- **最小复现锚**：打印 / 断言 `stepKa` / `stepKb` 实际值，核两者来源正确且非互相赋值。
- **实证**：ops-nn **#1577**。

### 案例 3｜K 对齐补零缺失（值域拼接处） —— #1246（mxfp8 blockmmad）

- **触发条件**：mxfp8 blockmmad，**A 转置 / B 不转置** 且 **ND** layout 场景。
- **根因（具体路径）**：值域拼接处 **K 对齐补零缺失** → K 维非对齐时 MMAD 结果错误（与 FP-A08 尾块 / 对齐同源，双向关联）。
- **修复范式（✅，示意）**：K 维尾块补齐中性零，覆盖全部转置 × layout 组合。
- **针对性发现（可执行）**：① grep `Pad|pad|duplicate|Duplicate`；② 逐「转置 × layout × 量化模式」组合核 K 补零完整性；③ 补零值须对矩阵乘中性。
