# FP-B15 aclnn 接口检视（fpb15-capacity-review）

对指定 aclnn 接口或算子做 FP-B15 专项检视：核查 **host/tiling 用定长数组承载「由入参决定的变长集合」而上界未校验**，命中即出 Bug 卡，输出报告。

## 0. 与相邻模式的边界

| 相邻模式 | 分工 |
|---|---|
| FP-B11（参数契约校验缺失） | B11 覆盖「单个参数自身合法性」——rank / 长度 / 值域 / 有限性；本模式**只**负责「**容器容量**与入参上界之间没有约束」这一类。两者常共现（同一处 `OP_CHECK_IF` 缺失可同时命中），修复一并落 |
| FP-B07（索引/偏移计算错误） | B07 是**下标算式算错**；本模式下标表达式完全正确，错在**容器长度不够** |
| FP-B13（int64→int32 窄化） | B13 是**数值宽度**不够（值被改写）；本模式是**数组长度**不够（写入越界或丢弃） |
| FP-G01（挂死） | 越界后的巨大循环上界可能演变为挂死，属下游后果 |
| FP-D01（显存/内存过度占用） | D01 是申请过多；本模式是**写在别人头上**，不是申请过多 |
| FP-F03（文档未披露上限） | 同一上限若文档也没写，则同时命中 `F03-7`；**判缺陷归属时以「实现该拒没拒」为 B15，以「文档该写没写」为 F03** |

## 1. FP-B15 模式卡摘要（检视依据，源自库内 `patterns/FP-B/FP-B15.md`）

- **编号 / 名称**：FP-B15 定长容器容量无校验（入参索引 + 越界写 + 静默截断）｜ **类别**：功能/兼容 ｜ **风险**：高（S3×O3=9）｜ **状态**：活跃
- **适用声明头**（照抄卡片）：仓 All ｜ 侧别 Host,Tiling ｜ 载体 Tiling源码,Host源码 ｜ 触发 \[256\]|MAX_TENSOR_NUM|tensorElements|listSize|groupNum ｜ 默认启用 true
- **故障机理**：tiling data 结构体里写死 `int64_t tensorElements[256]`，填充循环上界 `tensorNum = GetInstanceNum()` **来自调用方且无校验**，kernel 侧又用同一个未截断的 `tensorCount` 索引同一数组。三条后果同时存在：host 结构体越界写、kernel 越界读致 `507035` fault、超出容量的尾部张量被静默丢弃（两段都返回 0）。
- **触发条件**：① 存在 `Type name[N]` / `constexpr int MAX_... = N`；② 索引来自入参（`tensorNum` / `listSize` / `groupNum` / `tensorCount`）；③ **同族兄弟有 `OP_CHECK_IF(x > N)` 而本算子没有**——第 ③ 条是零成本强证据。
- **典型表现**：小规模全对、大规模静默错；返回 `ACLNN_SUCCESS` 但尾部数据缺失；再大则 `507035 Aicore kernel fault` 或 coredump。**错误只与「集合元素个数」有关，与 shape/dtype 无关**，故按 shape/dtype 铺的常规矩阵天然覆盖不到。
- **实证案例**：ops-nn **#8254** `aclnnForeachExpm1`——`op_host/arch35/foreach_expm1_tiling_arch35.cpp:79` 越界写、`op_kernel/arch35/foreach_expm1_tiling_data.h:25` 定义 `[256]`、整份 `op_host/` 无任何 `256` / `MAX_TENSOR` 校验；n=257 时 rc=0 但 sync=507035，n=258/300/512 有 2/86/510 处静默错误。对照组 `foreach_atan/op_host/arch35/foreach_atan_tiling.cpp:32`（`MAX_TENSOR_NUM = 256`）+ `:74`（`OP_CHECK_IF`）。**族内交叉核对 @b27fda2**：`foreach/` 下有 `tensorElements[256]` 的 19 个接口里 **18 个有校验、仅 expm1 没有**（`foreach_neg` 在 `:32`/`:60` 已有护栏）。**早期基于旧快照把 neg 列为同型候选的结论已在正式检出上推翻**——跨快照下结论前必须回正式检出重核。
- **关联**：FP-B11、FP-B07、FP-B13、FP-G01、FP-F03。

## 2. 检视输入与算子定位

**输入**：aclnn 接口名或算子目录；可选 ref。
**定位**：先看 `<op>/op_kernel/**/*tiling_data.h`（数组定义在哪、多大），再看 `<op>/op_host/**/*tiling*.cpp`（谁在填、上界从哪来），最后看 `<op>/op_api/aclnn_*.cpp`（列表长度从哪读）。
**族内定位**：`aclnnForeach*` / `*List` / `*Group` 这类「一个接口带一列表」的接口是本模式高发面，定位时**必须把同族目录一起列出来**做对拍。

## 3. 取数方式

优先本地克隆（行号证据绑定 commit）；否则 API（`contents`/`raw`，带 `User-Agent`，重试 2 次间隔 5 秒）。**`arch22/` 与 `arch35/` 必须分别取**——两侧校验常不同步，只查一侧会得出「有护栏」的假结论。

## 4. 检视清单（每点：查什么 → 何处 → 命中判据）

### ① 定长容器清单
- 查什么：`op_kernel/**/*tiling_data.h` 里所有 `T name[N] = {0}` 且 N ≥ 32。
- 命中判据：数组存在即进入下一项（不论 N 多大，都要回答"谁保证不超"）。

### ② 索引来源追溯
- 查什么：填充该数组的循环上界变量（`GetInstanceNum()` / `GetDynamicInputShape` 的 count / attr `groupNum`）。
- 命中判据：上界来自**调用方可控**的量 ⇒ 进入 ③；来自编译期常量或已 clamp 的值 ⇒ 反证排除（须给 `[文件]:[行号]`）。

### ③ 上界校验存在性
- 查什么：整份 `op_host/`（含 `arch22/`、`arch35/`）是否出现 `OP_CHECK_IF(<var> > <N>)` / `ACLNN_CHECK` / `if (... > MAX_...) return`；
  以及常量是否**定义了却没用于校验**（定义了不用 = 作者知道有上限但漏了拦截）。
- 命中判据：数组存在 + 上界来自入参 + **全 op_host 无任何上界校验** ⇒ 命中。

### ④ 兄弟对拍（零成本强证据）
- 查什么：同族目录逐个统计「有定长数组 / 有 MAX 校验」。
- 命中判据：族内**部分接口有、部分没有**，缺的那批即高置信候选——**不需要论证 N 的合理性**。
- 命令模板与 2026-11-06 实测结果见 [cases/false-upper-bounds.md](../../../cases/false-upper-bounds.md) 第三节。

### ⑤ kernel 侧消费一致性
- 查什么：kernel 用 `tensorCount` 还是 `min(tensorCount, N)` 索引同一数组。
- 命中判据：直接用 `tensorCount` ⇒ 越界读（后果②）。

### ⑥ 上游入口一致性
- 查什么：`op_api/aclnn_*.cpp` 里 `aclCreateTensorList` 的长度与 tiling 侧读到的 instance num 是否可能不一致。
- 命中判据：两者可能不一致（如 list 侧允许 512、tiling 侧按 256 抠） ⇒ 命中。

## 5. 检视流程

1. **定界**：确认接口、仓、ref，并**列出同族目录**（对拍需要）。
2. **枚举数组**：`grep -rn "\\[[0-9]\\{2,\}\\]" <op>/op_kernel/**/*tiling_data.h`。
3. **追溯上界**：对每个数组找填充循环与其上界变量。
4. **查校验**：`grep -rn "MAX_\\|NUM_MAX" <op>/op_host/`（**全目录**，不要只查 `*.cpp`）。
5. **兄弟对拍**：按第 4 节 ④ 的命令跑族内统计。
6. **反证排除**：上界被 clamp / 数组实际只用前 k 项 / 有 `CheckShape` 拦了长度（须附 `[文件]:[行号]`）。
7. **判定**：命中 / 观察项 / 反证排除。
8. **GitCode 查重**：按接口名 + 「上限 / 越界 / 静默」检索，命中的要读正文判失效面是否相同。
9. **业务可达性核查**（见第 6 节 B 轴）。
10. **出报告**：运行时结论标注「静态推演，需 NPU 实测确认」。

## 6. 风险定级（S×O）与业务影响评估（B 轴）

- **S**：S4 致命（host 越界写 + kernel fault）、S3 结果错误（尾部静默丢弃）、S2 功能受限、S1 资源浪费。
- **O**：O3 ≥2 条独立实证；O2 1 条；O1 仅静态。
- **风险 = S×O**：≥6 高；3/4 中；1/2 低。FP-B15 基准 S3×O3=9（高）。

### B 轴：业务影响评估（与 S×O 正交；报告层新增，不改卡片定级）

S×O 回答"多严重、多常见"，**不回答"真实业务能不能碰到"**。B 轴补这一问，只决定**修复优先级建议**，**不参与 S/O 取值、不改 S×O 档位与卡片元数据**。

**业务可达性（B）**——触发条件在真实负载中的可达程度：

| 等级 | 判据 | 证据要求 |
|---|---|---|
| B3 现实可达 | 主流框架/公开模型默认路径即可命中（如 PTA/torch_npu、vLLM、MindIE 常规调用） | 调用方或公开负载来源 |
| B2 条件可达 | 需特定 attr/dtype/shape 组合，业务中存在但非默认 | 该组合的业务来源 |
| B1 边界/不可达 | 需极端、超规格或非法参数（超出接口合理上限的 shape、退化/非法输入） | "为何不可达"的说明 |

- **默认保守**：无法证明不可达 → 记 **B3**；降为 B1/B2 必须附证据，**不得仅凭"业务应该不会这么用"**。
- 超规格参数是否算 B1 取决于**接口契约**：契约允许但业务不用 → B1；契约不允许（本应报错）→ 属校验缺失（FP-B04/B05 类），另行归属。

**业务影响类型**（命中后对用户可见结果的后果，用业务语言表述）：静默精度损失（模型效果下降 / loss 不收敛 / 偶发 NaN）｜ 任务失败中断（报错 / 崩溃 / 挂死）｜ 性能退化 ｜ 仅可观测性（日志 / 错误码 / 文档，不影响结果）。

**处置建议**（由两轴推导的报告结论，非新档位）：

| S×O \ B | B3 现实可达 | B2 条件可达 | B1 边界/不可达 |
|---|---|---|---|
| 高（≥6） | 尽快修 | 尽快修 | 排期修 |
| 中（3/4） | 尽快修 | 排期修 | 记录（业务难以触达） |
| 低（1/2） | 排期修 | 记录 | 记录 |

## 7. 判定标准与反误报原则

- **「常量名叫 MAX」不是上限**：先查 [cases/false-upper-bounds.md](../../../cases/false-upper-bounds.md) 第一节，`MUL_NC_MAX_DIM`、`CUMSUM_CUBE_MAX_SUPPORT_SIZE` 这类只用于模板选型/路径选择的常量**不构成本型载体**。
- **「结果变量是 int64」不是防护**：数组长度是编译期常量，写入越界与元素类型无关。
- **`[256]` 存在 ≠ 缺陷**：必须同时满足「索引来自入参」+「无上界校验」+（优先）「兄弟有校验」。三者缺一只能记观察项。
- **族内上限值可能不同**：foreach 族有 128 与 256 两种，不得按族内一例推广到全族。
- **`arch22/` 与 `arch35/` 分开核**：只查一侧会得出「有护栏」的假结论。
- **不臆造行号**；**静态推演声明**必写。

### 判定纪律补充（v3.6）：非对称增减、证据等级与误判记录

**增减不对称**：允许追加候选（有据即可，错了可由用户排除）；**撤销或否决候选必须附 `[文件]:[行号] [代码行]` 负向证据**。无证据的「看起来没问题」一律记为「未核查」，不得计入反证排除，也不得据此下调等级——否决造成的漏报用户不可见、不可恢复。

- **证据等级**（Bug 卡必填）：`静态可证` = 推导链完整且触发输入可静态构造；`需实测确认` = 依赖运行时输入规模、设备行为或环境差异。标 `需实测确认` 的条目**不得以「命中」名义出卡**，按观察项记录并附实测用例。
- **Agent 误判记录**（Bug 卡必填）：本次被推翻的假设、推翻它的证据（`[文件]:[行号] [代码行]` 或实测输出）、判定标准是否随之修订；无推翻写「无」。
- **误判回流**：同类误判在 3 次检视中重复出现，登记至 `cases/misjudgments.jsonl`（字段见 `cases/README.md`），并在本模式判定标准中新增对应防线；守门 C19d 校验台账字段合法。

## 9. 示例速览：aclnnForeachExpm1 vs aclnnForeachAtan

- **定位**：`ops-nn` → `foreach/foreach_expm1/`（缺陷）、`foreach/foreach_atan/`（正确对照）。
- **检视面提示**：
  - 数组：`foreach_expm1/op_kernel/arch35/foreach_expm1_tiling_data.h:25` `int64_t tensorElements[256] = {0};`
  - 越界写：`foreach_expm1/op_host/arch35/foreach_expm1_tiling_arch35.cpp:79` `tiling->tensorElements[i] = numel;`
  - 无校验的取证：`grep -rn "256|MAX_TENSOR" foreach_expm1/op_host/` → **零命中**
  - 兄弟护栏：`foreach_atan/op_host/arch35/foreach_atan_tiling.cpp:32` + `:74`
- **实测后果**：n=257 → rc=0 但 sync=507035 + kernel fault；n=258/300/512 → 2/86/510 处静默错误；910C 上表现为静默不写。
- 最终判定以第 4/5/7 节为准。

## 10. 能力边界与自检（v3.8）

### 能力边界

- **静态可证**：清单里能在源码内给出「`文件:行号` + 推导链」的部分，按第 7 节判据出卡。
- **需实测确认**：依赖运行时输入规模、设备行为或环境差异的结论，只能记观察项并附实测用例（证据等级见第 7 节）。
- **不覆盖**：本模式以外的机理（边界见第 0 节）与仓外框架侧行为；`TRIAGE.md` 只负责收敛候选，不构成判定依据。
- **找不到 ≠ 没有**：按清单未命中只说明「本轮未发现」，不得表述为「该算子无此缺陷」；抽样核查须在报告写明抽样口径。

### 自检

```bash
python3 scripts/gen_triage.py --check                          # 分诊表与映射一致
python3 scripts/scan_fp.py --only FP-B15 --format json <目标文件>  # 签名候选（非结论）
python3 scripts/verify_lines.py <报告.md> --root <被检仓>        # 行号校验
python3 check_fault_patterns.py                                # 全库守门
```

### 工作量与抽样（v4.0）

- **深度档：标准**（索引 `depth` 字段）——每映射点取前 20 处命中；同一映射点连续 20 处反证排除即停止该点并记录。报告须写「抽样口径：每点前 20 处」。
- **报告必填**：抽样口径（全量 / 每点前 N 处 / 每类 N 例）+ 停止点记录；未写口径视为未完成。

### 量化基线（数字来自卡片实证，引用须注明来源）

- ops-nn **#8254**（2026-11-06）：n=257 `rc=0` + `sync=507035` + kernel fault；n=258/300/512 → **2/86/510** 处静默错误；host 结构体越界写约 **2048 字节**。
- 对照组 `foreach_atan` 有 `MAX_TENSOR_NUM=256` 校验（`:32` 定义、`:74` 拦截）。
- 族内实测（`ops-nn` @ `9.3.0-beta.1`）：带 `int64_t tensorElements[256]` 的 foreach 接口中，**`foreach_expm1` 与 `foreach_neg` 无校验**，其余多数有。
- 判据：**只与列表长度有关，与 shape/dtype 无关**——按 shape/dtype 铺的矩阵天然覆盖不到。

### 探针矩阵（最小可执行集）

| 探针 | 构造 | 期望 / 判据 |
|---|---|---|
| 容量扫描 | 列表长度取 `1 / N-1 / N / N+1 / 2N` | 超上限必须明确报错；未超限时每个元素与单元素调用一致 |
| 逐元素对照 | `torch._foreach_*` 与逐元素调用逐个比 | 超出容量的尾部元素会暴露静默错值 |
| 返回码 + sync 双读 | 同时记两段返回码与 `aclrtSynchronizeStream` | 越界遭 kernel fault 时只有 sync 非 0，第二段仍 0 |
| 静态三件套 | 数组 × 入参索引 × 无校验 | 见第 4 节 ①–③ |
| 兄弟对拍 | 族内统计「有数组 / 有校验」 | 缺的那批即高置信候选 |
