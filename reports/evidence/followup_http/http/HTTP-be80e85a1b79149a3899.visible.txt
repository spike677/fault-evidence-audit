Describe the current behavior / 问题描述
A3 上
sparse_lightning_indexer_kl_loss_grad
的 BF16
dQ
在无可见压缩 KV 的 query 行保留显存旧值，导致训练首步
grad_norm=NaN
。所有浮点输入均有限；其他三个算子输出有限。无需 compile 即可复现。
已定位到 PR
#11435
，commit
d77a4cac919f3fca9a1bb6991e48a640db01986a
（SparseLightningIndexerKLLossGrad supports top-k generalization in the range of 1 to 8192）。
attention/sparse_lightning_indexer_kl_loss_grad/op_kernel/arch22/sparse_lightning_indexer_kl_loss_grad_base.h
的
ClearInvalidS1Output
（当前 master 613–622 行）由无条件清零改为：

T
) 分支；BF16 dQ 不满足类型判断，直接漏写。
CalcCoreClearRange
按元素均分，不能保证每段16个BF16元素对齐。后续计算会跳过无可见KV的query，无法补写这些位置。
在本复现的18个document、54个无有效KV的query、每行64×128个BF16、40个AIV的情况下，每核clear范围为
ceil(54*8192/40)=11060

383344

1e878a0cdf15eba39382def8cdd599e8233c11b8
中仍存在。
Environment Information / 环境信息
Ascend A3，单卡即可复现；非确定性模式。
CANN 9.2.0 w0916。
Python 3.12.10；torch distribution 2.14.0+cpu；torch_npu 2.14.0.dev20260916；cann-ops-transformer 1.0.0。
TND；q=[4096,64,128] BF16，k=[1016,1,128] BF16，w=[4096,64] FP32；topk=512，mask_mode=3，cmp_ratio=4。
使用cu_seqlens，不传seqused_q/k。

Describe the expected behavior / 预期结果
无可见压缩KV的query，其indexer KL loss对应dQ应全为零，与分配器旧数据无关；所有输入有限时，不应生成NaN/Inf。建议为BF16/FP16补齐未对齐清零路径，或按对齐块划分清零范围，并保证边界完整覆盖。
