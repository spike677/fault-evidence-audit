问题分析
核查 ops-math 提交
8c1f633e3679f83b55a237c552f842cdcf80462f
的
aclnn_reduce_sum.cpp
，
CheckDimValid
接受合法负轴，并用
GetPosDim
进行轴检查；但 BOOL→INT64 分支计算
reduceDims
时仍直接使用原始
dims
索引 shape，两处处理确实不一致。
该分支按归约元素数是否小于
2^24
选择 FLOAT 或 INT64，随后先将输入转换到所选类型再做归约。负轴未归一会破坏归约规模判断；若误入 FLOAT，16785409 无法被 fp32 精确表示，最后转回 INT64 也无法恢复精度。这与您提供的正负轴对照和奇偶计数结果一致。源码核查支持这一问题机制，设备结果以您报告的 910B2 / CANN 9.2.0 实测为依据。
处理方向
一个可行方案是在计算归约规模前将每个合法负轴归一到对应正轴，再计算
reduceDims
，保留大规模 BOOL 计数使用 INT64 的路径。同时需关注乘积溢出保护，以及空 dims、混合正负轴和
2^24
附近计数的边界。对当前例子，可先使用等价正轴
[0,1]
，您提供的对照结果表明该写法能得到正确计数。
