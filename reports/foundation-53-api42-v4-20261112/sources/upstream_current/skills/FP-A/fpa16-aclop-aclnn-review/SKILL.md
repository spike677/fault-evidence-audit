# FP-A16 aclnn 接口检视（fpa16-aclop-aclnn-review）

对用户指定的 aclnn 接口做 FP-A16 专项源码检视：先定位算子实现与各调用入口，再按清单逐项核查，每个结论给出**文件 + 行号 + 推导链**证据，命中即出 Bug 卡，输出检视报告。**本模式特殊纪律：① 缺陷表征是「同一算子同输入、换条调用路径结果就不同」——单路径用例天然测不出，必须先**枚举调用入口**再逐对核；② 路径轴是「调用入口 / 编译期决策」而非设备侧指令或 tiling 模板，定位时先定入口再定实现；③ 卡片触发为关键词（`aclop|GEIR`）——命中只作定位提示，真正的判据是**两条路径的预处理与编译期决策差异**；④ 修复方向必须为**路径行为对齐**而非单侧修数——单侧修数会掩盖另一路径的同源问题，检视时须核修复是否只改了一侧。**

## 0. 与相邻模式的边界

| 相邻模式 | 分工 |
|---|---|
| FP-A14（FFMA 与 MMAD 硬件指令差异） | 卡片关联项：同为「同输入两路径结果不同」家族，**路径轴不同**——A14 差在设备侧指令路径（Vector FFMA vs Cube MMAD），A16 差在 host / 图侧调用路径（aclnn 单算子 vs aclop / GEIR 图）——两轴可并存连打 |
| FP-D02（aclnn 内存占用高于 aclop） | 卡片关联项：同一「aclnn vs aclop」对照轴的**资源面**（D02 管内存占用）vs **精度面**（A16 管结果差异）——同一次双路径核验可同时出两类结论 |
| FP-A19（同算子多 tiling 路径覆盖盲区） | A19 的路径轴在**同一调用入口内的 tiling 模板**；A16 的路径轴在**调用入口**——先定入口再定模板，两卡连打可定位「哪条入口 × 哪条模板」出问题 |
| FP-A07（tiling 条件判断错误走入错误分支） | 路径间差异若源于 tiling 分流条件写错，归 A07；若源于某入口特有的编译期决策 / 预处理（常量折叠、pad），归 A16 |
| FP-F03（文档 / 声明面与实现面不一致） | 路径行为差异未在文档说明时属声明面缺口，可连打 F03 |
| FP-A08（切块粒度差异致离群点精度问题） | #4141 的 pad 差异直接暴露 kernel 的非对齐缺陷——非对齐 / 尾块机理归 A08，路径预处理差异归 A16 |

**症状反查定位**：同一输入经 aclnn 单算子与 GE 图（GEIR）结果不同 → 首查两条路径的编译期决策差异（#4254）；仅特定 mode / attr 组合 + **常量输入**才失败 → ACLNN 对常量输入触发的优化路径（#4254：mode=2 + 常量输入 + cos 全 broadcast，`output[1]` dcos **符号反转**、MARE=2.0）；图路径失败而单算子路径正常（或反之）且差异集中在**非对齐尾轴** → pad / 消 pad 预处理只在一条路径存在（#4141：aclnn 补 pad 48→64、图路径直连 48 非对齐）；单算子路径全 PASS、图路径批量 FAIL → 图路径缺预处理（#4141 27/30 batch）；同一算子在 aclop 与 aclnn 两接口下精度口径不同 → 双路径一致性核验。

## 1. FP-A16 模式卡摘要（检视依据，源自本库 `patterns/FP-A/FP-A16.md`，v3.1）

- **编号 / 名称**：FP-A16 aclop 与 aclnn 编译阶段精度差异 ｜ **类别**：精度 ｜ **风险**：高（S3×O3=9）｜ **状态**：活跃 ｜ **来源**：团队笔记 + CANN issue 检索（2026-09-16）
- **适用声明头**（照抄卡片）：仓 All ｜ 侧别 Host ｜ 载体 aclnn源码,IR与图配置 ｜ 触发 aclop|GEIR ｜ 默认启用 true
- **skill 核查面**：侧别 Host——skill 落地为 `op_api`（aclnn 单算子出口与常量处理分支）、IR / 图配置面（算子原型、图 pass 与编译期优化配置）、`op_host` tiling / infershape（路径分流与预处理插入点）；`op_kernel` 作为差异后果的落点一并核查
- **故障机理**：两条调用路径**编译期常量折叠 / 精度决策不同**，同一算子同输入结果不同。
- **触发条件**：同一算子分别经 aclop 与 aclnn 调用（实证中对应 **aclnn 单算子**与 **GE 图 / GEIR** 两条路径）。
- **典型表现**：同一算子两条调用路径精度不同。
- **源码审查映射点 / 检测签名**：映射点 = 编译期常量折叠 / 精度决策差异点、调用路径间**补 pad / 对齐等预处理决策**差异；卡片未给独立 grep 签名，触发词为 `aclop|GEIR`（关键词定位提示）。
- **测试拦截建议**：aclop / aclnn 双路径同输入一致性用例。
- **实证案例**：ops-transformer **#4254** `RotaryPositionEmbeddingGrad` 同一 kernel 两条调用路径结果不同——ACLNN 单算子路径 **97/3 FAIL**（仅 mode=2 + **常量输入** + cos 全 broadcast 的 3 例，`output[1]` dcos **符号反转**、MARE=2.0），GEIR 图路径 **10/0 PASS**；根因为 **ACLNN API 对常量输入触发优化路径，编译产物行为与源码不一致**（源码正确用原始 x 算 dcos，产物却用 `rotate(x)`），而 GEIR 经 GE 图框架直接调 kernel 不经过该优化。ops-transformer **#4141** `FlashAttentionScore` aclnn 单算子路径含 V 尾轴非对齐的补 pad / 消 pad 预处理（PadAiCore 48→64 → FA → Slice 64→48），GE 图路径 `dense_v` 直连无 pad，GE 图走 48 非对齐触发 kernel 缺陷致 **27/30 batch** 精度异常，而 aclnn 单算子同输入精度正常。**共性特征：同一算子经不同调用路径时，编译期常量优化与对齐 / 预处理决策不同，同输入结果不同；修复方向均为路径行为对齐而非单侧修数。**
- **关联**：FP-A14、FP-D02。

## 2. 检视输入与算子定位

**输入**：aclnn 接口名（必填，如 `aclnnRotaryPositionEmbeddingGrad`）；可选 ref（默认 master）、指定仓（默认自动定位）；可选现象描述（哪条路径失败 / 失败比例 / 失败集中在哪些 mode 或 attr 组合——用于症状反查）；可选对照路径（aclop 旧接口 / GE 图 / GEIR——默认两条都核）；可选复现输入（常量输入标记、attr 取值、非对齐尾轴尺寸）。

**接口名 → 算子目录换算**：去 `aclnn` 前缀 + 驼峰转下划线小写：
`aclnnRotaryPositionEmbeddingGrad → rotary_position_embedding_grad`、`aclnnFlashAttentionScore → flash_attention_score`、`aclnnConv2d → conv2d`。

**仓定位顺序**（GitCode `cann` 组织，逐仓用目录列表确认）：`ops-transformer`（attention / pos-embed 类——双路径实证集中地）→ `ops-nn` → `ops-math` → `ops-cv`。**类目名不总与直觉一致**，以目录列表为准。FP-A16 高发面：既有 aclnn 单算子入口又有图模式接入的算子（attention / moe / 大模板类）、带 pad / 对齐预处理的 kernel、含常量输入特化分支的实现、IR / 图 pass 配置中的算子原型注册面。

**算子目录结构约定**（已验证示例 `cann/ops-transformer` → attention 类算子目录）：

```text
{类别}/{op_name}/
├── op_api/（或 op_host/op_api/）  # aclnn 单算子出口——常量输入处理分支：主检视面之一
├── op_host/           # *_def.cpp（原型 / IR 配置面）、*_tiling*.cpp（路径分流与预处理插入点）
│   └── config/<soc>/  # *_binary.json
├── op_kernel/         # 差异后果落点：非对齐 / 常量形态特化（含 arch22/ arch35/ 变体）
├── tests/             # 单算子用例 vs 图模式用例（两套用例集是差异暴露面）
└── docs/ examples/
```

## 4. 双路径一致性检视清单（每点：查什么 → 何处 → 命中判据）

对 `op_api`、`op_host`（def / tiling / infershape）、IR 与图配置面、`op_kernel`、`tests` 逐点核查，**每点先查命中面、再做反证排除**，两条路径行为一致的实现也要记录为防护面证据。

### ① 调用入口清单与路径定界
- 查什么：该算子存在的调用入口（aclnn 单算子 / aclop 旧接口 / GE 图或 GEIR 路径）——各入口是否都能到达同一 kernel；入口处的预处理 / 优化开关差异；仓内是否有图模式接入的配置面（算子原型注册、图 pass 相关配置）。
- 何处：`op_api`（aclnn 出口）、`*_def.cpp`（原型 / IR 配置）、仓内 aclop 适配层（若存在）。
- 命中判据：≥2 条可达入口且入口处行为分支不同 ⇒ 进入双路径核查；仅一条入口 ⇒ 反证排除并记录结论（写入报告）。

### ② 编译期常量折叠 / 常量输入优化路径
- 查什么：**常量输入**是否触发特殊优化路径（#4254：ACLNN API 对常量输入触发优化，**编译产物行为与源码不一致**——源码用原始 x 算 dcos，产物用 `rotate(x)`）；常量折叠后参与计算的表达式是否与源码语义等价；该优化是否有注释 / 文档说明。
- 何处：`op_api` 的常量处理分支、图 / 编译期优化配置、`op_kernel` 对常量形态的模板特化。
- 命中判据：常量输入走的分支与非常量输入**语义不等价**（可给出表达式替换 / 符号反转的推导）⇒ 命中候选；两者语义等价 ⇒ 反证排除。

### ③ pad / 对齐等预处理决策差异
- 查什么：某条路径是否含补 pad / 消 pad 预处理（#4141：aclnn 单算子路径 `PadAiCore 48→64 → FA → Slice 64→48`；GE 图路径 `dense_v` 直连无 pad）；预处理只在一条路径存在时，另一条路径是否触发 kernel 的非对齐缺陷。
- 何处：`op_api` / 图 pass 的预处理插入点、`op_host` tiling 的对齐决策、`op_kernel` 的非对齐尾轴处理段。
- 命中判据：路径 A 有 pad、路径 B 无 pad 且 kernel 对非对齐输入存在缺陷 ⇒ 命中候选（同步核 FP-A08 尾块 / 对齐）。

### ④ 双路径一致性用例覆盖
- 查什么：卡片拦截建议的 aclop / aclnn 双路径同输入一致性用例是否存在；是否只测了一条路径（#4254 单算子路径 97/3 FAIL 而图路径 10/0 PASS，说明两路径用例集不同、覆盖面不重合）。
- 何处：`tests/` 用例集（图模式用例 / 单算子用例）、CI 配置。
- 命中判据：仅单路径用例覆盖 + 存在路径特有决策 ⇒ 记观察项（测试建设缺口）；两路径均有同输入一致性用例 ⇒ 记录为防护面。

### ⑤ 修复方向核对（路径行为对齐 vs 单侧修数）
- 查什么：卡片共性结论——修复方向应为**路径行为对齐**而非单侧修数；现存修复是否只改了一侧（单侧修数会掩盖另一路径的同源问题）；是否已在文档标注路径差异。
- 何处：对照修复 diff / 版本轴（本地克隆 `git log` / `git diff`）、docs。
- 命中判据：修复仅单侧且未消除路径差异 ⇒ 记观察项；路径行为已对齐 ⇒ 反证排除并记录防护面。

## 5. 检视流程

1. **定界**：换算 op 目录、确认所在仓与 ref；按用户现象（哪条路径失败 / 失败比例 / 常量输入标记）反查优先清单点；确认对照路径与复现输入。
2. **枚举**：目录列表列出 `op_api`、`op_host`（def / tiling / infershape / config）、IR 与图配置面、`op_kernel`、`tests` 全部相关文件，产出文件清单与**入口清单**。
3. **触发词扫描**：按 `aclop|GEIR|GE\b`、常量输入相关标记（`const|Const|constant` 与输入处理同现）、`Pad|pad|Slice|pad_ai_core`、`IsCapable|REGISTER_TILING_TEMPLATE` 定位风险面（本地仓用 grep；API 模式逐文件拉取后检查）。**签名零命中时清单仍须逐项核查**（单入口算子可直接反证排除，须写明结论）。
4. **逐点核查**：每点记录命中面与防护面证据（文件:行号）；对每条路径写出「入口 → 预处理（有 / 无 pad）→ 编译期决策 → kernel 输入形态 → 结果」五项对表。
5. **反证排除**：单入口、两路径语义等价、两路径预处理一致、双路径一致性用例齐备、修复已对齐 → 明确写出反证理由。
6. **判定**：按第 7 节标准给出 命中 / 观察项 / 反证排除。
7. **GitCode 查重**（仅命中项）：issues API 按接口名 + `aclnn|图|精度|常量|pad` 检索，逐条比对是否同机理；无同机理才立卡。
8. **业务可达性核查**（仅命中项）：判 B 等级、定业务影响类型、给处置建议；默认保守（无法证明不可达即记 B3），降档须附证据；B 不改 S×O 档位。
9. **出报告**：按第 8 节模板落盘；所有数值后果标注「静态推演，需 NPU 实测确认」，并附双路径同输入一致性用例方案。

## 6. 风险定级（S×O）与业务影响评估（B 轴）

- **S**：S3（同输入两路径结果不同——结果错但可运行；#4254 dcos 符号反转 MARE=2.0、#4141 27/30 batch 精度异常）；S2（差异在容差内、仅极端组合触发）；S1（仅测试覆盖缺口、路径行为一致）。
- **O**：O3 = ≥2 条独立实证；O2 = 1 条独立实证；O1 = 仅静态扫描命中或团队笔记（实证 = 确认对应的 issue / PR，或经跨仓、跨分支核验确认的缺陷记录，同权计入）。静态推演命中且无实证默认 **O1**；升档须在报告中给出实证依据。
- **风险 = S×O**：≥6 高；3/4 中；1/2 低。FP-A16 基准：模式卡整体 **S3×O3=9（高）**；纯静态命中 S3×O1=3（中，暂定），双路径实测后复评。

### B 轴：业务影响评估（与 S×O 正交；报告层新增，不改卡片定级）

S×O 回答"多严重、多常见"，**不回答"真实业务能不能碰到"**。B 轴补这一问，只决定**修复优先级建议**，**不参与 S/O 取值、不改 S×O 档位与卡片元数据**。

**业务可达性（B）**——触发条件在真实负载中的可达程度：

| 等级 | 判据 | 证据要求 |
|---|---|---|
| B3 现实可达 | 主流框架/公开模型默认路径即可命中（如 PTA/torch_npu、vLLM、MindIE 常规调用） | 调用方或公开负载来源 |
| B2 条件可达 | 需特定 attr/dtype/shape 组合，业务中存在但非默认 | 该组合的业务来源 |
| B1 边界/不可达 | 需极端、超规格或非法参数（超出接口合理上限的 shape、退化/非法输入） | "为何不可达"的说明 |

- **默认保守**：无法证明不可达 → 记 **B3**；降为 B1/B2 必须附证据，**不得仅凭"业务应该不会这么用"**。
- 超规格参数是否算 B1 取决于**接口契约**：契约允许但业务不用 → B1；契约不允许（本应报错）→ 属校验缺失（FP-B04/B05 类），另行归属。

**业务影响类型**（命中后对用户可见结果的后果，用业务语言表述）：静默精度损失（模型效果下降 / loss 不收敛 / 偶发 NaN）｜ 任务失败中断（报错 / 崩溃 / 挂死）｜ 性能退化 ｜ 仅可观测性（日志 / 错误码 / 文档，不影响结果）。

**处置建议**（由两轴推导的报告结论，非新档位）：

| S×O \ B | B3 现实可达 | B2 条件可达 | B1 边界/不可达 |
|---|---|---|---|
| 高（≥6） | 尽快修 | 尽快修 | 排期修 |
| 中（3/4） | 尽快修 | 排期修 | 记录（业务难以触达） |
| 低（1/2） | 排期修 | 记录 | 记录 |

## 7. 判定标准与反误报原则

- **签名 / 触发词命中 ≠ 成立**：`aclop` / `GEIR` 命中只说明该算子与两条路径有关——必须过「入口清单 + 预处理差异 + 常量决策等价性」三关；单入口算子直接反证排除。
- **三种判定**：
  - **命中**（可静态证路径差异）：两路径预处理 / 常量决策不等价的推导链完整（可给出表达式替换、符号反转、pad 有无的对表）+ 触发输入可构造 ⇒ 立 Bug 卡；
  - **观察项**：差异需运行时双路径实测确认、或图侧行为不在算子仓内无法静态判定 ⇒ 记录并附双路径一致性用例方案，按 S3×O1 暂定；
  - **反证排除**：单入口、两路径语义与预处理一致、双路径一致性用例齐备、修复已对齐 → 写出防护面证据与反证理由。
- **图侧行为不臆测**：GE / GEIR 的常量折叠与图 pass 不在算子仓内——只能核 aclnn 出口的常量处理分支与预处理插入点；图侧结论须标注「需结合图配置 / 运行时验证」。
- **修复必须路径对齐**：命中的修复建议为「路径行为对齐」，不接受「单侧修数」；检视现存修复时若只改一侧，记观察项并说明掩盖风险。
- **「单路径用例全绿」不是反证**：本型识别特征正是「一条路径绿、另一条路径才暴露」——用例覆盖面须按入口分别核。
- **不臆造行号**：每条证据必须是实际读到的 文件:行号；引用 #4254 / #4141 时注明 issue 时点行号与本地 HEAD 的漂移。
- **静态推演声明**：无 NPU 环境时，所有运行时行为结论必须标注「静态推演，需 NPU 实测确认」。

### 判定纪律补充（v3.6）：非对称增减、证据等级与误判记录

**增减不对称**：允许追加候选（有据即可，错了可由用户排除）；**撤销或否决候选必须附 `[文件]:[行号] [代码行]` 负向证据**。无证据的「看起来没问题」一律记为「未核查」，不得计入反证排除，也不得据此下调等级——否决造成的漏报用户不可见、不可恢复。

- **证据等级**（Bug 卡必填）：`静态可证` = 推导链完整且触发输入可静态构造；`需实测确认` = 依赖运行时输入规模、设备行为或环境差异。标 `需实测确认` 的条目**不得以「命中」名义出卡**，按观察项记录并附实测用例。
- **Agent 误判记录**（Bug 卡必填）：本次被推翻的假设、推翻它的证据（`[文件]:[行号] [代码行]` 或实测输出）、判定标准是否随之修订；无推翻写「无」。
- **误判回流**：同类误判在 3 次检视中重复出现，登记至 `cases/misjudgments.jsonl`（字段见 `cases/README.md`），并在本模式判定标准中新增对应防线；守门 C19d 校验台账字段合法。

## 9. 示例速览：RotaryPositionEmbeddingGrad（ops-transformer #4254）与 FlashAttentionScore（ops-transformer #4141）

- **定位**（算子目录与关键文件；类目以目录列表确认，行号以本地 HEAD 为准）：
  - `cann/ops-transformer` → `rotary_position_embedding_grad` 算子目录（类目以目录列表确认）；关键文件：`op_api` 出口（常量输入处理分支）、`op_kernel` 的 dcos 计算段（**源码用原始 x、产物却用 `rotate(x)`——#4254 的核心差异点**）、mode 分支与 broadcast 处理段、`tests/` 的单算子用例与图模式用例（97/3 FAIL vs 10/0 PASS 的差异面）。
  - `cann/ops-transformer` → attention 类目下的 `flash_attention_score` 算子目录（类目以目录列表确认）；关键文件：`op_api` / 图侧预处理插入点（PadAiCore 48→64 / Slice 64→48）、`op_kernel` 的 `dense_v` 非对齐尾轴处理段（#4141 差异面）。
- **检视面提示**（引导，不预设结论，仍须逐点核查）：
  - 清单①：先枚举入口——aclnn 单算子路径与 GE 图 / GEIR 路径是否都存在、是否到达同一 kernel；
  - 清单②：核**常量输入**分支（#4254：mode=2 + 常量输入 + cos 全 broadcast 的 3 例，`output[1]` dcos 符号反转、MARE=2.0）——常量输入与非常量输入的表达式是否语义等价；
  - 清单③：核 pad / 消 pad 预处理的有无（#4141：aclnn 侧 PadAiCore 48→64 → FA → Slice 64→48，图侧 `dense_v` 直连 48 非对齐），并同步按 FP-A08 核 kernel 非对齐缺陷；
  - 清单④：`tests/` 是否具备双路径同输入一致性用例（两路径用例集不重合是本型暴露面）；
  - 清单⑤：修复方向是否为路径行为对齐（#4254 / #4141 的共性结论），现存修复若只改一侧须记观察项。
- 任何一点的最终判定以第 4/5/7 节口径为准，禁止凭算子类型直接下结论。

## 10. 能力边界与自检（v3.8）

### 能力边界

- **静态可证**：清单里能在源码内给出「`文件:行号` + 推导链」的部分，按第 7 节判据出卡。
- **需实测确认**：依赖运行时输入规模、设备行为或环境差异的结论，只能记观察项并附实测用例（证据等级见第 7 节）。
- **不覆盖**：本模式以外的机理（边界见第 0 节）与仓外框架侧行为；`TRIAGE.md` 只负责收敛候选，不构成判定依据。
- **找不到 ≠ 没有**：按清单未命中只说明「本轮未发现」，不得表述为「该算子无此缺陷」；抽样核查须在报告写明抽样口径。
