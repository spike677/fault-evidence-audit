# FP-A08 aclnn 接口检视（fpa08-kernel-review）

对用户指定的 aclnn 接口（如 aclnnBatchMatMul）做 FP-A08 专项源码检视：先定位算子实现，再按清单逐项核查，每个结论给出**文件 + 行号 + 推导链**证据，命中即出 Bug 卡，输出检视报告。**本模式特殊纪律：① 缺陷集中在「尾块/尾核」这一**非对齐边界**而非均匀主块——均匀 shape 全过、极端 shape 才失败；② 判据是「同 shape 换 tiling 粒度对比 + 离群点输入」——须给出「切块粒度改变浮点归约分组 / padding 值参与计算」的推导链；③ 触发签名 `tileSize|tileNum|Tail|tail` 在 tiling 与 kernel 中普遍存在，命中只表示「值得人工核」，不表示成立；④ 与 A02（归约拓扑）、A05（脏数据）、A07（分支条件）、B07（尾块偏移越界）同族交界，须按主导机理归因并双向关联。**

## 0. 与相邻模式的边界

| 相邻模式 | 分工 |
|---|---|
| FP-A02（归约/累加实现顺序与竞品不一致） | **粒度 vs 拓扑**二分：A02 是归约**拓扑本身**与标杆不一致（实现顺序面）；A08 是**切块粒度**改变导致归约分组变化（粒度参数面）——同一偏差可两者共因，按主导因素归属并双向关联 |
| FP-A05（脏数据/数据踩踏） | **值 vs 机理**二分：A05 管尾块 padding **未覆盖/残留脏数据**的机理；A08 管 padding **值本身选择不当参与计算**引入的偏差——按主导视角归属 |
| FP-A07（tiling 条件判断错误走入错误分支） | A07 是**条件表达式写错**走入错误分支（逻辑本身错）；A08 是**分支选对了但粒度/尾块处理不当**（数值后果）——先验表达式（A07）再看粒度后果（A08） |
| FP-B07（索引/偏移计算错误致越界） | A08 管尾块 **padding 值参与计算**引入的精度偏差；尾块**偏移/下标算错致越界**（如实证 #3081 尾块 `preCoreNum` 未清零致 index 计算 `uint64_t` 负数溢出）归 B07——报告双向关联 |
| FP-A03（竞品高精度中间计算，NPU 直接低精度） | A03 是**大面积**超阈（位宽损失，与数据分布无关）；A08 是**离群点/极端 shape** 下的局部偏差——按「大面积 vs 局部」分 |
| FP-A06（确定性开关下结果不固定） | A06 是**未清零 padding 残留随机数**导致的不确定；A08 是**padding 值确定但不当**引入的确定性偏差——按「是否随机」分 |

**症状反查定位**：同一 shape 换 tiling 粒度后结果变化 → 切块粒度面（清单①）；shape 紧贴某实现上限（如 ND2NZ on-the-fly 上限 65535，实证 #5519 取 K=65533）时精度超阈 → 尾块面（清单②）；含 ±inf / 极大极小值的离群点输入精度失败 → padding/分组面（清单③）；分核不整除的尾核场景异常 → 尾核面（清单④）；FM 非全载 / L0B 全载等模板切换处的尾块异常 → 模板分支尾块面。

## 1. FP-A08 模式卡摘要（检视依据，源自本库 `patterns/FP-A/FP-A08.md`，v3.1）

- **编号 / 名称**：FP-A08 切块粒度差异致离群点精度问题 ｜ **类别**：精度 ｜ **风险**：高（S3×O3=9）｜ **状态**：活跃
- **适用声明头**（照抄卡片）：仓 All ｜ 侧别 Tiling,Kernel ｜ 载体 Tiling源码,Kernel源码 ｜ 触发 tileSize|tileNum|Tail|tail ｜ 默认启用 true
- **skill 核查面**：侧别 Tiling,Kernel——skill 落地为 `op_host` 的 `*_tiling*.cpp`（切块/分核/尾块参数计算）与 `op_kernel/` 的搬运与计算实现（尾块处理、padding 值选择，含 arch35 / regbase / SIMT 等架构变体）；`config/<soc>/*_binary.json` 的分核配置同步核对
- **故障机理**：不同切块大小下浮点归约分组不同；尾块 padding 值参与计算引入偏差。
- **触发条件**：极端 shape、离群点数据、尾块场景。
- **典型表现**：离群点/极端 shape 下精度失败。
- **源码审查映射点**：切块大小计算、尾块处理、padding 值选择。
- **检测签名**（命中即候选缺陷点位）：`tileSize|tileNum|Tail|tail`（切块粒度与尾块实现定位点）。
- **测试拦截建议**：同 shape 换 tiling 粒度对比；含 ±inf/极大极小值的离群点用例。
- **实证案例**：ops-nn **#5519** aclnnBatchMatMul fp32 且 K=65533（紧贴 ND2NZ on-the-fly 上限 65535）时**尾块路径**精度超阈（相对误差比例 3.099 > 阈值 2.0）；**#3391** slice 场景 m 方向**尾块切块 slicem 对齐**与负载均衡修复；**#5061** conv2d FM 非全载 Cin 尾块计算错误；**#3281** Conv weightUb 模板 K 轴尾块处理异常；**#5138** singlecorebatch 尾块、尾核场景；**#3273** 尾核尾块场景 L0B 全载 weight 时搬进搬出指令偏移错误；**#4239** dynamic_quant 尾块场景精度不达标；ops-transformer **#3081** AllGatherMatmulV2 尾块 `preCoreNum` 未清零致某些 shape 的 UpdateBasicIndex 计算 index 时 `uint64_t` 负数溢出。**共性特征：缺陷集中在「尾块/尾核」这一非对齐边界，而非均匀主块。**
- **关联**：FP-A02、FP-A05、FP-A07。

## 2. 检视输入与算子定位

**输入**：aclnn 接口名（必填，如 `aclnnBatchMatMul`）；可选 ref（默认 master）、指定仓（默认自动定位）；可选现象描述（失败 shape / 是否紧贴某上限 / 是否离群点输入 / 尾核场景——用于直接定位粒度面）；可选标杆实现。

**接口名 → 算子目录换算**：去 `aclnn` 前缀 + 驼峰转下划线小写：
`aclnnBatchMatMul → batch_mat_mul`、`aclnnAllGatherMatmulV2 → all_gather_matmul_v2`、`aclnnDynamicQuant → dynamic_quant`。

**仓定位顺序**（GitCode `cann` 组织，逐仓用目录列表确认）：`ops-nn`（matmul/conv 类——实证集中地）→ `ops-transformer`（attention/moe/通信融合类）→ `ops-math`（math/conversion 类）→ `ops-cv`。**类目名不总与直觉一致**，以目录列表为准。FP-A08 高发面：matmul 类（ND2NZ / K 轴切分 / 非对齐尾块）、conv 类（FM 非全载、weightUb 模板、Cin/K 轴尾块）、量化类（dynamic_quant 尾块）、通信融合类（AllGather+Matmul 的尾核与 `preCoreNum`）、带 `singlecorebatch` / 尾核特化模板的算子。

**算子目录结构约定**（以实证算子为例，具体布局以目录列表为准）：

```text
{类别}/{op_name}/
├── op_host/                  # *_tiling*.cpp——切块/分核/尾块参数：主检视面之一
│   └── config/<soc>/         # *_binary.json（分核配置）
├── op_kernel/                # kernel 头文件——尾块处理与 padding 值：主检视面之一
│   └── arch35/ regbase/ ...  # 架构变体
├── op_graph/  tests/  docs/  examples/   # 视算子而定
```

## 4. 检视清单（每点：查什么 → 何处 → 命中判据）

对算子的 `op_host` tiling（切块/分核/尾块参数）与 `op_kernel/`（尾块处理、padding 值，含架构变体）全部相关文件逐点核查，`config/<soc>/*_binary.json` 同步核对，**每点先查命中面、再做反证排除**；已对齐尾块/已正确选 padding 的实现要记录为防护面证据。

### ① 切块大小计算与归约分组
- 查什么：`tileSize` / `tileNum` / 分块粒度的**计算链**（`CeilDiv(total, tile)`、分核块数、负载均衡参数）——粒度是否随 shape 变化导致浮点归约**分组不同**（同 shape 换粒度结果变化即本型特征）；粒度取值是否与指令/硬件约束（如 ND2NZ on-the-fly 上限 65535）匹配（实证 #5519：K=65533 紧贴上限走尾块路径）。
- 何处：`op_host` tiling 的切块/分核计算段、`config/<soc>/*_binary.json` 分核配置。
- 命中判据：能写出「粒度取值使归约分组改变 / 紧贴约束上限走异常尾块路径 → 精度偏差」的推导链 ⇒ 命中候选（须附实测方案）。

### ② 尾块处理（mask / padding 覆盖与对齐）
- 查什么：尾块（非对齐末块）的 mask / `DataCopyPad` 精确字节覆盖是否完整、对齐是否正确（实证 #3391：slice 场景 m 方向**尾块切块 slicem 对齐**与负载均衡修复；#5061 conv2d FM 非全载 Cin 尾块计算错误；#3281 Conv weightUb 模板 K 轴尾块处理异常；#3273 尾核尾块场景 L0B 全载 weight 搬进搬出指令偏移错误）。
- 何处：kernel 尾块搬运/计算段、tiling 尾块参数计算。
- 命中判据：存在「尾块覆盖不完整 / 对齐错误 / 尾块计算与实际 shape 不符」的路径 ⇒ 命中候选。

### ③ padding 值选择
- 查什么：尾块 padding **值本身**的选择——是否参与浮点计算并引入偏差（如以 0 之外的值填充、padding 值参与归约/乘加）；padding 是否应为中性元（加法用 0、max 用 -inf、min 用 +inf）；离群点输入下 padding 值是否与真实数据量级冲突。
- 何处：kernel 的 padding 填充段、归约/矩阵乘的边界处理。
- 命中判据：存在「padding 值非中性元且参与计算 → 引入偏差」的路径 ⇒ 命中候选（机理侧同步关联 A05）。

### ④ 尾核 / 分核不整除
- 查什么：分核数与 shape 不整除时的**尾核处理**（实证 #5138 singlecorebatch 尾块、尾核场景；#3081 尾块 `preCoreNum` 未清零致 `UpdateBasicIndex` 计算 index 时 `uint64_t` 负数溢出）；尾核的偏移/计数变量是否初始化、尾核与主核的语义是否一致。
- 何处：tiling 分核逻辑、kernel 尾核分支、`preCoreNum` / `blockFactor` 类变量。
- 命中判据：存在「尾核变量未初始化 / 尾核偏移计算错误」的路径 ⇒ 命中候选（若致越界则主导归 B07，双向关联）。

### ⑤ 离群点与极端 shape 用例覆盖
- 查什么：`tests/` 是否有「同 shape 换 tiling 粒度对比」用例、含 **±inf / 极大极小值**的离群点用例、紧贴实现上限（如 65535）的边界 shape 用例、尾核（分核不整除）用例。
- 何处：`tests/` 的精度用例与 shape 覆盖矩阵。
- 命中判据：无粒度对比 / 无离群点 / 无上限边界用例 ⇒ 记观察项（测试面缺口）。

## 5. 检视流程

1. **定界**：换算 op 目录、确认所在仓与 ref；确认 tiling 布局与 `config/<soc>/`；记录用户现象（失败 shape / 是否紧贴上限 / 是否离群点 / 尾核）。
2. **枚举**：目录列表列出 `op_host` tiling 文件、`config/<soc>/*_binary.json`、`op_kernel/`（含架构子目录）、`tests/`，产出文件清单。
3. **触发词扫描**：按 `tileSize|tileNum|Tail|tail`、`DataCopyPad|Duplicate|mask|preCoreNum|blockFactor`、`CeilDiv|FloorDiv` 定位风险面（本地仓用 grep；API 模式逐文件拉取后检查）。**触发为关键词：签名零命中时清单仍须逐项核查完毕**。
4. **逐点核查**：按第 4 节 ①~⑤ 记录命中面与防护面证据（文件:行号）；对尾块/尾核处理给出「非对齐边界上的覆盖与对齐」推导。
5. **反证排除**：粒度与约束匹配且不改变归约分组、尾块覆盖完整且对齐正确、padding 为中性元或不参与计算、尾核变量已初始化且语义一致 → 明确写出反证理由。
6. **判定**：按第 7 节标准给出 命中 / 观察项 / 反证排除。
7. **GitCode 查重**（仅命中项）：issues API 按接口名 + `尾块|尾核|精度|tiling|离群` 检索，逐条比对是否同机理；无同机理才立卡。
8. **业务可达性核查**（仅命中项）：判 B 等级、定业务影响类型、给处置建议；默认保守（无法证明不可达即记 B3），降档须附证据；B 不改 S×O 档位。
9. **出报告**：按第 8 节模板落盘；所有精度结论标注「静态推演，需换粒度对比 + 离群点实测确认」并附实测方案。

## 6. 风险定级（S×O）与业务影响评估（B 轴）

- **S**：S3（离群点/极端 shape 下精度失败——结果错但可运行）；S2（仅非对齐尾块场景可见的轻微偏差）；S1（偏差远低于阈值）。
- **O**：O3 = ≥2 条独立实证；O2 = 1 条独立实证；O1 = 仅静态扫描命中或团队笔记（实证 = 确认对应的 issue / PR，或经跨仓、跨分支核验确认的缺陷记录，同权计入）。静态推演命中且无实证默认 **O1**；升档须在报告中给出实证依据。
- **风险 = S×O**：≥6 高；3/4 中；1/2 低。FP-A08 基准：模式卡整体 S3×O3=9（高）；纯静态命中 S3×O1=3（中，暂定，实测后复评）。

### B 轴：业务影响评估（与 S×O 正交；报告层新增，不改卡片定级）

S×O 回答"多严重、多常见"，**不回答"真实业务能不能碰到"**。B 轴补这一问，只决定**修复优先级建议**，**不参与 S/O 取值、不改 S×O 档位与卡片元数据**。

**业务可达性（B）**——触发条件在真实负载中的可达程度：

| 等级 | 判据 | 证据要求 |
|---|---|---|
| B3 现实可达 | 主流框架/公开模型默认路径即可命中（如 PTA/torch_npu、vLLM、MindIE 常规调用） | 调用方或公开负载来源 |
| B2 条件可达 | 需特定 attr/dtype/shape 组合，业务中存在但非默认 | 该组合的业务来源 |
| B1 边界/不可达 | 需极端、超规格或非法参数（超出接口合理上限的 shape、退化/非法输入） | "为何不可达"的说明 |

- **默认保守**：无法证明不可达 → 记 **B3**；降为 B1/B2 必须附证据，**不得仅凭"业务应该不会这么用"**。
- 超规格参数是否算 B1 取决于**接口契约**：契约允许但业务不用 → B1；契约不允许（本应报错）→ 属校验缺失（FP-B04/B05 类），另行归属。

**业务影响类型**（命中后对用户可见结果的后果，用业务语言表述）：静默精度损失（模型效果下降 / loss 不收敛 / 偶发 NaN）｜ 任务失败中断（报错 / 崩溃 / 挂死）｜ 性能退化 ｜ 仅可观测性（日志 / 错误码 / 文档，不影响结果）。

**处置建议**（由两轴推导的报告结论，非新档位）：

| S×O \ B | B3 现实可达 | B2 条件可达 | B1 边界/不可达 |
|---|---|---|---|
| 高（≥6） | 尽快修 | 尽快修 | 排期修 |
| 中（3/4） | 尽快修 | 排期修 | 记录（业务难以触达） |
| 低（1/2） | 排期修 | 记录 | 记录 |

## 7. 判定标准与反误报原则

- **签名 / 触发词命中 ≠ 成立**：`tail`/`tileSize` 在 tiling 与 kernel 中普遍存在且多数正确——命中只是定位提示，必须证明「尾块/尾核处理或 padding 值选择不当且触发 shape 可构造」。
- **三种判定**：
  - **命中**（可静态证缺陷路径）：「切块粒度/尾块覆盖/padding 值/尾核处理不当 → 精度偏差」的推导链完整 + 触发 shape 可构造 → 立 Bug 卡（档级按实测证据定）；
  - **观察项**：尾块逻辑存疑但后果依赖实测、或仅测试面覆盖缺口 → 记录并附实测方案，按 S3×O1 暂定；
  - **反证排除**：粒度不改变归约分组、尾块覆盖完整对齐正确、padding 为中性元、尾核变量已初始化 → 明确写出反证理由（防护面证据）。
- **均匀 shape 通过不是反证**：本型只在非对齐尾块/尾核/离群点下暴露，须专门构造边界 shape 与离群点输入。
- **「精度失败」先归因再立卡**：尾块偏差须先排除 A05（脏数据）、A07（分支写错）、B07（偏移越界），确认主导机理为粒度/padding 后才归 A08。
- **不臆造行号**：每条证据必须是实际读到的 文件:行号；引用实证样板时同样给出路径与行号，issue 时点行号与本仓 HEAD 漂移时注明。

## 11. 已知缺陷案例库：触发条件 / 根因 / 修复范式 / 针对性深挖（v5.1）

> 本节把本型**已确认缺陷**拆到「触发条件 → 根因（具体路径）→ 修复范式（✅ 正确代码）→ 针对性发现步骤 → 最小复现锚」的代码级颗粒度。
> 修复范式为**正确形态示意**；路径引用取自卡片实证，行号以被检仓本地 HEAD 为准，**不得臆造**。

### 案例 1｜紧贴 ND2NZ on-the-fly 上限的尾块精度超阈 —— #5519（batch_mat_mul）

- **触发条件**：aclnnBatchMatMul fp32 且 **K=65533**（紧贴 ND2NZ on-the-fly 上限 **65535**），走尾块路径。
- **根因（具体路径）**：K 轴紧贴实现上限 → 尾块路径归约分组/覆盖与主块不同 → 相对误差比例 **3.099 > 阈值 2.0**（fp32 精度超阈）。
- **修复范式（✅，示意）**：修正紧贴上限 shape 的尾块路径（尾块切块对齐 / 覆盖补齐；对齐同族已修复样板）。
- **针对性发现（可执行）**：① 在 `*_tiling*.cpp` 定位 ND2NZ on-the-fly 上限常量（65535）与 K 轴切块；② 找 K=65535 附近的尾块分支；③ 核尾块归约分组是否随粒度变化。
- **最小复现锚**：K=65533、fp32 输入与 GPU 参考逐元素 utol，看相对误差比例是否超 2.0。
- **实证**：ops-nn **#5519**。

### 案例 2｜尾块 `preCoreNum` 未清零致 index 溢出 —— #3081（all_gather_matmul_v2）

- **触发条件**：AllGatherMatmulV2 尾块 / 分核不整除场景，某些 shape 触发。
- **根因（具体路径）**：尾块 `preCoreNum` **未清零** → `UpdateBasicIndex` 计算 index 时 `uint64_t` **负数溢出**（若致越界则主导归 FP-B07，双向关联）。
- **修复范式（✅，示意）**：

```cpp
// ❌ 尾块 preCoreNum 未清零 → uint64_t 下溢
// uint64_t idx = base - preCoreNum;   // preCoreNum 残留
// ✅ 每个尾块分支显式清零 / 初始化
// preCoreNum = 0;
// uint64_t idx = base + offset;
```

- **针对性发现（可执行）**：① grep `preCoreNum|blockFactor|UpdateBasicIndex`；② 逐尾块分支核变量是否初始化；③ 判是否致越界 → 归 B07 或 A08。
- **最小复现锚**：构造分核不整除尾核 shape，观察 index 计算与越界。
- **实证**：ops-transformer **#3081**。

### 案例 3｜slice m 方向尾块 slicem 对齐与负载均衡 —— #3391（slice）

- **触发条件**：slice 场景 m 方向非对齐尾块。
- **根因（具体路径）**：m 方向**尾块切块 slicem 对齐**与**负载均衡**不当 → 尾块归约分组/覆盖偏差。
- **修复范式（✅，示意）**：尾块切块 slicem 对齐修正 + 负载均衡修正。
- **针对性发现（可执行）**：① grep `slicem|tileSize|Tail`；② 核 m 方向尾块对齐；③ 核分核负载均衡参数。
- **最小复现锚**：m 方向非对齐 shape + 换 tiling 粒度对比。
- **实证**：ops-nn **#3391**。

### 案例 4｜conv2d FM 非全载 Cin 尾块计算错误 —— #5061（conv2d）

- **触发条件**：conv2d 走 **FM 非全载**模板，Cin 轴非对齐尾块。
