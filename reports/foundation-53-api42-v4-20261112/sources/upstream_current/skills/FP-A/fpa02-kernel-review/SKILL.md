# FP-A02 aclnn 接口检视（fpa02-kernel-review）

对用户指定的 aclnn 接口（如 aclnnRmsNormGrad）做 FP-A02 专项源码检视：先定位算子实现，再按清单逐项核查，每个结论给出**文件 + 行号 + 推导链**证据，命中即出 Bug 卡，输出检视报告。**本模式特殊纪律：① 缺陷不是「算错」而是「浮点加法不满足结合律」——实现功能正确、单点小 shape 可过，偏差随归约规模与分组方式放大，判据是「同输入多轮/多实现对比的可复现偏差」；② 触发签名 `ReduceSum|WholeReduceSum|BlockReduce|ReduceMax` 在 kernel 中普遍存在，命中只表示「值得人工核」——必须给出「归约拓扑（树形 vs 串行 / 分组顺序）与标杆不一致」的推导链；③ 性能优化 PR 是最高发引入点——审查须对比优化前后浮点结合顺序是否改变（实证 #5537 即性能优化改结合顺序致 EVB 精度失败）。**

## 0. 与相邻模式的边界

| 相邻模式 | 分工 |
|---|---|
| FP-A06（确定性开关下结果不固定） | **最易混淆项**：A02 是**顺序固定但与标杆不一致**（可复现偏差，重复跑同一实现结果一致）；A06 是**顺序本身不定**（原子加/多核归约未定序，同输入两次结果不同）。判据：连续多轮是否 bitwise 一致 |
| FP-A08（切块粒度差异致离群点精度问题） | A08 是**切块粒度**改变导致归约分组变化（粒度参数面）；A02 是**归约拓扑本身**与标杆不一致（实现顺序面）——同一归约结果偏差可能两者共因，按主导因素归属并双向关联 |
| FP-A03（竞品高精度中间计算，NPU 直接低精度） | A03 是**累加位宽**不足（fp16/bf16）；A02 是**累加顺序**不一致（位宽相同、拓扑不同）——位宽归 A03，顺序归 A02 |
| FP-A05（脏数据/数据踩踏） | A05 是**数据本身脏**（未初始化/踩踏）；A02 是**数据干净但结合顺序不同**——先排除脏数据再判顺序 |
| FP-C01（端到端耗时占比高） | C01 是**性能问题**（慢）；A02 是**精度问题**（顺序差异）——但性能优化 PR 常是 A02 的引入源，核 C01 时同步核 A02 |
| FP-E01（golden/UT 期望值失配） | A02 偏差常在**恰好卡阈值**时被 UT 放过——UT 通过不构成反证，须看归约规模是否覆盖 |

**症状反查定位**：大 shape 归约类算子（sum/mean/norm 梯度）精度波动而小 shape 全过 → 归约规模面（清单①）；同输入多轮结果**一致**但均与标杆有稳定偏差 → 拓扑不一致面（清单②）；性能优化 PR 合入后精度回归 → 结合顺序重排面（清单③）；多核并行归约、核数变化时偏差量级跳变 → 分组顺序面（清单④）。

## 1. FP-A02 模式卡摘要（检视依据，源自本库 `patterns/FP-A/FP-A02.md`，v3.1）

- **编号 / 名称**：FP-A02 归约/累加实现顺序与竞品不一致 ｜ **类别**：精度 ｜ **风险**：高（S3×O3=9）｜ **状态**：活跃
- **适用声明头**（照抄卡片）：仓 All ｜ 侧别 Kernel ｜ 载体 Kernel源码 ｜ 触发 ReduceSum|WholeReduceSum|BlockReduce|ReduceMax ｜ 默认启用 true
- **skill 核查面**：侧别 Kernel——skill 落地为 `op_kernel/` 中归约与累加的实现文件（含 arch35 / regbase / SIMT 等架构变体）；延伸至 `op_host` 侧影响分核/分组顺序的 tiling 参数（核数、分组粒度）与性能优化相关注释/PR 痕迹
- **故障机理**：浮点加法不满足结合律，二分归并式求和 vs 顺序累加、多核并行归约的分组顺序差异引入可复现偏差；性能优化重排结合顺序会放大该差异。
- **触发条件**：大规模归约（sum/mean/norm 梯度类）、多核并行归约、性能优化改写计算拓扑。
- **典型表现**：网络精度波动、精度差异、EVB 精度失败。
- **源码审查映射点**：归约/累加实现顺序；大规模求和的树形归约 vs 串行累加；性能优化 PR 是否改变浮点结合顺序。
- **检测签名**（命中即候选缺陷点位）：`ReduceSum|WholeReduceSum|BlockReduce|ReduceMax`（归约实现定位点）。
- **测试拦截建议**：同输入多轮执行结果一致性；与标杆实现逐元素 utol 且覆盖大 shape 归纳场景。
- **实证案例**：ops-nn **#5560** RmsNormGrad dx 计算顺序与 PyTorch CUDA 不一致（PR !9873，`Reg::Axpy` 对齐标杆拓扑修复）；ops-nn **#5537** SwigluMxQuant EVB 精度失败——性能优化改变浮点结合顺序（PR #9828 已修）。
- **关联**：FP-A06、FP-A08。

## 2. 检视输入与算子定位

**输入**：aclnn 接口名（必填，如 `aclnnRmsNormGrad`）；可选 ref（默认 master）、指定仓（默认自动定位）；可选现象描述（失败 shape / 偏差量级 / 是否随核数变化 / 是否有性能优化 PR 在前——用于直接定位归约面）；可选标杆实现（如 PyTorch CUDA 对应算子）。

**接口名 → 算子目录换算**：去 `aclnn` 前缀 + 驼峰转下划线小写：
`aclnnRmsNormGrad → rms_norm_grad`、`aclnnSwigluMxQuant → swiglu_mx_quant`、`aclnnLayerNormGrad → layer_norm_grad`。

**仓定位顺序**（GitCode `cann` 组织，逐仓用目录列表确认）：`ops-nn`（norm/loss/activation 类——实证集中地）→ `ops-math`（math 类）→ `ops-transformer`（attention/moe 类）→ `ops-cv`。**类目名不总与直觉一致**，以目录列表为准。FP-A02 高发面：含大规模归约的 norm 梯度类算子、多核并行归约（分核 + 二次归约）实现、近期有性能优化改动的归约算子、arch35 等新架构上重写的归约路径。

**算子目录结构约定**（以实证算子为例，具体布局以目录列表为准）：

```text
{类别}/{op_name}/
├── op_kernel/                # kernel 头文件——主检视面（归约/累加拓扑）
│   └── arch35/ regbase/ ...  # 架构变体（归约实现可能逐架构不同）
├── op_host/                  # def / infershape / tiling——分核与分组参数面
│   └── op_api/               # aclnn_*.cpp（若存在）
├── op_graph/  tests/  docs/  examples/   # 视算子而定
```

## 4. 检视清单（每点：查什么 → 何处 → 命中判据）

对算子的 `op_kernel/`（含架构变体）全部相关文件逐点核查，`op_host` 分核/分组参数与性能优化痕迹同步核对，**每点先查命中面、再做反证排除**；已对齐标杆拓扑的实现要记录为防护面证据。

### ① 归约拓扑：树形归并 vs 串行累加
- 查什么：大规模求和的实现是**二分/树形归并**还是**串行顺序累加**；与标杆（如 PyTorch CUDA 的归约实现）是否同拓扑。树形归并的分组层级不同即引入可复现偏差（实证 #5560：RmsNormGrad dx 计算顺序与 PyTorch CUDA 不一致，PR !9873 用 `Reg::Axpy` 对齐标杆拓扑）。
- 何处：kernel 中归约主循环、`ReduceSum` / `WholeReduceSum` / `BlockReduce` 调用点、累加器更新语句。
- 命中判据：能写出「本实现归约分组顺序 vs 标杆顺序不同 → 浮点结合顺序不同 → 大 shape 下偏差放大」的推导链 ⇒ 命中候选（须附实测方案）。

### ② 多核并行归约的分组顺序
- 查什么：多核场景下各核的**部分和分组方式**与最终二次归约顺序——核数变化时偏差量级是否跳变；分组边界（按行/按块/按 chunk）是否与标杆一致；`BlockReduce` 的块内归约顺序是否固定且与标杆可比。
- 何处：kernel 的分核部分和计算段、跨核二次归约（workspace 汇总）段、tiling 的分核参数。
- 命中判据：分组顺序与标杆不一致且失败 shape 可使偏差超阈 ⇒ 命中候选。

### ③ 性能优化 PR 是否重排浮点结合顺序
- 查什么：近期性能优化改动（向量化、循环展开、分块重排、指令替换）是否改变了浮点**结合顺序**（如把 `(a+b)+c` 改成 `a+(b+c)`、把串行累加改成树形、把多次累加合并为 FMA 链）——实证 #5537 SwigluMxQuant EVB 精度失败即性能优化改结合顺序（PR #9828 已修）。
- 何处：归约/累加相关代码段、性能优化注释、近期 diff。
- 命中判据：存在「性能优化改写累加顺序且未做精度回归」的路径 ⇒ 命中候选。

### ④ 累加位宽与中间缓冲（与 A03 交界）
- 查什么：累加器与中间缓冲的位宽——该 fp32 累加却用 fp16/bf16 属 A03；本条仅核查**位宽正确但顺序不同**的情形，避免与 A03 重复归因。
- 何处：归约累加器声明、中间缓冲类型。
- 命中判据：位宽已为 fp32 但拓扑仍与标杆不同 ⇒ 归本条；位宽不足 ⇒ 归 A03。

### ⑤ 一致性测试与标杆对齐基线
- 查什么：是否具备「同输入多轮执行结果一致性」用例、与标杆实现逐元素 utol 且覆盖**大 shape 归约**场景；UT 是否只覆盖小 shape（小 shape 结合顺序差异不可见，天然漏检）。
- 何处：`tests/` 的精度用例与 shape 覆盖矩阵。
- 命中判据：无大 shape 归约用例 / 无多轮一致性用例 ⇒ 记观察项（测试面缺口）。

## 5. 检视流程

1. **定界**：换算 op 目录、确认所在仓与 ref；确认架构变体布局；记录用户现象（失败 shape / 偏差是否随核数变化 / 性能优化 PR）。
2. **枚举**：目录列表列出 `op_kernel/`（含架构子目录）与 `op_host` 相关文件、`tests/`，产出文件清单。
3. **触发词扫描**：按 `ReduceSum|WholeReduceSum|BlockReduce|ReduceMax`、`Sum\(|Add\(|Axpy|Muls|Fma`、分核/分组参数定位风险面（本地仓用 grep；API 模式逐文件拉取后检查）。**触发为关键词：签名零命中时清单仍须逐项核查完毕**。
4. **逐点核查**：按第 4 节 ①~⑤ 记录命中面与防护面证据（文件:行号）；对归约路径给出「分组顺序 vs 标杆」的拓扑对比。
5. **反证排除**：已对齐标杆拓扑（如 `Reg::Axpy` 类显式对齐）、累加顺序与标杆逐层一致、性能优化未改变结合顺序、大 shape 与多轮一致性用例在位 → 明确写出反证理由。
6. **判定**：按第 7 节标准给出 命中 / 观察项 / 反证排除。
7. **GitCode 查重**（仅命中项）：issues API 按接口名 + `精度|归约|顺序|一致|EVB` 检索，逐条比对是否同机理；无同机理才立卡。
8. **业务可达性核查**（仅命中项）：判 B 等级、定业务影响类型、给处置建议；默认保守（无法证明不可达即记 B3），降档须附证据；B 不改 S×O 档位。
9. **出报告**：按第 8 节模板落盘；所有精度结论标注「静态推演，需与标杆逐元素 utol 实测确认」并附实测方案。

## 6. 风险定级（S×O）与业务影响评估（B 轴）

- **S**：S3（精度差异 / 网络精度波动 / EVB 精度失败——结果错但可运行）；S2（仅极端大 shape 才可见的轻微偏差）；S1（偏差远低于阈值）。
- **O**：O3 = ≥2 条独立实证；O2 = 1 条独立实证；O1 = 仅静态扫描命中或团队笔记（实证 = 确认对应的 issue / PR，或经跨仓、跨分支核验确认的缺陷记录，同权计入）。静态推演命中且无实证默认 **O1**；升档须在报告中给出实证依据。
- **风险 = S×O**：≥6 高；3/4 中；1/2 低。FP-A02 基准：模式卡整体 S3×O3=9（高）；纯静态命中 S3×O1=3（中，暂定，实测后复评）。

### B 轴：业务影响评估（与 S×O 正交；报告层新增，不改卡片定级）

S×O 回答"多严重、多常见"，**不回答"真实业务能不能碰到"**。B 轴补这一问，只决定**修复优先级建议**，**不参与 S/O 取值、不改 S×O 档位与卡片元数据**。

**业务可达性（B）**——触发条件在真实负载中的可达程度：

| 等级 | 判据 | 证据要求 |
|---|---|---|
| B3 现实可达 | 主流框架/公开模型默认路径即可命中（如 PTA/torch_npu、vLLM、MindIE 常规调用） | 调用方或公开负载来源 |
| B2 条件可达 | 需特定 attr/dtype/shape 组合，业务中存在但非默认 | 该组合的业务来源 |
| B1 边界/不可达 | 需极端、超规格或非法参数（超出接口合理上限的 shape、退化/非法输入） | "为何不可达"的说明 |

- **默认保守**：无法证明不可达 → 记 **B3**；降为 B1/B2 必须附证据，**不得仅凭"业务应该不会这么用"**。
- 超规格参数是否算 B1 取决于**接口契约**：契约允许但业务不用 → B1；契约不允许（本应报错）→ 属校验缺失（FP-B04/B05 类），另行归属。

**业务影响类型**（命中后对用户可见结果的后果，用业务语言表述）：静默精度损失（模型效果下降 / loss 不收敛 / 偶发 NaN）｜ 任务失败中断（报错 / 崩溃 / 挂死）｜ 性能退化 ｜ 仅可观测性（日志 / 错误码 / 文档，不影响结果）。

**处置建议**（由两轴推导的报告结论，非新档位）：

| S×O \ B | B3 现实可达 | B2 条件可达 | B1 边界/不可达 |
|---|---|---|---|
| 高（≥6） | 尽快修 | 尽快修 | 排期修 |
| 中（3/4） | 尽快修 | 排期修 | 记录（业务难以触达） |
| 低（1/2） | 排期修 | 记录 | 记录 |

## 7. 判定标准与反误报原则

- **签名 / 触发词命中 ≠ 成立**：`ReduceSum`/`BlockReduce` 在归约类 kernel 中普遍存在且多数与标杆等价——命中只是定位提示，必须给出「分组顺序/结合顺序与标杆不一致」的推导链。
- **三种判定**：
  - **命中**（可静态证缺陷路径）：「归约拓扑与标杆不一致 → 结合顺序不同」的推导链完整 + 失败 shape 可构造 → 立 Bug 卡（档级按实测证据定）；
  - **观察项**：拓扑存在差异但偏差是否超阈依赖实测、或仅测试面覆盖缺口 → 记录并附实测方案，按 S3×O1 暂定；
  - **反证排除**：已对齐标杆拓扑、结合顺序逐层一致、性能优化未动顺序 → 明确写出反证理由（防护面证据）。
- **「同输入多轮一致」是 A02 而非 A06 的判据**：A02 结果**可复现**（多轮一致、与标杆稳定偏差）；若多轮**不一致**则转 A06。
- **「UT 通过」不是反证**：小 shape 下结合顺序差异不可见，须核 UT 是否覆盖大 shape 归约与核数变化场景。
- **精度劣化不静态断言「必然不过」**：静态只能立「候选点位 + 实测方案」，实测前不升级为「已确认」。
- **不臆造行号**：每条证据必须是实际读到的 文件:行号；引用实证样板时同样给出路径与行号，issue 时点行号与本仓 HEAD 漂移时注明。

### 案例 1｜dx 归约拓扑与标杆不一致 —— #5560（rms_norm_grad）

- **触发条件**：rms_norm_grad 反向 dx 的大规模归约、多核并行归约场景；小 shape 天然不可见。
- **根因（具体路径）**：dx 计算的归约/累加（分组与结合顺序）与 PyTorch CUDA 不一致 → 浮点加法不满足结合律 → 大 shape 偏差稳定放大；修复以 `Reg::Axpy` 显式对齐标杆拓扑（PR **!9873**）。
- **修复范式（✅，示意）**：

```cpp
// ❌ 自定义归并分组，顺序与 CUDA 标杆不同
// acc = ReduceSum(local);   // 树形分组未对齐标杆
// ✅ 显式对齐标杆拓扑逐层累加
// Reg::Axpy(dx, dy, coeff); // 按 PyTorch CUDA 拓扑
```

- **针对性发现（可执行）**：① 签名 `ReduceSum|WholeReduceSum|BlockReduce` 定位归约实现；② 找 `Reg::Axpy` 类对齐写法（有则记防护面）；③ 对比 CUDA 归约分组层级。
- **最小复现锚**：大 shape rms_norm_grad 与 PyTorch CUDA 逐元素 utol；**同输入多轮结果应一致**（不一致则转 A06）。
- **实证**：ops-nn **#5560**（PR **!9873**）。

### 案例 2｜性能优化重排浮点结合顺序致 EVB 失败 —— #5537（swiglu_mx_quant）

- **触发条件**：近期性能优化改动（向量化 / 循环展开 / 分块重排 / 合并 FMA 链）触及累加段的算子路径。
- **根因（具体路径）**：性能优化把串行累加改为树形或合并 FMA 链 → 浮点结合顺序改变且未做精度回归 → EVB 精度失败；PR **#9828** 已修。
- **修复范式（✅，示意）**：

```cpp
// ❌ 性能优化合并累加链，改写结合顺序
// s = Fma(a, b, Fma(c, d, e));   // 顺序漂移
// ✅ 恢复标杆结合顺序（并补精度回归门禁）
// s = (a * b + c * d) + e;
```

- **针对性发现（可执行）**：① 查近期性能优化 diff（git log/diff）；② 逐段核累加结合顺序是否变化；③ 优先核「优化合入后精度回归」记录。
- **最小复现锚**：优化前后同输入对拍 + 大 shape 归约，看偏差量级是否跳变。
- **实证**：ops-nn **#5537**（PR **#9828**）。

### 案例 3｜候选型：多核分组 / 二次归约顺序（无独立实证）
