# FP-B06 空 tensor（numel==0）输入分支处理缺失

> [← 库索引](../../README.md) ｜ [变更记录](../../CHANGELOG.md) ｜ 类别：功能/兼容 ｜ 风险：高（S3×O2=6） ｜ 状态：活跃

- **元数据**：类别 功能/兼容 ｜ 风险 高（S3×O2=6）｜ 状态 活跃 ｜ 来源 ops-nn PR #9197 / issue #5149 + 四仓 aclnn 接口静态扫描（2026-09-14）+ ops-transformer#4531 / ops-cv#928/#935（快速路径前置，v6.1）
- **适用**：仓 All ｜ 侧别 Host,Tiling,Kernel ｜ 载体 aclnn源码,Tiling源码,Kernel源码 ｜ 触发 必须触发 ｜ 默认启用 true
- **故障机理**：aclnn 两段式接口对「空 tensor（numel==0，即 shape 含 0 维）」这一**语义可能合法的输入形态**缺少分支处理，五种子形态：① **判空覆盖不全**——同一接口只对部分输入调 `IsEmpty()`（典型：`selfRef`/`mask` 判了、`source`/`updates` 类第二输入漏判）；② **完全未判空**——空 tensor 被当正常输入继续 `l0op::Contiguous` / `Cast` / 算子构建（部分实现已有 `if (source->IsEmpty()) sourceContiguous = source;` 之类半程保护，但仅跳过连续化，仍把 0 元素 buffer 交给算子）；③ **平台分支不对称**——`!Ops::NN::AclnnUtil::IsRegbase()`（arch22 / A2A3）与 regbase（arch35 / 950）各有一套实现与 kernel，修复常只 gate 一侧；④ **快速路径前置于校验**（v6.1 显式化）——接口内**确有空输入 / no-op 早退分支**，但位置排在参数校验**之前**（或校验被写在该早退之后），于是**非法组合随空态一并被放行**：`InplacePartialRotaryMulGrad` 的 no-op 提前返回排在 `CheckRotaryModeShapeRelation` 之前，零长度但越界的 `partial_slice=[9,9]` 与负起点 `[-1,0]` 都返回 `GRAPH_SUCCESS`（#4531）；`UpsampleNearestExact2d` 与 `BoundingBoxEncode` 的空输入快速路径同样绕过参数校验（#928、#935）。**⑤ 空态被过严校验拒绝（v6.13 新增）**——与 ①~④ 方向相反：接口对空 tensor 做**无条件** `Size() != 0` / `IsEmpty() → 报错` 判断，把**资料明确支持的空输入**直接判为非法（`aclnnConvTbcBackward` 的 `OP_CHECK(self->Size() != 0, ... return ACLNN_ERR_PARAM_INVALID)` 不在任何 SoC 分支内，A2/950 一致与资料四处「支持空 Tensor」相反，#7060；`aclnnAddLayerNormGrad` 空张量 `(M=0,H>0)` 返回 561002，而同算子正向 `aclnnAddLayerNorm` 已支持，#7055）。判据是**以资料/对标的空态语义为准**：该支持却拒绝 → 本子型；该拒绝却放行 → ①~④。与 ①②③ 的本质区别是**分支存在而顺序错**——只查「分支是否存在」的静态扫描（含本节 `absence_signatures` 规则）**查不出这一类**，须按「早退块是否在校验之后」逐接口人工核。空输入进入 arch22 算子后，tiling/kernel 未适配 0 元素：kernel `Init()` 用**由 mask/shape 推导的元素数**（而非该 tensor 自身元素数）去 `SetGlobalBuffer`，等于把 0 字节分配注册成非 0 长度；source 元素数不足时更会读到分配外地址（越界/NaN）。
- **触发条件**：任一输入（尤其可选输入/第二输入：masked_scatter 的 `source`、Dropout 的 `mask`、量化类的 `scales`/`zeroPoints`/`smoothScale`）numel==0；平台为 A2/A3（非 regbase）；同算子 tiling/kernel 未对 0 元素早退。语义上「空输入是否合法」须以 PyTorch 为准（如 masked_scatter 中 `source` 为空**仅当 mask 无 true 元素时合法**，此时应为 no-op 而非报错）。
- **典型表现**：**PyTorch CPU/CUDA 同用例 PASS、NPU 侧第一段接口报错或执行失败**（合法空输入被误拦截）；或判空早退把**非法**组合（mask 有 true 而 source 空）静默吞成 SUCCESS，掩盖参数错误；或内核读越界 / 读出 NaN；或图模式下 shape/dtype 推导异常。特征信号：失败用例的输入里必有一个含 0 维的 shape。
- **源码审查映射点**：`op_api/aclnn_*.cpp` 的 `GetWorkspaceSize` 内逐参数核对——每个 `const aclTensor*`（输入）与 `aclTensor*`（inplace 张量如 `selfRef`）是否都有 `->IsEmpty()` 判断，判空后是否 `*workspaceSize = 0; uniqueExecutor.ReleaseTo(executor); return ACLNN_SUCCESS;` 早退；空 tensor 是否只跳过 `Contiguous` 却仍透传给 `l0op::Xxx`；`!Ops::NN::AclnnUtil::IsRegbase()` 两侧是否各自有空 tensor 策略（含 `ProcessBroadcast` 这类 regbase 专用分支）；arch22 `op_host/*_tiling.cpp` 是否对 0 元素校验/早退；kernel `Init()` 中 `SetGlobalBuffer(tensor, 长度)` 的长度是否取自该 tensor 自身元素数；`docs/aclnn*.md` 的元素数约束（如「source 元素数量需要大于等于 mask 中元素为 true 的数量」）与代码判空行为是否自洽。
- **检测签名**：静态扫描「aclnn 接口 × 每个输入参数 × 是否有 `IsEmpty()`」——接口内 `IsEmpty()` 覆盖的输入数 < 输入张量个数 ⇒ **判空遗漏（PARTIAL）**；接口与同算子 host/kernel 层均无 `IsEmpty|EmptyTensor|GetShapeSize()==0` 关键字 ⇒ **全链路无感知（HIGH）**。四仓基线（2026-09-14，1040 个 aclnn 接口）：**PARTIAL 141 / HIGH 461 / 有 kernel 感知 88 / 全覆盖 328**；其中 ops-transformer 全覆盖仅 8/250，ops-math 有 182 个 HIGH。工具：一次性审计脚本（**未收录本仓**，故不能直接当 CI 静态门禁）产出上列四仓基线；本仓用 `python3 scripts/scan_fp.py --only FP-B06 --format json <目录>` 出候选，再按本节判据逐接口核 `IsEmpty()` 覆盖率。
- **控制变量（v6.30）**：**必须固定**——**只置空 ≥2 维的数据张量**，1 维参数（`gamma` / `scale` / `weight`）保持原值；置空后重算与其它张量的维度依赖并确认仍成立 ｜ **允许变动**——被置空的那一个数据张量 ｜ **多变量同变的典型误判**——1 维参数 `gamma=[8]` 也一起置空 → 与 `x` 末维不再匹配，报 561002；看起来正是「该支持却报错」，改回「只置空数据张量」后不报错——561002 完全是输入改坏造成的（差点提上去的假候选）
- **测试拦截建议**：空 tensor 探针矩阵 =「接口 × 输入位置 × 空形态（0 维标量 / 含 0 维 shape / 正常）」；期望值以 PyTorch CPU 参考实现为准（合法空输入 → 输出等价于 no-op；非法组合 → 明确报错而非静默 SUCCESS）；**优先覆盖「已写判空但漏了一个输入」的接口**（作者已具备空 tensor 意识，遗漏概率最高）；空用例须同时跑 regbase 与非 regbase 平台（修复常只 gate 一侧）；「mask 无 true + source 空」这类合法组合必须显式建例（PyTorch 侧全 PASS 而 NPU 曾失败）；建议把上述静态扫描纳入 CI，新增判空遗漏即失败。
- **实证案例**：ops-nn **PR #9197 / issue #5149**（2026-08-25 合入 master）——`index/masked_scatter/op_api/aclnn_masked_scatter.cpp` 的 `aclnnInplaceMaskedScatterGetWorkspaceSize` 原有 `if (selfRef->IsEmpty() || mask->IsEmpty())` 早退但**漏了 `source`**，修复新增 `if (!Ops::NN::AclnnUtil::IsRegbase() && source->IsEmpty()) { *workspaceSize = 0; uniqueExecutor.ReleaseTo(executor); return ACLNN_SUCCESS; }`（仅 gate arch22，950 走 `ProcessBroadcast` 自带保护）；issue 复现组合 `target=(4,8), mask=(4,1) 或 (4,8), mask_true=0, source=(0,8)` 在 PyTorch CPU/CUDA 四组全 PASS 而 **910b（A2）侧失败**。同仓 2026-04-29 issue「masked_scatter 当 updates 元素不够时存在内存访问越界或读取 NAN（A3）」为同源风险的另一侧（元素数不足而非恰为 0）。该修复的两点不足已记录：**未覆盖非 inplace 的 `aclnnMaskedScatter`**、**未沉淀 ST 用例**（现有 200 条 ST 用例无 0 维 shape，PR「测试」仅贴 PyTorch 参考输出）。 **v6.1 补（快速路径前置子型 ④）**：**ops-transformer#4531**（open，InplacePartialRotaryMulGrad）为支持空切片与空 Tensor 新增 no-op 提前返回，`CheckAttr` 在 `CheckRotaryModeShapeRelation` **之前**判 `sliceLength_ == 0` 或输入 Tensor 为空即直接 `return ge::GRAPH_SUCCESS`，致零长度但越界的 `partial_slice=[9,9]`、含负起点的 `[-1,0]` 被接受（反而**未命中**设备侧越界，因走的是 no-op 分支）；**ops-cv#928**（open，UpsampleNearestExact2d）空 Tensor 快速路径绕过参数校验；**ops-cv#935**（open，BoundingBoxEncode）空输入快速路径绕过 `means`/`stds` 校验。三条共同点：**空态分支本身有，但校验被它挡在了后面**。

  **v6.13 补（子型 ⑤ 过严拒绝，2026-10-21）**：`ops-nn` **#7060**（`ConvTbcBackward`）——`op_api/convtbc_backward_checker.cpp:172-176` 用无条件 `OP_CHECK(inputTensor_.self->Size() != 0, ... return ACLNN_ERR_PARAM_INVALID)` 拒绝空输入，而资料四处声明 `self`/`input`/`weight`/`gradInput`/`gradWeight`/`gradBias` 支持空 Tensor，约束表还明确「支持 N、C、L 维度大于等于 0」；该检查不在任何 SoC 分支内，950 与 A2 行为一致。`ops-nn` **#7055**（`AddLayerNormGrad`）——空张量 `(M=0,H>0)` 返回 561002 失败，而正向 `aclnnAddLayerNorm` 已支持同形态空张量。**注意方向**：本子型不是「没写判空」，而是「判空写反了」——修法是按资料语义放行空态并走 no-op/零输出路径，不要直接删掉检查（否则 ①~④ 的放行问题会回来）。
