# FP-A15 aclnn 接口检视（fpa15-kernel-review）

对用户指定的 aclnn 接口做 FP-A15 专项源码检视：先定位算子实现，再按清单逐项核查，每个结论给出**文件 + 行号 + 推导链**证据，命中即出 Bug 卡，输出检视报告。**本模式特殊纪律：① 缺陷表征是「nan 用例判断失败、常规用例全过」——常规数值用例天然漏检特殊值分支，必须做**特殊值专项**核查；② 卡片触发为关键词（`isnan|IsNan|NAN|INFINITY`）——命中只作定位提示，真正的判据是**该分支的走向与标杆是否一致**（`isnan` 写对但分支内容错同样命中）；③ 同一 `#5562` 在 FP-A18 与 FP-A15 两卡分别记录（kernel isnan 分支 / tiling 极值转换比较），检视该算子时两卡须同时核、报告互相引用；④ 特殊值语义的最终判据是运行时数值与标杆比对——静态只能立「特殊值分支走向与标杆不一致」的推导。**

## 0. 与相邻模式的边界

| 相邻模式 | 分工 |
|---|---|
| FP-A18（int32 边界值转 float 舍入致比较语义偏差） | 卡片关联项：同为**比较语义**问题——A18 因 int32→float 尾数舍入使阈值比较失真（**有限值**），A15 因 nan/inf 特殊值使比较分支走向错（**非有限值**）。同一比较点两侧须分别核；实证 #5562 同时含 kernel isnan 分支（A15）与 tiling 极值转换比较（A18）两面，须连打 |
| FP-A09（对标 TF 语义与 PTA 不一致） | 卡片关联项：标杆口径本身与 TF / PTA 语义不同时，nan / inf 行为差异可能源于**标杆口径**而非实现——先核 A09 口径，再核 A15 实现 |
| FP-A04（功能问题演变为精度静默故障） | 输出含 nan 但输入无 nan 时，nan 由吞错 / 降级 / 脏数据产生——源头归 A04 / A05，A15 只对「特殊值的处理语义」下判 |
| FP-A12（大整数转 fp32 计算精度损失） | float 上溢产生 inf 的路径与 A12 的转换点同源——转换损失归 A12，特殊值传播归 A15 |
| FP-A08（切块粒度差异致离群点精度问题） | 未参与计算 / 未覆盖的尾块可能读出 nan 类脏值——数据源问题归 A08 / A05，特殊值语义归 A15 |
| FP-E01（golden/UT 期望值失配） | golden 对 nan / inf 的期望值口径若与标杆不一致，用例判据本身就错——先核 E01，再核 A15 实现 |

**症状反查定位**：nan 用例判断失败而常规用例全过 → 首查该算子的 `isnan` / nan 比较分支（#5562）；输入含 inf / nan 时结果与标杆不一致 → inf 传播与 clamp 语义；`float == NaN` 类**恒假**比较写法 → 比较写法错误；`max` / `min` / `clamp` 对 nan 的返回（nan 被吞掉 / 被选中）与标杆不同 → 特殊值分支语义；输出含 nan 但输入无 nan → 计算过程产生（0/0、inf−inf），先按 A04 / A05 分流源头；阈值 / 掩码类算子（threshold / relu / clip 类）nan 行为异常 → 优先核本型。

## 1. FP-A15 模式卡摘要（检视依据，源自本库 `patterns/FP-A/FP-A15.md`，v3.1）

- **编号 / 名称**：FP-A15 inf/nan 特殊值行为差异 ｜ **类别**：精度 ｜ **风险**：高（S3×O3=9）｜ **状态**：活跃 ｜ **来源**：团队笔记 + 缺陷检视记录
- **适用声明头**（照抄卡片）：仓 All ｜ 侧别 Kernel ｜ 载体 Kernel源码 ｜ 触发 isnan|IsNan|NAN|INFINITY|rsqrt|sqrt|E\[x²\] ｜ 默认启用 true
- **skill 核查面**：侧别 Kernel——skill 落地为 `op_kernel` 的比较 / 阈值 / 掩码 / clamp 分支（主检视面）、`op_host` tiling 下发的阈值与常量（界定分支取值）、`tests/` 与 golden 的 nan / inf 用例与期望值口径（横切面）
- **故障机理**：nan 比较分支结果（如 nan 与阈值比较的判断走向）、inf 传播与标杆不一致；`float == NaN` 恒假类分支写错。
- **触发条件**：输入含 nan / inf 或计算过程中产生。
- **典型表现**：特殊值场景结果不一致、nan 用例判断失败。
- **源码审查映射点 / 检测签名**：映射点 = 特殊值处理：inf / nan 传播、比较分支、clamp 对 nan 的行为；卡片未给独立 grep 签名，触发词为 `isnan|IsNan|NAN|INFINITY`（关键词定位提示）。
- **测试拦截建议**：nan / inf 专项用例矩阵（**输入携带 / 计算产生 / 输出注入**三类来源）。
- **实证案例**：ops-nn **#5562** `threshold_grad_v2_d` nan 用例判断失败（PR **!9773**，**kernel isnan 分支未对齐标杆**）。同号 issue 另在 FP-A18 记录 `threshold_grad_v2_d_tiling_arch35.cpp:92-93` 的 `constexpr float int32MinAsFloat/int32MaxAsFloat` 极值转换比较面——同一算子两卡连打。
- **关联**：FP-A09、FP-A18。

## 2. 检视输入与算子定位

**输入**：aclnn 接口名（必填）；可选 ref（默认 master）、指定仓（默认自动定位）；可选现象描述（nan 用例失败 / inf 结果不一致 / 阈值类算子异常——用于症状反查）；可选复现输入（nan / inf 注入位置与取值）；可选标杆来源（TF / PTA / golden.py——口径核对用）。

**接口名 → 算子目录换算**：去 `aclnn` 前缀 + 驼峰转下划线小写：
`aclnnThresholdGradV2D → threshold_grad_v2_d`（接口名以 `docs/aclnn*.md` 为准）、`aclnnRelu → relu`、`aclnnClipByValue → clip_by_value`。

**仓定位顺序**（GitCode `cann` 组织，逐仓用目录列表确认）：`ops-nn`（activation / norm / loss 类——阈值与分段函数高发）→ `ops-math`（math / conversion 类）→ `ops-cv` → `ops-transformer`。**类目名不总与直觉一致**，以目录列表为准。FP-A15 高发面：含阈值 / 掩码 / 分段（`threshold` / `relu` / `clip` / `mask`）的 kernel、带 `isnan` / `IsNan` 分支的实现、含除法与 `log` / `sqrt` / `exp`（易产生 inf / nan）的算子、golden 对特殊值有显式口径的算子。

**算子目录结构约定**（已验证示例 `cann/ops-nn` → `activation/threshold_grad_v2_d/` 类目录，类目以目录列表确认）：

```text
{类别}/{op_name}/
├── op_host/           # *_tiling*.cpp（含 arch35/ 变体）——阈值 / 常量下发，界定比较分支取值
│   └── op_api/（或顶层 op_api/）  # aclnn_*.cpp——特殊值入参校验与早退
├── op_kernel/         # 主检视面：isnan / 阈值比较 / clamp / 掩码分支（含 arch22/ arch35/ 变体）
├── tests/             # nan / inf 用例矩阵与 golden（特殊值期望值口径）
└── docs/
```

## 4. 特殊值与定义域检视清单（①~④ 特殊值输入；⑤ 定义域越界产出）

对 `op_kernel` 特殊值分支、`op_host` 阈值下发、`tests/` 与 golden 逐点核查，**每点先查命中面、再做反证排除**，正确的特殊值处理（显式 `isnan` 判断 + 与标杆一致的分支）也要记录为防护面证据。

### ① isnan 比较分支与判据写法
- 查什么：`isnan` / `IsNan` / `x != x` / `x == x` 等 nan 判据的写法与**分支走向**——`float == NaN` 恒假类写法是否被误用；nan 与阈值比较（`x < thr` / `x > thr` 对 nan 均假）时的实际走向是否符合标杆（实证 #5562：`threshold_grad_v2_d` kernel isnan 分支未对齐标杆）。
- 何处：`op_kernel` 的比较 / 阈值 / 掩码分支（`activation/threshold_grad_v2_d` 类算子）。
- 命中判据：能给出「输入 nan → 分支实际走向 ≠ 标杆走向 → 输出不一致」的推导 ⇒ 命中候选；nan 分支与标杆逐分支一致 ⇒ 反证排除。

### ② inf 传播与运算链
- 查什么：inf 参与加减乘除（`inf−inf=nan`、`inf×0=nan`、inf 与 0 相除）时结果是否符合标杆；是否有显式 inf 处理（`INFINITY` / `numeric_limits<float>::infinity()`）；中间量上溢产生 inf 的路径是否被识别。
- 何处：kernel 的算术链与特殊值判断、除法 / 对数 / 开方 / 指数运算点。
- 命中判据：inf 输入下结果与标杆不一致且无显式处理 ⇒ 命中候选；算术链与标杆一致 ⇒ 反证排除。

### ③ clamp / max / min 对 nan 的行为
- 查什么：`Min` / `Max` / `Clamp` 类硬件指令或函数对 nan 的返回语义（返回 nan / 返回另一操作数 / 饱和）；`Relu` 类分段函数对 nan 的走向——与 golden / 标杆口径是否一致。
- 何处：kernel 的 clamp / 激活 / 边界处理段。
- 命中判据：nan 输入下 clamp / max / min 返回值与标杆不同 ⇒ 命中候选；语义一致 ⇒ 反证排除。

### ④ 特殊值来源三分类与测试矩阵
- 查什么：卡片拦截建议的三类来源（**输入携带 / 计算产生 / 输出注入**）是否在用例矩阵中覆盖——输入携带（直接注入 nan / inf）、计算产生（0/0、inf−inf、大数上溢）、输出注入（golden 侧含特殊值）；纯数值断言用例天然漏检本型。
- 何处：`tests/` 用例与输入生成脚本、golden 资产。
- 命中判据：无 nan / inf 专项用例 + 存在静态命中的特殊值分支 ⇒ 记观察项（测试建设缺口）；三类来源覆盖且与标杆比对 ⇒ 记录为防护面。

### ⑤ 定义域越界产出（子型 A15-2，v2.18 新增）

> **与前四点的根本区别**：①~④ 是「输入里有 nan/inf，处理得对不对」；本点是「输入**全部合法有限**，中间表达式自己算出定义域外的值」。所以**任何 nan 专项用例都抓不到它**——必须专门构造。

- 查什么：
  1. **平方和相减形态**：`E[x²]-E[x]²`、`sumSq - n*mean²`、`Σ(x-μ)²` 被展开成 `Σx² - (Σx)²/n` 的写法。数学等价、数值不等价：方差极小时两个大数相减，舍入误差可使结果为 `-ε`。
  2. **开方/求逆前的钳制**：`sqrt(variance)`、`rsqrt(variance + eps)`、`log(x)`、`1/x`、`acos/asin` 的实参是否做过定义域钳制（`Max(x, 0)`、`Max(x, eps)`）；**钳制点是否覆盖所有消费方**（一处钳、另一处仍用未钳的变量 = 未修）。
  3. **`eps` 的量纲与位置**：加在方差上还是 std 上（两者量纲不同，效果差一个数量级）；eps 是否可能被大数吃掉。
  4. **归约方式**：单遍（平方和相减）还是双遍 / Welford（先均值再偏差）——只有单遍才有本型风险。
- 何处：`op_kernel` 的 norm / loss / 统计类算子（LayerNorm、InstanceNorm、BatchNorm、RMSNorm、`in_training_update`、`mse_loss`、`std`/`var` 计算），以及 `op_host` 中同公式的 tiling 侧预估；TBE 实现（`ops/built-in/tbe/impl/**`）同样适用。
- 命中判据：存在「平方和相减」形态 **且** 其下游有 `sqrt`/`rsqrt`/`log`/除法 **且** 该下游实参无定义域钳制 ⇒ **候选**（立卡前须能构造出负中间值的输入）。**反证排除**：给出钳制行的 `[文件]:[行号]` 且该钳制覆盖全部消费方；或改用双遍/Welford 的实现行；或说明该量数学上恒非负（如已是平方值）。
- **探针（本点的核心，必须能构造出负中间值）**：
  - 零元素比例阶梯 `0% → 50% → 90% → 99%`（零越多，方差越接近 0，抵消越严重）；
  - 常数列（方差理论为 0）；`x` 与 `x + 1e-7` 并置；极大极小混合（动态范围 > 1e7）；
  - 判据不是「与参考差值小」，而是**输出有限且定义域内**：`variance >= 0`、`std >= 0`、`rsqrt` 非 inf/nan、`log` 实参 > 0；
  - **必须做修复前后对照**：固化输入 + 固定种子，确认「旧实现中间方差为负、新实现非负」——只看到新版通过不能证明缺陷曾存在。
- **实证**：ops-math `INTrainingUpdateV2`（现网 25-11）——`E[x²]-E[x]²` 在舍入抵消下产生负方差并传播为 NaN；修复在 `after_v200()` 路径加 `max(variance, 0)`。**该修复只钳了被开方的一次**，审查同类算子时须确认所有 `sqrt/rsqrt` 消费方都被覆盖。

### 横切面：标杆口径核对（A09 / E01 连打）
- 查什么：golden / 标杆对 nan / inf 的期望值口径是否与 TF / PTA 一致（A09）；golden 是否按错误实现编写（E01）。
- 何处：`tests/assets/golden.py`、参考实现、docs 语义说明。
- 命中判据：标杆口径本身不一致 ⇒ 移交 A09；golden 与实现同源同错 ⇒ 连打 E01；口径一致 ⇒ 本卡判定有效。

## 5. 检视流程

1. **定界**：换算 op 目录、确认所在仓与 ref；按用户现象（nan 用例失败 / inf 不一致）反查优先清单点；收集特殊值注入位置与标杆来源。
2. **枚举**：目录列表列出 `op_kernel`（含架构子目录）、`op_host`（tiling / infershape / op_api）、`tests`（含 golden）全部相关文件，产出文件清单。
3. **触发词扫描**：按 `isnan|IsNan|NAN|INFINITY`、`Min|Max|Clamp|Relu`、除法 / `log|sqrt|exp` 定位特殊值分支（本地仓用 grep；API 模式逐文件拉取后检查）。**签名零命中时清单仍须逐项核查**（无显式 nan 判断本身就是命中面：nan 会走默认分支）。
4. **逐点核查**：每点记录命中面与防护面证据（文件:行号）；对每个特殊值分支写出「输入（nan / +inf / −inf）→ 分支判据 → 实际走向 → 标杆走向 → 输出差异」五项对表。
5. **反证排除**：显式 nan 判断且分支与标杆一致、inf 传播符合标杆、clamp 语义一致、三类来源用例齐全 → 明确写出反证理由。
6. **判定**：按第 7 节标准给出 命中 / 观察项 / 反证排除。
7. **GitCode 查重**（仅命中项）：issues API 按接口名 + `nan|inf|特殊值|精度` 检索，逐条比对是否同机理；无同机理才立卡。
8. **业务可达性核查**（仅命中项）：判 B 等级、定业务影响类型、给处置建议；默认保守（无法证明不可达即记 B3），降档须附证据；B 不改 S×O 档位。
9. **出报告**：按第 8 节模板落盘；所有数值后果标注「静态推演，需 NPU 实测确认」，并附三类来源的特殊值用例矩阵。

## 6. 风险定级（S×O）与业务影响评估（B 轴）

- **S**：S3（特殊值场景结果不一致——结果错但可运行，nan 用例判断失败）；S2（仅在极端特殊值输入下差异、可容差）；S1（仅测试覆盖缺口、实现正确）。
- **O**：O3 = ≥2 条独立实证；O2 = 1 条独立实证；O1 = 仅静态扫描命中或团队笔记（实证 = 确认对应的 issue / PR，或经跨仓、跨分支核验确认的缺陷记录，同权计入）。静态推演命中且无实证默认 **O1**；升档须在报告中给出实证依据。
- **风险 = S×O**：≥6 高；3/4 中；1/2 低。FP-A15 基准：模式卡整体 **S3×O3=9（高）**；纯静态命中 S3×O1=3（中，暂定），实测比对后复评。

### B 轴：业务影响评估（与 S×O 正交；报告层新增，不改卡片定级）

S×O 回答"多严重、多常见"，**不回答"真实业务能不能碰到"**。B 轴补这一问，只决定**修复优先级建议**，**不参与 S/O 取值、不改 S×O 档位与卡片元数据**。

**业务可达性（B）**——触发条件在真实负载中的可达程度：

| 等级 | 判据 | 证据要求 |
|---|---|---|
| B3 现实可达 | 主流框架/公开模型默认路径即可命中（如 PTA/torch_npu、vLLM、MindIE 常规调用） | 调用方或公开负载来源 |
| B2 条件可达 | 需特定 attr/dtype/shape 组合，业务中存在但非默认 | 该组合的业务来源 |
| B1 边界/不可达 | 需极端、超规格或非法参数（超出接口合理上限的 shape、退化/非法输入） | "为何不可达"的说明 |

- **默认保守**：无法证明不可达 → 记 **B3**；降为 B1/B2 必须附证据，**不得仅凭"业务应该不会这么用"**。
- 超规格参数是否算 B1 取决于**接口契约**：契约允许但业务不用 → B1；契约不允许（本应报错）→ 属校验缺失（FP-B04/B05 类），另行归属。

**业务影响类型**（命中后对用户可见结果的后果，用业务语言表述）：静默精度损失（模型效果下降 / loss 不收敛 / 偶发 NaN）｜ 任务失败中断（报错 / 崩溃 / 挂死）｜ 性能退化 ｜ 仅可观测性（日志 / 错误码 / 文档，不影响结果）。

**处置建议**（由两轴推导的报告结论，非新档位）：

| S×O \ B | B3 现实可达 | B2 条件可达 | B1 边界/不可达 |
|---|---|---|---|

## 7. 判定标准与反误报原则

- **签名 / 触发词命中 ≠ 成立**：`isnan` 命中只说明存在 nan 判断——须核**分支内容与标杆是否一致**；反之**无 `isnan` 也是命中面**（nan 走默认分支）。
- **三种判定**：
  - **命中**（可静态证缺陷路径）：特殊值分支走向与标杆不一致的推导链完整（或该分支缺失导致 nan 走默认路径）+ 触发输入可构造 ⇒ 立 Bug 卡；
  - **观察项**：走向一致但数值量级需实测、或标杆口径待确认（A09 / E01 未决）⇒ 记录并附特殊值用例方案，按 S3×O1 暂定；
  - **反证排除**：显式 nan 判断且与标杆逐分支一致、inf 传播符合标杆、clamp 语义一致 → 写出防护面证据与反证理由。
- **「常规用例全绿」不是反证**：本型识别特征正是「常规用例全过、nan 用例才失败」——UT green 不排除特殊值分支缺陷。
- **先定口径再定实现**：标杆口径本身可疑时（A09 / E01）不得直接判实现缺陷；报告中须写明口径核对结论。
- **与 A18 连打纪律**：同一比较点若同时涉及极值转换（有限值）与特殊值（非有限值），两卡分别立并互相引用；实证 #5562 即此形态。
- **不臆造行号**：每条证据必须是实际读到的 文件:行号；引用 #5562 时注明 issue 时点行号与本地 HEAD 的漂移。
- **静态推演声明**：无 NPU 环境时，所有运行时行为结论必须标注「静态推演，需 NPU 实测确认」。

### 判定纪律补充（v3.6）：非对称增减、证据等级与误判记录

**增减不对称**：允许追加候选（有据即可，错了可由用户排除）；**撤销或否决候选必须附 `[文件]:[行号] [代码行]` 负向证据**。无证据的「看起来没问题」一律记为「未核查」，不得计入反证排除，也不得据此下调等级——否决造成的漏报用户不可见、不可恢复。

- **证据等级**（Bug 卡必填）：`静态可证` = 推导链完整且触发输入可静态构造；`需实测确认` = 依赖运行时输入规模、设备行为或环境差异。标 `需实测确认` 的条目**不得以「命中」名义出卡**，按观察项记录并附实测用例。
- **Agent 误判记录**（Bug 卡必填）：本次被推翻的假设、推翻它的证据（`[文件]:[行号] [代码行]` 或实测输出）、判定标准是否随之修订；无推翻写「无」。
- **误判回流**：同类误判在 3 次检视中重复出现，登记至 `cases/misjudgments.jsonl`（字段见 `cases/README.md`），并在本模式判定标准中新增对应防线；守门 C19d 校验台账字段合法。

## 12. 已知缺陷案例：触发条件 / 根因 / 修复范式 / 针对性深挖（v5.1）

### 案例 1｜平方和相减产生负方差并传播为 NaN —— 子型 A15-2

- **触发条件**：`INTrainingUpdateV2`（BN 类 in-training 统计更新）在 `E[x²]-E[x]²` 单遍算法下，输入含大量零元素或方差极小时，中间方差因**灾难性抵消**落到 `-ε`，经后续 `sqrt`/`rsqrt` 传播为 NaN。输入侧查不到任何 nan/inf。
- **根因**：`E[x²]-E[x]²` 数学等价但**数值不等价**——两个接近的大数相减丢弃有效位；结果未做定义域钳制即交给开方/求逆。
- **修复范式（✅）**：

```python
# ❌ 单遍：舍入抵消可为负
variance = square_sum - mean * mean
inv_std  = rsqrt(variance + eps)
# ✅ 钳制下界（25-11 采用的修复形态）
variance = maximum(square_sum - mean * mean, 0.0)
inv_std  = rsqrt(variance + eps)
# ✅ 更稳：双遍 / Welford，从根上避免抵消
```

- **针对性发现**：① grep `E[x²]|square_sum|sq_sum|mean_square|sum_sq` 与紧随其后的减法；② 找 `sqrt|rsqrt|log|/` 的实参是否来自该减法；③ **钳制点是否覆盖所有消费方**——25-11 只钳了被开方的一次，同类算子若有两处开方仍会漏；④ 单遍 vs 双遍/Welford 的归约方式判定。
- **最小复现锚**：零元素比例阶梯 `0% → 50% → 90% → 99%`；常数列；`x` 与 `x+1e-7` 并置；断言 `variance >= 0` 且输出有限。**必须做修复前后对照**（固化输入 + 固定种子），只看到新版通过不能证明缺陷曾存在。
- **实证**：现网修复 25-11（`INTrainingUpdateV2`，canndev `pulls/62301`）——`after_v200()` 路径新增 `max(variance, 0)`。**实际文件:行号待定位**：该实现位于 canndev 仓 `ops/built-in/tbe/impl/dynamic/in_training_update_v2.py`，本地未检出 canndev，故本案例**暂无可机读真锚**（按库纪律不臆造行号）。
