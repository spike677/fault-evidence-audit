描述

背景

Ascend950（DAV_3510）MatMulV3 在 fixpipe 绑定（Bound）场景下，低精度输入 + FP32 输出（fp16/bf16 -> float）原走 ND_FIXPIPE_1_1 且未置位 splitM，输出精度异常（实测 74.78%）。

根因

GetL0C2OutDav3510（matmul/mat_mul_v3/op_host/op_tiling/arch35/matmul_v3_tiling_helper.cpp）此前按输入 dtype 选择 fixpipe 模式：fp16/bf16 输入一律 1V1，仅 FP32 输入时才置位 splitM。但 splitM 的语义是“fixpipe 场景 FP32 输出按 M 轴切分、由双 AIV 拷出”，应由输出 dtype决定。

改动

  1. 按输出 dtype（cType == DT_FLOAT）选择 ND_FIXPIPE_1_2 并置位 splitM；
  2. 删除不可达的 aType == DT_FLOAT 分支（DAV_3510 支持的 dtype 组合中 FP32 输入必然 FP32 输出）；
  3. 兜底由 ND_FIXPIPE_1_2 收敛为 ON_THE_FLY；
  4. 补充 1V1/1V2 与 splitM 选择的 UT。

影响面

  • fp16/bf16 -> fp32：由 1V1 改为 1V2 + splitM（本次修复）；
  • fp32 -> fp32、fp16/bf16 -> fp16/bf16：行为不变；
  • 未改动 kernel：B 全载 + 1V2 在 kernel 侧已有分支（mat_mul_v3.cpp 中 FULL_LOAD == MAT_MUL_B_FULL_LOAD && MODEL == MAT_MUL_BASIC && L0C2OUT_MODEL == MAT_MUL_1V2_ND_ALIG_FIXPIPE），mat_mul_tiling_key.h 也已注册该组合，无需在 CheckBL1FullLoad 中排除 fixpipe。

关联的Issue

  • 关联 Issue #8656：https://gitcode.com/cann/ops-nn/issues/8656

测试

  • 新增 UT（matmul/mat_mul_v3/tests/ut/op_host/arch35/test_matmul_v3_tiling.cpp）：
    • GetL0C2Out_Dav3510_Fp32Out_Fixpipe1V2WithSplitM（fp32 -> fp32，1V2 + splitM）
    • GetL0C2Out_Dav3510_Fp16InFp32Out_Fixpipe1V2WithSplitM（fp16 -> fp32，1V2 + splitM）
    • GetL0C2Out_Dav3510_Fp16Out_Fixpipe1V1WithoutSplitM（fp16 -> fp16，1V1，无 splitM）
  • mat_mul_v3 op_host UT 全量：380/380 通过（bash build.sh -u --ophost --ops=mat_mul_v3 --soc=ascend950，CANN 9.3.0）
  • Ascend950PR_9589 实测：CANN 10-28、11-04 包各 42/42 用例通过
