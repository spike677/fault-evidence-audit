# FP-G01 执行挂死与调度超时（死循环 / 回绕长循环 / 通信等待 / kernel 超时）

- **故障机理**：任务**无法完成**——进程存活但永不返回，或被超时强制中断。五种独立成因（编号与五子型一一对应）：① **迭代求解循环不推进**——host tiling 的 `while(true)` 迭代求解在异常分支下不更新推进变量（如 `updateDivRect` 未置位）且无「不推进即退出」防护，CPU 空转死循环；② **集合通信与流同步等待超时**——多卡训练 `rank_table` 配置无误仍随机出现初始化连接超时、个别 rank 掉线，等待时长由 `HCCL_CONNECT_TIMEOUT` / `HCCL_EXEC_TIMEOUT` / `HCCL_RETRY_CNT` / `HCCL_DFS_CONFIG` 等超时与重传配置项决定，配置缺失或换算错误致等待无界/超时；③ **循环上界由回绕值得出**——rank-0 / 空输入经 `size_t` 下溢回绕成 `SIZE_MAX`，后续按该上限循环，Host 线程长时间不返回；④ **设备侧算子执行超时**——kernel 长时间不返回，报 `vector core execution timed out` 并升级为 `aic error`；⑤ **资源泄漏累积**——内存申请-释放不成对，长期调用致设备内存耗尽，把正常算子推向挂死/闪退。另有**横切成因（独立于①~⑤、不单独成子型）：超时机制自身错误/死代码**——超时判定代码的溢出检查是**死代码**（`double` 先截断为 `u32` 后，`u32` 不可能大于 `UINT32_MAX`），大超时值被截断反而**误超时**，横切于②④（通信等待与设备超时）的超时判定面。**共性：缺陷不是「算错了」，而是「永远算不完」；且在没有单用例超时熔断的框架里表现为卡死而非失败，掩盖真实失败点。**
- **触发条件**：host tiling / infershape 中的迭代求解循环（`while(true)` / `for(;;)`）遇到异常输入或异常中间状态；整数下溢 / 回绕值被用作循环上界；rank-0、空 tensor、退化 shape；分核 / 切分参数使循环不收敛；设备侧大 shape 或异常模板致 kernel 长时占用；超时值配置超过 `uint32_t`；长期高频调用累积资源泄漏；**测试框架缺单用例超时熔断**（卡死会一直等下去）。
- **典型表现**：进程存活但 CPU 空转（90%+）或 0% 占用、长时间无任何输出；CI 单用例长时间不动（**不是失败，是"不动"**）；`Exit code 124`（超时）；`vector core execution timed out` / `aic error`；日志停在进入某函数之前（如实测需先看现象才知道根因是 `GetSoftMaxMinTmpSize` 返回 0）；挂死是否复现**依赖用例执行顺序**（前序用例造成的单例污染）；设备内存随调用次数持续上涨。**关键识别特征：日志完全无进展。**
- **源码审查映射点**：host 侧迭代求解循环（`AdjustC*Tiling`、`AdjustNTiling` 类）**循环体内是否有更新推进变量的语句**、异常分支是否「不推进即 `return GRAPH_FAILED`」；循环上界的来源类型（`size_t` / `uint32_t` 参与减法是否可能回绕，`x - 1` 在 `x == 0` 时的行为）；设备侧 kernel 是否有超时相关日志与早退路径；超时判定代码中的溢出 / 截断检查**是否可达**（先截断再比较即必然为假的死代码）；资源申请与释放是否成对（**异常分支 `return` 前是否释放**）；测试框架是否具备单用例超时熔断；全局单例（`PlatformAscendCManager` 等）是否有 fixture 级重置。
- **检测签名（判别性指纹，命中即候选缺陷点位）**：`while\s*\(\s*(true|1)\s*\)`（**须人工确认循环体内是否含推进变量更新与不推进退出**；hccl 实测命中 **9 处**，含 `examples/05_custom_ops_allgather/aiv/inc/aiv_communication_base_v2.h:245`）；`for\s*\(\s*;\s*;\s*\)`；`Exit code 124|execution timed out|vector core`（超时 / 设备侧超时日志信号）；`malloc|new\s` 与多分支 `return` 同现且无统一释放（泄漏致内存耗尽）；`setTimeout|SetTimeout|TIME_S_TO_US`。
- **审查关键词（`keywords` 字段；命中只表示该处值得人工审，不是缺陷候选）**：`static_cast<size_t>|\(size_t\)` 与 `-` 同现（下溢回绕嫌疑，hccl 实测 31 处——正常转换占绝大多数，必须逐个看是否用作循环上界）；`UINT32_MAX|numeric_limits<u32>::max\(\)` 之前的溢出判断（**须人工确认是否为死代码**：先截断再比较必然为假；hccl 实测 34 处）。
- **控制变量（v6.30）**：**必须固定**——超时阈值、用例规模、机器负载三项固定；挂死判定必须配 `--minutes` 硬熔断与精确计时 ｜ **允许变动**——被测用例本身（一次只加一个可疑输入） ｜ **多变量同变的典型误判**——把「慢退出」当「挂死」——实测 62s 慢退出曾被写成「仅调 GWS 即挂死」的假 P0；换机器/换负载后同一用例可能不挂
- **测试拦截建议**：① **单用例超时熔断（最高优先级）**——CI 对每个用例设硬超时（如 10 分钟），超时**转失败**并 dump 堆栈；否则卡死只表现为「任务不动」，是全库最贵的排查成本来源；② **断言「不返回」而不仅断言精度**——挂死类缺陷根本走不到数值比较步，现有精度用例天然漏检；③ **UT 执行顺序随机化**——顺序依赖造成的单例污染只有固定顺序才会被掩盖；④ **fixture 强制重置全局单例**并在每个 tiling 用例显式 `SetSocVersion`，禁止依赖前序用例状态；⑤ **边界输入探针**——rank-0 / 空 tensor / 退化 shape 单独成类（覆盖下溢与回绕路径）；⑥ 对迭代求解循环加**静态门禁**（循环体内必须有推进语句与不推进退出）；⑦ **超时配置边界**（超过 2^32 微秒、负值）与**长稳看护**（设备内存持续上涨即告警）。
- **实证案例**：**ops-transformer #5032**（closed）`bash build.sh --PR_UT` 时 `PromptFlashAttentionTiling310P.PromptFlashAttention_310p_tiling_0` **卡死（CPU 空转 90%+）**；技术根因：`CheckArgsLegal` 失败且不置 `updateDivRect` → `AdjustCVTiling` 的 `while(true)` 循环**无法推进**；修复 **PR #11411**（2026-09-07 17:26 合入）在 `!updateDivRect` 时直接 `return GRAPH_FAILED`，**产品代码 1 行防御修复**；触发依赖 FASG 前置用例（`FlashAttentionScoreGrad_tiling_1/2`）造成的单例污染，单独跑不复现——**「死循环 + 无防护 + 无超时熔断」三件套叠加，卡死掩盖了真实失败点**。**ops-cv #933**（closed）experimental NMSWithMask InferShape 对 rank-0 输入直接做 `size_t` 的 `x - 1` → **回绕为 `SIZE_MAX`** → 后续按该上限循环，**Host 线程长时间不返回（3s 超时退出码 124）**；修复 MR `!1571`（与 #946 / #938 / #925 / #923 / #935 / #915 同族 6 条，同一基线 commit 同日关闭）。**ops-transformer #5337**（closed）MoeInitRoutingV4 部分用例**超时导致 `aic error`**，日志为 `vector core excution timed out`；复现条件 arch35(Ascend950) + quant + mode=0（静态量化）+ fullload **可复现挂死**。**cann/hccl #567**（closed）`src/ops/op_common/template/aiv/hccl_aiv_utils.cc` 第 368-374 行 `GetAivTimeout` 的**整数溢出检查是死代码**——`timeoutUs = execTimeOut * TIME_S_TO_US`（`double` 先截断为 `u32`），第 369 行再判断 `timeoutUs > UINT32_MAX` 必然为假，**大超时值被截断致误超时**。**cann/hccl #141**（closed）`BatchSendRecvOutPlace` 动态申请堆内存后**异常分支未释放**，长期高频调用致设备内存持续上涨，**最终内存耗尽报错、任务卡死/闪退**（资源泄漏 → 挂死的完整链条）。**cann/hccl #147**（closed）多卡分布式训练 `rank_table` 配置无误但**随机出现初始化连接超时、个别 rank 掉线**；超时/重传相关配置项为 `HCCL_CONNECT_TIMEOUT`（rank 初始化建链超时）/ `HCCL_EXEC_TIMEOUT`（通信执行超时）/ `HCCL_RETRY_CNT` / `HCCL_DFS_CONFIG`。**静态扫描基线**：2026-09-07 日报的 **F5 指纹（「无退出条件循环」）在四仓命中 36 处**（ops-transformer 28 / ops-nn 5 / ops-math 2 / ops-cv 1），已列入待人工确认清单——**说明本型的产品代码风险面远比已报 issue 数量大**。
