# FP-B12 空/退化输入早退路径未写非空输出（SUCCESS + 未初始化输出）

> [← 库索引](../../README.md) ｜ [变更记录](../../CHANGELOG.md) ｜ 类别：功能/兼容 ｜ 风险：高（S3×O3=9） ｜ 状态：活跃

- **元数据**：类别 功能/兼容 ｜ 风险 高（S3×O3=9）｜ 状态 活跃 ｜ 来源 ops-cv 全量 issue 语料（2026-10-17，本簇 **5 条**，全部 `进行中`，全部为反向/梯度算子）+ 2026-10-21 补 B12-2 子型
- **适用**：仓 All ｜ 侧别 Host ｜ 载体 aclnn源码 ｜ 触发 IsEmpty() ｜ 默认启用 true
- **故障机理**：接口**已有** `IsEmpty()` 判空分支（因此不属于 [FP-B06](FP-B06.md) 的"分支缺失"），但早退体只做 `*workspaceSize = 0; uniqueExecutor.ReleaseTo(executor); return ACLNN_SUCCESS;`，**不写任何输出张量**。而输出 shape 与输入强绑定，存在"**输入为空、输出非空**"的合法组合——尤其是反向算子：`gradOutput` 为空而正向输入（`input`/`grad_x`/`features`）非空时，梯度输出（`inputGrad`/`grad_y`）与之同形且非空。此时调用方拿到的是自己预分配的未初始化内存（NaN/随机值），却被当作合法梯度返回。**本型含四个子型（v6.13 起，v6.26 增 B12-3）**：**B12-1 早退不写任何非空输出**（上面的主形态，5 条 ops-cv 案例 + #7033）；**B12-2 输出覆盖不全**——**没有早退**，返回 `ACLNN_SUCCESS` 但只写入了部分元素（#3747 `uint32`/`int64` 约一半输出一个字节都没写，未写元素数恒为 `ceil(n/2)`）。**B12-3 非空辅助输出被早退跳过（v6.26）**——早退块**确实写了主输出**（或主输出本就该为空，写不写都"对"），但**形状由其它入参/属性决定、与触发早退的那个空维无关**的辅助输出（`*Scale` / `*Out` / `rstd` / `invRms` / `gradWeight` / `bagSize` / `maxIndices` / `amax` / `outputScale`）被整块跳过。**这是判据口径的关键升级**：旧口径只问"早退块内写没写输出"，遇到"主输出本来就该为空"的接口会直接判 clean，而真正受害的是辅助输出。正确问法是：**该输出的 shape 域是否与触发早退的空维无关？无关且非空 ⇒ 必查是否被写。**B12-2 只负责识别「返回成功但输出未写全」这一**结果面**；若根因是 dtype→执行模板映射错配，**机理归 [FP-A22](../FP-A/FP-A22.md)**，不要在本条重复定级。 **B12-4 早退旁路参数校验（v6.33）**：`IsEmpty()` 的 `return ACLNN_SUCCESS` 排在参数校验之前，**非法 dtype/shape 与空输入同时出现时被早退直接放行**，既不报错也不写输出；与 B12-1 的区别是「早退块本身也错了」——不是漏写，而是根本不该走到早退。
- **触发条件**：至少一个输入 `numel==0`，且**至少一个输出非空**；以反向/梯度类算子为主（`*Backward`、`*Grad`）；正向算子若输入全空则输出也为空（no-op 成立，不触发）。典型组合：`gradOutput` 空 × `input` 非空；`grid` 空 × `input` 非空；`roisN==0` × `gradInput` 非空。
- **典型表现**：**接口返回 `ACLNN_SUCCESS`（0），但输出内容为未初始化内存**——同一次运行重复调用结果不同、换机器结果不同、`mssanitizer`/canary 观察到未写区域；用 PyTorch 同类反向 API 对照时，无采样点/无 ROI 的梯度应为 **0**，而 NPU 侧返回随机值或 NaN，表现为"loss 偶发 NaN""梯度爆炸"这类难以归因的现象。与 FP-A04 的区别：A04 是"有结果但精度不对"，本条是"**结果从未被写入**"。
- **源码审查映射点**：逐个 `aclnnXxxGetWorkspaceSize` 找 `IsEmpty()` 早退块，**先给每个输出标注 shape 域来源**（由哪些入参 / 属性决定），再检查 `return ACLNN_SUCCESS` **之前**是否遍历了所有 `aclTensor*` 输出：非空输出是否被 `l0op::Duplicate`/`InitOutput`/清零算子处理；判空条件是否**逐输入**（`gradOutput->IsEmpty() || input->IsEmpty() || grid->IsEmpty()` 三选一即早退时要特别小心）；`CheckShape` 是否拦截了"空/非空交叉"组合（多数没拦，因为形状一致性仍然成立）；文档 `docs/aclnn*.md` 若声明"支持空 Tensor"，则本节适用性直接成立。 **B12-3 加查（v6.26）**：对每个输出回答"它的 shape 由谁决定"——若 shape 只依赖 `attr` / 非空输入（典型 `outputScale` 恒 `[m]`、`amax` 强制 `[1]`、`gradWeight` 同 weight、`bagSize` 由 `offsets`+attr 决定），则**它与触发早退的那个空维无关，必须逐个确认早退块内是否写了它**；这类输出名可直接按 `*Scale|*Out\b|rstd|invRms|gradWeight|gradBias|bagSize|maxIndices|amax|outputScale` 正则捞。
- **检测签名**：静态扫描「函数体内存在 `IsEmpty()` 且其后 `return ACLNN_SUCCESS` 的早退块」× 「该函数签名中存在非 inplace 的 `aclTensor*` 输出」× 「早退块内无任何写输出调用（`Duplicate|InitOutput|Memset|l0op::` 作用于输出）」⇒ **候选命中**；再核对 `CheckShape` 是否已排除"空输入 × 非空输出"组合，未排除即成立。ops-cv 基线：5 个接口命中，全部为 `*Backward`。**B12-3 签名（v6.26）**：函数体内存在 `IsEmpty()` 早退 × 签名含 `*Scale|*Out|rstd|invRms|gradWeight|gradBias|bagSize|maxIndices|amax` 类输出 × 早退块内**未出现该输出名**（与 B12-1 的"无任何写输出"是不同判据：这里主输出可能已写）⇒ 候选。注意 `*Out\b` 会误捞 `output`（`output` 本身常是主输出），落候选后必须人工看该输出是主输出还是辅助输出。 **initcheck 前置判据（v6.48）**：`mssanitizer --tool=initcheck` 要求 kernel 以 `--cce-enable-sanitizer` 重编译；未重编译时日志会**同时**出现 `No active sanitizer tool on kernel ...` 与大量 `ERROR: uninitialized read of size N`，后者**不得作为缺陷证据**（2026-11-08 实测：`mla_prolog`、`lightning_indexer_v2`、`inplace_partial_rotary_mul` 的官方 example 均命中该形态；同一二进制跑 `--tool=memcheck` 却是真检且 0 error）。判据：逐 kernel 检查是否出现 `initcheck is not supported ... temporarily ignored`，出现即判「不可判定」，必须先按 `--cce-enable-sanitizer` 重编内核再跑。
- **控制变量（v6.30）**：**必须固定**——触发早退的空维只来自**一个**输入；其余输入保持非空；输出侧逐张量记录「shape 由谁决定」后逐个核对是否被写 ｜ **允许变动**——被置空的那一个输入 ｜ **多变量同变的典型误判**——主输出本来就该为空时，看「早退块内写没写输出」判不出问题——真正受害的是 shape 与空维无关的辅助输出（`*Scale` / `amax` / `rstd` / `gradWeight`）；旧口径对 4 条真缺陷全部判 clean
- **测试拦截建议**：建「空输入 × 输出非空」矩阵——对每个反向算子，把所有输入**逐个**置空（shape 含 0 维），断言两件事：① 返回码为 0；② **非空输出的每个元素等于 0**（PyTorch 语义：无贡献点的梯度为 0）。禁止只断言返回码——这正是 5 条 issue 长期未被发现的原因。建议在 ST 里加 canary：输出 buffer 预填魔数，跑后检查残留魔数比例。 **B12-3 加测（v6.26）**：断言范围必须覆盖**所有输出**而不只是主输出——`*Scale`/`amax`/`rstd`/`gradWeight` 等即使主输出为空也要逐个检查魔数残留；只断言主输出等于空/等于 0，正是 B12-3 长期漏检的直接原因。
