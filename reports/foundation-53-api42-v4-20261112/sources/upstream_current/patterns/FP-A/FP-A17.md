# FP-A17 A1 与 A2 硬件代际精度差异

- **实证状态**：未证实（2026-10-17 复核：检索无确认对应；来源为团队笔记 / 静态观察）——按 O1 计档；**v6.30 起有了反向实证（96/101 bit 一致），状态改为「已证伪常见形态」**，引用时须标注「跨代 bit 差异在正常用例上未复现」，不得表述为已确认缺陷
- **适用**：仓 All ｜ 侧别 All ｜ 载体 Tiling源码,Kernel源码 ｜ 触发 GetSocVersion|SOC_VERSION|socVersion ｜ 默认启用 true
- **故障机理**：SOC 代际间指令精度规格/默认路径不同，代际分支含精度相关硬编码遗漏一侧。
- **触发条件**：跨代芯片（A1/A2/A5 等）部署同一算子。
- **典型表现**：跨代芯片精度不一致。
- **源码审查映射点**：SOC 代际分支中的精度相关硬编码。
- **测试拦截建议**：（v6.30 补判据分层）**先做 bit 一致基线，再做容差对比，不做无容差的数值比较**。三档：
  ① **bit 一致（默认档）**：同一探针源、同一输入、同版本编译，两代芯片输出逐字节相同 ⇒ **不成立**。
   实测 2026-11-06：101 个在两代机器上均有有效输出的接口中，**96 个签名逐字节一致**，另 3 个差异经归因   **全部落在用例侧**（TopK 全并列选索引未定义 / 一侧 baseline 失败 / 输入含重复索引）。
  ② **容差一致**：bit 不同但落在资料声明的误差界内 ⇒ 不成立，记「跨代数值路径不同但精度达标」。
  ③ **超容差**：只有这一档才是缺陷。
  ⚠️ **只报「bit 不同」而不给容差判据，会把不同 kernel 实现造成的正常末位差异当成缺陷**——若判据是「数值是否 1 ulp 内一致」，96 个全算差异，等于该模式对绝大多数算子恒成立，**没有判别力**。
- **必须声明的对照能力（v6.30）**：判定前先确认实验室是否具备「**同 CANN 版本、不同芯片**」或「**同芯片、不同 CANN 版本**」的对照环境。两者都没有时，任何差异都**不可归因**，该模式应落 `unknown` 而不是 `hit`。这一条是被实测打出来的：曾同时换芯片（910B2→910B3）与 CANN（9.3.0→26.1.1），得到的 1 例「跨代差异」无法归因，只能记待定。
- **实证案例**：**v6.30 补反向实证**——**2026-11-06 跨代三机专项**——442 接口中 101 个在两代（A2 + CANN 9.3.0 / A3 + CANN 26.1.1）上均有有效输出，**96 个输出签名逐字节完全相同**，3 个差异经逐条归因全部落在用例侧（`aclnnBSASelectBlockMask` 输入 q/k 全为 `0.1f`、score 完全并列，两代选不同索引；`aclnnNsaCompressAttention` 全为常数 `1.0`，差异全落在 `topkIndicesOut`；另一例一侧 baseline 失败）。即**该模式下跨代 bit 差异在正常用例上未复现**。**结论按「风险 中」维持不变**，但把判据改成上述三档分层——原「待补充」状态同时解除（有了反向实证，比继续挂着「未证实」更有用：它明确了「什么不算」）。
  **原检索记录（保留）**：2026-09-16 gitcode CANN 组织 12 仓约 1.4 万条 issue 全量关键词检索，命中多为 cubeMathType 降精度模式口径分歧（ops-nn #5655）、cast 舍入口径 1 ulp 分歧（ops-nn #5656）、跨代性能咨询（ops-nn #3436、ops-transformer #1574）等异机理条目，无「跨代芯片同算子精度不一致」的确认对应实证）。
**索引类输出不得比 bit**：输出含 TopK/ArgMax/排序置换时，输入并列则选择不唯一，该输出不参与跨代 bit 比对——见 [EVIDENCE_DISCIPLINE.md](../../EVIDENCE_DISCIPLINE.md) D11。
