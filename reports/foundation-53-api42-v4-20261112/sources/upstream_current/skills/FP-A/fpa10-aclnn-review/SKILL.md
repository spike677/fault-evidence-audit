# FP-A10 aclnn 接口检视（fpa10-aclnn-review）

对用户指定的 aclnn 接口（如 aclnnQkvRmsNormRopeCache）做 FP-A10 专项源码检视：先定位算子实现，再按清单逐项核查，每个结论给出**文件 + 行号 + 推导链**证据，命中即出 Bug 卡，输出检视报告。**本模式特殊纪律：① 缺陷是「高精度标量 attr 在低精度链路上被静默降级」——不报错、不崩溃，仅精度失效（如 double epsilon 未转换，1e-10 级值下溢为 0）；② 触发签名 `GetAttrPointer|Attr` 普遍存在，命中只表示「值得人工核」——必须给出「该 attr 在原型中的声明类型 + 解析分支的实际承载类型」的降级推导链；③ 小值域敏感：attr 传 1e-8 / 1e-10 级值时 double→float 降级直接致下溢为 0，须以「高精度敏感值」为探针；④ 与 A11（double dtype 张量）、A13（输入截断）同源于「高精度值被静默降级」，按「标量 attr vs 张量 dtype vs 输入预处理」三分归因。**

## 0. 与相邻模式的边界

| 相邻模式 | 分工 |
|---|---|
| FP-A11（AiCore 不支持 double 类型） | **标量 vs 张量**二分：A10 是**标量 Attr**（proto 属性）的 double 承载/解析降级；A11 是**张量 dtype** 的 double 输入/输出底层不支持。两者同源于「高精度值在低精度链路上被静默降级」，按承载对象归属并双向关联 |
| FP-A13（输入尾数截断才能通过精度标准） | A13 侧重**输入预处理阶段**的尾数截断；A10 是**attr 解析链路**的 double→float 降级——按「张量输入 vs 标量 attr」分 |
| FP-A09（对标 TF 语义与 PTA 不一致） | A09 是**语义/默认值**对标差异；A10 是**类型承载**降级（语义相同、精度丢失）——按「语义 vs 类型」分 |
| FP-B04（aclnn 必选入参空指针校验缺失） | `GetAttrPointer` 返回**空指针未判空**归 B04；返回**有效指针但类型降级**归 A10——先判空再判类型 |
| FP-B09（动态 shape 标签未参与校验） | B09 是 `-1/-2` **哨兵被当实数**（语义识别缺失）；A10 是 attr **类型承载**降级——哨兵识别正常但类型丢精度归 A10 |
| FP-A18（int32 边界值转 float 舍入） | A18 是**整型转浮点**的舍入语义；A10 是**双精度转单精度**的承载降级——按源类型分 |

**症状反查定位**：epsilon/scale 类小值 attr（1e-8 / 1e-10 级）传入后结果异常、日志出现 `Interpreted as 32-bit float: 0.000000000000000e+00` → double 未显式转换面（清单①②）；attr 传 double 后精度**直接失效**（下溢为 0）而全程无报错 → 静默降级面（清单③④）；tensor/scalar 的 fp16/double 混合场景精度丢失 → 类型分派面（清单⑤）；attr 缺省正常、显式传高精度值反而不对 → 解析分支类型面。

## 1. FP-A10 模式卡摘要（检视依据，源自本库 `patterns/FP-A/FP-A10.md`，v3.1）

- **编号 / 名称**：FP-A10 原型 Attr 不支持 Double ｜ **类别**：精度 ｜ **风险**：高（S3×O3=9）｜ **状态**：活跃
- **适用声明头**（照抄卡片）：仓 All ｜ 侧别 All ｜ 载体 IR与图配置 ｜ 触发 GetAttrPointer|Attr ｜ 默认启用 true
- **skill 核查面**：侧别 All——skill 落地为 `op_host` 的 `*_def.cpp`（proto Attr 类型定义，即「IR与图配置」的落地处）与 `op_api/aclnn_*.cpp`（`GetAttrPointer` 取值与解析分支的承载类型）；延伸至 kernel 侧对降级后标量的使用点与 `docs/` 中 attr 类型/取值说明
- **故障机理**：算子原型（proto）Attr 类型不含 double，或解析分支静默降级为 float，精度丢失。
- **触发条件**：含标量 attr（scale/eps/阈值）且用户传入 double。
- **典型表现**：Double 数据类型精度问题。
- **源码审查映射点**：Attr 解析分支中 double 类型的支持与静默降级。
- **检测签名**（命中即候选缺陷点位）：`GetAttrPointer|Attr`（attr 取值与解析分支定位点）。
- **测试拦截建议**：attr 传高精度敏感值（如 1e-8 级 eps）边界用例。
- **实证案例**：ops-transformer **#1952** qkv_rms_norm_rope_cache 在 aclnn 侧**没有把传入的 epsilon 从 double 转换成 float**，导致特定场景精度问题（910C，输入取值范围 [-1e-10, 1e-10]；日志显示 `[Epsilon Debug] Interpreted as 32-bit float: 0.000000000000000e+00`——double 未转换致下溢为 0，精度直接失效）；ops-math **#2006** truncate_div 在 tensor/scalar 的 **fp16/double 场景**下精度丢失。**共性特征：double 标量 attr 未做显式转换/未纳入 proto Attr 类型定义，静默降级致精度失效。**
- **关联**：FP-A11、FP-A13（同源于「高精度值在低精度链路上被静默降级」，A13 侧重输入预处理截断）。

## 2. 检视输入与算子定位

**输入**：aclnn 接口名（必填，如 `aclnnQkvRmsNormRopeCache`）；可选 ref（默认 master）、指定仓（默认自动定位）；可选现象描述（失败 attr 名 / 传入取值 / 输入取值范围 / 是否出现降级日志——用于直接定位解析分支）；可选高精度敏感值（如 1e-8 / 1e-10 级）。

**接口名 → 算子目录换算**：去 `aclnn` 前缀 + 驼峰转下划线小写：
`aclnnQkvRmsNormRopeCache → qkv_rms_norm_rope_cache`、`aclnnTruncateDiv → truncate_div`、`aclnnLayerNorm → layer_norm`。

**仓定位顺序**（GitCode `cann` 组织，逐仓用目录列表确认）：`ops-transformer`（attention/moe 类——实证集中地）→ `ops-math`（math/conversion 类）→ `ops-nn`（norm/activation 类）→ `ops-cv`。**类目名不总与直觉一致**，以目录列表为准。FP-A10 高发面：含标量 attr（epsilon/scale/阈值）的算子、attr 类型在 proto 中声明为 float 的接口、融合类算子（多 attr 组合）、tensor/scalar 双形态入参的算子。

**算子目录结构约定**（以实证算子为例，具体布局以目录列表为准）：

## 4. 检视清单（每点：查什么 → 何处 → 命中判据）

对算子的 `op_host`（`*_def.cpp` proto 定义）/ `op_api`（attr 取值与解析）/ kernel 使用点逐点核查，`docs/` 同步核对，**每点先查命中面、再做反证排除**；已做显式转换或已纳入 double 类型的实现要记录为防护面证据。

### ① proto Attr 类型定义是否含 double
- 查什么：`*_def.cpp` 中每个标量 attr（epsilon/scale/阈值）的**声明类型**——是否含 `Float`/`Double`；若 proto 仅声明 `Float`，则用户传 double 时框架侧的行为（截断/降级/报错）是否被处理；attr 的 `ParamType` 与 `AttrType` 组合是否与语义一致。
- 何处：`op_host/*_def.cpp` 的 `Attr` 定义段。
- 命中判据：attr 声明类型为 `Float` 但语义要求 double 承载 / 未提供 double 路径 ⇒ 命中候选。

### ② Attr 解析分支的 double 支持与显式转换
- 查什么：`op_api` 中 `GetAttrPointer` 取值后的**解析分支**是否处理 double——是否把传入的 double **显式转换**（`static_cast<float>` / `ToFloat` 类）后再使用；还是按错误类型直接解读（实证 #1952：aclnn 侧没有把 epsilon 从 double 转换成 float，日志 `Interpreted as 32-bit float: 0.000000000000000e+00`）；多类型 attr 的 `switch/if` 分支是否覆盖 double 档。
- 何处：`op_api/aclnn_*.cpp` 的 attr 解析段、`op_host` 的属性解析。
- 命中判据：存在「传入 double 未被正确解读/转换」的分支 ⇒ 命中候选。

### ③ 静默降级为 float（无报错）
- 查什么：降级路径是否**静默**——类型不匹配时是否报错或告警，还是直接按低精度解读继续执行（精度失效但无任何提示）；与 B01（该拦不拦）交界：本型是「放行了但类型读错」。
- 何处：attr 解析的错误处理分支、类型转换点。
- 命中判据：类型不匹配无报错/无告警且继续执行 ⇒ 命中候选。

### ④ 小值域下溢
- 查什么：高精度小值 attr（1e-8 / 1e-10 级）在 double→float 降级后是否**下溢为 0**（实证 #1952：输入取值范围 [-1e-10, 1e-10]，降级后 epsilon 变为 0，精度直接失效）；该 attr 在计算中的作用位置（除法/开方/裁剪）对 0 值的敏感度。
- 何处：attr 使用点（norm 的 eps、scale、阈值）、降级后的承载类型。
- 命中判据：能写出「attr 取值 1e-K → float 承载 → 下溢为 0 → 结果精度失效」的推导 ⇒ 命中候选（须附高精度敏感值探针）。

### ⑤ tensor / scalar 类型分派
- 查什么：同一入参可作 **tensor 或 scalar** 时（实证 #2006 truncate_div 的 tensor/scalar 形态）——scalar 分支的承载类型是否足够（fp16/double 场景）；tensor 与 scalar 两条路径的精度语义是否一致。
- 何处：`op_api` 的 tensor/scalar 分派、kernel 的标量使用点。
- 命中判据：scalar 分支承载类型低于 tensor 分支 / fp16 场景精度丢失 ⇒ 命中候选。

### ⑥ 高精度敏感值边界用例覆盖
- 查什么：`tests/` 是否有 attr 传**高精度敏感值**（如 1e-8 级 eps）的边界用例；是否覆盖 double 传入场景；用例是否校验「非零且与高精度参考一致」。
- 何处：`tests/` 的 attr 边界用例。
- 命中判据：无高精度敏感值用例 / 只测默认值 ⇒ 记观察项（测试面缺口）。

## 5. 检视流程

1. **定界**：换算 op 目录、确认所在仓与 ref；记录用户现象（失败 attr 名 / 传入取值 / 是否出现降级日志）。
2. **枚举**：目录列表列出 `op_host/*_def.cpp`、`op_api/aclnn_*.cpp`、kernel 使用点、`docs/`、`tests/`，产出文件清单。
3. **触发词扫描**：按 `GetAttrPointer|Attr`、`Float|Double|float|double`、`static_cast<float>|ToFloat|GetAttr` 定位风险面（本地仓用 grep；API 模式逐文件拉取后检查）。**触发为关键词：签名零命中时清单仍须逐项核查完毕**。
4. **逐点核查**：按第 4 节 ①~⑥ 记录命中面与防护面证据（文件:行号）；对每个标量 attr 给出「proto 声明类型 → 解析承载类型 → 使用点」的链路表。
5. **反证排除**：attr 已含 double 类型、解析分支已显式转换、类型不匹配有报错、scalar 分支承载足够 → 明确写出反证理由。
6. **判定**：按第 7 节标准给出 命中 / 观察项 / 反证排除。
7. **GitCode 查重**（仅命中项）：issues API 按接口名 + `double|精度|epsilon|attr|下溢` 检索，逐条比对是否同机理；无同机理才立卡。
8. **业务可达性核查**（仅命中项）：判 B 等级、定业务影响类型、给处置建议；默认保守（无法证明不可达即记 B3），降档须附证据；B 不改 S×O 档位。
9. **出报告**：按第 8 节模板落盘；所有结论标注「静态推演，需高精度敏感值 attr 探针实测确认」并附实测方案。

## 6. 风险定级（S×O）与业务影响评估（B 轴）

- **S**：S3（精度失效——结果错但可运行，如 epsilon 下溢为 0）；S2（仅高精度敏感值场景可见）；S1（降级不影响结果）。
- **O**：O3 = ≥2 条独立实证；O2 = 1 条独立实证；O1 = 仅静态扫描命中或团队笔记（实证 = 确认对应的 issue / PR，或经跨仓、跨分支核验确认的缺陷记录，同权计入）。静态推演命中且无实证默认 **O1**；升档须在报告中给出实证依据。
- **风险 = S×O**：≥6 高；3/4 中；1/2 低。FP-A10 基准：模式卡整体 S3×O3=9（高）；纯静态命中 S3×O1=3（中，暂定，实测后复评）。

### B 轴：业务影响评估（与 S×O 正交；报告层新增，不改卡片定级）

S×O 回答"多严重、多常见"，**不回答"真实业务能不能碰到"**。B 轴补这一问，只决定**修复优先级建议**，**不参与 S/O 取值、不改 S×O 档位与卡片元数据**。

**业务可达性（B）**——触发条件在真实负载中的可达程度：

| 等级 | 判据 | 证据要求 |
|---|---|---|
| B3 现实可达 | 主流框架/公开模型默认路径即可命中（如 PTA/torch_npu、vLLM、MindIE 常规调用） | 调用方或公开负载来源 |
| B2 条件可达 | 需特定 attr/dtype/shape 组合，业务中存在但非默认 | 该组合的业务来源 |
| B1 边界/不可达 | 需极端、超规格或非法参数（超出接口合理上限的 shape、退化/非法输入） | "为何不可达"的说明 |

- **默认保守**：无法证明不可达 → 记 **B3**；降为 B1/B2 必须附证据，**不得仅凭"业务应该不会这么用"**。
- 超规格参数是否算 B1 取决于**接口契约**：契约允许但业务不用 → B1；契约不允许（本应报错）→ 属校验缺失（FP-B04/B05 类），另行归属。

**业务影响类型**（命中后对用户可见结果的后果，用业务语言表述）：静默精度损失（模型效果下降 / loss 不收敛 / 偶发 NaN）｜ 任务失败中断（报错 / 崩溃 / 挂死）｜ 性能退化 ｜ 仅可观测性（日志 / 错误码 / 文档，不影响结果）。

**处置建议**（由两轴推导的报告结论，非新档位）：

| S×O \ B | B3 现实可达 | B2 条件可达 | B1 边界/不可达 |
|---|---|---|---|
| 高（≥6） | 尽快修 | 尽快修 | 排期修 |
| 中（3/4） | 尽快修 | 排期修 | 记录（业务难以触达） |
| 低（1/2） | 排期修 | 记录 | 记录 |

## 7. 判定标准与反误报原则

- **签名 / 触发词命中 ≠ 成立**：`Attr`/`GetAttrPointer` 在算子中普遍存在且多数正确——命中只是定位提示，必须给出「该 attr 的 proto 声明类型 + 解析承载类型不匹配（double 被降级/误读）」的推导链。
- **三种判定**：
  - **命中**（可静态证缺陷路径）：「double attr 未显式转换 / proto 不含 double / 静默降级 / 小值域下溢」的推导链完整 + 高精度敏感值探针可构造 → 立 Bug 卡（档级按实测证据定）；
  - **观察项**：降级链路存在但后果依赖实测、或仅测试面覆盖缺口 → 记录并附实测方案，按 S3×O1 暂定；
  - **反证排除**：attr 已含 double 类型 / 解析已显式转换 / 类型不匹配有报错 → 明确写出反证理由（防护面证据）。
- **「attr 缺省正常」不是反证**：本型只在**显式传入 double / 高精度值**时暴露，须专门构造该输入。
- **先判空再判类型**：`GetAttrPointer` 返回空指针未判空属 B04，须先排除 B04 再判本条的类型降级。
- **精度失效不静态断言「必然发生」**：静态只能立「候选点位 + 探针方案」，实测前不升级为「已确认」。
- **不臆造行号**：每条证据必须是实际读到的 文件:行号；引用实证样板时同样给出路径与行号，issue 时点行号与本仓 HEAD 漂移时注明。

### 判定纪律补充（v3.6）：非对称增减、证据等级与误判记录

**增减不对称**：允许追加候选（有据即可，错了可由用户排除）；**撤销或否决候选必须附 `[文件]:[行号] [代码行]` 负向证据**。无证据的「看起来没问题」一律记为「未核查」，不得计入反证排除，也不得据此下调等级——否决造成的漏报用户不可见、不可恢复。

- **证据等级**（Bug 卡必填）：`静态可证` = 推导链完整且触发输入可静态构造；`需实测确认` = 依赖运行时输入规模、设备行为或环境差异。标 `需实测确认` 的条目**不得以「命中」名义出卡**，按观察项记录并附实测用例。
- **Agent 误判记录**（Bug 卡必填）：本次被推翻的假设、推翻它的证据（`[文件]:[行号] [代码行]` 或实测输出）、判定标准是否随之修订；无推翻写「无」。
- **误判回流**：同类误判在 3 次检视中重复出现，登记至 `cases/misjudgments.jsonl`（字段见 `cases/README.md`），并在本模式判定标准中新增对应防线；守门 C19d 校验台账字段合法。

## 10. 能力边界与自检（v3.8）

### 能力边界

- **静态可证**：清单里能在源码内给出「`文件:行号` + 推导链」的部分，按第 7 节判据出卡。
- **需实测确认**：依赖运行时输入规模、设备行为或环境差异的结论，只能记观察项并附实测用例（证据等级见第 7 节）。
- **不覆盖**：本模式以外的机理（边界见第 0 节）与仓外框架侧行为；`TRIAGE.md` 只负责收敛候选，不构成判定依据。
- **找不到 ≠ 没有**：按清单未命中只说明「本轮未发现」，不得表述为「该算子无此缺陷」；抽样核查须在报告写明抽样口径。
