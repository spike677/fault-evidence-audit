Use the padded stride consistently in local/remote preprocessing and GMM1 offsets.

变更摘要
此 PR 主要修复了在 W4A8 量化模式下，当
k < n/2
时 GMM1 输入与 SwiGLU/GMM2 输入共享工作空间可能导致数据被意外覆盖的问题。核心思路是显式引入并传递行步幅（row stride）参数
gmmA1PreRowStride
，替代原先多处硬编码使用
problemShape.k()
或
hiddenSize
作为行偏移计算依据的做法，确保在非标准维度下内存布局计算仍然正确。
主要改动
mega_moe_a2.h
中
LayoutA
/
layoutD1
构造新增行步幅参数
: 当
isW4A8
时，
layoutA1RowStride
和
layoutA2RowStride
统一使用
RoundUp(max(k_, k2), ALIGN_128)
，避免因
k
与
k2
不一致导致的行数据重叠；
layoutD1
也同步使用
layoutA2RowStride
保证一致性。
mega_moe_kernel_a2_bf16_w4a8.hpp
新增成员
gmmA1PreRowStride
并贯穿调用链
: 在
TilingData
中新增
gmmA1PreRowStride
字段并从
layoutA.stride(0)
初始化；
FetchAndPreprocessInt8ToInt4
新增
aStride
参数替代原
hiddenSize
计算行偏移；
SendTokensV3
/
RecvTokensV3
调用以及 workspace 偏移量计算均改用
gmmA1PreRowStride
替代
problemShape.k()
。
block_epilogue_w4a8post_pertoken_swiglu.hpp
的
Run
新增
gmmDPreRowStride
参数
: 用于控制 D 张量按行切片时的实际步幅；当传入值大于 0 时优先使用，否则回退到
ChunkTileLen
，
gmTileD
索引逻辑相应调整。
