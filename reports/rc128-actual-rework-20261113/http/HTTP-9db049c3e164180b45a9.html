描述

修复 Ascend950 TopKV2 的索引处理范围和标量读取后的缓冲区复用同步。

  • 单核及多核 Radix 路径将 INT32/INT64 输出索引的 Adds 处理数量改为当前 tile 实际选出的元素数，避免按输入 tile 长度访问输出索引缓冲区。单核路径缓存该数量，供 TopK、Cast、Adds、CopyOut 及输出偏移累加统一使用。
  • 单核 Radix 的累计 tile K 循环及 CalTileK 在读取累计和后补充 S_MTE2 配对事件，保证下一次搬入覆盖同一缓冲区前，标量读取已经完成。
  • 分批 finalize 在每批返回后补充 S_V 配对事件，保护共享 flag 缓冲区的批次间复用及后续 Sort 临时区复用，同时覆盖内部早退路径。

变更摘要

本 PR 修复 Ascend950 TopKV2 算子内核中的两处正确性问题：一是多核 Radix 路径在将局部索引转换为全局索引时，AscendC::Adds 的处理长度由输入 tile 长度 nowTileSize 改为实际选出的有效索引数 validIndexCount，避免越界访问输出索引缓冲区；二是单核 Radix 累计和读取与分批 finalize 的标量读取场景补充 S_MTE2、S_V 配对事件，确保缓冲区在下一次搬入或批次复用前标量读取已完成。

主要改动

  • 索引转换范围收敛: 在 radix_sort_top_k.h 的 RadixSortTopK 中新增 validIndexCount（由 tileTopkValue_(tileTopkValueIndex) 转换得到），INT32 与 INT64 两条分支的 AscendC::Adds 均改用该值作为处理元素数，避免按 nowTileSize 访问输出索引缓冲区造成越界。
  • 单核累计 tile K 读取同步: 在 radix_sort_top_k_single_core.h 的 RadixSortTopKSingleCore 累计 tile K 循环中，标量累加后补充 S_MTE2 事件 SetFlag/WaitFlag，保证下一次搬入覆盖同一缓冲区前标量读取已完成。
  • CalTileK 双向标量读取同步: CalTileK 在读取 tileCusumLocal(boundaryBin) 与前一 bin 累计和后补充 S_MTE2 配对事件，确保两次标量读取在累计和缓冲区复用前完成。
  • 分批 finalize 标志缓冲区同步: 在 top_k_small_bitonic_packed_simt.h 的 RunBitonicSmallTopKFinalizeWithFlags 中，每批 BitonicSmallRegFinalizeSelectionFlagBatch 返回后补充 S_V 配对事件，保护共享 flag 缓冲区在批次间复用及后续 Sort 临时区复用，同时覆盖内部早退路径。
