Describe the current behavior / 问题描述

A3 上 sparse_lightning_indexer_kl_loss_grad 的 BF16 dQ 在无可见压缩 KV 的 query 行保留显存旧值，导致训练首步 grad_norm=NaN。所有浮点输入均有限；其他三个算子输出有限。无需 compile 即可复现。

已定位到 PR #11435，commit d77a4cac919f3fca9a1bb6991e48a640db01986a（SparseLightningIndexerKLLossGrad supports top-k generalization in the range of 1 to 8192）。

attention/sparse_lightning_indexer_kl_loss_grad/op_kernel/arch22/sparse_lightning_indexer_kl_loss_grad_base.h 的 ClearInvalidS1Output（当前 master 613–622 行）由无条件清零改为：

constexpr int64_t align = 32 / static_cast<int64_t>(sizeof(CLEAR_T));
if ((gmOffset % align == 0) && (n % align == 0)) {
    AscendC::InitOutput(outputGm[gmOffset], n, static_cast<CLEAR_T>(0));
} else if constexpr (IsSameType<CLEAR_T, T>::value) {
    vectorService.ZeroFp32Gm(outputGm, gmOffset, n);
}

未对齐时只有 FP32 (T) 分支；BF16 dQ 不满足类型判断，直接漏写。CalcCoreClearRange 按元素均分，不能保证每段16个BF16元素对齐。后续计算会跳过无可见KV的query，无法补写这些位置。

在本复现的18个document、54个无有效KV的query、每行64×128个BF16、40个AIV的情况下，每核clear范围为 ceil(54*8192/40)=11060 个元素。逐段模拟上述判断得到漏写 383344 个元素，与NPU实测完全一致。对应改动在检查时的master 1e878a0cdf15eba39382def8cdd599e8233c11b8 中仍存在。

Environment Information / 环境信息

  • Ascend A3，单卡即可复现；非确定性模式。
  • CANN 9.2.0 w0916。
  • Python 3.12.10；torch distribution 2.14.0+cpu；torch_npu 2.14.0.dev20260916；cann-ops-transformer 1.0.0。
  • TND；q=[4096,64,128] BF16，k=[1016,1,128] BF16，w=[4096,64] FP32；topk=512，mask_mode=3，cmp_ratio=4。
  • 使用cu_seqlens，不传seqused_q/k。

Steps to reproduce the issue / 重现步骤

以下脚本仅生成随机输入，不依赖模型、训练数据或保存的tensor。先加载上述CANN环境，再用空闲A3卡执行。预填充值用于暴露未写入的输出，reused=True 确认输出确实复用了被预填的缓冲区。

"""A3/CANN 9.2 w0916: standalone SLIG dQ allocator-sentinel regression."""
import torch
import torch_npu
import cann_ops_transformer

torch.manual_seed(42)
torch.use_deterministic_algorithms(False)
device = 'npu'
# Packed documents; each has three queries with no visible compressed key.
lengths = [390, 282, 128, 39, 270, 256, 229, 106, 45, 341, 394, 126, 419, 388, 47, 146, 263, 227]
cuq = torch.tensor([0] + lengths, dtype=torch.int32).cumsum(0).int()
cuk = torch.tensor([0] + [n // 4 for n in lengths], dtype=torch.int32).cumsum(0).int()
t, tk, h, d, topk = int(cuq[-1]), int(cuk[-1]), 64, 128, 512
q = (torch.randn(t, h, d) * 0.2).bfloat16().to(device)
k = (torch.randn(tk, 1, d) * 0.2).bfloat16().to(device)
w = (torch.randn(t, h) * 0.01).to(device)
indices = torch.full((t, 1, topk), -1, dtype=torch.int32)
teacher = torch.zeros((t, 1, topk), dtype=torch.float32)
for start, length in zip(cuq[:-1].tolist(), lengths):
    for pos in range(length):
        visible = min((pos + 1) // 4, topk)
        if visible:
            indices[start + pos, 0, :visible] = torch.arange(visible)
            teacher[start + pos, 0, :visible] = 1.0 / visible
no_key = (indices < 0).all(-1).flatten()
cuq, cuk = cuq.to(device), cuk.to(device)
residual = torch.tensor([n % 4 for n in lengths], dtype=torch.int32, device=device)
metadata = torch.ops.cann_ops_transformer.sparse_lightning_indexer_kl_loss_grad_metadata(
    h, 1, d, cu_seqlens_q=cuq, cu_seqlens_k=cuk, cmp_residual_k=residual,
    batch_size=len(lengths), max_seqlen_q=max(lengths), max_seqlen_k=max(n // 4 for n in lengths),
    topk=topk, layout_q='TND', layout_k='TND', mask_mode=3, cmp_ratio=4,
)
kwargs = dict(q=q, k=k, w=w, sparse_indices=indices.to(device),
              attn_softmax_l1_norm=teacher.to(device), cu_seqlens_q=cuq,
              cu_seqlens_k=cuk, cmp_residual_k=residual, metadata=metadata,
              layout_q='TND', layout_k='TND', mask_mode=3, cmp_ratio=4)
fn = torch.ops.cann_ops_transformer.sparse_lightning_indexer_kl_loss_grad
out = fn(**kwargs)
torch.npu.synchronize()
for fill in (float('nan'), 123.0, 0.0):
    del out
    buffers = [torch.full_like(q, fill) for _ in range(16)]
    pointers = {b.data_ptr() for b in buffers}
    torch.npu.synchronize()
    del buffers
    out = fn(**kwargs)
    torch.npu.synchronize()
    dq = out[0].cpu()
    bad = ~torch.isfinite(dq).all(-1).all(-1)
    print(dict(fill=fill, reused=out[0].data_ptr() in pointers,
               bad_rows=int(bad.sum()), bad_rows_with_valid_kv=int((bad & ~no_key).sum()),
               empty_support_nonzero=int((dq[no_key] != 0).sum())), flush=True)

Describe the expected behavior / 预期结果

无可见压缩KV的query，其indexer KL loss对应dQ应全为零，与分配器旧数据无关；所有输入有限时，不应生成NaN/Inf。建议为BF16/FP16补齐未对齐清零路径，或按对齐块划分清零范围，并保证边界完整覆盖。
