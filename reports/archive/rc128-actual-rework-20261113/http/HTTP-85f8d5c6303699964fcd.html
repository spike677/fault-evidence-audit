变更摘要

此 PR 主要聚焦于 FP8 GQA Fullquant 场景下的 stride 校验增强与 golden 测试脚本优化。在算子 Host 端新增了 CheckStrideFP8GQAFullquant 方法，对 key_antiquant_scale、key 和 value 三个张量的 stride 进行严格校验；同时大幅度改造了 golden 测试脚本，改善数据生成策略、支持外部 NPU 排布数据加载，并修复了 dequant_scale_k 在非连续场景下的提取方式。

主要改动

  • 新增 CheckStrideFP8GQAFullquant stride 校验: 在 dequant_checker.cpp 中新增方法，校验 FP8 GQA fullquant 场景下 kScaleStrides（3 维）、keyStrides（4 维）和 valueStrides（4 维）的 stride 值是否与预期的 cache block 排布一致，并在 CheckCrossFeature 中调用该方法。

  • Golden 测试数据生成策略改进: fia_fullquant_gqa_golden.py 中 query/key 数据生成从简单均匀分布改为指数幅度分布（np.power(10.0, log-uniform)），value 数据生成改为按 head 幅度缩放，以覆盖更大动态范围的测试场景。

  • Golden 测试支持外部 NPU 排布输入: 新增 load_external_data.py 模块（ExternalData 类 + load_data_from_dir 函数），可从指定目录加载 rank0 的 pt 文件作为 NPU 排布输入；golden 脚本中新增 external_to_bnsd 及配套的 _ntd_to_bnsd、_bnbd_to_bnsd 等排布转换函数，并新增 npu_fp8_full_quant_external 路径支持外部数据直接调用 NPU 算子。

  • 修复 dequant_scale_k 提取逻辑: fa_run_npu 和 npu_fp8_full_quant 中改为通过 view(torch.uint8).view(float32) 从 k cache 末尾的 scale 区域提取 dequant_scale_k，避免 .float() 调用破坏原始 stride 导致非连续校验失效。
