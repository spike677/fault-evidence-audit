# FP-A20 aclnn 接口检视（fpa20-determinism-review）

对用户指定的 aclnn 接口做 FP-A20 专项源码检视：先定位算子实现，再按清单逐项核查，每个结论给出**文件 + 行号 + 推导链**证据，产出「输出 × 路径 × shape 区间」确定性分级表；分级标注缺失即出 Bug 卡（表达型），命中的归约路径缺陷另立卡。**本模式特殊纪律：① 这是**表达型**模式——算子代码可能全对，问题在「确定性等级没分级标注」导致测试比对策略选错（假阴性：该 bitwise 的用容差，缺陷被吞；误报：非确定的做 bitwise，用例被标 flaky 后关停）；② 卡片触发为关键词（`SyncAll|AtomicAdd|ReduceSum`）——这些原语在归约类算子中普遍存在且多数正确，命中只作定位提示，判据是**归约方式是否依赖运行时参数 / 是否跨核**；③ 分级必须**逐输出**（如 dx 与 dgamma 等级不同）而非逐算子，按算子级二元标注下结论即误判；④ 确定性等级需**重复运行实测**确认（严格确定 = 重复 100 次 bitwise 全等），静态只能立「归约方式依赖运行时参数」的推导。**

## 0. 与相邻模式的边界

| 相邻模式 | 分工 |
|---|---|
| FP-A06（确定性开关下结果不固定） | 卡片关联项：A06 是**缺陷型**（确定性开关失效、结果确实不固定）；A20 是**表达型**（确定性等级描述不足、比对策略选错）——同一非确定归约点可两卡连打：开关失效归 A06，等级未分级归 A20 |
| FP-A19（同算子多 tiling 路径覆盖盲区） | 卡片关联项：多 tiling 路径是**确定性分级的载体**——A19 管「新路径没被测到」，A20 管「不同路径的确定性等级不同却没分级标注」；两卡常同源连打（big_m 路径既是覆盖盲区也是非确定路径） |
| FP-A02（归约 / 累加实现顺序与竞品不一致） | 卡片关联项：A02 管**归约顺序本身**与竞品不一致（顺序导致的差异）；A20 管**归约顺序是否依赖运行时参数**（依赖则非确定）——顺序轴 vs 确定性轴 |
| FP-C05（确定性场景性能大幅劣于非确定性） | 卡片关联项：C05 的前提正是「先分清哪些算子是确定的」——A20 的分级结论是 C05 评估的输入 |
| FP-F03（文档 / 声明面与实现面不一致） | #4890 的六算子文档声明「默认非确定」而实现默认确定性——声明面错位本身归 F03，A20 管分级标注不足（表达型），两卡连打 |
| FP-E01（golden/UT 期望值失配） | 比对策略选错（容差吞掉 bitwise 可查的缺陷）与 E01 的期望值问题同属测试有效性面——A20 定位策略分级，E01 定位期望值正确性 |

**症状反查定位**：用例长期 **flaky** 后被关停 → 非确定输出被做了 bitwise 比对（误报，表现②）；**该 bitwise 的没 bitwise**、缺陷被容差吞掉 → 严格确定的输出被容差比对（假阴性，表现①）；文档写「该算子非确定」但线上同输入两次结果不同、无法复现 → 特定 shape 才走非确定路径（表现③）；跨 tiling 路径结果差异 → 逐路径核归约方式；同一输出在不同 shape 区间确定性不同 → big_m 类路径分流（tilingKey 9000/9010）；文档声明「默认非确定」而代码 tiling 不读该开关 → 声明面错位（#4890 + F03 连打）。

## 1. FP-A20 模式卡摘要（检视依据，源自本库 `patterns/FP-A/FP-A20.md`，v3.1）

- **编号 / 名称**：FP-A20 确定性等级未分级标注（「确定 / 非确定」二元描述掩盖条件确定性）｜ **类别**：精度 ｜ **风险**：高（S2×O3=6）｜ **状态**：活跃 ｜ **来源**：rms_norm_grad 跨分支核验（2026-09-13）+ CANN issue 检索（2026-09-16）
- **适用声明头**（照抄卡片）：仓 All ｜ 侧别 Tiling,Kernel ｜ 载体 Tiling源码,Kernel源码 ｜ 触发 SyncAll|AtomicAdd|ReduceSum ｜ 默认启用 true
- **skill 核查面**：侧别 Tiling,Kernel——skill 落地为 `op_kernel` 各路径的归约实现（映射点①②③④）、`op_host` tiling 的切核维度与核数下发（映射点③④）、`*_tiling.h` 的 tilingKey 注册面（输出 × 路径映射）、`tests/` 的比对策略与 docs 的确定性声明（映射点⑤）
- **故障机理**：算子文档 / 测试结论仅以「确定性算子」「非确定性算子」二元标注，但实际存在**条件确定性**——同一算子不同 tiling 路径、不同输出（如 `dx` 与 `dgamma`）、不同 shape 区间的确定性等级不同。二元描述使测试用例的比对策略（`torch.equal` 严格比对 vs 容差比对）选错：对严格确定的输出用了容差比对 → **掩盖真实缺陷**（假阴性）；对非确定的输出用了 bitwise 比对 → **误报**。
- **触发条件**：算子含多条 tiling 路径；同一 kernel 内不同输出走不同归约实现；跨核归约与核内归约混用；测试用例的比对策略按「算子级」而非「输出级 + 路径级」设定。
- **典型表现**：① 该 bitwise 的没 bitwise，缺陷被容差吞掉；② 不该 bitwise 的做了 bitwise，长期误报致用例被标记为 flaky 后关停；③ 测试结论写「该算子非确定」但线上抱怨「同样输入两次结果不同」而无法复现，实际是特定 shape 才走非确定路径。
- **源码审查映射点**：① 逐**输出**（非逐算子）确定归约方式；② 区分「**核内归约**」（`ReduceSum<AR/RA>`、二叉树折叠、`WholeReduceSum`）与「**跨核归约**」（`SyncAll()` 后单核累加、原子加 float、workspace 二次归约）；③ 归约顺序是否依赖**运行时平台参数**（核数、`blockDim`、`vlFp32`）——依赖则非确定；④ 归约切分维度：按**输出不重叠维度**（如 N 轴列切分）切核 = 确定，按**归约维度**（M 轴行切分）切核 = 非确定。
- **检测签名**：搜索 kernel 中的 `SyncAll()` + 后续 `if (blockIdx != 0)` 单核累加模式；搜索 `ReduceSum` 的 `srcShape` 是否包含核数维度（如 `{usedCoreNum, ...}`）；搜索原子加 float 路径。
- **测试拦截建议**：按「**输出 × 路径 × shape 区间**」三级矩阵设定比对策略；严格确定用 `torch.equal`（重复 100 次全等）；数值确定用同 tiling 多次比对 + 跨 tiling 容差；非确定只能容差并**在结论中显式标注触发 shape 区间**；对判定为「确定」的输出，建议在回归中保留 bitwise 用例作看护（一旦失效即暴露实现变更）。
- **实证案例**：ops-nn `norm/rms_norm_grad`（950，2026-09-13）——**同一算子内三种等级并存**：`dx` 两条路径（`RegbaseDxFullLoad` / `RegbaseDxSplitD`）分别用 `ReduceSum<AR>` 与 `ReduceSumImpl`，均**严格确定**；常规 `dgamma` 按 N 轴列切分、核间无交叉归约，**数值确定**；`big_m` `dgamma`（tilingKey 9000/9010）用 `SyncAll()` + 0 核跨核 `ReduceSum<RA>`，且核内累加顺序随 `BasicBlockLoop` 动态变化、参与核数随 M 变化，属**非确定**。若按算子级二元标注为「确定」并对全部输出做 bitwise 比对，big_m 路径用例将误报；反之标注为「非确定」则 dx 的严格确定性看护丢失。补充实证：ops-nn **#4890**（closed）BatchNorm / BatchNormElemt / BatchNormBackward / GroupNormBackward / RmsNormGrad / RmsNormGradQuant 六算子 A5 文档声明「默认非确定、支持 aclrtCtxSetSysParamOpt 开启」，代码核查实际默认确定性且 tiling 不读取该开关——**声明面与行为面整体错位**（另收录于 FP-F03）。
- **关联**：FP-A06（A06 是「确定性开关失效」的缺陷型，本型是「确定性等级描述不足」的表达型，二者互补）、FP-A02（归约顺序差异）、FP-A19（多路径是分级的载体）、FP-C05（确定性场景性能劣化，其前提也是先分清哪些算子是确定的）。

## 2. 检视输入与算子定位

**输入**：aclnn 接口名（必填，如 `aclnnRmsNormGrad`）；可选 ref（默认 master）、指定仓（默认自动定位）；可选现象描述（flaky / 容差吞缺陷 / 两次结果不一致——用于症状反查）；可选 tilingKey / 路径清单；可选平台常量（核数、`vlFp32`——归约顺序依赖判定的关键输入）；可选测试比对脚本（现状策略核对）。

**接口名 → 算子目录换算**：去 `aclnn` 前缀 + 驼峰转下划线小写：
`aclnnRmsNormGrad → norm/rms_norm_grad`、`aclnnLayerNormGrad → layer_norm_grad`、`aclnnReduceSum → reduce_sum`。

**仓定位顺序**（GitCode `cann` 组织，逐仓用目录列表确认）：`ops-nn`（norm / loss / index 类——多路径归约高发，实证集中地）→ `ops-transformer`（attention / moe 大模板）→ `ops-math`（reduction 类）→ `ops-cv`。**类目名不总与直觉一致**（如 reduce_std_v2_update 在 `math/`），以目录列表为准。FP-A20 高发面：同目录多个 `*_tiling*.cpp`（`*_big_m_tiling.cpp` / `*_tail_tiling.cpp` 类命名）的算子、含 `SyncAll()` / 跨核 `ReduceSum` / 原子加 float 的 kernel、按归约维度切核的归约类算子、多输出算子（如 norm 系列的 dx 与 dgamma）。

**算子目录结构约定**（已验证示例 `cann/ops-nn` → `norm/rms_norm_grad/`）：

```text
{类别}/{op_name}/
├── op_host/                  # 多个 *_tiling*.cpp（多路径）+ *_tiling.h（tilingKey 注册面：输出 × 路径映射）
├── op_kernel/                # 主检视面：按路径分文件的归约实现
│   └── arch22/ arch35/       # 平台 / 代际变体（*_dgamma*.h 类按路径分文件）
├── tests/                    # 比对策略与用例（输出 × 路径 × shape 区间三级矩阵的核对输入）
└── docs/                     # 确定性声明面（与实现是否一致，F03 连打）
```

## 4. 确定性分级检视清单（每点：查什么 → 何处 → 命中判据）

对 `op_kernel` 各路径归约实现、`op_host` tiling 切核与 key 注册、`tests` 比对策略、`docs` 声明面逐点核查，**每点先查命中面、再做反证排除**，已分级标注的确定性说明也要记录为防护面证据。

### ① 逐输出归约方式枚举（映射点①）
- 查什么：对**每个输出**（非逐算子）单独判定其归约实现——同一算子不同输出可能走不同归约（`rms_norm_grad`：`dx` 与 `dgamma` 等级不同）；输出的 tiling 路径与 tilingKey 映射（`*_tiling.h` 注册面）。
- 何处：`op_kernel` 按输出分文件 / 分函数的实现、`op_host/*_tiling.h` 的 key 注册。
- 命中判据：同一算子内 ≥2 个输出的归约方式不同 ⇒ 进入分级核查；单一输出单一路径 ⇒ 简化判定但仍须核映射点 ③。

### ② 核内归约 vs 跨核归约区分（映射点②）
- 查什么：归约原语归类——**核内归约**（`ReduceSum<AR/RA>`、二叉树折叠、`WholeReduceSum`）为确定；**跨核归约**（`SyncAll()` 后单核累加、原子加 float、workspace 二次归约）为非确定。检测签名：`SyncAll()` + 后续 `if (blockIdx != 0)` 单核累加模式、`ReduceSum` 的 `srcShape` 含核数维度（如 `{usedCoreNum, ...}`）、原子加 float 路径。
- 何处：`op_kernel` 各路径的归约调用点。
- 命中判据：同一输出在两条路径下归约方式不同（一条核内、一条跨核）⇒ 分级差异命中面；全路径同为核内或同为跨核 ⇒ 记录并进入 ③。

### ③ 归约顺序对运行时参数的依赖（映射点③）
- 查什么：归约顺序是否依赖**运行时平台参数**（核数、`blockDim`、`vlFp32`）或运行时 shape（核内累加顺序随 `BasicBlockLoop` 动态变化、参与核数随 M 变化——`big_m` `dgamma` 即此）——依赖则非确定。
- 何处：归约循环的步长 / 上界表达式、tiling 下发的核数。
- 命中判据：归约顺序随运行时参数变化 ⇒ 该输出判非确定；顺序与参数无关 ⇒ 判确定（仍须 ④ 复核）。

### ④ 归约切分维度（映射点④）
- 查什么：切核维度是**输出不重叠维度**（如 N 轴列切分——确定）还是**归约维度**（如 M 轴行切分——非确定）。
- 何处：`op_host` tiling 的分核逻辑。
- 命中判据：按归约维度切核 ⇒ 非确定；按输出不重叠维度切核 ⇒ 确定。

### ⑤ 测试比对策略分级（输出 × 路径 × shape 区间）
- 查什么：比对策略是否按「**输出 × 路径 × shape 区间**」三级矩阵设定——严格确定用 `torch.equal`（重复 100 次全等）；数值确定用同 tiling 多次比对 + 跨 tiling 容差；非确定只能容差并**在结论中显式标注触发 shape 区间**；对判定为「确定」的输出保留 bitwise 用例作看护。
- 何处：`tests/` 用例与比对脚本、`docs/` 的确定性声明。
- 命中判据：按算子级二元标注设定比对策略 ⇒ 命中候选（假阴性 / 误报两面）；三级矩阵齐备且与实现分级一致 ⇒ 反证排除（记录防护面）。

### 横切面：声明面与行为面一致性（#4890 + F03 连打）
- 查什么：`docs/` 的确定性声明（如「默认非确定、支持某开关开启」）与代码实际行为是否一致——tiling 是否真的读取该确定性开关（#4890：六算子声明「默认非确定、支持 aclrtCtxSetSysParamOpt 开启」，代码实际默认确定性且 tiling 不读该开关）。
- 何处：`docs/` 精度 / 确定性说明、`op_host` tiling 中开关读取点。
- 命中判据：声明与实现错位 ⇒ 命中候选并连打 FP-F03（声明面）与 FP-A06（若开关确实失效）。

## 5. 检视流程

1. **定界**：换算 op 目录、确认所在仓与 ref；按用户现象（flaky / 容差吞缺陷 / 两次结果不一致）反查优先清单点；收集 tilingKey 清单、平台常量与现状比对脚本。
2. **枚举**：目录列表列出 `op_host`（全部 tiling + `*_tiling.h`）、`op_kernel`（含 arch 子目录与按路径分文件）、`tests`、`docs` 全部相关文件，产出文件清单与**输出 × 路径清单**。
3. **触发词扫描**：按 `SyncAll`、`AtomicAdd|SetAtomicAdd`、`ReduceSum|WholeReduceSum`、`blockIdx\s*!=\s*0`、`REGISTER_TILING_DATA_CLASS` 定位归约与 key 注册面（本地仓用 grep；API 模式逐文件拉取后检查）。**签名零命中时清单仍须逐项核查**（无显式原语的算子可整体反证排除，须写明结论）。
4. **逐点核查**：每点记录命中面与防护面证据（文件:行号）；对每个输出 × 路径写出「输出 → 路径 / tilingKey → 归约原语 → 核内 / 跨核 → 顺序依赖参数 → 切核维度 → 确定性等级」七项对表。
5. **反证排除**：全输出全路径核内归约且顺序与参数无关、切核按输出不重叠维度、比对策略已三级分级、声明面与实现一致 → 明确写出反证理由。
6. **判定**：按第 7 节标准给出 分级命中 / 观察项 / 反证排除。
7. **GitCode 查重**（仅命中项）：issues API 按接口名 + `确定|不确定|两次.*不一致|bitwise|flaky` 检索，逐条比对是否同机理；无同机理才立卡。
8. **业务可达性核查**（仅命中项）：判 B 等级、定业务影响类型、给处置建议；默认保守（无法证明不可达即记 B3），降档须附证据；B 不改 S×O 档位。
9. **出报告**：按第 8 节模板落盘；分级表为报告主体，所有确定性等级标注「静态推演，需重复运行实测确认」。

## 6. 风险定级（S×O）与业务影响评估（B 轴）

- **S**：S2（**表达型问题降档**——比对策略选错致缺陷被掩盖或误报，本身不直接产出错误结果）；S3（当被掩盖的缺陷实际存在时——假阴性的后果面，须先证明缺陷存在）；S1（仅文档标注缺失、比对策略无实际影响）。
- **O**：O3 = ≥2 条独立实证；O2 = 1 条独立实证；O1 = 仅静态扫描命中或团队笔记（实证 = 确认对应的 issue / PR，或经跨仓、跨分支核验确认的缺陷记录，同权计入）。静态推演命中且无实证默认 **O1**；升档须在报告中给出实证依据。
- **风险 = S×O**：≥6 高；3/4 中；1/2 低。FP-A20 基准：模式卡整体 **S2×O3=6（高）**；纯静态命中 S2×O1=2（低，暂定），重复运行实测后复评。

### B 轴：业务影响评估（与 S×O 正交；报告层新增，不改卡片定级）

S×O 回答"多严重、多常见"，**不回答"真实业务能不能碰到"**。B 轴补这一问，只决定**修复优先级建议**，**不参与 S/O 取值、不改 S×O 档位与卡片元数据**。

**业务可达性（B）**——触发条件在真实负载中的可达程度：

| 等级 | 判据 | 证据要求 |
|---|---|---|
| B3 现实可达 | 主流框架/公开模型默认路径即可命中（如 PTA/torch_npu、vLLM、MindIE 常规调用） | 调用方或公开负载来源 |
| B2 条件可达 | 需特定 attr/dtype/shape 组合，业务中存在但非默认 | 该组合的业务来源 |
| B1 边界/不可达 | 需极端、超规格或非法参数（超出接口合理上限的 shape、退化/非法输入） | "为何不可达"的说明 |

- **默认保守**：无法证明不可达 → 记 **B3**；降为 B1/B2 必须附证据，**不得仅凭"业务应该不会这么用"**。
- 超规格参数是否算 B1 取决于**接口契约**：契约允许但业务不用 → B1；契约不允许（本应报错）→ 属校验缺失（FP-B04/B05 类），另行归属。

**业务影响类型**（命中后对用户可见结果的后果，用业务语言表述）：静默精度损失（模型效果下降 / loss 不收敛 / 偶发 NaN）｜ 任务失败中断（报错 / 崩溃 / 挂死）｜ 性能退化 ｜ 仅可观测性（日志 / 错误码 / 文档，不影响结果）。

**处置建议**（由两轴推导的报告结论，非新档位）：

| S×O \ B | B3 现实可达 | B2 条件可达 | B1 边界/不可达 |
|---|---|---|---|
| 高（≥6） | 尽快修 | 尽快修 | 排期修 |
| 中（3/4） | 尽快修 | 排期修 | 记录（业务难以触达） |
| 低（1/2） | 排期修 | 记录 | 记录 |

## 7. 判定标准与反误报原则

- **签名 / 触发词命中 ≠ 成立**：`SyncAll` / `ReduceSum` 在归约类算子中普遍存在且多数正确——必须过「逐输出归约方式 + 顺序依赖参数 + 切核维度」三关；命中数大只说明核查工作量大。
- **三种判定**：
  - **分级命中**（表达型）：同一算子内确定性等级不同（输出级 / 路径级 / shape 区间级）而标注未分级、比对策略按算子级设定 ⇒ 立 Bug 卡（表达型，S2 起档）；若同时证明某确定输出被容差比对掩盖了真实缺陷，按 S3 定档并连打相应缺陷模式；
  - **观察项**：分级差异静态可推但需重复运行实测确认、或声明面错位待文档侧确认 ⇒ 记录并附实测方案，按 S2×O1 暂定；
  - **反证排除**：全输出全路径同等级且已分级标注、比对策略三级矩阵齐备、声明面与实现一致 → 写出防护面证据与反证理由。
- **必须逐输出、逐路径、逐 shape 区间**：按算子级二元标注下结论即误判（实证 `rms_norm_grad` 三种等级并存）；报告中分级表按「输出 × 路径 × shape 区间」三列展开。
- **「用例 flaky 所以关停」是掩盖不是处理**：非确定输出被 bitwise 比对导致的误报，正确处理是分级后改容差并标注触发 shape 区间，不是关停用例。
- **表达型 ≠ 无缺陷**：分级缺失本身即命中（表达型）；但不得据此断言「结果必然不确定」——确定性等级须实测，静态只立归约方式推导。
- **与 F03 / A06 连打纪律**：声明面错位（#4890）连打 F03；确定性开关失效连打 A06；报告中须写明分工。
- **不臆造行号**：每条证据必须是实际读到的 文件:行号；引用实证样板时注明 issue 时点行号与本地 HEAD 的漂移。
- **静态推演声明**：无 NPU 环境时，所有确定性等级结论必须标注「静态推演，需重复运行实测确认」。

### 判定纪律补充（v3.6）：非对称增减、证据等级与误判记录

**增减不对称**：允许追加候选（有据即可，错了可由用户排除）；**撤销或否决候选必须附 `[文件]:[行号] [代码行]` 负向证据**。无证据的「看起来没问题」一律记为「未核查」，不得计入反证排除，也不得据此下调等级——否决造成的漏报用户不可见、不可恢复。

- **证据等级**（Bug 卡必填）：`静态可证` = 推导链完整且触发输入可静态构造；`需实测确认` = 依赖运行时输入规模、设备行为或环境差异。标 `需实测确认` 的条目**不得以「命中」名义出卡**，按观察项记录并附实测用例。
- **Agent 误判记录**（Bug 卡必填）：本次被推翻的假设、推翻它的证据（`[文件]:[行号] [代码行]` 或实测输出）、判定标准是否随之修订；无推翻写「无」。
- **误判回流**：同类误判在 3 次检视中重复出现，登记至 `cases/misjudgments.jsonl`（字段见 `cases/README.md`），并在本模式判定标准中新增对应防线；守门 C19d 校验台账字段合法。

- **检视面提示**（引导，不预设结论，仍须逐点核查；行号以本地 HEAD 为准）：
  - 映射点①④：`rms_norm_grad_tiling.h` 的 key 注册面（Regbase 族 `RmsNormGrad_7000/7001/7010/7011`、BigM 族 `RmsNormGrad_9000/9010`、Empty 族 `RmsNormGrad_8000`）——逐 key 对应到输出的归约方式，产出「输出 × 路径 × shape 区间」分级表；

## 11. 已知缺陷案例库：触发条件 / 根因 / 修复范式 / 针对性深挖（v5.1）

> 本节把本型**已确认缺陷**拆到「触发条件 → 根因（具体路径）→ 修复范式（✅ 正确代码）→ 针对性发现步骤 → 最小复现锚」的代码级颗粒度。
> 修复范式为**正确形态示意**；路径引用取自卡片实证，行号以被检仓本地 HEAD 为准，**不得臆造**。

### 案例 1｜文档声明「默认非确定」而实现默认确定、tiling 不读开关 —— ops-nn #4890（BatchNorm / BatchNormElemt / BatchNormBackward / GroupNormBackward / RmsNormGrad / RmsNormGradQuant）

- **触发条件**：六算子 A5 文档声明「默认非确定、支持 `aclrtCtxSetSysParamOpt` 开启」；用户按声明设定比对策略或依赖该开关。
- **根因（具体路径）**：`docs/` 声明开关可开 → 代码核查实际**默认确定性**且 tiling **不读取该开关** → 声明面与行为面整体错位（另录 FP-F03）→ 比对策略按声明设定即错（该 bitwise 的以为是非确定）。
- **修复范式（✅，示意）**：

```cpp
// ❌ 声明「默认非确定」但 tiling 无开关读取点
// ✅ 二选一：实现真正读取开关；或修正文档为按输出 × 路径 × shape 区间的分级标注
```

- **针对性发现（可执行）**：① 读 `docs/` 确定性声明；② `git grep -n "aclrtCtxSetSysParamOpt\|SysParamOpt"` 核 tiling 是否有读取点；③ 逐算子重复运行实测默认确定性。
- **最小复现锚**：同输入重复 100 次比对输出 bit 是否全等，与文档声明对照。
- **实证**：#4890（closed），另收录于 FP-F03。

### 案例 2｜同一算子内三种确定性等级并存、标注未分级 —— rms_norm_grad 跨分支核验（2026-09-13）

- **触发条件**：同一算子的 `dx` 与 `dgamma` 两个输出、常规与 big_m 两条路径。
- **根因（具体路径）**：`dx` 两条路径（`RegbaseDxFullLoad` 用 `ReduceSum<AR>` / `RegbaseDxSplitD` 用 `ReduceSumImpl`）均**严格确定**；常规 `dgamma` 按 N 轴列切分、核间无交叉归约 = **数值确定**；big_m `dgamma`（tilingKey 9000/9010）= **非确定**；算子级二元标注无法承载三级差异 → 比对策略选错（表现① ②）。
- **修复范式（✅，示意）**：按「输出 × 路径 × shape 区间」三列表给出每格等级，比对策略按格设定（严格确定 = `torch.equal` 重复 100 次；数值确定 = 同 tiling 多次 + 跨 tiling 容差；非确定 = 容差 + 标注触发区间）。
- **针对性发现（可执行）**：① `git grep -n "ReduceSum\|ReduceSumImpl"` 逐输出定位归约原语；② 判核内 / 跨核；③ 比对策略落地到输出级（非算子级）。
- **最小复现锚**：分别对 `dx` 与 `dgamma` 同输入重复 100 次——`dx` 应 bitwise 全等，big_m `dgamma` 不必。
