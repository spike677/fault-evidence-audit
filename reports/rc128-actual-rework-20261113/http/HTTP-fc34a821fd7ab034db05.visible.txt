#3652 合入后 master 上 AllReduce NDA 出现精度问题，而 ReduceScatter / AllGather 正常。
根因
：
DpuAllReduceSequenceMeshNHRNDA
（sequence NDA，小数据量路径）的 4 个模板中，中间两个 inter NDA 模板的代码被
#ifndef AICPU_COMPILE
包裹：
ins_temp_reduce_scatter_mesh_1D_nda_inter.cc
：KernelRun 整段 body +
REGISTER_TEMPLATE_V2
ins_temp_all_gather_nhr_nda_inter.cc
：KernelRun body + RunNHR body +
REGISTER_TEMPLATE_V2
NDA 算法经 STARS(AICPU_TS) 在
kernel 侧
执行，上述包裹使这两个模板在
hccl_aicpu_kernel
编译单元中被剪成 no-op：step2（inter ReduceScatter NDA）与 step3（inter AllGather NDA）直接返回成功，ACK/DATA_SIGNAL/FIN_ACK 握手与 HcommWrite 数据写均不执行。由于 notify Record/Wait 对称置空不会死锁，
表现为流程正常完成但跨 rank 数据未搬运 → AllReduce 精度错误
（单独 ReduceScatter/AllGather 的 NDA 模板无该包裹，因此不受影响；板上现象与之一致：sequenceNDA 选中后仅中间两个 inter 模板无执行痕迹）。
修复
：与
SendRecvWriteForNda
原语已有的去裁剪处理保持一致，移除模板层共 5 处包裹（纯删除 10 行，无其他改动）。kernel 侧依赖（
SendRecvWriteForNda
、
LocalCopy
/
LocalReduce
、
HcommBatchMode*
、
GetAlgRank
）均已存在——ReduceScatter/AllGather 的无包裹 NDA 模板已在 kernel 侧验证使用同样依赖。
关联的Issue
NA
测试
clang-format v18.1.8 幂等校验通过（两遍格式化 diff 一致）；
git diff
仅 10 行 guard 删除，无语义/格式噪声；未新增文件，无版权头变更。
待上板验证（NDA 环境）：AllReduce NDA 精度泛化（重点 ≤4MB sequence 路径），确认
InsTempReduceScatterMesh1dNdaInter
/
InsTempAllGatherNhrNdaInter
两个 inter 模板在 kernel 侧实际执行、跨 rank 数据正常搬运；回归 ReduceScatter / AllGather NDA 及 >4MB omnipipe 路径。

RunNHR 在第 141 行只检查了 channel 存不存在、vector 空不空，第 148-149 行取出 txChannel/rxChannel 后，第 164 行就直接把 txChannel.remoteCclMem.addr 当成远端写基址塞进 tx 切片；同一个 PR 里的 ins_temp_reduce_scatter_mesh_1D_nda_inter.cc 第 89 行对同样场景是判了 link.remoteCclMem.addr == nullptr 并返回 HCCL_E_PARA 的。裁剪移除后这段代码第一次真正执行，一旦某个 NHR 对端的远端 CCL 内存没建起来，就会拿 nullptr 加偏移当远端地址去调 HcommWriteOnThread，最终只能得到一个语义不明的 HCOMM 失败码，板上定位成本很高。建议在第 149 行之后、构造切片之前补一段判空：txChannel.remoteCclMem.addr 为空时打 HCCL_ERROR（带上 step、toRank、fromRank）并返回 HCCL_E_PARA，与 ReduceScatter 模板的判空口径统一。既然本 PR 的主题就是把这条路径从死代码激活，顺手补齐这处防御比留到下一次更划算。
