变更摘要

此 PR 修复了 LightningIndexerServiceVector 中 TopK 结果无效值填充（duplicate）的缓冲区大小不足和掩码越界问题。主要将 valueOutBuf_ 和 scoreOutBuf_ 的初始化大小各增加了安全余量，同时将 ProcessTopK 函数中无效值填充的覆盖范围从 64 个元素扩展到 128 个元素，并修正了 mask 数组大小以匹配新的覆盖范围。

主要改动

  • InitBuffers 中缓冲区大小扩展：valueOutBuf_ 的初始化大小从 topkCountAlign256_ * sizeof(K_T) 改为 (topkCountAlign256_ + 128) * sizeof(K_T)，scoreOutBuf_ 从 topkCountAlign256_ * sizeof(SCORE_T) 改为 (topkCountAlign256_ + 64) * sizeof(SCORE_T)，为无效值填充提供额外空间，防止越界写入。
  • mask 数组大小修正：在 ProcessTopK 中将 uint64_t mask[1] 改为 uint64_t mask[2]，并新增 mask[1] = ~0 初始化，支持对 128 个元素范围的位掩码控制，修复了原单元素掩码数组无法覆盖完整填充区域的问题。
  • 无效值填充偏移量调整：将第二个 Duplicate 调用的起始偏移从 validS2Len / 16 * 16 + 64 改为 validS2Len / 16 * 16 + 128，对应的条件检查也同步修改，确保带掩码的 Duplicate 负责前 128 个元素的精确填充，无掩码的 Duplicate 从第 128 个元素之后批量填充。
