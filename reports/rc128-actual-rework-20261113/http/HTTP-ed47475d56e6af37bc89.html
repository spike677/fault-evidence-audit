GMM1-->[m, k] x [k, n] -> [m, n]
swiglu-->[m, n/2]
GMM1和swiglu输出（gmm2左矩阵）复用，当n/2 > k时，swiglu输出shape更大，可能会覆盖gmm1未计算的专家
如下图:

图中红色矩阵为专家1的GMM1的A矩阵, 绿色为专家2的GMM1的A矩阵, 蓝色为专家1的GMM2的A矩阵, 蓝色如果计算比较快会踩踏绿色

修改后将每个专家GMM1的A矩阵占用空间为[m, max(k, n/2)]

变更摘要

此 PR 修复了 mega_moe 在 K2 > K 场景下，GMM1 的 A 矩阵与 GMM2 的 A 矩阵因复用同一块 workspace 地址而导致的数据踩踏问题。核心改动是引入 gmm1InputExpertSlotWidth 字段，将每个专家占用的 workspace 宽度从原来的 K 改为 max(K, K2)，确保先完成的专家的 SwiGLU 输出（K2 宽度）不会覆盖后序专家尚未消费的 GMM1 输入（K 宽度），同时在 dispatch 偏移计算和 workspace 分配逻辑中统一使用该新宽度。

主要改动

  • 新增 gmm1InputExpertSlotWidth 字段：在 Params 结构体中增加 gmm1InputExpertSlotWidth 成员，其值为 max(K, K2)（即 problemShape.k() 与 problemShape.n() / 2 的较大值），用于表示每个专家在 GMM1 输入 workspace 中占用的实际槽位宽度。

  • 修改 gmGroupOffsetA 累加逻辑：将原来的 gmGroupOffsetA += inGroupProblemShape.m() * inGroupProblemShape.k() 改为 gmGroupOffsetA += inGroupProblemShape.m() * params.gmm1InputExpertSlotWidth，使得按 group 累加偏移时遵循新的非密排宽度，避免跨专家地址重叠。

  • 修正 dispatch 阶段的 A 矩阵偏移计算：在跨 rank 搬运 token 的 dispatch 逻辑中，将原来基于 layoutA.GetOffset(offsetA) 的偏移计算替换为手动计算 prevGroupSum1 * gmm1InputExpertSlotWidth + rowStartInGroup * problemShape.k()，保证专家间按槽位宽度跳转而专家内部仍按 K 密排。

  • 统一 workspace 空间分配：在 WorkspaceInfo 构造函数中，将原本内联的 max(K, K2) 计算替换为直接使用 params.gmm1InputExpertSlotWidth，使 ptrA / ptrA1Int4 等指针的起始偏移与前述逻辑保持一致，并移除了未使用的局部变量 n2。
