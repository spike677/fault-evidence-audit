# FP-B08 节点级配置未参与派发决策（属性在某一跳被丢弃：fallback 回调 / 前端插件 / fusion pass）

- **适用**：仓 canndev ｜ 侧别 Host ｜ 载体 IR与图配置 ｜ 触发 GetAttrPointer|ParseOpToGraph|fallback|AddNode ｜ 默认启用 true
- **故障机理**：**图模式**下算子经 **aclnn fallback 回调**执行时，回调实现只读取**全局配置**（如 `allow_hf32`、`precision_mode`）来决定派发/执行模式，**未读取节点携带的节点级属性**（如 `opImplMode`、`enable_hf32`、`groups`），导致节点级配置**不参与**执行模式决策。① 节点级开启了某模式而全局未开 → **节点配置被静默忽略**，走默认路径；② 反向：全局开了而节点显式关闭 → 仍按全局开执行（无节点级否决权）；③ 与「直接 aclnn 调用路径」表现不一致——**aclnn 直调正常，图模式 fallback 异常**，这是本型最典型的定位特征。根因多为回调实现按 `GetNodeType()` 分支处理时只覆盖部分算子（如仅 `MatMulV3`），或**属性按位置索引取值**（`GetAttrPointer<T>(3)`）而属性顺序变更后静默取错。**同一机理在三个不同载体上均有实证，且修复时机不同（2026-09-16 逐分支实测）**：① **fallback 回调**（#1790）—— 9.1.0 起修复；② **ONNX 插件解析函数**——新增前端属性未纳入解析透传清单（#1647）—— 9.1.0 起修复；③ **图 fusion pass**——新建节点时未把源节点属性拷到新节点（#1639）—— **9.1.0-beta.2 起修复（早于 ①②）**。三者共性是**「属性在某一跳被丢弃」**，而非读取逻辑本身错误。**注意版本矩阵不可统一按「9.1.0 前都带 bug」构造**：载体③在 `9.1.0-beta.2` / `9.1.0-beta.3` 上已修复。
- **触发条件**：**四元组同时成立**——① 走 **GE 图模式**（非 aclnn 直调）；② 该算子**经由 aclnn fallback 回调**执行；③ 节点上**设置了节点级配置属性**（且与全局配置不一致）；④ 该算子的回调分支**已被实现**但未读取该属性。**aclnn 直调路径不触发**。**载体泛化**：任一「属性需跨越一跳传递」的环节——图模式 fallback 回调、前端（ONNX/TF）插件解析、图 fusion pass 新建节点——只要该跳**未显式透传属性**，即可能触发；**前端框架版本升级新增属性**（如 ONNX13+ 引入 `noop_with_empty_axes`）是高频触发场景。
- **典型表现**：节点级配置**未生效但无任何报错**——执行模式不符合预期；**可能表现为性能下降或精度差异**（取决于配置项语义）；图模式与 aclnn 直调**结果/性能不一致**；全局配置能生效、节点级配置不生效；无 error 日志（属性读取失败时仅 `OP_LOGE` 后 `return false`，静默降级）。
- **源码审查映射点**：① fallback 回调中决定派发模式的函数（如 `GetMatmulPrecisionMode`）是否**既读全局也读节点属性**，最终判定是否为二者的**合理组合**（OR 还是 AND，是否与语义一致）；② `GetNodeType()` 分支是否**覆盖全部会走该回调的算子**（当前仅 `MatMulV3`，`BatchMatMulV3` 等同族是否遗漏）；③ **属性取值方式**——`attrs->GetAttrPointer<T>(N)` **按位置索引**取值是高危写法（属性顺序变更即静默取错），应改为按属性名获取或加索引常量与 proto 定义的一致性校验；④ 属性读取失败（`attrs == nullptr` / 指针为空）时是**静默降级 return false** 还是上报，降级是否会导致"节点配置被忽略"；⑤ 全局配置指针（如 `GetAllowHf32()` 返回 `nullptr`）是否有**空指针校验**（原实现直接 `strcmp` 会崩）；⑥ **前端插件解析函数**（如 ONNX 的 `ParseOpToGraph*`）是否把**新版本新增的属性**纳入解析与透传清单（新增属性易被漏掉，旧属性仍正常）；⑦ **fusion pass 新建/替换节点**时，是否把**源节点的全部相关属性**拷贝到新节点（漏拷属性会导致下游编译或执行期行为异常）。
- **检测签名**：`GetAttrPointer\s*<[^>]+>\s*\(\s*\d+\s*\)`（**按数字索引取属性**）；`strcmp\s*\(\s*\w*[Nn]odeType\s*,\s*"` （节点类型硬编码分支）；`strcmp\s*\(\s*\w*[Aa]llow_?[Hh]f32`；含 `_hf32|Hf32|HF32` 的布尔判定函数中**是否出现 `attrs`/`GetAttr` 调用**（若整函数无 `GetAttr`，即为「只看全局」嫌疑）；`GetAttrPointer` 失败分支为 `return false;` 且无 `OP_LOGE`；**`ParseOpToGraph[A-Za-z0-9]+` 函数内**：属性名清单与目标算子 proto 中声明的属性集做**差集扫描**（差集非空即漏透传）；**fusion pass** 中「**属性读端与写端不在同一函数**」的断链形态——若存在 `SetInt(<新节点 opDesc>, <ATTR>, <局部变量>)` 而**找不到**同名的 `GetInt(<源节点 desc>, <ATTR>, <同一变量>)`（或反向），即为嫌疑点；**变量名可作跨函数关联线索**（#1639 中读端在 `CheckConv2dTransposeDescInfo()`、写端在 `CreateRearrangeOp()`，两侧变量名均为 `attrGroups`）。⚠️ 仅扫 `AddNode`/`CreateNode` 前后若干行**会漏判**——#1639 的读、写分落两个函数且都不紧邻 `AddNode`。
- **测试拦截建议**：① **节点级 × 全局级交叉矩阵**——对每个可配节点属性构造 `{节点开, 全局关} / {节点关, 全局开} / {双开} / {双关}` 四组，**断言四组行为两两可区分**；② **图模式 vs aclnn 直调对拍**——同一 shape/dtype 分别走 GE 图（经 fallback）与 aclnn 直调，比对**执行模式（可由 profiler 的 kernel 类型/耗时反查）与数值结果**是否一致；③ 对按位置索引取属性的写法，补一条「**属性顺序变更后单测**」或静态门禁，比对 `GetAttrPointer<T>(N)` 的 N 与 proto 定义中属性声明顺序；④ 节点级配置生效性纳入**泛化用例矩阵**（不要只测全局开关）。
- **实证案例**：canndev **#1790**（closed）「MM 算子通过 GE aclnn fallback 回调执行时，HF32 属性没有正确传递到底层」——现象：MM fallback 回调**未读取 MatMulV3 节点携带的 `opImplMode` 属性**，HF32 判断仍只依赖全局 `allow_hf32`，导致**节点级 HF32 配置未参与 `cubeMathType` 的生成**；影响：GE 图模式下走 aclnn fallback 的 MatMulV3 场景中 HF32 未按节点配置生效，**可能带来性能下降或精度差异**，**直接 aclnn 调用路径不受影响**；复现：`ge 图设置 matmul 节点传入 opImplMode 为 0x40`；环境：A2/A3/A5；修复 PR **#82099**（master）+ **#82101**（`9.2.0-beta.1` 回合），改 `ops/built-in/op_fallback/fallback_common_2stages.cpp`（+44/−4）：新增 `OpImplMode` 位枚举（`ENABLE_HF32 = 0x40`）、新增 `IsMatMulV3Hf32Enabled()` 读节点 `opImplMode`、将 `GetMatmulPrecisionMode()` 由「只看全局」改为「**节点级 OR 全局**」并补 `GetAllowHf32()` 空指针防护。**同机理独立实证（2026-09-16 增补，O2→O3 依据）**：**#1647**（open）「ReduceSum 算子 Onnx 插件未正确处理 `noop_with_empty_axes` 属性」——ONNX13 之后 `reduceSum` 获取到 `noop_with_empty_axes` 属性后**没有把这个属性往下传递**，代码路径 `ops/built-in/framework/onnx_plugin/reduce_sum_plugin.cc` 函数 `ParseOpToGraphReduceSum13`；现象为属性未透传到 GE 的 OP 上（Ascend910C / CANN8.5）；**#1639**（closed）「Fix ExtendConvTranspose A16W8 group」——A16W8 量化模式下算子缺少对 `groups` 属性的正确处理：**fusion pass 未获取 conv2dtranspose 算子的 `groups` 属性**，且在**创建 rearrange 算子时未将 `groups` 正确设置到新节点**，导致 ATC 编译失败。载体路径 `ops/convolution/extend_conv_transpose/graph_plugin/fusion_pass/conv2d_transpose_fixpipe_fusion_pass.cc`（**注意在算子自有 `graph_plugin/` 下，不在 `ops/built-in/fusion_pass/`**）；修复提交 `1f65a691`（+7 行，2026-05-12，MR `!81593`），三处改动为「读 `GetInt(conv2dtransposeDesc_, GROUPS, attrGroups)` + 写 `SetInt(opDesc, GROUPS, attrGroups)` + 初始化 `attrGroups = 1`」，并引入 `InsertA16W8WeightFzTransferOp()`。**版本边界实测（2026-09-16）**：9.0.0 / 9.0.0-beta.2 / 9.1.0-beta.1 **带 bug**；**9.1.0-beta.2 起已修复**（beta.3 / 9.1.0 / 9.2.0 / master 同）。**#1647 版本边界实测**：9.0.0 / 9.0.0-beta.2 / 9.1.0-beta.1 / 9.1.0-beta.3 **带 bug**；9.1.0 / 9.2.0 / master **已修复**（修复提交 `cce77adb`，2026-06-01，MR `!81676`；⚠️ 该提交描述中关联的是 issue **#1674** 而非 #1647，两者关系待确认）。**#1771**（open，同族待查）「BatchMatMulV3 原型修改：将 attr `enable_hf32` 改为 `opImplMode`」——同族算子的**属性语义迁移**，属本型③「按位置索引取属性」的直接风险来源（原型改属性即触发顺序/语义变更）。
