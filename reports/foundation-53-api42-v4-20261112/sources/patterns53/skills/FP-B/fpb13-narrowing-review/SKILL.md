# FP-B13 aclnn 接口检视（fpb13-narrowing-review）

对指定 aclnn 接口或算子做 FP-B13 专项检视：核查 **host 侧把 int64 属性/维度塞进 int32 或让乘积在 32 位域完成**，命中即出 Bug 卡，输出报告。

## 0. 与相邻模式的边界

| 相邻模式 | 分工 |
|---|---|
| FP-B07（索引/偏移越界） | B07 错在**索引/偏移算式**（后果是越界读写）；本模式错在**参数值本身**（后果是 shape/tiling 配置错误），发生在 shape 推导阶段 |
| FP-A12（大整数转 fp32） | A12 是 int→float 的**精度**损失；本模式是整型**回绕**，不涉及浮点 |
| FP-A18（int32 边界转 float 比较） | A18 是边界值转 float 后比较语义偏差；本模式是值在整型域内已被截断 |
| FP-B11（参数契约校验缺失） | B11 看"有没有校验"，本模式看"数值承载够不够"；两者常共现，修复可一并落 |
| FP-G01（挂死） | 回绕后的巨大循环上界可能演变为挂死，属下游后果 |

## 1. FP-B13 模式卡摘要（检视依据，源自库内 `patterns/FP-B/FP-B13.md`）

- **编号 / 名称**：FP-B13 host 侧 int64→int32 窄化/乘积溢出（参数值静默改变）｜ **类别**：功能/兼容 ｜ **风险**：高（S3×O3=9）｜ **状态**：活跃
- **适用声明头**（照抄卡片）：仓 All ｜ 侧别 Host ｜ 载体 aclnn源码,Tiling源码 ｜ 触发 static_cast<int32_t> ｜ 默认启用 true
- **故障机理**：proto 里属性/维度是 **int64 语义**（`ListInt`/`ListInt64`/shape），host 实现却用 `int32_t` 承接或在 32 位域完成乘积：`static_cast<int32_t>(attr)` 无范围判断，或 `H*W`、`offsets+size`、`totalPairs` 的操作数全为 32 位。超界即回绕，**参数值被静默改写**（`2^32+1` → `1`、`2^31` → 负数），随后参与 shape 推导、约束判定与 tiling data 填充，导致参数、shape、tiling 三者不一致。
- **触发条件**：`ListInt` 属性接近或超过 `INT32_MAX`；shape 维度乘积超 int32；`int64` 偏移相加；`size_t` 在 rank-0 输入下下溢。CV 算子中这类"极大属性"多来自 fuzz/边界测试或图上常量折叠结果。
- **典型表现**：**常规输入全 PASS，只有超大值输入出错**；输出 shape 与调用方给的 `output_size` 不一致、tiling 参数被改成小值、或生成非法 shape；返回码 SUCCESS、日志无报错。特征信号：只在 `2^31`/`2^32` 附近出现，改小值后现象消失（与 B11 的"非法输入"不同，这里是**合法但极大**）。
- **实证案例**：ops-cv **#950** `Dilation2DBackpropInput` 将 `strides`/`rates`/`pads` 从 int64 转 int32，`2^32+1` 被当成 `1`；**#937** `RoiAlignV2` 超 int32 的 pooled size 窄化为错误 shape；**#995** `ImageProjectiveTransform` 极大 `output_shape` 乘积溢出后仍返回成功；**#1009** `Crop` `offsets+size` int64 溢出未防护；**#933** `NMSWithMask` rank-0 输入 `size_t` 下溢。
- **关联**：FP-B07、FP-A12、FP-A18、FP-B11、FP-G01。

## 2. 检视输入与算子定位

**输入**：aclnn 接口名或算子目录；可选 ref。
**定位**：`op_host/` 的 `*_infershape.cpp`、`*_tiling.cpp`、`op_api/aclnn_*.cpp`；属性定义在 `op_graph/*_proto.h`（看 attr 的声明类型是否 int64 语义）。

## 3. 取数方式

优先本地克隆；否则 API（`contents`/`raw`，带 `User-Agent`，重试 2 次间隔 5 秒）。行号证据绑定 commit。

## 4. 检视清单（每点：查什么 → 何处 → 命中判据）

### ① 属性窄化
- 查什么：所有 `static_cast<int32_t>(attr)`、`int32_t x = GetAttr...`。
- 命中判据：转换前无范围判断，且属性契约允许超 int32 → 命中。

### ② 维度窄化
- 查什么：shape 维度读成 `int32_t` 后参与运算。
- 命中判据：维度可超 int32（大 shape）且后续用于 shape/tiling → 命中。

### ③ 乘积溢出
- 查什么：`H*W`、`D*H*W`、`N*C*H*W`、`H*W*C*kh*kw` 等乘积的操作数类型。
- 命中判据：全为 32 位操作数且上界可达 `INT32_MAX` → 命中（即使结果赋给 int64 也没用，回绕已发生）。

### ④ 偏移相加
- 查什么：`offset + size`、`base + idx * stride` 类加法是否先提升 64 位。
- 命中判据：两操作数为 32 位且可达上界 → 命中。

### ⑤ size_t 下溢
- 查什么：`vector.size() - 1`、`rank - 1` 在空/rank-0 输入下的行为。
- 命中判据：无 `empty()` 判断即相减 → 命中。

## 5. 检视流程

1. **定界**：确认算子与 ref。
2. **枚举**：op_api / op_host（infershape + tiling）/ op_graph。
3. **扫描**：`static_cast<int32_t>`、`int32_t` 承接属性、连续乘积、`size_t` 相减。
4. **反推上界**：对每个候选按接口契约推算可达最大值（属性上限、shape 上限），判断是否越过 `INT32_MAX`。
5. **反证排除**：确认上游是否已判范围（`OP_CHECK` / `CheckShape`），或该属性是否被框架限制在小值域。
6. **判定**：命中 / 观察项 / 反证排除。
7. **GitCode 查重**。
8. **业务可达性核查**（见第 6 节 B 轴）。
9. **出报告**：运行时结论标注「静态推演，需 NPU 实测确认」。

## 6. 风险定级（S×O）与业务影响评估（B 轴）

- **S**：S4 致命（回绕后越界/挂死）、S3 结果错误（shape/tiling 被改错）、S2 功能受限、S1 资源浪费。
- **O**：O3 ≥2 条独立实证；O2 1 条；O1 仅静态。
- **风险 = S×O**：≥6 高；3/4 中；1/2 低。FP-B13 基准 S3×O3=9（高）。

### B 轴：业务影响评估（与 S×O 正交；报告层新增，不改卡片定级）

S×O 回答"多严重、多常见"，**不回答"真实业务能不能碰到"**。B 轴补这一问，只决定**修复优先级建议**，**不参与 S/O 取值、不改 S×O 档位与卡片元数据**。

**业务可达性（B）**——触发条件在真实负载中的可达程度：

| 等级 | 判据 | 证据要求 |
|---|---|---|
| B3 现实可达 | 主流框架/公开模型默认路径即可命中（如 PTA/torch_npu、vLLM、MindIE 常规调用） | 调用方或公开负载来源 |
| B2 条件可达 | 需特定 attr/dtype/shape 组合，业务中存在但非默认 | 该组合的业务来源 |
| B1 边界/不可达 | 需极端、超规格或非法参数（超出接口合理上限的 shape、退化/非法输入） | "为何不可达"的说明 |

- **默认保守**：无法证明不可达 → 记 **B3**；降为 B1/B2 必须附证据，**不得仅凭"业务应该不会这么用"**。
- 超规格参数是否算 B1 取决于**接口契约**：契约允许但业务不用 → B1；契约不允许（本应报错）→ 属校验缺失（FP-B04/B05 类），另行归属。

**业务影响类型**（命中后对用户可见结果的后果，用业务语言表述）：静默精度损失（模型效果下降 / loss 不收敛 / 偶发 NaN）｜ 任务失败中断（报错 / 崩溃 / 挂死）｜ 性能退化 ｜ 仅可观测性（日志 / 错误码 / 文档，不影响结果）。

**处置建议**（由两轴推导的报告结论，非新档位）：

| S×O \ B | B3 现实可达 | B2 条件可达 | B1 边界/不可达 |
|---|---|---|---|
| 高（≥6） | 尽快修 | 尽快修 | 排期修 |
| 中（3/4） | 尽快修 | 排期修 | 记录（业务难以触达） |
| 低（1/2） | 排期修 | 记录 | 记录 |

## 7. 判定标准与反误报原则

- **`int32_t` 声明不必然溢出**：必须反推可达上界；属性契约上限只有几百时判反证排除。
- **"结果变量是 int64"不是防护**：`int64_t x = a * b;` 若 a/b 为 int32，回绕在赋值前已发生。
- **区分业务不可达与不可达**：契约允许极大值但业务不用 → B1；契约不允许（应报错）→ 同时命中 FP-B11。
- **不臆造行号**；**静态推演声明**必写。

### 判定纪律补充（v3.6）：非对称增减、证据等级与误判记录

**增减不对称**：允许追加候选（有据即可，错了可由用户排除）；**撤销或否决候选必须附 `[文件]:[行号] [代码行]` 负向证据**。无证据的「看起来没问题」一律记为「未核查」，不得计入反证排除，也不得据此下调等级——否决造成的漏报用户不可见、不可恢复。

- **证据等级**（Bug 卡必填）：`静态可证` = 推导链完整且触发输入可静态构造；`需实测确认` = 依赖运行时输入规模、设备行为或环境差异。标 `需实测确认` 的条目**不得以「命中」名义出卡**，按观察项记录并附实测用例。
- **Agent 误判记录**（Bug 卡必填）：本次被推翻的假设、推翻它的证据（`[文件]:[行号] [代码行]` 或实测输出）、判定标准是否随之修订；无推翻写「无」。
- **误判回流**：同类误判在 3 次检视中重复出现，登记至 `cases/misjudgments.jsonl`（字段见 `cases/README.md`），并在本模式判定标准中新增对应防线；守门 C19d 校验台账字段合法。

## 9. 示例速览：aclnnDilation2DBackpropInput

- **定位**：`ops-cv` → `image/dilation2_d_backprop_input/`（Host InferShape + arch35 tiling）。
- **检视面提示**：`strides`/`rates`/`pads` 的 `ListInt` 读取处是否直接赋 `int32_t`；转换前是否判 `INT32_MAX`；转换后的值是否参与输出空间计算与约束判定。
- **实证**：ops-cv #950 中 `2^32+1` 被当成 `1`，大 stride 使 1×1 的 VALID 输出被按 3×3 接受。
- 最终判定以第 4/5/7 节为准。

## 10. 能力边界与自检（v3.8）

### 能力边界

- **静态可证**：清单里能在源码内给出「`文件:行号` + 推导链」的部分，按第 7 节判据出卡。
- **需实测确认**：依赖运行时输入规模、设备行为或环境差异的结论，只能记观察项并附实测用例（证据等级见第 7 节）。
- **不覆盖**：本模式以外的机理（边界见第 0 节）与仓外框架侧行为；`TRIAGE.md` 只负责收敛候选，不构成判定依据。
- **找不到 ≠ 没有**：按清单未命中只说明「本轮未发现」，不得表述为「该算子无此缺陷」；抽样核查须在报告写明抽样口径。

## 11. 子型对照、量化基线与探针矩阵

### 子型对照

| # | 子型 / 检查面 | 检视落点 | 命中判据 |
|---|---|---|---|
| ① | cast 无范围判断 | `static_cast<int32_t>(attr)` | 超 INT32_MAX 回绕为小值/负数 |
| ② | 32 位乘积溢出 | `H*W`、`N*C*H*W` 操作数全 32 位 | 乘积回绕后参与 shape 推导 |
| ③ | 偏移相加溢出 | `offsets + size` 未先转 int64 | 偏移变成负值或小值 |
| ④ | size_t 下溢 | rank-0 时 `size()-1` | 回绕为 SIZE_MAX |

### 量化基线（数字来自卡片实证，引用须注明来源）

- ops-cv **5 例**：#950（`2^32+1` 被当成 1，VALID 输出按 3×3 接受）、#937、#995、#1009、#933。
- 判据：**改小值后现象消失**（合法但极大的输入才触发），与 FP-B11 的「非法输入」区分。

### 探针矩阵（最小可执行集）

| 探针 | 构造 | 期望 / 判据 |
|---|---|---|
| 2^31/2^32 边界 | 属性取 INT32_MAX+1、2^32+1 | shape/配置与入参一致，无静默改写 |
| 改小值复测 | 同用例把超大值改成常规值 | 现象消失 → 佐证窄化 |
| 类型审计 | grep `static_cast<int32_t>` 与 32 位乘积链 | 乘法前提升到 int64 |
| tiling 字段 | 对照 proto 的 int64 语义与 tiling data 字段类型 | 字段类型不窄于 proto |
