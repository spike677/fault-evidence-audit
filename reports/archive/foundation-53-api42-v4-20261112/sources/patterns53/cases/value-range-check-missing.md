# 范围校验缺失：资料写了取值范围，但校验函数的形参列表里根本没有那个属性

> **这是什么**：一份「结构性校验缺失」的识别法 —— 不是边界写错、不是条件写反，而是**校验函数压根没接那个参数**。
> **谁该读**：做 FP-B11（入参契约校验）、FP-B12（空 tensor 早退）、FP-B04（判空缺失）检视的人。
> **为什么单列**：这类缺陷在动态侧表现为「非法值被静默接受并产出结果」，看起来和「实现比文档宽松」几乎一样，仅靠错误码对拍分不开；但只要看一眼校验函数的**形参列表**，就能一刀切定性。

## 一、识别法（三步，全静态可做）

1. 从资料参数表定位**该属性的取值范围**（例：`minlength` 的取值范围 `[0, 2147483647]`）；
2. 打开 `op_api/aclnn_<op>.cpp`，看 `CheckParams(...)` 的**形参列表**；
3. **形参里没有这个属性** ⇒ 不是「边界写错」，是**这条校验在实现里没有任何载体** ⇒ 结构性缺失，必成立。

```cpp
// ops-math/math/bincount/op_api/aclnn_bincount.cpp:102
static aclnnStatus CheckParams(const aclTensor* self, const aclTensor* weights, const aclTensor* out)
//                                            ^^^^^ 只有三个 tensor，没有 int64_t minlength
```

对照：同一文件的 `GetWorkspaceSize` 形参里**有** `int64_t minlength`，说明属性本身传进来了，只是校验没接。

## 二、算子为什么「看起来正常」——负值被其它运算吸收

```cpp
// :224
int64_t size = (sizes > minlength) ? sizes : minlength;   // minlength=-1 被 max 吸收 → size = sizes
// :226
if (size > MAXIMUM_SIZE) { ... return ACLNN_ERR_PARAM_INVALID; }   // 只查上界
```

⇒ 负数参与了一个 `max` 运算，结果与合法输入无差别，后续只校验上界 ⇒ **静默跑完并写出正确形状的输出**。
这类「被吸收」的写法让缺陷更难在代码评审里被发现——**它看起来像是在做范围保护**。

## 三、实测证据（2026-11-09，A2/910B3/CANN 9.2.0）

| 用例 | 唯一变化 | rc1 | rc2 | 输出 |
|---|---|---:|---:|---|
| 基线 | `minlength=0` | 0 | 0 | out 5/5 已写 |
| 对照 | `minlength=1` | 0 | 0 | out 5/5 已写 |
| **变异** | **`minlength=-1`** | **0** | **0** | **out 5/5 已写** |
| **变异** | **`minlength=-5`** | **0** | **0** | **out 5/5 已写** |
| **负对照** | `self` 改 2 维（资料明写 161002） | **161002** | -1 | — |

**负对照不可省**：同接口换一个必然非法的输入仍能拿到 161002，证明探针不是「永远读 0」。

## 四、判别红线（防止把这条打偏）

| 情形 | 判定 |
|---|---|
| 校验函数形参缺该属性 + 资料写了取值范围 + 实测 rc=(0,0) | **缺陷（P1）** |
| 校验函数**有**该属性但边界写错（`>` vs `>=`） | 缺陷（P2），属 off-by-one，不是本型 |
| 资料没写取值范围，只是实现比文档宽松 | 不是缺陷（`impl-accepts-more-than-doc`） |
| 属性是 dtype 白名单，超白名单被接受 | 不是缺陷（能力更强） |
| 参数名无 `Optional` 后缀就判必选、置空被接受 | **不可**作为判据：契约在 `CheckNotNull` 的分组条件里（存在「A 与 B 至少给一个」的写法） |

## 五、排查捷径

对某个属性报「范围未校验」前，先跑：

```bash
grep -n 'CheckParams' op_api/aclnn_<op>.cpp | head -3
# 看形参列表里有没有该属性；没有 ⇒ 结构性缺失，直接定性
grep -nE 'MAXIMUM|MAX_|LIMIT' op_api/aclnn_<op>.cpp | head
# 看是不是只做了单侧上界校验（负值方向无人管）
```
