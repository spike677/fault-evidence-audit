# FP-D02 aclnn 接口检视（fpd02-aclnn-review）

对用户指定的 aclnn 接口（如 aclnnMatmul）做 FP-D02 专项源码检视：先定位算子实现，再按三映射点清单逐项核查，每个结论给出**文件 + 行号 + 推导链**证据，命中即出 Bug 卡，输出检视报告。**本模式特殊纪律：① 判据是「相对值」不是「绝对值」——单看申请量大不构成缺陷，必须建立 aclop（旧路径）与 aclnn（新路径）的**双路径对比基线**，aclnn 侧偏高才归本条；② 优化手段高度一致（地址复用 + 删除未使用块 + 按场景裁剪申请），命中一处常预示同模板族批量命中；③ 峰值内存差异需运行时打点（`torch.npu.memory_allocated` 类）量化，静态检视只能立「缺少 lifetime 分析 / 存在未使用块」的申请面推导，不可直接表述为「必然高于 aclop」。**

## 0. 与相邻模式的边界

| 相邻模式 | 分工 |
|---|---|
| FP-D01（显存/内存过度占用） | **最易混淆项**：均指向 workspace 计算与内存复用缺失。D01 关注**绝对值超限**（迁移/图模式下申请量超出实需与容量、OOM）；本条关注**相对值**（同一算子 aclop 与 aclnn 双路径、或两个版本/模板间占用差异）——「A 卡 OOM 而 B 卡不 OOM」先按 D02 归属；无对比基线的绝对超限归 D01 |
| FP-A16（双路径对比的精度差异） | **同族对称**：同属双路径对比类——A16 比**精度**，D02 比**内存**。双路径对比基础设施可共用（同 shape/同 dtype 的 aclop vs aclnn 双跑），断言维度不同 |
| FP-A05（脏数据/数据踩踏） | **同一批「内存问题」的二分**：D02 管内存**容量**（相对占用高），A05 管内存**正确性**（脏数据） |
| FP-B07（索引/偏移越界） | 偏移算式错导致越界访问归 B07；**申请量算多**（写了大数但读写范围仍在界内）归本条 |
| FP-G01（挂死/超时） | 资源泄漏累积致内存耗尽把正常算子推向挂死/闪退（G01 成因⑤）：泄漏路径与「耗尽→挂死」后果链归 G01，**双路径容量差**归本条 |

**症状反查定位**：同一算子 aclop 与 aclnn 双路径峰值内存对比、aclnn 侧偏高 → 本条；「A5 比 A2 内存大」「新模板比旧模板占用高」→ 本条；「Workspace 占用比例大」且可列出复用/裁剪优化项 → 本条；绝对 OOM 且**无对比基线** → 先 D01；`mssanitizer` / memcheck 报错 → FP-A05 → FP-B07。

## 1. FP-D02 模式卡摘要（检视依据，源自本库 `patterns/FP-D/FP-D02.md`，v3.1）

- **编号 / 名称**：FP-D02 aclnn 内存占用高于 aclop ｜ **类别**：资源/内存 ｜ **风险**：中（S1×O3=3）｜ **状态**：活跃
- **适用声明头**（照抄卡片）：仓 All ｜ 侧别 Host ｜ 载体 aclnn源码 ｜ 触发 workspace|GetWorkspaceSize ｜ 默认启用 true
- **skill 核查面**：侧别 Host——skill 落地为 `op_api/aclnn_*.cpp` 的 `GetWorkspaceSize` 出口与 op_host tiling 的 workspace/中间 tensor 申请推导；kernel 的实际读写引用作为「未使用块」的对照面；调用侧形态问题（框架整量复制等）只记录观察项并归因调用方
- **故障机理**：workspace/中间 tensor **复用逻辑缺失**、**lifetime 分析缺失**——新模板/aclnn 路径按「每块独立、最坏情况」申请，未做生命周期重叠分析与场景化裁剪，致 aclnn 侧内存占用高于 aclop 基线。
- **触发条件**：同一算子 aclop 与 aclnn **双路径对比**；非量化/量化模板切换、dtype/场景分支切换；跨版本/跨 SoC（A2 与 A5 等）同算子对照。
- **典型表现**：aclnn 路径内存占用偏高；同 shape 同 dtype 下 A5 比 A2 内存大；Workspace 占用比例大且可列出「地址复用 / 删除未使用块 / 按场景裁剪」优化项。
- **源码审查映射点**：workspace/中间 tensor 复用逻辑、lifetime 分析。
- **测试拦截建议**：双路径峰值内存对比基线（aclop 与 aclnn 同 shape/dtype 双跑，`torch.npu.memory_allocated` 前后打点量化）。
- **实证案例**：ops-nn **#5033** aclnnMatmul 部分场景内存 **A5 比 A2 大**——非量化 cube 模板存在**无效内存占用**，用 `torch.npu.memory_allocated` 前后打点量化，期望「算子内存 A5 不比 A2 差」；ops-transformer **#3606** MegaMoe A2 **Workspace 占用比例大**，可优化项明确列出（gmm2/gmm1 复用输出地址、非量化场景不再申请 scale workspace、删除未使用的 `ptrTokenPerExpert` 块、W4A8 场景取消未使用的 GMM 切分）。**共性特征：优化手段高度一致——地址复用 + 删除未使用块 + 按场景裁剪申请；证明 aclnn/新模板路径的内存申请普遍缺少 lifetime 分析与场景化裁剪。**
- **关联**：FP-A16（同属双路径对比类：A16 比精度、D02 比内存）、FP-D01（绝对值 vs 相对值分工）。

## 2. 检视输入与检视对象定位

**输入**：aclnn 接口名（必填，如 `aclnnMatmul`）；可选 ref（默认 master）、指定仓（默认自动定位）、目标 SoC 与对照口径（A2 vs A5、量化 vs 非量化——决定对比基线与场景裁剪面）；可选**对比基线来源**（aclop 旧路径或旧版本/旧模板）与用户实测峰值内存数据。

**接口名 → 算子目录换算**：去 `aclnn` 前缀 + 驼峰转下划线小写：
`aclnnMatmul → mat_mul`、`aclnnRmsNormGrad → rms_norm_grad`、`aclnnMegaMoe → mega_moe`。

**仓定位顺序**（GitCode `cann` 组织，逐仓用目录列表确认）：`ops-nn`（matmul/norm/loss/activation 类）→ `ops-math`（math/conversion 类）→ `ops-cv`（image/vision 类）→ `ops-transformer`（attention/moe 类）。**类目名不总与直觉一致**（如 mega_moe 在 `mc2/` 而非 `moe/`），以目录列表为准。FP-D02 高发面：带多块 workspace 的 matmul/moe 类大算子、非量化 cube 模板（无效占用高发）、跨 SoC 多模板算子、含量化/非量化分支与 W4A8 等场景分支的 tiling。

**算子目录结构约定**（示例 `cann/ops-transformer` → `mc2/mega_moe/`，`cann/ops-nn` → `matmul/`）：

```text
{类别}/{op_name}/
├── op_host/
│   ├── {op}_def.cpp、{op}_tiling*.cpp/.h   # workspace/中间 tensor 申请与复用推导（主检视面）
│   ├── config/<soc>/{op}_binary.json       # 分核/模板配置——场景裁剪与 SoC 差异核对点
│   └── op_api/aclnn_{op}.cpp               # GetWorkspaceSize 出口（申请量一致性核对点）
├── op_kernel/                              # 实际读写引用——「未使用块」的对照面
├── tests/  docs/  examples/
└── CMakeLists.txt
```

## 4. 三映射点检视清单（每点：查什么 → 何处 → 命中判据）

以 op_host tiling 的 workspace/中间 tensor 推导为主，op_api 的 `GetWorkspaceSize` 出口与 kernel 实际读写引用作一致性核对。**每点先查命中面、再做反证排除**，防护面（已有的复用/裁剪）也要记录。

### ① workspace/中间 tensor 复用逻辑（地址复用）
- 查什么：非重叠生命周期的 buffer 是否共享同一 workspace 段；**输出地址能否复用为中间块**（实证 #3606：gmm2/gmm1 复用输出地址）；是否按「每块独立、最坏情况」申请而未做复用分析。
- 何处：`*_tiling*.cpp` 的 buffer 划分与 workspace 推导、op_api 的 `GetWorkspaceSize`、kernel 各 Phase 对同一 workspace 的读写时序（同一份时序既证正确性也证复用可行性）。
- 命中判据：能静态列出「生命周期不重叠 / 输出可承载中间结果」的 buffer 列表且合并无语义风险 ⇒ 命中；**边界**：复用会**破坏正确性**的场景归 FP-A05 观察项，不按本条立卡。

### ② lifetime 分析
- 查什么：每个 buffer 的生命周期区间是否重叠；是否存在全生命周期常驻但实际只在某一阶段使用的块；aclnn/新模板路径是否**根本未做** lifetime 分析（实证共性：普遍缺失）。
- 何处：tiling 推导函数、kernel Phase 边界与读写点。
- 命中判据：能写出「buffer B 仅在 Phase X 使用、其生命周期与 buffer A 不重叠」的静态推导 ⇒ 命中。

### ③ 未使用块与场景化裁剪
- 查什么：是否存在从未被 kernel 读写的申请块（实证 #3606：`ptrTokenPerExpert` 未使用块）；**非量化场景**是否仍申请 scale workspace；**W4A8 场景**是否申请未使用的 GMM 切分（#3606 明确列出）；是否按量化/非量化、dtype、shape 场景裁剪申请。
- 何处：tiling 的每个申请点 × kernel 全模板对该块的实际读写引用（对照有无）；`config/<soc>/*_binary.json` 的场景分支。
- 命中判据：某申请块在 kernel 全模板中查无读写引用，或某场景分支下申请的块在该分支不被使用 ⇒ 命中。

### ④ 双路径对比口径与峰值内存基线（判据成立的前提）
- 查什么：是否建立 aclop（旧路径）与 aclnn（新路径）**同 shape/同 dtype 的双路径峰值内存对比**；期望基线是否明确（实证 #5033：「算子内存 A5 不比 A2 差」）；量化手段是否可复现（`torch.npu.memory_allocated` 前后打点）。
- 何处：测试资产（对比用例）、tiling 的分模板申请差异（非量化 cube 模板 vs 量化模板、A2 vs A5 模板）。
- 命中判据：对比口径可复现且 aclnn 侧偏高可静态归因到具体申请块 ⇒ 命中；**无对比基线**时记观察项，归因「相对值判据未建立」（不可直接立卡）。

### ⑤ 防护面与反证（记录用）
- 查什么：已有的地址复用、场景裁剪、`min()` 截断到实需上限、buffer 生命周期合并、SoC 差异处理——作为反证依据逐条记录（文件:行号）。

## 5. 检视流程

1. **定界**：换算 op 目录、确认所在仓与 ref、目标 SoC 与对照口径（A2 vs A5 / 量化 vs 非量化）；确认对比基线来源是否提供。
2. **枚举**：目录列表列出 tiling / op_api 出口 / config / kernel 全部相关文件，产出文件清单。
3. **触发词扫描**：按 `workspace|GetWorkspaceSize|TmpSize|BufferSize|WorkspaceSize` 定位风险面（本地仓用 grep；API 模式逐文件拉取后检查）。
4. **三映射点逐项核查**：每点记录命中面与防护面证据（文件:行号）；与 kernel 实际读写引用做「未使用块」对照；对照实证样板（#3606 的四项优化项）与同族已优化算子做同族反证。
5. **反证排除**：穷尽反证再下结论——复用会破坏正确性、块确需全生命周期常驻、场景裁剪已在别处完成、对齐 padding 必需、SoC 差异属预期。
6. **判定**：按第 7 节标准给出 命中 / 观察项 / 反证排除。
7. **GitCode 查重**（仅命中项）：issues API 按接口名 + `内存|workspace|aclnn|aclop` 检索，逐条比对是否同机理；无同机理才立卡。
8. **业务可达性核查**（仅命中项）：判 B 等级、定业务影响类型、给处置建议；默认保守（无法证明不可达即记 B3），降档须附证据；B 不改 S×O 档位。
9. **出报告**：按第 8 节模板落盘；运行时结论标注「静态推演，需 NPU 双路径实测确认」，并附峰值内存对比方案。

## 6. 风险定级（S×O）与业务影响评估（B 轴）

- **S**：S1（aclnn 路径内存占用偏高但未致 OOM——资源浪费、可优化）；S2 仅当对比下 aclnn 侧确实 OOM 时升级（须实测依据）。
- **O**：O3 = ≥2 条独立实证；O2 = 1 条独立实证；O1 = 仅静态扫描命中或团队笔记（实证 = 确认对应的 issue / PR，或经跨仓、跨分支核验确认的缺陷记录，同权计入）。静态推演命中且无实证默认 **O1**；升档须在报告中给出实证依据。
- **风险 = S×O**：≥6 高；3/4 中；1/2 低。FP-D02 基准：模式卡整体 S1×O3=3（中）；纯静态命中 S1×O1=1（低）。

### B 轴：业务影响评估（与 S×O 正交；报告层新增，不改卡片定级）

S×O 回答"多严重、多常见"，**不回答"真实业务能不能碰到"**。B 轴补这一问，只决定**修复优先级建议**，**不参与 S/O 取值、不改 S×O 档位与卡片元数据**。

**业务可达性（B）**——触发条件在真实负载中的可达程度：

| 等级 | 判据 | 证据要求 |
|---|---|---|
| B3 现实可达 | 主流框架/公开模型默认路径即可命中（如 PTA/torch_npu、vLLM、MindIE 常规调用） | 调用方或公开负载来源 |
| B2 条件可达 | 需特定 attr/dtype/shape 组合，业务中存在但非默认 | 该组合的业务来源 |
| B1 边界/不可达 | 需极端、超规格或非法参数（超出接口合理上限的 shape、退化/非法输入） | "为何不可达"的说明 |

- **默认保守**：无法证明不可达 → 记 **B3**；降为 B1/B2 必须附证据，**不得仅凭"业务应该不会这么用"**。
- 超规格参数是否算 B1 取决于**接口契约**：契约允许但业务不用 → B1；契约不允许（本应报错）→ 属校验缺失（FP-B04/B05 类），另行归属。

**业务影响类型**（命中后对用户可见结果的后果，用业务语言表述）：静默精度损失（模型效果下降 / loss 不收敛 / 偶发 NaN）｜ 任务失败中断（报错 / 崩溃 / 挂死）｜ 性能退化 ｜ 仅可观测性（日志 / 错误码 / 文档，不影响结果）。

**处置建议**（由两轴推导的报告结论，非新档位）：

| S×O \ B | B3 现实可达 | B2 条件可达 | B1 边界/不可达 |
|---|---|---|---|
| 高（≥6） | 尽快修 | 尽快修 | 排期修 |
| 中（3/4） | 尽快修 | 排期修 | 记录（业务难以触达） |
| 低（1/2） | 排期修 | 记录 | 记录 |

## 7. 判定标准与反误报原则

- **签名 / 触发词命中 ≠ 成立**：`workspace` 命中是定位提示，必须过「双路径对比口径 + 申请面推导链 + 反证排除」三关；**无对比基线不立卡**。
- **「大」不必然浪费**：须证某块**无语义必要**才立卡——确因流水/对齐/正确性需要的申请属反证排除（对照 #3606 的反面教材：可复用却独立申请、未使用却申请）。
- **三种判定**：
  - **命中**（可静态证缺陷路径）：「生命周期不重叠却未复用」「kernel 全模板查无读写引用的申请块」「场景分支下未使用的申请」任一推导链完整 + 触发场景可静态指认 → 立 Bug 卡；
  - **观察项**：需 NPU 双路径实测才能量化、或复用与否取决于运行时流水行为 → 记录并附对比方案，按 S1×O1 暂定；
  - **反证排除**：对齐必需 / 块确需常驻 / 场景裁剪已在别处 / 复用会破坏正确性 → 明确写出反证理由（防护面证据）。
- **可达性分析要给出可复现反例**：具体 shape / dtype / SoC / 场景（量化与否、W4A8）组合写具体值，不写「大 shape」泛称。
- **不臆造行号**：每条证据必须是实际读到的 文件:行号；引用实证样板时同样给出路径与行号，issue 时点行号与本仓 HEAD 漂移时注明。
- **静态推演声明**：无 NPU 环境时，所有运行时行为结论必须标注「静态推演，需 NPU 双路径实测确认」，并附实测建议（`torch.npu.memory_allocated` 前后打点、同 shape/dtype 双跑）。

### 判定纪律补充（v3.6）：非对称增减、证据等级与误判记录

**增减不对称**：允许追加候选（有据即可，错了可由用户排除）；**撤销或否决候选必须附 `[文件]:[行号] [代码行]` 负向证据**。无证据的「看起来没问题」一律记为「未核查」，不得计入反证排除，也不得据此下调等级——否决造成的漏报用户不可见、不可恢复。

- **证据等级**（Bug 卡必填）：`静态可证` = 推导链完整且触发输入可静态构造；`需实测确认` = 依赖运行时输入规模、设备行为或环境差异。标 `需实测确认` 的条目**不得以「命中」名义出卡**，按观察项记录并附实测用例。
- **Agent 误判记录**（Bug 卡必填）：本次被推翻的假设、推翻它的证据（`[文件]:[行号] [代码行]` 或实测输出）、判定标准是否随之修订；无推翻写「无」。
- **误判回流**：同类误判在 3 次检视中重复出现，登记至 `cases/misjudgments.jsonl`（字段见 `cases/README.md`），并在本模式判定标准中新增对应防线；守门 C19d 校验台账字段合法。
