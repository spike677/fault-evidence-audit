PR功能描述 / 为什么需要这个合入:

npu._npu_dropout 没有 seed 入参、内部使用 RNG，不是确定性算子。但 torch._functorch.compile_utils.fx_graph_cse 只跳过 rand_ops 名单中的算子：aten.native_dropout 在名单内，npu._npu_dropout 不在。

当 torch._inductor.config.fallback_random=True 时，native_dropout 会下沉为 npu._npu_dropout。训练路径会经过 AOTAutograd min-cut 分区并调用 fx_graph_cse，此时两个结构完全相同的 dropout 调用会被合并成一个，导致：

  • 两次 dropout 共用同一 mask/output，随机性丢失、分支强相关；
  • RNG 只消费一次，后续随机序列错位。

本 PR 在 torch_npu 侧把 NPU 随机 dropout 系列算子补充进 rand_ops，让 CSE 不再合并它们。

def _patch_cse_rand_ops():
    import torch as _torch
    from torch._functorch import compile_utils as _compile_utils
    for _name in ("_npu_dropout", "npu_dropout_gen_mask",
                  "npu_dropout_do_mask", "npu_dropout_with_add_softmax"):
        _op = getattr(_torch.ops.npu, _name, None)
        if _op is not None and _op not in _compile_utils.rand_ops:
            _compile_utils.rand_ops.append(_op)

复现与验证:

  • 复现条件：fallback_random=True + 训练，模型内两个相同的 F.dropout(x, 0.5, training=True)。
  • 打补丁前：torch.equal(a, b) == True（两个 dropout 被 CSE 合并）。
  • 打补丁后：torch.equal(a, b) == False（两次独立采样）。
  • 后端覆盖：npu-triton 与 npu-ascendc 均验证通过；纯推理路径和 fallback_random=False 默认路径行为不变。
  • 说明：验证时需关闭 Inductor/AOT 磁盘缓存（torch._inductor.config.fx_graph_cache=False + 新的 TORCHINDUCTOR_CACHE_DIR），否则会复用打补丁前的编译图导致误判。

变更摘要

本 PR 针对 torch_npu/_inductor/__init__.py 中 Inductor 初始化流程的补充：新增 _patch_cse_rand_ops 函数并在模块加载时立即调用，将 NPU 侧非确定性的随机 dropout 系列算子注册进 torch._functorch.compile_utils.rand_ops。原因是 npu._npu_dropout 无 seed 入参、依赖内部 RNG，却未被 fx_graph_cse 的随机算子名单覆盖；在 fallback_random=True 的训练路径中，结构相同的两次 dropout 会被 CSE 合并为一次，导致 mask 共用、随机性丢失及后续 RNG 序列错位。该改动使 CSE 跳过这些算子，恢复独立采样。

主要改动

  • 新增 _patch_cse_rand_ops 补丁函数: 在 torch_npu/_inductor/__init__.py 中导入 torch._functorch.compile_utils，向 rand_ops 追加 NPU 随机算子，从源头阻止 CSE 合并。
  • 扩充随机算子名单: 依次处理 _npu_dropout、npu_dropout_gen_mask、npu_dropout_do_mask、npu_dropout_with_add_softmax 四个 torch.ops.npu 算子，覆盖 NPU dropout 及掩码生成/应用等关联形态。
  • 注册的幂等与兼容处理: 通过 getattr 判断算子是否存在，并检查 _op not in _compile_utils.rand_ops 后才追加，避免算子缺失报错与重复注册。
  • 模块导入时自动生效: 在 npu_patch_meta()、_dynamo_register_interface_for_device()、register_device_op_overrides_npu() 之后直接调用 _patch_cse_rand_ops()，使补丁先于 _apply_common_patches() 的 triton/mlir 后端补丁执行。
