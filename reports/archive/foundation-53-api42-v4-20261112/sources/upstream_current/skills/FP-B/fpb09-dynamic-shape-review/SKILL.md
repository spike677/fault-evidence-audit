# FP-B09 算子检视（fpb09-dynamic-shape-review）

对用户指定算子（如 ProdVirialSeA）做 FP-B09 专项源码检视：定位 infershape / verifier / tiling 入口，按清单逐项核查，每个结论给出**文件 + 行号 + 推导链**证据，命中即出 Bug 卡并输出报告。**本模式特殊纪律：① 判定对象是「动态 shape 哨兵值」——`-1` = `UNKNOWN_SHAPE`（维数已知、某维长度未知）、`-2` = `UNKNOWN_RANK`（连维数都未知）；校验代码把哨兵值当普通维度参与运算即命中；② 报错信息与真实原因**完全不符**（「维度不为 1」「维数不为 2」「shape 不合法」），而输入本就是合法动态 shape——排查先确认输入是否带动态标签，勿被报错引向输入数据；③ 修复范式是「**校验前先判动态标签，命中则跳过维数/取值/一致性校验并让输出相应置 -1**」，而非给静态校验打补丁——检视以此为对齐基准；④ 静态 shape 输入不触发，静态用例全绿不是安全证据；动态行为须动态编译/GEIR 双通路实跑，静态只能立候选点位。**

## 0. 与相邻模式的边界

| 相邻模式 | 分工 |
|---|---|
| FP-B01（支持面校验过严误拦截合法输入） | **最易混淆项**：B01 是「校验过严误拦截**合法静态输入**」，本条是「校验未识别**动态标签**」——二者同属「校验面与输入面不一致」，但 B01 的输入是合法静态值、本条是合法动态哨兵值，**排查时须先确认输入到底是不是动态** |
| FP-B02（tiling 未适配多种芯片核数） | 同属「编译期前置校验/适配考虑不全」：本条是**维数未知**未适配、B02 是**核数档位**未适配——先分清是动态标签还是型号/核数差异 |
| FP-B07（索引/偏移计算错误致越界） | 本条形态② 也是越界，但**根因是动态 shape 下维度数不确定**（`GetDims()` 短向量）而非偏移算错，且发生时点在 host 校验期而非 kernel 期 |
| FP-A19（同算子多路径覆盖盲区） | **高发诱因同源**：动静双通路只测静态即得盲区；A19 是 tiling 多路径只测其一，本条是 infershape/verifier 未覆盖动态通路 |
| FP-F03（文档/声明面与实现面不一致） | 算子若声明支持动态 shape 而校验不接受，即两型复合——声明面归 F03，校验未识别标签归本条 |
| FP-E01（golden/UT 期望值失配） | 本条需靠「断言不报错」拦截，**只比精度的 UT 天然漏检**此类（根本没跑到比较步） |

**症状反查定位**：infershape / verifier 阶段直接报错、编译期中断（「维度不为 1」「维数不为 2」「shape 不合法」）→ 首查该输入 shape 校验前是否有动态标签前置门；`{-2}`（UNKNOWN_RANK）场景**崩溃**而非有序报错 → `GetDims()` 返回 size=1 却按下标 `inputShape[1]`（越界读）；`GetShapeRange()` 取值不完整 → 取 range 前未 `MakeUpRange`；**动态编译能跑、GEIR 报错**（或反向）→ 动静双通路不一致；新上库/刚同步配置算子出错 → 校验骨架照抄静态版；infershape 1.0 与 2.0 双实现行为不同 → 双套一致性缺陷。**关键识别特征：错误发生在图编译/推导阶段，且报错指向的「非法输入」实际合法。**

## 1. FP-B09 模式卡摘要（检视依据，源自本库 `patterns/FP-B/FP-B09.md`，v3.1）

- **编号 / 名称**：FP-B09 动态 shape 标签未参与校验决策（`-2`/`-1` 被当真实维度） ｜ **类别**：功能/兼容 ｜ **风险**：高（S2×O3=6）｜ **状态**：活跃
- **适用声明头**（照抄卡片）：仓 All ｜ 侧别 Host ｜ 载体 IR与图配置 ｜ 触发 UNKNOWN_RANK|UNKNOWN_SHAPE|GetShapeRange|GetDims ｜ 默认启用 true
- **skill 核查面**：与卡片载体一致——canndev 仓内算子的 infershape（1.0/2.0 双套）/ verifier / tiling 入口的 shape 校验与推导代码；延伸至 proto 与文档声明（动态 shape 支持面，作「输入合法」依据）
- **故障机理**：GE 动态 shape 以**哨兵值**表达未知——`-1` = `UNKNOWN_SHAPE`（维数已知、某维长度未知）、`-2` = `UNKNOWN_RANK`（连维数都未知）。**校验/推导代码（infershape、verifier、tiling 入口）把哨兵值当普通维度直接参与运算**，于是合法动态 input 被判非法。三种成因：① **哨兵当实数用**——`-2`/`-1` 参与「维度必须为 N」「各维必须相等」「维度数必须为 N」判断必假，**infershape 直接失败**；② **短向量按下标访存**——`GetDims()` 对 `{-2}` 返回 **size=1** 向量，代码按静态假设访问 `inputShape[1]`/`inputShape[2]`，**越界读致崩溃**；③ **取 shape range 前未 `MakeUpRange`**——`GetShapeRange()` 返回「补全后」上下界，未先 `MakeUpRange` 即取值会拿错误区间，后续校验基于错误前提。**共同修复范式**：**校验前先判动态标签，命中则跳过维数/取值/一致性校验并让输出相应置 `-1`**（#1786、#1787 修复方案即此），而非给静态校验打补丁。
- **触发条件**：**任一动态 shape 输入**——① 输入 tensor 带 `-2`（UNKNOWN_RANK）或 `-1`（UNKNOWN_SHAPE）标签；② 该输入的校验/推导路径**未在入口前置动态标签判断**；③ 算子为**新上库/刚同步配置**（#1673「新增 AdaptiveAvgPool2dGrad，同步修改 cann 仓原有配置」即此类，易照抄静态校验骨架）。**静态 shape 输入不触发**，故静态用例全绿也测不出；**动态编译能过而静态编译失败**（或反向）是典型旁证。
- **典型表现**：**infershape / verifier 阶段直接报错、编译期中断**（非运行期结果错）——报错形如「维度不为 1」「维数不为 2」「shape 不合法」，**与真实原因（输入本为合法动态 shape）完全不符**，最易把排查引向输入数据；`{-2}` 场景可能**崩溃**而非有序报错；同一算子**动态编译能跑、GEIR 报错**（#1786）；**精度无从谈起**，与「跑起来但精度不对」的 FP-A 族本质不同。**关键识别特征：错误发生在图编译/推导阶段，且报错指向的「非法输入」实际合法。**
- **源码审查映射点**：① 每个 shape 校验分支前**是否先判动态标签**——`GetShapeSize()`/`GetDimNum()`/`GetDims()` 结果参与判断前有无 `IsUnknownShape()`/`IsUnknownRank()`/比对 `-1`/`-2` 的前置门；② **`GetDims()` 是否先查 size 再下标访存**——`GetDims()[i]`/`inputShape[i]` 是否先校验 `size > i`（`{-2}` 只返回 size=1，`[1]` 即越界，**崩溃**直接成因）；③ **`GetShapeRange()` 前是否 `MakeUpRange`**（#1766 明确点名，并给出可对照的 YUV4442YUV422）；④ **输出 shape 是否随之置 `-1`**（#1786 修复要求「输出 shape 相应设为 -1」）；⑤ **新上库算子校验骨架是否为静态版复制**——review 需专确认动态分支；⑥ **infershape 1.0 与 2.0 双套一致性**——是否存在「1.0 有缺陷而 2.0 正常」或反之（#1804 直接**屏蔽 infershape1.0 改用子仓 infershape2.0** 规避，#1673 亦点名 infershape1.0），两套需**同输入同断言**对照。
- **检测签名**：`GetShapeSize\(\)|GetDimNum\(\)` 与 `-1|-2|UNKNOWN_SHAPE|UNKNOWN_RANK` 比较前无 `IsUnknown` 前置判断；`GetDims\(\)\s*\[`（`GetDims()` 结果直接下标访问，高危）；`inputShape\s*\[\s*[1-9]`（假定维数 ≥2 的硬下标）；`(GetDim\w*|GetShape\w*|GetStorageDim\w*)\s*\([^)]*\)\s*(==|!=)\s*-(1|2)\b`（维度语境哨兵值直连比较——`GetDims()`/`GetShapeSize()` 等维度查询接口返回值直接与 `-1`/`-2` 比较，需人判是动态标签前置门还是哨兵当实数误用）；`GetShapeRange\(\)` 调用点前 200 行内无 `MakeUpRange`（`MakeUpRange` 为修复态特征、不作存在型签名，索引侧以缺失型规则 absence 承载：infershape 文件含 `GetShapeRange` 调用而无 `MakeUpRange` 即候选，文件级粗筛）；同一算子目录内 `_infershape_2\.0|InferShape2|infershape1\.0` 双实现并存。
- **测试拦截建议**：① **每算子必配动态 shape 最小集**——`{-2}`（UNKNOWN_RANK）、`{-1}`、`{-1,-1,-1}`、`{-1,-1,-1,-1}` 四组，**断言不报错而非只断言精度**（缺陷是「跑不起来」，只比精度的用例走不到比较步）；② **动态用例进泛化矩阵与门禁**——新算子/新配置合入时动态与静态用例**同等必过**，不可标可选；③ **动静一致性对拍**——同语义输入分别走静态与动态编译，**两者都应成功且结果一致**；④ 对 `GetDims()` 下标访问加**静态门禁**（要求前置 size 校验）；⑤ **专项覆盖新上库算子**——按 #1673 模式，新增算子因照抄静态骨架而高发，review checklist 须含动态分支项。
- **实证案例**：canndev 仓 6 条**同机理独立实证**（3 closed / 3 open，2026-05-30 ~ 2026-08-10，覆盖 6 个不同算子）：**#1673**（closed，AdaptiveAvgPool2dGrad）「动态 shape 为 `-2` 时 **infershape1.0 把 `-2` 当真实维度参与校验致报错**」，复现「复跑带 `-2` 标签用例即可」，环境 Ascend950 / CANN9.1.0，期望「无校验报错且精度 100%」——**形态① 哨兵当实数用的教科书案例**；**#1770**（open，SparseSegmentSumGrad）「动态 shape 下第二、三个输入为 `-2` 会**判断维度不为 1，导致 infershape 失败**」——形态①，「维度必须为 1」硬校验的高发；**#1766**（closed，RGB2YUV422）「inferShape 未考虑 UnknownRank，**`GetShapeRange` 前没有 `MakeUpRange`**，应参考 YUV4442YUV422」，复现「跑 `(-2)` 和 `(-1,-1,-1)` 必现」，环境 Ascend950 / CANN9.1.0——**形态③ 的唯一实证，附可对照的正确实现**；**#1786**（open，ProdVirialSeA）「GEIR 通路跑动态 shape 用例（`-2`/`-1`）报错：`ProdVirialSeAVerify` 和 `ProdVirialSeAInferShape` **硬校验输入维度必须为 2**，动态下 `GetDims()` 返回 `{-2}`/`{-1}`，**size 不为 2 直接报错**」，修复范式「**对每个输入的 shape 校验前先判动态 shape**：动态时跳过维度与值校验、nframes 设 -1、输出 shape 设为 -1；静态保持原逻辑」——**形态① 完整闭环，含官方修复范式**；**#1787**（open，Yolo）「修复 `YoloVerify` 动态 shape 校验失败：**完全未知 `(-2,)`：`GetDims()` 返回 size=1，`inputShape[1]` 越界崩溃**；部分未知 `(-1,-1,-1,-1)`：channelNum=-1，channel 一致性校验失败」，修复「size==1 跳过维度校验、channelNum 设 -1；channelNum==-1 跳过 channel 一致性校验」——**形态② 越界崩溃的唯一实证，兼形态① 叠加**；**#1804**（open，SparseApplyAdagradV2）「**屏蔽 infershape1.0，使用子仓 infershape2.0**」，UT 以 `{-2}`/`{-1,-1}` 组合构造（`var({-2},{-2})`/`accum({-1,-1},{-1,-1})`/`lr({-2},{-2})`），期望输出 `{{-2},{-2}}`——**揭示「infershape 1.0 与 2.0 双套实现」结构性诱因，「屏蔽旧版」本身即回避缺陷的旁证**。
- **关联**：FP-B01（**最易混淆项**）、FP-B02（维数未知 vs 核数档位）、FP-B07（形态② 亦越界，根因是动态 shape 下维度数不确定）、FP-A19（多路径盲区，高发诱因同源）、FP-F03（声明面与实现面不一致）、FP-E01（golden/UT 期望失配——须靠「断言不报错」拦截，只比精度的 UT 漏检）。

## 2. 检视输入与算子定位

**输入**：算子名（必填，如 `ProdVirialSeA`、`Yolo`、`AdaptiveAvgPool2dGrad`）；可选 ref（默认 master）；可选现象描述（infershape 报错原文 / 崩溃 / 动态编译能跑而 GEIR 报错——用于症状反查）；可选 infershape 版本线索（1.0 / 2.0 双套——决定优先核对哪套）。

**算子名 → 实现定位**：本型目标仓为 **canndev**，实现散落在算子目录的 infershape / verifier / tiling 与 proto 中：

```text
cann/canndev/ops/{域}/{op_name}/
├── op_graph/                 # *_infershape.cpp / *_infershape_2.0.cpp（或 InferShape2 实现）——形态①②③④ 主检视面
│                             # *_proto.h（属性/输入声明，动态 shape 支持面依据）
├── （verifier 实现）          # *Verify 函数（如 ProdVirialSeAVerify / YoloVerify）——硬校验维度数的高发点
├── （tiling 入口）            # tiling 的 shape 校验前置段——形态① 的延伸面
└── （tests/UT）               # 动态 shape 用例（{-2} / {-1,-1,...} 组合）的覆盖证据
```

**定位顺序**：先按症状锁定实现面——报「维数不为 2 / 维度不为 1」→ 查 `*Verify` 与 `*InferShape` 的维度硬校验；崩溃 → 查 `GetDims()` 下标访问；range 相关 → 查 `GetShapeRange()` 调用点与 `MakeUpRange`。再确认**双套实现**（infershape 1.0 与 2.0）是否并存——并存时两套都要核。

## 4. 动态 shape 检视清单（每点：查什么 → 何处 → 命中判据）

对算子的 infershape（双套）/ verifier / tiling 入口逐点核查，**每点先查命中面、再做反证排除**，已有的动态前置门与 `MakeUpRange` 也要记录（防护面证据）。

### ① 校验分支前的动态标签前置门（形态①：哨兵当实数用）
- 查什么：每个 shape 校验分支前**是否先判动态标签**——`GetShapeSize()` / `GetDimNum()` / `GetDims()` 结果参与「维度必须为 N」「各维必须相等」「维度数必须为 N」等判断前，是否有 `IsUnknownShape()` / `IsUnknownRank()` / 直接比对 `-1`/`-2` 的前置门；`-2`/`-1` 参与算术与相等判断必然为假。
- 何处：`*_infershape*.cpp` / `*Verify` / tiling 入口的全部维度校验分支。
- 命中判据：存在「哨兵值参与维数/取值/一致性判断且无前置门」的路径 ⇒ 命中（实证样板 #1673 / #1770 / #1786）。

### ② `GetDims()` 短向量下标访存（形态②：越界崩溃）
- 查什么：`GetDims()` 返回值是否**先查 size 再按下标访存**——`GetDims()[i]`、`inputShape[i]` 等下标访问是否先校验 `size > i`；`{-2}`（UNKNOWN_RANK）只返回 size=1，`[1]` 即越界读致崩溃。
- 何处：全部 `GetDims()[...]` / `inputShape[...]` 下标访问点。
- 命中判据：存在未校验 size 的下标访问且索引 ≥ 1（或索引可能 ≥ size）⇒ 命中（实证样板 #1787 `inputShape[1]` 越界崩溃）。

### ③ `GetShapeRange()` 前是否 `MakeUpRange`（形态③）
- 查什么：取 shape range / 连续区间 / 对齐推导前是否先 `MakeUpRange`——未补全即取值会拿到不完整/错误区间，后续校验基于错误前提（#1766 明确点名，并给出可对照的正确实现 YUV4442YUV422）。
- 何处：`GetShapeRange()` 调用点及其上游（检测签名：调用点前 200 行内无 `MakeUpRange`）。
- 命中判据：`GetShapeRange()` 使用点上游无 `MakeUpRange` ⇒ 命中（给出「调用点 → 缺失的 MakeUpRange」链，并与对照实现比对）。

### ④ 动态分支下输出 shape 是否置 `-1`（形态④）
- 查什么：动态分支跳过校验后，**输出 shape 是否相应置 `-1`**——输出仍按静态推导会给下游埋错（#1786 修复要求「输出 shape 相应设为 -1」，#1804 期望输出 `{{-2},{-2}}`）。
- 何处：infershape 的输出 shape 设置段。
- 命中判据：动态分支下输出按静态值推导（未置 `-1`）⇒ 命中（下游影响需对拍确证）。

### ⑤ 新上库算子的校验骨架来源（形态⑤）
- 查什么：新增算子 / 新增配置项的校验骨架是否为**静态版复制**（#1673：新增 AdaptiveAvgPool2dGrad 同步修改 cann 仓原有配置即此类）；review 是否含动态分支项。
- 何处：新增算子的 infershape / verifier 实现；算子合入清单。
- 命中判据：新增算子校验骨架无动态前置门 ⇒ 命中（按 #1673 模式，新增算子高发）。

### ⑥ infershape 1.0 与 2.0 双套一致性（形态⑥）
- 查什么：同一算子目录内是否存在 `_infershape_2.0` / `InferShape2` / `infershape1.0` 双实现；两套对**同输入同断言**是否一致（#1804 直接屏蔽 infershape1.0 改用子仓 infershape2.0 规避，#1673 亦点名 infershape1.0）——「屏蔽旧版」本身即回避缺陷的旁证。
- 何处：同目录 infershape 双实现文件。
- 命中判据：双实现并存且动态行为不一致（或某套被屏蔽/绕过）⇒ 命中（给出两套对同一 `{-2}` 输入的行为差）。

## 5. 检视流程

1. **定界**：确定算子与其 infershape/verifier 位置、确认 ref 与目标仓 `canndev`；按报错原文反查优先形态（维数报错 → ①；崩溃 → ②；range → ③）；确认有无双套实现。
2. **枚举**：目录列表 + 文件名检索列出 infershape（双套）/ verifier / tiling / proto / tests 文件清单。
3. **触发词扫描**：按 `GetDims\(\)\s*\[`、`inputShape\s*\[\s*[1-9]`、`GetShapeSize\(\)|GetDimNum\(\)` 与 `-1|-2|UNKNOWN_SHAPE|UNKNOWN_RANK` 同现、`GetShapeRange\(\)`、`_infershape_2\.0|InferShape2|infershape1\.0` 定位风险面（本地 grep；API 模式逐文件拉取后查）。
4. **清单逐项核查**：按第 4 节 ①~⑥ 逐点记录命中面与防护面证据（文件:行号）；对 ⑥ 做**双套同输入对照**。
5. **反证排除**：校验分支有动态前置门、`GetDims()` 下标前查 size、`GetShapeRange()` 前有 `MakeUpRange`、动态分支输出置 `-1`、新增算子含动态分支、双套一致 → 写出反证理由（防护面证据）。
6. **判定**：按第 7 节给 命中 / 观察项 / 反证排除。
7. **GitCode 查重**（仅命中项）：issues API 按算子名 + `动态shape|UNKNOWN_RANK|UNKNOWN_SHAPE|-2|infershape|MakeUpRange` 检索，逐条比对同机理；无同机理才立卡。
8. **业务可达性核查**（仅命中项）：判 B 等级、定影响类型、给处置建议；默认保守（无法证明不可达即 B3），降档附证据；B 不改 S×O。
9. **出报告**：按第 8 节模板落盘；静态结论一律附**动态 shape 最小集 + 动静一致性对拍**方案（断言不报错，非只比精度）。

## 6. 风险定级（S×O）与业务影响评估（B 轴）

- **S**：S2（infershape / verifier 报错致编译期中断——功能不可用、不崩溃不损数据；本型基准档）；S3（形态② `GetDims()` 短向量下标越界致**崩溃**——可静态证崩溃路径按 S3 起步，须给依据）；S1（动态分支输出未置 `-1` 等下游一致性面）。
- **O**：O3 = ≥2 条独立实证；O2 = 1 条；O1 = 仅静态扫描命中或团队笔记（实证 = 确认对应 issue/PR，或经跨仓、跨分支核验确认的缺陷记录，同权计入）。静态推演无实证默认 **O1**；升档须给实证依据。
- **风险 = S×O**：≥6 高；3/4 中；1/2 低。FP-B09 基准：模式卡整体 S2×O3=6（高）；纯静态命中 S2×O1=2（低，暂定，动态复现后复评；形态② 可静态证崩溃按 S3×O1=3 中）。

### B 轴：业务影响评估（与 S×O 正交；报告层新增，不改卡片定级）

S×O 回答"多严重、多常见"，**不回答"真实业务能不能碰到"**。B 轴补这一问，只决定**修复优先级建议**，**不参与 S/O 取值、不改 S×O 档位与卡片元数据**。

**业务可达性（B）**——触发条件在真实负载中的可达程度：

| 等级 | 判据 | 证据要求 |
|---|---|---|
| B3 现实可达 | 主流框架/公开模型默认路径即可命中（如 PTA/torch_npu、vLLM、MindIE 常规调用） | 调用方或公开负载来源 |
| B2 条件可达 | 需特定 attr/dtype/shape 组合，业务中存在但非默认 | 该组合的业务来源 |
| B1 边界/不可达 | 需极端、超规格或非法参数（超出接口合理上限的 shape、退化/非法输入） | "为何不可达"的说明 |

- **默认保守**：无法证明不可达 → 记 **B3**；降为 B1/B2 必须附证据，**不得仅凭"业务应该不会这么用"**。
- 超规格参数是否算 B1 取决于**接口契约**：契约允许但业务不用 → B1；契约不允许（本应报错）→ 属校验缺失（FP-B04/B05 类），另行归属。

**业务影响类型**（命中后对用户可见结果的后果，用业务语言表述）：静默精度损失（模型效果下降 / loss 不收敛 / 偶发 NaN）｜ 任务失败中断（报错 / 崩溃 / 挂死）｜ 性能退化 ｜ 仅可观测性（日志 / 错误码 / 文档，不影响结果）。

**处置建议**（由两轴推导的报告结论，非新档位）：

| S×O \ B | B3 现实可达 | B2 条件可达 | B1 边界/不可达 |
|---|---|---|---|
| 高（≥6） | 尽快修 | 尽快修 | 排期修 |
| 中（3/4） | 尽快修 | 排期修 | 记录（业务难以触达） |
| 低（1/2） | 排期修 | 记录 | 记录 |

## 7. 判定标准与反误报原则

- **哨兵比较签名命中 ≠ 成立**：`== -1`/`!= -2` 可能是**正确动态判断**也可能是误用，须人工确认是「识别动态标签」还是「把哨兵当实数」。`GetDims()[...]` 命中须证明索引可能 ≥ 向量 size（`{-2}` 场景 size=1）。
- **三种判定**：
  - **命中**（可静态证缺陷路径）：「哨兵参与维数/取值判断无前置门」「`GetDims()` 短向量下标越界」「`GetShapeRange()` 前无 `MakeUpRange`」「动态分支输出未置 `-1`」「双套不一致」的完整推导链 → 立 Bug 卡；
  - **观察项**：崩溃后果需动态用例确证、双套不一致但旧套已屏蔽、新增算子动态分支缺项 → 记录并附动态用例方案；
  - **反证排除**：校验前有动态前置门、下标前查 size、`MakeUpRange` 在位、输出置 `-1`、双套一致 → 写出防护面证据。
- **先确认输入是否动态**：与 FP-B01 的最易混淆点——报错输入若**不带** `-2`/`-1` 标签则不是本型（转 B01）；判定前必须确认输入面。
- **静态用例全绿不是反证**：静态输入不触发本型，只比精度的 UT 天然漏检；须以**动态 shape 最小集**（`{-2}`/`{-1}`/`{-1,-1,-1}`/`{-1,-1,-1,-1}`）断言「不报错」。
- **修复范式须对齐**：正确修复是「校验前判动态标签 → 跳过维数/取值/一致性校验 → 输出置 `-1`」，非给静态校验打补丁；检视建议须按此范式给出。
- **不臆造行号**：每条证据须实际读到的 文件:行号；引用实证样板（#1673 / #1766 / #1770 / #1786 / #1787 / #1804）须给出本仓位置，行号漂移时注明基准版本。

### 判定纪律补充（v3.6）：非对称增减、证据等级与误判记录

**增减不对称**：允许追加候选（有据即可，错了可由用户排除）；**撤销或否决候选必须附 `[文件]:[行号] [代码行]` 负向证据**。无证据的「看起来没问题」一律记为「未核查」，不得计入反证排除，也不得据此下调等级——否决造成的漏报用户不可见、不可恢复。

- **证据等级**（Bug 卡必填）：`静态可证` = 推导链完整且触发输入可静态构造；`需实测确认` = 依赖运行时输入规模、设备行为或环境差异。标 `需实测确认` 的条目**不得以「命中」名义出卡**，按观察项记录并附实测用例。
- **Agent 误判记录**（Bug 卡必填）：本次被推翻的假设、推翻它的证据（`[文件]:[行号] [代码行]` 或实测输出）、判定标准是否随之修订；无推翻写「无」。
- **误判回流**：同类误判在 3 次检视中重复出现，登记至 `cases/misjudgments.jsonl`（字段见 `cases/README.md`），并在本模式判定标准中新增对应防线；守门 C19d 校验台账字段合法。

## 11. 已知缺陷案例库：触发条件 / 根因 / 修复范式 / 针对性深挖（v5.1）

> 本节把本型**已确认缺陷**拆到代码级颗粒度（触发 → 根因/路径 → 修复范式 ✅ → 发现 → 复现锚）。修复范式为**示意**，路径取自卡片实证，**不臆造行号**。

### 案例 1｜infershape1.0 把 -2 当真实维度 —— #1673（AdaptiveAvgPool2dGrad）

- **触发**：输入 `-2`（UNKNOWN_RANK）。
- **根因**：infershape1.0 将 `-2` 当真实维度参与「维度必须为 N」→ 必假 → 报错（形态①）。
- **修复范式（✅，示意）**：校验前判 `IsUnknownRank/IsUnknownShape` → 跳过维数/取值校验，输出置 `-1`。
- **发现**：校验分支前是否有 `IsUnknownShape()/IsUnknownRank()` 前置门；新算子骨架是否静态版复制。
- **复现锚**：`-2` 用例断言「无校验报错」。
- **实证**：#1673（closed）。

### 案例 2｜GetShapeRange 前未 MakeUpRange —— #1766（RGB2YUV422）

- **触发**：UnknownRank；`(-2)` 与 `(-1,-1,-1)` 必现。
- **根因**：inferShape 未考虑 UnknownRank，且 `GetShapeRange()` 前无 `MakeUpRange` → 区间不完整（形态③，可对照 YUV4442YUV422）。
- **修复范式（✅，示意）**：

```cpp
// ❌ auto range = input.GetShapeRange();
// ✅ input.MakeUpRange(); auto range = input.GetShapeRange();
```

- **发现**：`GetShapeRange()` 前 200 行无 `MakeUpRange` 即缺失型；对照 YUV4442YUV422。
- **复现锚**：`(-2)`/`(-1,-1,-1)` 必现。
- **实证**：#1766（closed）。

### 案例 3｜硬校验维数必须为 2（含官方修复范式）—— #1786（ProdVirialSeA）
