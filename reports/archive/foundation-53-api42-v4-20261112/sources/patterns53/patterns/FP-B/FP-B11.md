- **元数据**：类别 功能/兼容 ｜ 风险 高（S3×O3=9）｜ 状态 活跃 ｜ 来源 ops-cv 全量 issue 语料（2026-10-17，1 250 条中 232 条 bug-report，本簇 **52 条**，受理 32 条）+ ops-math#2820 前后段不对称实证（v6.1）
- **适用**：仓 All ｜ 侧别 Host ｜ 载体 aclnn源码,Tiling源码 ｜ 触发 InferShape|CheckShape|GetDimNum|IsFinite|GetAttrPointer ｜ 默认启用 true
- **故障机理**：第一段接口（`aclnnXxxGetWorkspaceSize`）与图模式 `InferShape` 的校验只覆盖"**形状之间的一致性**"（如 `grid[4]==3`、`inputC==gradOutputC`），不覆盖"**单个参数自身的合法性**"——rank 是否为契约值、`ListInt` 长度是否足/是否超、维度是否为正、属性是否落在 int32 可表达范围、`scale`/`sigma` 是否有限、dtype 组合是否被支持。五种子形态：① **未校验**（25/52）——完全没有对应检查；② **放行**（24/52）——有检查但条件写反或范围写宽（如只判 `< 0` 不判 `== 0`）；③ **校验对象选错**（3/52）——检查函数读了错误的张量（`CheckUplimit` 五个维度全取自 `gradOut`，`inputSize`/`gradInput` 从未参与）。**④ 前后段不对称**（v6.1 显式化）：同一契约在 op_api、InferShape、tiling 三处各写一遍且**不同步**，出现"InferShape 放行、tiling 拒绝"或反之。**⑥ 标量属性值域未校验**（v6.27）：前三类子型全部落在**张量**上——shape/rank/dtype/连续化。但 `aclnn` 签名里还有一类形参是**值传递标量**（`double eps` / `float scale` / `int64_t dim` / `bool keepdim`），它们同样来自调用方，同样能造出非法输入（`eps < 0` → 输出整块 NaN、`dim` 越界、`scale` 为 NaN），却常常**连一次比较都没有**。2026-11-06 实测 `aclnnLayerNorm` 的 `CheckParamsWithImplMode`只查 dtype / shape / meanOut/rstdOut 的 shape，**完全不看 `eps` 的值域**，`eps=-1` 一路进 kernel 后输出 100% NaN。同批扫描（`ops-nn` 408 个 `aclnn_*.cpp` / 480 个接口 / 501 个标量形参）：**336 个（67.1%）标量形参在所在文件里找不到任何比较**，其中 `eps`/`epsilon` 类 **31 个**。该子型的判据特征是**只看张量不看标量**——`CheckShape` / `CheckInputDtype` 写了一长串，但没有一行 `eps >= 0`。**⑤ 参数有限性未校验**（v6.13）：用 `<= std::numeric_limits<float>::min()`（即 `FLT_MIN`）代替 `> 0` 判正值——最小正正规数被误拒，而 **NaN / ±Inf 与任何值比较恒假**，直接绕过校验进入 kernel；或用 `if (scale > 0)` 分支承载合法性判断，非有限值落入"未提供"回退路径被静默接受。该子型的判据特征是**比较表达式对 NaN 恒为 false**，只做范围上下界检查而不调用 `isfinite` 即命中。 **⑦ 错误码族选错（v6.33）**：校验确实命中并返回了非 0，但把「参数非法」映射成**内部错误码**（`ACLNN_ERR_INNER_NULLPTR` / `561103`、`561002`、`361001`），而资料错误码表要求 `161001`/`161002`；调用方按返回码分类时会把参数错误当内部故障。判据：同一接口的其它非法分支返回正确族、唯独该分支返回内部码。 **⑧ 校验顺序倒置（v6.33）**：`GetOptionalInputShape()` / `->` 解引用排在能排除该状态的校验之前，执行到解引用时守卫尚未运行。 **⑨ 平台分支复用超集白名单（v6.41）**：按 `IsRegbase()` / SoC 分支裁剪校验时，非 RegBase 分支（A2/A3/310P）直接复用了 RegBase（950）的 dtype 白名单，而资料在 `npu="..."` 分段里把该产品的支持集收得更窄；结果是「白名单包含、该 SoC 实际不支持」的 dtype 在第一段被放行，掉到执行段才以 561000/561002 失败。判据：同一 dtype 在资料的分产品段里写着「仅支持 X」，而代码白名单是跨产品并集且分支内无 SoC 判断。 **⑩ API dtype 白名单超出算子原型/kernel 注册面（v6.44）**：`op_api/aclnn_*.cpp` 的首段校验白名单包含某 dtype（如 `DT_DOUBLE`），但 `op_host/*_def.cpp` 的 `DataType` 列表与 `AICore().AddConfig` 从未注册该 dtype / 该 SoC，于是非法组合在第一段被放行、执行段掉进 `AiCpu` 回退并以设备异常（实测 `507018` `ACL_ERROR_RT_AICPU_EXCEPTION`）失败。与 ⑨ 的分界：⑨ 是**平台分支之间**复用超集，⑩ 是 **API 层白名单与算子原型注册面**之间不一致；判据是「API 支持列表 − def.cpp 注册集」非空且资料把该 dtype 写成支持。**⑩ 的前置排除（v6.47）**：判本子型前必须先排除 **AICPU 回退**——若 `op_api/<op>.cpp` 中存在该 dtype 的 `*AiCpu` 分支（如 `AddcdivAiCpu`），且交付包 `opp/built-in/op_impl/host_aicpu/libcpu_kernels.so` 中已注册该算子名，则 `def.cpp` 只注册 AICore 配置属**正常结构**（AICPU 内核另包交付），不构成缺陷。2026-11-07 实测：ops-math#4612/#4613/#4614/#4615 与 ops-nn#8384 五单均因漏做该排除而误判，已全部撤回（详见「实证案例」v6.47）。
- **触发条件**：rank 与契约不符（rank-0 当 rank-1、ND 当 4-D）；`ListInt` 属性长度不足（如只传 1 个 `scales`）或超长（`output_size` 传 3 个）；维度 ≤ 0（零 batch、负 `pooled_h`）；属性超 int32（大 `stride`/`rate`/`pad`）；`scale`/`sigma` 为 NaN/Inf；dtype 组合不在支持矩阵内（`img` 与 `lut_table` 不一致）；可选输入与主输入的 batch/空间尺寸交叉不匹配；资料 `npu="..."` 分段把某产品的 dtype 支持集收窄，而代码白名单是跨产品并集（B11-9）；API dtype 白名单含某 dtype，而 `op_host/*_def.cpp` 的 `DataType` 未注册该 dtype 或 `AddConfig` 未覆盖该 SoC（B11-10）。
- **典型表现**：**第一段接口返回 `ACLNN_SUCCESS`，到 tiling 才以 561002（`ACLNN_ERR_INNER_TILING_ERROR`）失败**，真实原因（参数非法）被内部错误码掩盖；或非法 shape 被发布给下游（`ResizeNearestNeighborV2` 接受零输出尺寸并生成非法 shape）；或 tiling 越界读取属性数组（`output_size` 长度不足时读两元素/读短 `input_size`）；或直接 coredump（`aclnnUpsampleNearest3d` 空 `outputSize` 数组）。对照组特征：同一输入在 PyTorch 侧报 `RuntimeError`，而在 NPU 侧"通过第一段、挂在第二段"。
- **源码审查映射点**：`op_api/aclnn_*.cpp` 的 `CheckShape`/`CheckParams` 是否在"一致性校验"之外包含 **rank / 长度 / 值域 / 有限性** 四类检查；**且这四类必须对「值传递标量形参」也做一遍**（B11-6）——签名里的 `double eps` / `float scale` / `int64_t dim` 不是张量，不会被 `CheckShape` 覆盖；逐个标量形参在**整个文件**内检索 `<name> <值>` 形态的比较，零命中即候选（注意：只搜 `CheckParams` 函数体会漏掉委托给 helper 的写法，实测 `aclnnAddRmsNorm` 的 `epsilon >= 0.0` 在 `:198` 而 `CheckParams` 早已返回）；`op_host/*_infershape.cpp` 与 `op_host/**/*_tiling.cpp` 对同一输入的接受集合是否**完全相同**（不一致本身即缺陷）；检查函数实参是否与形参语义对应（`CheckUplimit` 类误用）；`GetOriginFormat` 与 `GetFormat` 是否在 format 校验中混用（图优化后 format 变化导致误判）；`docs/aclnn*.md` 的"约束说明"逐条与代码校验点比对，文档写了但代码没做即命中。
