Background（背景信息）

broadcast 模板 tilingData 单一结构 576B，小 shape 算子调用密集场景下，序列化 + H2D 搬运开销在单次 launch 时延中占比过高，且无法摊薄。

Origin（信息来源）

Ascend 950PR broadcast 消费算子 launch 开销剖析。

Benefit / Necessity （价值/作用）

NDDMA 路径 tilingData 缩至 184B（单 cacheline 内），主机侧序列化 + H2D 搬运 -68%，小 shape launch 密集场景直接受益。

Design（设计方案）

1. NDDMA 路径 small/large 双轨 tiling 结构（新增 schMode 3，advance）

  • 新增 BroadcastNddmaAdvanceTilingData（184B）：标量计数器 int64 保总量语义，dims/strides 降 uint32，裁剪 NDDMA 路径不消费的 Brc dims 字段
  • host 侧 CheckTilingDataFitSmall 四项门控（shapeLen≤5、坍缩后全维 dim/stride≤UINT32_MAX、乘积计数 int64 无溢出、coreNum≤255 设备防御），超限回退 large，行为与 master 等价
  • 布局小于单 cacheline（256B），主机侧序列化 + H2D 搬运开销随字节数等比下降
  • 调度器复用 BroadcastNddmaSch（TilingDataT 模板参数化），保持 TPipe 形态，master 的 large 路径不受影响

2. one_dim（schMode 201）去 TPipe 静态编址

  • BroadcastOneDimSch 改为静态 LocalTensor 编址（TPosition + 槽位偏移直构），移除 TPipe/TBuf/tensorPool 依赖
  • 该调度器不继承 BroadcastBaseSch、广播原语为自研 Vec::Duplicate，不经过官方 Broadcast gather 路径（PopStackBuffer/g_tpipeImpl 系统块），去 TPipe 无依赖残留
  • 同步语义逐 token 保持 master（Kirin 3003/3113 三段式 SetFlag/WaitFlag 事件链原样保留）

3. utils 数组参数 D 模板化

  • BroadcastGetAxesIndices/BroadcastGetGmOffset/BroadcastNddma* 函数族数组参数元素类型参数化：advance 直接读 tiling 区 uint32 数组，无需 kernel 侧扩宽副本；master 的 int64 实例化保持不变

不改动的部分

  • NDDMA（1/2）、UB BRC（101-109）、非连续族（301-305）保持 master 的 TPipe/TQue/TBuf 调度实现，零改动
  • 202（one_dim advance）为 master 原生无 TPipe 形态，保持原样

详见关联 PR。
