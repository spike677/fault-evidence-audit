# workflows：任务级编排

> `skills/` 回答「**一条模式怎么查**」，`workflows/` 回答「**一类任务按什么顺序查、查完怎么合并**」。
> 单个 skill 是检视手册，workflow 是体检套餐——它决定先跑谁、后跑谁、哪些结果要合并、什么时候停。
>
> 路由：先按任务选 workflow，再按 workflow 的阶段取 skill；**不要在 51 个 skill 里凭感觉挑**。

| 任务 | workflow | 典型输入 | 产出 |
|---|---|---|---|
| 新算子 / 新接口准入 | [operator-admission](operator-admission.md) | 仓 + 算子目录 / aclnn 接口名 | 准入体检报告（命中 / 观察 / 反证 / 跳过） |
| 只有现象、要定位根因 | [symptom-triage](symptom-triage.md) | 现象描述（卡死 / 超差 / 报错…） | 定位报告（收敛到 1~2 条模式） |
| 跨仓迁移 / 重构 / 分支合并 | [migration-audit](migration-audit.md) | 迁移 diff 或提交区间 | 迁移风险清单（防御丢失 / 透传 / 交付面） |
| 单跑通过、批跑/复跑失败；新进程首调才暴露 | [stability-soak](stability-soak.md) | 算子/ kernel 文件 + 现象口径（通过率、轮换、内存曲线） | 累积型/间歇性缺陷挖掘报告（机理定性 + 探针矩阵 + 回挂 FP-G02） |
| **已有一处锚点，要查「它的兄弟实现有没有同款病」** | [sibling-diff](sibling-diff.md) | 一处已知缺陷/可疑点 + 仓与 ref | 兄弟对拍矩阵（七对齐面 × N 对）、有意差异 vs 候选缺陷、单变量对照用例 |

> **sibling-diff 的定位**：其他三个 workflow 是「按范围查」，它按**差异**查——同一逻辑的多条实现路径之间，缺陷会成组出现。适用面最窄（必须先有锚点）但**杠杆最高**，而且是库自我生长的入口（反复出现却无卡可挂的差异类型，应回去加子型）。

## 通用纪律（四个 workflow 都适用）

1. **先筛适用面**：每条模式先核「适用」声明（仓 / 侧别 / 载体），不匹配的写进跳过清单并给理由——跳过不是沉默。
2. **证据分级**：`静态可证` 才能出卡；`需实测确认` 只记观察项并附实测用例（见各 skill 第 7 节）。
3. **去重按位置，不按模式**：同一 `文件:行号` 被多个模式命中时合并为一条，标注主模式 + 关联模式；**禁止按模式 ID 合并**（会掩盖多机理叠加）。
4. **抽样要声明**：按各模式 `depth` 执行（深度=全量 / 标准=每点前 20 处 / 宽浅=签名 + 每类 3 例），报告写「全量」或「抽样 + 口径」。
5. **停止条件**：同一映射点连续 20 处命中均反证排除 → 停止该点并记录；候选模式 ≥2 条但都只有弱证据 → 输出「未定界」而不是硬选一条。
6. **报告头**：仓 / ref / HEAD、任务类型、workflow 名、阶段完成情况、判定统计、证据等级分布。
