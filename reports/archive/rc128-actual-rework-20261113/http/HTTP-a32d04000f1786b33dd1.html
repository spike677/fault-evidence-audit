描述

1、变更概述

CSV 校验器会把 NaN/Inf 清零后比较，导致 [NaN] 对 [0]、[+Inf] 对 [-Inf] 等错误输出最终通过。修复在清零前检查 ordinary dtype 输出的非有限值模式，失败时设置 Result=fail 和包含输出下标的 ActualError，由现有结果汇总稳定判为失败。

Fixes https://atomgit.com/cann/ascend-transformer-boost/issues/509

2、变更类型

Bug 修复。

3、修改内容

仅修改 tests/framework/python/CsvOpsTestTool/atb_csv_ops_test.py，增加私有静态检查方法及比较入口保护，并按仓库 Ruff 规则对新增赋值换行。NaN mask、Inf mask、Inf 符号必须一致；匹配的特殊值继续沿用原有处理。FP8/HiFloat8 专用路径保留。

校验入口直接记录失败，避免旧标准将一次 0 精度与大量成功执行平均后重新判为通过。已有 CsvOpsResult.add_result/compute_result 负责累计失败，不新增 CSV 列或改变有限值阈值。

变更摘要

本 PR 修复 tests/framework/python/CsvOpsTestTool/atb_csv_ops_test.py 中 CSV 精度校验器对非有限值不匹配的误通过问题：原逻辑在比较前将 NaN/Inf 清零，导致 [NaN] 与 [0]、[+Inf] 与 [-Inf] 等错误输出仍被判为通过。改动新增私有静态方法 __nonfinite_patterns_match，在 precision_performance_analysis 比较入口清零前先校验 NaN 位置、Inf 位置与 Inf 符号是否完全一致；不一致时直接写入 Result=fail 与包含输出下标的 ActualError 并返回，由既有 CsvOpsResult.add_result/compute_result 汇总稳定判为失败。FP8/HiFloat8 等专用低精度分支保持原有处理。

主要改动

  • 新增非有限值模式一致性检查: 新增静态方法 __nonfinite_patterns_match，通过 torch.isnan、torch.isinf 及对 Inf 元素取值的比较，要求实际输出与 golden 输出的 NaN mask、Inf mask 和 Inf 符号三者全部一致。
  • 比较入口增加前置保护: 在 precision_performance_analysis 的逐输出循环中，于精度标准分支之前调用上述检查，不再依赖清零后的数值比较。
  • 校验失败直接标记并短路返回: 不匹配时写入 Result=fail 与 ActualError（含 output index），并立即 return，避免单次失败被后续大量成功执行平均后重新判为通过。
  • 保留低精度与既有阈值逻辑: 通过 dtype 判断排除 torch.float8_e5m2、torch.float8_e4m3fn、torch.bits8，FP8/HiFloat8 专用路径及原有有限值误差阈值、CSV 列结构均不变。
