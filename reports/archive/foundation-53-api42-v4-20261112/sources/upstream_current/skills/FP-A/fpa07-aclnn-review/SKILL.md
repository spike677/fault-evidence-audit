# FP-A07 aclnn 接口检视（fpa07-aclnn-review）

对用户指定的 aclnn 接口（如 aclnnMhcPost）做 FP-A07 专项 tiling 源码检视：先定位算子实现，再按清单逐项核查，每个结论给出**文件 + 行号 + 推导链**证据，命中即出 Bug 卡，输出检视报告。**本模式特殊纪律：① 静态命中纪律——四仓 issue 中本型多以「精度失败」表征而非直述「走错分支」，卡片仅收录边界逻辑写错本身被明确定位的两条实证；静态命中默认观察项，立卡须给出**边界反例推导**（某 shape 取值下表达式走入错误分支的代数验算）；② 卡片触发为关键词（`Tiling|IsCapable`）——命中只是定位提示，边界算符与尾块表达式必须逐个验算，不可按命中数下结论；③ 构建期分支判断写错（CMake 逻辑）与精度型 tiling 分支错误同族但落在构建期，清单单独设点。**

## 0. 与相邻模式的边界

| 相邻模式 | 分工 |
|---|---|
| FP-A19（多 tiling 路径覆盖盲区） | **最易混淆项**：A19 关注**测不到**（新路径 0 覆盖）；A07 关注**判错**（条件表达式本身写错）。阈值边界写错 = A07 的一种——盲区路径里的边界错误更难发现，核 A19 时同步验算 A07 |
| FP-A08（切块粒度致归约分组不同） | A08 是**粒度参数正确**但归约分组边界带来数值后果；A07 是**条件表达式写错**走入错误分支——先验表达式、再看粒度后果 |
| FP-B02（阈值依赖平台参数跨平台不一致） | B02 是**参数来源**问题（同一逻辑、不同平台常量导致行为差）；A07 是**逻辑本身**写错（算符方向 / off-by-one / 奇异值路径） |
| FP-C01 子型②（调度层膨胀） | C01 子型② 是循环「**多算但结果对**」（耗时变长）；A07 是「**走错分支结果错**」——精度全对只有耗时问题归 C01 |
| FP-B09（动态 shape 标签未参与校验） | B09 是 `-1/-2` **哨兵被当实数**（语义识别缺失）；A07 是边界算符 / 奇异值推导错误——哨兵识别正常但比较写错归 A07 |
| FP-G01（挂死） | 边界写错若致循环上界回绕 → G01 子型③（不返回）；正常返回但值错 → A07 |

**症状反查定位**：特定 shape 精度失败（其余 shape 全过）→ 首查该 shape 命中的分支边界；网络 loss 不收敛且输入含奇异维度 → 奇异 shape 推导路径；shape 取阈值 ±1 时结果跳变 → `IsCapable` / 分流表达式；构建期分支（编译产物异常、某平台产物缺失）→ CMake 逻辑判断。

## 1. FP-A07 模式卡摘要（检视依据，源自本库 `patterns/FP-A/FP-A07.md`，v3.1）

- **编号 / 名称**：FP-A07 tiling 条件判断错误走入错误分支 ｜ **类别**：精度 ｜ **风险**：高（S3×O3=9）｜ **状态**：活跃
- **适用声明头**（照抄卡片）：仓 All ｜ 侧别 Tiling ｜ 载体 Tiling源码 ｜ 触发 Tiling|IsCapable ｜ 默认启用 true
- **skill 核查面**：侧别 Tiling——skill 落地为 `op_host` 的 `*_tiling*.cpp`（含 arch22 / arch35 平台分支目录）中的分流条件、`IsCapable` 阈值表达式、尾块 / 分配计算；延伸至构建期的 `CMakeLists.txt` 分支判断（实证 #862 变体）
- **故障机理**：tiling 分支边界条件（`<` 与 `<=`、off-by-one、shape 奇异值）写错，进入错误处理路径。
- **触发条件**：奇异 shape（0/1、极小/极大、非对齐）。
- **典型表现**：网络 loss 不收敛、特定 shape 精度失败。
- **源码审查映射点**：tiling 分支条件、边界判断（`<`/`<=`）、shape 奇异值路径。
- **测试拦截建议**：shape 边界值用例集（0、1、blocksize±1、非对齐尾块、极值维度）。
- **实证案例**：ops-transformer #862 moe 算子 tiling **cmake 逻辑判断错误**（构建期分支判断写错，与精度型 tiling 分支错误同族但落在构建期）；ops-transformer #1438 `mhc/mhc_post/op_kernel/arch35/mhc_post.h` L97-101 init 函数**分配计算中的边界逻辑错误**。注：本型在四仓 issue 中多以「精度失败」表征而非直述「走错分支」，故归因需结合上表映射点做源码侧确认，当前仅收录边界逻辑写错本身被明确定位的两条。（每日 tiling 类扫描持续覆盖）
- **关联**：FP-A08、FP-B02。

## 2. 检视输入与算子定位

**输入**：aclnn 接口名（必填，如 `aclnnMhcPost`）；可选 ref（默认 master）、指定仓（默认自动定位）；可选现象描述（特定 shape 精度失败 / loss 不收敛 / 失败 shape 的具体取值——用于直接验算该 shape 命中的边界表达式）。

**接口名 → 算子目录换算**：去 `aclnn` 前缀 + 驼峰转下划线小写：
`aclnnMhcPost → mhc/mhc_post`（mhc 系列为独立类目目录）、`aclnnRmsNormGrad → norm/rms_norm_grad`。

**仓定位顺序**（GitCode `cann` 组织，逐仓用目录列表确认）：`ops-transformer`（attention/moe/mamba/mhc 类——实证集中地）→ `ops-nn`（norm/index 类）→ `ops-math` → `ops-cv`。**类目名不总与直觉一致**，以目录列表为准；实证旧路径可能已随目录重构迁移（如 mhc 系列的 tiling 从 `op_kernel/arch35/*.h` 迁至 `op_host/op_tiling/arch35/*.cpp`），引用实证时须先确认当前布局。FP-A07 高发面：带 `IsCapable` / shape 阈值分流的 tiling、含 CeilDiv / 尾块分配计算的 tiling、`Inplace` 与多变体接口、带平台分支目录（arch22/ arch35/ 或 op_tiling/）的算子。

**算子目录结构约定**（已验证示例 `cann/ops-transformer` → `mhc/mhc_post/`）：

```text
{类别}/{op_name}/
├── op_host/                  # tiling 主检视面——位置随算子而异：
│   ├── *_tiling*.cpp         #   直接平铺（norm/rms_norm_grad 类）
│   ├── arch22/ arch35/       #   平台分支目录
│   └── op_tiling/arch22|35/  #   独立 op_tiling 子树（mhc 系列）
├── CMakeLists.txt            # 构建期分支判断（#862 变体检视点）
├── op_kernel/ tests/
```

## 4. 边界条件检视清单（每点：查什么 → 何处 → 命中判据）

对 `op_host` 全部 tiling 文件（含平台分支目录）与 `CMakeLists.txt` 逐点核查，**每点先查命中面、再做反证排除**；写对的表达式要记录为反证证据。

### ① 分流 / 能力判断的边界算符
- 查什么：`IsCapable()` 与 shape 分流条件中的比较算符**方向与端点包含性**——`<` vs `<=`、`>` vs `>=`：阈值本身该走哪一侧？`rows_ < cols_ * 2` 与 `rows_ <= cols_ * 2` 在 `rows == 2*cols` 这一整族 shape 上分流出不同路径；分流表达式与注释意图是否一致（注释说「≥64 时走 A」而代码写 `> 64`）。
- 何处：全部 `IsCapable`、`if (shape...)` 分流条件、tiling key 选择的条件链。
- 命中判据：能写出「shape 取 X 时按设计意图应走路径 A、按代码实际走入路径 B」的反例推导 ⇒ 命中候选（结合第 7 节静态命中纪律定档）。

### ② CeilDiv / 尾块分配计算验算
- 查什么：分配计算链——`outer = CeilDiv(total, inner)`、`tail = total - (outer - 1) * inner`、`per = CeilDiv(total, cores); used = CeilDiv(total, per); tailCore = total - (used - 1) * per` 类表达式的**代数正确性**：整除时 tail 是否等于 inner（而非 0 或负）；total < inner 时 outer=1、tail=total 是否成立；链式推导（per→used→tailCore）逐档验算。
- 何处：tiling 的分核 / 分块 / 尾块计算段（实证 #1438 的 init 函数分配计算即此类）。
- 命中判据：对 {0, 1, 恰整除, 非整除, 极值} 五类输入代入后 tail / 尾块出现 0、负数或越过 total 的结果 ⇒ 命中候选。

### ③ 奇异 shape 推导路径
- 查什么：0 维 / 1 维 / 极小 / 极大 / 非对齐 shape 在条件链中的落点——是否存在「按错误分支处理」（如把 0 维当 1 维、把极小 shape 推入大 shape 专用路径）；下标访问 `shape[i]` 是否有奇异值防护（防越界崩溃属 B07，防走错分支属本条）。
- 何处：shape 解包与维度推导段、`GetDims` 后的下标访问。
- 命中判据：奇异 shape 的实际落点与语义预期路径不一致 ⇒ 命中候选。

### ④ 二次能力检查与回退分支
- 查什么：模板内 `DoOpTiling()` 的二次能力检查——不通过返回 `GRAPH_PARAM_INVALID` 回退时，回退**落点**是否为预期兜底路径（隐式第三态）；回退后状态是否被当作成功继续（与 A04 交界：回退吞错归 A04）。
- 何处：模板类 tiling 的能力复查分支。
- 命中判据：回退落点与设计意图不符或不可观测 ⇒ 命中候选。

### ⑤ 构建期分支判断（CMake 变体）
- 查什么：`CMakeLists.txt` 的平台 / arch / 开关分支逻辑——条件写错使某平台的 tiling 源**没被编译**或编译了错误变体（实证 #862 moe 算子 tiling cmake 逻辑判断错误）；与 tiling 源的平台分支目录（arch22/ arch35/）是否一一对应。
- 何处：算子目录与仓级 `CMakeLists.txt`、cmake 模块。
- 命中判据：分支条件与目录实际内容矛盾（该编译的没编译 / 重复编译）⇒ 命中候选。

### ⑥ 归因核对（issue 精度失败 → 分支错误）
- 查什么：用户给出「特定 shape 精度失败」类 issue 时——先验算失败 shape 命中的分支边界表达式，确认归因成立；不能确认时按其他精度模式（A05/A08/A19）分流，不强行归 A07。
- 何处：失败 shape 取值 + 分流表达式验算。
- 命中判据：验算通过且反例推导完整才立 A07 卡。

## 5. 检视流程

1. **定界**：换算 op 目录、确认所在仓与 ref；确认 tiling 文件布局（平铺 / arch 子目录 / op_tiling 子树）；记录用户现象（失败 shape 取值）。
2. **枚举**：目录列表列出全部 `*_tiling*.cpp`（含平台分支目录）与 `CMakeLists.txt`，产出文件清单。
3. **触发词扫描**：按 `IsCapable`、`CeilDiv|FloorDiv`、`<\s*=|>\s*=` 分流条件、`CMakeLists` 分支定位风险面（本地仓用 grep；API 模式逐文件拉取后检查）。签名零命中时清单仍须逐项核查（无 `IsCapable` 的单路径 tiling 核 ②③⑤）。
4. **逐表达式验算**：对每个边界条件与分配计算代入五类输入（0/1/恰整除/非整除/极值），写出落点推导；用户给了失败 shape 时优先验算该值。
5. **反证排除**：算符方向与端点语义一致、尾块五类输入验算全对、CMake 分支与目录内容对应 → 明确写出反证理由。
6. **判定**：按第 7 节标准给出 命中 / 观察项 / 反证排除（静态命中纪律：命中也默认带「观察项」性质，档级暂定）。
7. **GitCode 查重**（仅命中项）：issues API 按接口名 + `精度|边界|shape|分支` 检索，逐条比对是否同机理；无同机理才立卡。
8. **业务可达性核查**（仅命中项）：判 B 等级、定业务影响类型、给处置建议；默认保守（无法证明不可达即记 B3），降档须附证据；B 不改 S×O 档位。
9. **出报告**：按第 8 节模板落盘；每条命中附「失败 shape 反例 + 代数验算」。

## 6. 风险定级（S×O）与业务影响评估（B 轴）

- **S**：S3（走错分支致精度失败——结果错但可运行）；S2（构建期变体——产物错误但构建可发现）。
- **O**：O3 = ≥2 条独立实证；O2 = 1 条独立实证；O1 = 仅静态扫描命中或团队笔记（实证 = 确认对应的 issue / PR，或经跨仓、跨分支核验确认的缺陷记录，同权计入）。静态推演命中且无实证默认 **O1**；升档须在报告中给出实证依据。
- **风险 = S×O**：≥6 高；3/4 中；1/2 低。FP-A07 基准：模式卡整体 S3×O3=9（高）；纯静态命中 S3×O1=3（中，暂定，反例实测后复评）。

### B 轴：业务影响评估（与 S×O 正交；报告层新增，不改卡片定级）

S×O 回答"多严重、多常见"，**不回答"真实业务能不能碰到"**。B 轴补这一问，只决定**修复优先级建议**，**不参与 S/O 取值、不改 S×O 档位与卡片元数据**。

**业务可达性（B）**——触发条件在真实负载中的可达程度：

| 等级 | 判据 | 证据要求 |
|---|---|---|
| B3 现实可达 | 主流框架/公开模型默认路径即可命中（如 PTA/torch_npu、vLLM、MindIE 常规调用） | 调用方或公开负载来源 |
| B2 条件可达 | 需特定 attr/dtype/shape 组合，业务中存在但非默认 | 该组合的业务来源 |
| B1 边界/不可达 | 需极端、超规格或非法参数（超出接口合理上限的 shape、退化/非法输入） | "为何不可达"的说明 |

- **默认保守**：无法证明不可达 → 记 **B3**；降为 B1/B2 必须附证据，**不得仅凭"业务应该不会这么用"**。
- 超规格参数是否算 B1 取决于**接口契约**：契约允许但业务不用 → B1；契约不允许（本应报错）→ 属校验缺失（FP-B04/B05 类），另行归属。

**业务影响类型**（命中后对用户可见结果的后果，用业务语言表述）：静默精度损失（模型效果下降 / loss 不收敛 / 偶发 NaN）｜ 任务失败中断（报错 / 崩溃 / 挂死）｜ 性能退化 ｜ 仅可观测性（日志 / 错误码 / 文档，不影响结果）。

**处置建议**（由两轴推导的报告结论，非新档位）：

| S×O \ B | B3 现实可达 | B2 条件可达 | B1 边界/不可达 |
|---|---|---|---|
| 高（≥6） | 尽快修 | 尽快修 | 排期修 |
| 中（3/4） | 尽快修 | 排期修 | 记录（业务难以触达） |
| 低（1/2） | 排期修 | 记录 | 记录 |

## 7. 判定标准与反误报原则

- **签名 / 触发词命中 ≠ 成立**：`IsCapable`、`CeilDiv` 在大型 tiling 文件普遍存在且多数正确——必须逐表达式验算；命中数大只说明验算工作量大。
- **三种判定**：
  - **命中（候选）**（反例推导完整）：五类输入代入后「设计意图路径 ≠ 实际路径」的代数验算可复写 ⇒ 立 Bug 卡（档级按静态命中纪律暂定）；
  - **观察项**：验算依赖运行时才知的 shape 取值 / 平台常量 → 记录并附验算方案；
  - **反证排除**：算符、端点、尾块、CMake 分支逐项验算全对 → 写出反证理由。
- **「精度失败」issue 不直接归 A07**：必须先验算失败 shape 命中的边界表达式，验算不通过则分流 A05/A08/A19——卡片仅收录边界逻辑写错被明确定位的实证，归因从严。
- **旧路径失效不算新证据**：实证引用的原始路径已迁移时，按当前布局重新定位对应逻辑后再下结论。
- **不臆造行号**：每条证据必须是实际读到的 文件:行号；引用实证样板时注明路径迁移状态。

### 判定纪律补充（v3.6）：非对称增减、证据等级与误判记录

**增减不对称**：允许追加候选（有据即可，错了可由用户排除）；**撤销或否决候选必须附 `[文件]:[行号] [代码行]` 负向证据**。无证据的「看起来没问题」一律记为「未核查」，不得计入反证排除，也不得据此下调等级——否决造成的漏报用户不可见、不可恢复。

- **证据等级**（Bug 卡必填）：`静态可证` = 推导链完整且触发输入可静态构造；`需实测确认` = 依赖运行时输入规模、设备行为或环境差异。标 `需实测确认` 的条目**不得以「命中」名义出卡**，按观察项记录并附实测用例。
- **Agent 误判记录**（Bug 卡必填）：本次被推翻的假设、推翻它的证据（`[文件]:[行号] [代码行]` 或实测输出）、判定标准是否随之修订；无推翻写「无」。
- **误判回流**：同类误判在 3 次检视中重复出现，登记至 `cases/misjudgments.jsonl`（字段见 `cases/README.md`），并在本模式判定标准中新增对应防线；守门 C19d 校验台账字段合法。

## 10. 能力边界与自检（v3.8）

### 能力边界

- **静态可证**：清单里能在源码内给出「`文件:行号` + 推导链」的部分，按第 7 节判据出卡。
- **需实测确认**：依赖运行时输入规模、设备行为或环境差异的结论，只能记观察项并附实测用例（证据等级见第 7 节）。
- **不覆盖**：本模式以外的机理（边界见第 0 节）与仓外框架侧行为；`TRIAGE.md` 只负责收敛候选，不构成判定依据。
- **找不到 ≠ 没有**：按清单未命中只说明「本轮未发现」，不得表述为「该算子无此缺陷」；抽样核查须在报告写明抽样口径。
