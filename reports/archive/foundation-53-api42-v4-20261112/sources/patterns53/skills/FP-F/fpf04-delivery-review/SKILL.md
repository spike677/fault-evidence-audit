# FP-F04 交付面检视（fpf04-delivery-review）

对用户指定的 aclnn 接口（如 aclnnMoeInitRoutingV4）做 FP-F04 专项交付面完整性检视：先定位算子实现与全部注册/导出清单，再按六成因清单做**差集核查**，每个结论给出**文件 + 行号 + 推导链**证据，命中即出 Bug 卡，输出检视报告。**本模式特殊纪律：「实现已完成」≠「接口可用」——本型的失败多为静默（构建退出码 0、target 显示 Done、不报错、静默回退 CPU），仅查顶层退出码永远查不出本型；检视动作是清单差集，不是调用链走查。**

## 0. 与相邻模式的边界

| 相邻模式 | 分工 |
|---|---|
| FP-F01（构建/工程配置不一致） | **共用同一套 def × binary.json 门禁但断言方向相反**：F01 断言「**注册了就必须有产物**」（配置不一致致编译/链接失败或产物静默跳过）；本条断言「**产物里必须有符号**」（交付清单缺失致接口不可用）。缺口方向相反，门禁可合并实现 |
| FP-B03（迁移漏防御代码） | B03 是迁移时把**防御代码**漏掉（机理 = 防御逻辑漏迁）；本条成因⑥ 是「**接口本体**没迁、或跳转没配」（机理 = 交付清单漏项），二者不同源 |
| FP-F03（文档声明支持而接口实际不可用） | 属两型**复合**：文档声明（F03 面）+ 接口不可用（本条面），命中 F03 时同步核本条 |
| FP-B01（校验过严误拦截） | 镜像关系：B01 是接口被校验层**误拦**；本条是接口**根本没走到校验层**（压根没交付） |
| FP-G01（挂死/超时） | 同属「**退出码不可信**」家族：本条是**不报错地失败**，G01 是**不返回地卡住**；实证 #5337 商分未合入直接表现为用例挂死（后果链归 G01） |
| FP-B10（HCCL 侧注册/导出类问题） | 通信库侧的同源问题；算子仓命中本条时，如涉及通信算子族可参照 B10 |

**症状反查定位**：`undefined symbol` 且构建退出码 0 → 成因①；`torch.ops.<ns>.<op>` 不存在 → 成因②；「未注册 tilingkey」→ 成因③；dynamo 下静默回退 CPU → 成因④；代码在主干但发布包能力缺失 / 用例挂死 → 成因⑤；内网可调通但开源包找不到接口、文档「跳转源码」断链 → 成因⑥。多症状同族出现（同族多入口同报错）通常是**同一根因**，勿分别立卡。

## 1. FP-F04 模式卡摘要（检视依据，源自本库 `patterns/FP-F/FP-F04.md`，v3.1）

- **编号 / 名称**：FP-F04 算子接口交付面缺失（符号未导出 / 原型未注册 / 未纳入商分） ｜ **类别**：工程/交付 ｜ **风险**：高（S2×O3=6）｜ **状态**：活跃
- **适用声明头**（照抄卡片）：仓 All ｜ 侧别 All ｜ 载体 构建配置与日志,aclnn源码,IR与图配置 ｜ 触发 undefined symbol|dlsym|AddConfig ｜ 默认启用 true
- **skill 核查面**：载体为构建配置与日志、aclnn 源码、IR 与图配置——skill 落地为七类交付面文件：`op_host/*_def.cpp`（原型注册）、`op_host/config/<soc>/*_binary.json`（分核配置产物）、`op_api/`（aclnn 出口）、`op_kernel/*_apt.cpp`（apt 派发）、`torch_extension/`（PTA/torch 侧注册）、构建脚本与构建日志（符号导出/解析）、`docs/`（跳转链接）；发布形态差异（商分/开源、sanitizer、选择性打包、跨 toolkit）由用户提供后纳入核查
- **故障机理**：算子的**实现已经完成**，但在「把接口交付到用户手里」的清单上漏项，使接口在用户侧不可用、或被**静默降级**。六种独立成因：① **`.so` 符号未导出**——`libopapi.so` / `liboptiling.so` 中缺少 aclnn 接口或 typeinfo 符号，框架侧 `dlsym` 返回 `nullptr`；② **公开算子名未注册**——PTA / 框架侧公开名（如 `cann_ops_transformer::compressor`）未注册，`torch.ops.<ns>.<op>` 不可用；③ **派发表未同步注册**——算子跨版本复用兄弟实现（v4 复用 v3 的 tiling/kernel）时，上游新增的 tilingkey 未同步适配，走到该模板即报「未注册 tilingkey」；④ **适配层注册缺失致静默降级**——算子未在 torch_npu 注册，dynamo 时**静默 fall back 到 CPU**（不报错，仅性能与行为变化）；⑤ **商分清单未合入**——代码已进社区主干但未进商业发行分支，表现为能力缺失或用例挂死；⑥ **接口/源码未同步至开源仓、文档跳转缺失**——接口本体只存在于内部 dev 仓、未随发布同步到开源仓，或资料中的「跳转源码」链接指向不存在的路径。**共同特征：交付面缺失，而构建/调用链不报错、或只打 `ERROR` 日志仍返回成功。**
- **触发条件**：新增算子或新增接口后未同步更新导出符号表 / 公开名注册 / `binary.json` / apt 派发表；算子跨版本复用且上游新增 tilingkey；选择性打包（sanitizer、商分裁剪、形态裁剪）；跨 toolkit 版本发布；框架侧适配层未同步算子清单；接口从内部 dev 仓向开源仓同步时遗漏、文档跳转链接未随仓迁移更新。
- **典型表现**：`undefined symbol: ...`（如加载 `liboptiling.so` 失败）而**构建退出码仍为 0**、target 显示 `Done` / `Built target`、且继续产出 `.o` / `.json` 产物；`dlsym` 返回 `nullptr`（`EXEC_NPU_CMD` 查不到 aclnn API）；`torch.ops.<ns>.<op>` 不存在；「未注册 tilingkey」报错；dynamo 静默 fallback 到 CPU；同一算子族的多个 mode 稳定报同一错（同根因）；按文档「跳转源码」链接点进去路径不存在或指向兄弟算子；开源仓接口清单与内部清单不一致。
- **实证案例**：ops-transformer **#4967**（closed）Ascend 950 sanitizer 多算子选择性打包时，构建命令**最终返回 0**、相关 target 显示 `Done`，但完整日志含 `asc_opc` 加载 `liboptiling.so` 失败——`undefined symbol: _ZTIN8optiling24GroupedQmmBasicApiTilingE`（解码为 `typeinfo for optiling::GroupedQmmBasicApiTiling`），共 4 行 `[ERROR]`，错误发生后 `asc_opc` **仍返回成功并继续生成 `.o` 与 `.json` 产物**（成因① + 静默成功的教科书案例）；ops-transformer **#5434**（closed）`compressor` 的 PTA 公开算子名 `cann_ops_transformer::compressor` 未注册，`torch.ops` 不可用（成因②）；Ascend/op-plugin **#242**（closed）`EXEC_NPU_CMD(aclnnScatterReduce, ...)` 走 `dlsym` 查找 `aclnnScatterReduce` / `...GetWorkspaceSize` 返回 `nullptr`——发布版 `libopapi.so` 未导出 ScatterReduce 家族 aclnn API，3 个失败 test（sum/amax/amin）**同族多入口同根因**（成因①）；Ascend/op-plugin **#416**（closed）`aclnnRepeatInterleaveTensor` 未注册 pta，dynamo 时**静默 fall back 到 CPU**（成因④）；ops-transformer **#5104**（closed）`moe_init_routing_v4` 复用 v3 的 tiling 与 kernel，v3 新增 tilingkey 而 **v4 的 apt 未适配**，走到该模板时 v4 报未注册 tilingkey（ascend950 / cann9.2.0，成因③）；ops-transformer **#5337**（closed）MoeInitRoutingV4 部分用例超时挂死，备注明确「**商分未合入**」（成因⑤，挂死后果见 FP-G01）。
- **关联**：FP-F01（边界：配置不一致 vs 交付清单缺失，门禁共用断言方向相反）、FP-F03（复合）、FP-B01（镜像）、FP-G01（#5337 商分未合入表现为挂死）、FP-B10（HCCL 侧同源）。

## 2. 检视输入与算子定位

**输入**：aclnn 接口名（必填，如 `aclnnMoeInitRoutingV4`）；可选 ref（默认 master）、指定仓（默认自动定位）；可选**构建日志**（用户提供，静态检视无法自取）；可选**目标交付形态**（sanitizer 打包 / 商分 / 选择性裁剪 / 跨 toolkit 版本——决定成因①⑤ 的核查深度）；可选**框架侧仓可达性**（torch_npu / op-plugin 等适配层仓——成因②④ 需要）。

**接口名 → 算子目录换算**：去 `aclnn` 前缀 + 驼峰转下划线小写：
`aclnnMoeInitRoutingV4 → moe_init_routing_v4`、`aclnnDiagV2 → diag_v2`、`aclnnSwiGlu → swi_glu`。

**仓定位顺序**（GitCode `cann` 组织，逐仓用目录列表确认）：`ops-nn`（norm/loss/activation/matmul 类）→ `ops-math`（math/conversion 类）→ `ops-cv`（image/vision 类）→ `ops-transformer`（attention/moe 类）。**跨版本复用识别**：目录名带版本号（`_v2`/`_v3`/`_v4`）时，检查同族兄弟目录是否存在——存在即触发成因③ 的复用差集核查。

**算子目录结构约定**（已验证示例 `cann/ops-transformer` → `moe/moe_init_routing_v4/`）：

```text
{类别}/{op_name}/
├── op_host/
│   ├── {op}_def.cpp            # 原型注册（AddConfig——成因①③ 的注册面）
│   ├── {op}_infershape.cpp
│   ├── {op}_tiling_arch*.cpp   # tiling 实现（复用兄弟版本时含跨目录 include）
│   ├── config/<soc>/{op}_binary.json   # 分核/tilingkey 派发配置——与 def 的差集面
│   └── op_api/                 # aclnn 出口（libopapi 符号来源）
├── op_kernel/{op}_apt.cpp      # apt 派发实现——成因③ 的适配面
├── torch_extension/            # PTA / torch 侧注册——成因②④ 的注册面
├── tests/ docs/ examples/      # 文档跳转链接存在性——成因⑥
└── CMakeLists.txt              # 构建配置（符号导出表引用）
```

## 4. 六成因检视清单（每点：查什么 → 何处 → 命中判据）

对算子七类交付面文件逐点核查，**每点先做差集、再做反证排除**；已正确注册的面也要记录（作为反证依据）。

### 成因① `.so` 符号未导出
- 查什么：aclnn 出口（`aclnn{Op}` / `aclnn{Op}GetWorkspaceSize`）与 tiling 符号是否进入导出面——version script / `*_symbol.txt` 等导出清单与接口清单的**双向差集**；构建工具（`asc_opc` 类）在符号解析失败时是否仍返回成功。
- 何处：`op_api/` 接口实现、构建脚本（CMake）的导出配置、构建日志（若用户提供）中的 `undefined symbol` / `lib*\.so` 加载失败行。
- 命中判据：差集非空（导出清单缺该接口）或日志中出现 `undefined symbol`；`typeinfo`（`_ZTI...` 前缀）缺失与接口本体缺失同判。反证：接口符号在导出清单中但形态被裁剪（须与目标交付形态比对后才算命中）。

### 成因② 公开算子名未注册
- 查什么：PTA / 框架侧公开名（`<namespace>::<op>`）注册表与算子清单的差集；`m.def(` / `TORCH_LIBRARY` / `register_op` 类注册点是否覆盖该算子。
- 何处：`torch_extension/`（csrc、`__init__.py`）、框架侧仓（op-plugin / torch_npu 映射表）。
- 命中判据：`torch.ops.<ns>.<op>` 访问不可达 + 注册表中查无该名（实证 #5434 同族）。

### 成因③ 派发表未同步注册（跨版本复用兄弟实现）
- 查什么：算子是否跨目录复用兄弟版本的 tiling/kernel（相对路径 `include` 兄弟目录、类继承兄弟实现）；上游兄弟版本新增的 tilingkey 是否同步进本版本的 **apt 派发表**与 `binary.json`——上游加、本版没跟，走到该模板即报「未注册 tilingkey」。
- 何处：`{op}_tiling_arch*.cpp` 的 include 段与继承声明、`op_kernel/{op}_apt.cpp` 的 tilingkey 分派、`config/<soc>/*_binary.json` 与 `*_def.cpp` 的 `AddConfig` 差集、兄弟版本目录（`../{op}_v{N-1}/`）的新增 tilingkey 清单。
- 命中判据：能写出「上游模板 tilingkey T（存在于兄弟版本 binary.json / tiling 分派）→ 本版本派发表查无 T」的静态差集（实证 #5104 同族：v3 新增 tilingkey，v4 的 apt 未适配）。

### 成因④ 适配层注册缺失致静默降级
- 查什么：算子在 torch_npu / dynamo 适配层的映射表是否注册；未注册时 dynamo **静默 fall back 到 CPU**（不报错——最易漏检的形态）。
- 何处：适配层仓映射表、`torch_extension/` 注册面；用户侧可复测：dynamo 下检查计算图是否被打断/回退。
- 命中判据：适配层映射表查无该算子 + 该算子本应注册（同族其他算子已注册即为旁证）；实证 #416 同族。

### 成因⑤ 商分清单未合入
- 查什么：代码在社区主干存在但商业发行分支清单未合入——静态源码只能查「主干有、清单引用缺」的**嫌疑**（商分分支本身不在开源仓）。
- 何处：算子目录在主干的存在性 × 发布形态清单（用户提供）；用例挂死/能力缺失类 issue 备注（实证 #5337 备注明确「商分未合入」）。
- 命中判据：主干实现完整 + 用户侧发布包能力缺失，且无其他成因可解释；标注「需发布侧清单比对确认」。

### 成因⑥ 接口/源码未同步至开源仓、文档跳转缺失
- 查什么：文档中「跳转源码」链接路径是否真实存在（`docs/**/*.md` 的仓内跳转路径存在性扫描）；接口清单与开源仓实际文件的双向差集。
- 何处：`docs/*.md`、README、接口文档中的源码链接；开源仓目录列表比对。
- 命中判据：链接指向的路径在目标仓目录列表中不存在，或指向兄弟算子目录；接口在内部清单存在而开源仓查无。

### 横切面：构建静默成功
- 查什么：构建门禁只看退出码的盲区——`undefined symbol` 出现时构建仍返回 0（#4967 实证 `asc_opc` 在 ERROR 后继续产出 `.o`/`.json`）。
- 何处：构建日志全文（若用户提供）。
- 命中判据：日志含 `undefined symbol` / `[ERROR]` 加载失败行而退出码为 0——该证据同时使成因① 嫌疑升级为实证。

## 5. 检视流程

1. **定界**：换算 op 目录、确认所在仓与 ref、目标交付形态（sanitizer/商分/裁剪/跨 toolkit）、框架侧仓可达性；识别跨版本复用（同族兄弟目录是否存在）。
2. **枚举**：列出七类交付面文件清单（def / binary.json / op_api / apt / torch_extension / 构建脚本 / docs）。
3. **触发词扫描**：按 `undefined symbol|dlsym|AddConfig`、`m\.def\(|TORCH_LIBRARY|register_op`、`fall\s*back|fallback` 定位风险面（本地仓用 grep；API 模式逐文件拉取后检查）。
4. **六成因差集核查**：每点记录命中面与防护面证据（文件:行号）；成因①③ 做双向差集，成因②④ 核注册表，成因⑤⑥ 记录嫌疑并附验证命令。
5. **反证排除**：形态裁剪属预期行为（对照目标交付形态）、符号延迟绑定/弱符号机制、注册在别处完成（框架侧统一注册仓）、文档链接指向外部仓。
6. **判定**：按第 7 节标准给出 命中 / 观察项 / 反证排除。
7. **GitCode 查重**（仅命中项）：issues API 按接口名 + `undefined symbol|tilingkey|dlsym|fallback` 检索，逐条比对是否同机理；无同机理才立卡。
8. **业务可达性核查**（仅命中项）：判 B 等级、定业务影响类型、给处置建议；默认保守（无法证明不可达即记 B3），降档须附证据；B 不改 S×O 档位。
9. **出报告**：按第 8 节模板落盘；静态差集结论标注「需符号实测/日志解析确认」并附验证命令（`dlsym` 冒烟、日志正则断言）。

## 6. 风险定级（S×O）与业务影响评估（B 轴）

- **S**：S2（交付受限/接口在用户侧不可用、静默降级损性能与行为）；S3 仅当静默降级改变了数值结果口径时升级。
- **O**：O3 = ≥2 条独立实证；O2 = 1 条独立实证；O1 = 仅静态扫描命中或团队笔记（实证 = 确认对应的 issue / PR，或经跨仓、跨分支核验确认的缺陷记录，同权计入）。静态推演命中且无实证默认 **O1**；升档须在报告中给出实证依据。
- **风险 = S×O**：≥6 高；3/4 中；1/2 低。FP-F04 基准：模式卡整体 S2×O3=6（高）；纯静态命中 S2×O1=2（低，差集嫌疑待实测升级）。

### B 轴：业务影响评估（与 S×O 正交；报告层新增，不改卡片定级）

S×O 回答"多严重、多常见"，**不回答"真实业务能不能碰到"**。B 轴补这一问，只决定**修复优先级建议**，**不参与 S/O 取值、不改 S×O 档位与卡片元数据**。

**业务可达性（B）**——触发条件在真实负载中的可达程度：

| 等级 | 判据 | 证据要求 |
|---|---|---|
| B3 现实可达 | 主流框架/公开模型默认路径即可命中（如 PTA/torch_npu、vLLM、MindIE 常规调用） | 调用方或公开负载来源 |
| B2 条件可达 | 需特定 attr/dtype/shape 组合，业务中存在但非默认 | 该组合的业务来源 |
| B1 边界/不可达 | 需极端、超规格或非法参数（超出接口合理上限的 shape、退化/非法输入） | "为何不可达"的说明 |

- **默认保守**：无法证明不可达 → 记 **B3**；降为 B1/B2 必须附证据，**不得仅凭"业务应该不会这么用"**。
- 超规格参数是否算 B1 取决于**接口契约**：契约允许但业务不用 → B1；契约不允许（本应报错）→ 属校验缺失（FP-B04/B05 类），另行归属。

**业务影响类型**（命中后对用户可见结果的后果，用业务语言表述）：静默精度损失（模型效果下降 / loss 不收敛 / 偶发 NaN）｜ 任务失败中断（报错 / 崩溃 / 挂死）｜ 性能退化 ｜ 仅可观测性（日志 / 错误码 / 文档，不影响结果）。

**处置建议**（由两轴推导的报告结论，非新档位）：

| S×O \ B | B3 现实可达 | B2 条件可达 | B1 边界/不可达 |
|---|---|---|---|
| 高（≥6） | 尽快修 | 尽快修 | 排期修 |
| 中（3/4） | 尽快修 | 排期修 | 记录（业务难以触达） |
| 低（1/2） | 排期修 | 记录 | 记录 |

## 7. 判定标准与反误报原则

- **差集必须双向**：只查「注册了没产物」（F01 方向）会漏掉本条；只查「产物里没符号」（本条方向）会漏掉 F01——两向都要跑，报告中分别标注。
- **三种判定**：
  - **命中**（可静态证差集或已有实测证据）：注册面/导出面差集可静态指认 + 触发路径可达（用户形态下确实会走到），或用户提供了 `undefined symbol` 日志 / `dlsym` 空指针实测 → 立 Bug 卡；
  - **观察项**：差集依赖目标交付形态（商分/裁剪）或需 `.so` 实测才能确认 → 记录并附验证命令，按 S2×O1 暂定；
  - **反证排除**：选择性打包属预期、注册在框架侧统一完成、链接指向外部仓 → 明确写出反证理由。
- **同族合并**：同一算子族多个 mode / 多入口稳定报同一错，是**同一根因**的信号（#242 三 mode 同根因）——立一张卡，族内入口列证据清单。
- **静默降级与合法 CPU 路径区分**：判据是「该算子**本应**注册 NPU 而未注册」（同族已注册算子为旁证），不是「存在 CPU 回退」本身。
- **不臆造清单内容**：差集两边都必须实际读取（注册表、binary.json、导出配置），引用具体文件与键名；推断性的商分清单比对必须标注「未实测」。

### 判定纪律补充（v3.6）：非对称增减、证据等级与误判记录

**增减不对称**：允许追加候选（有据即可，错了可由用户排除）；**撤销或否决候选必须附 `[文件]:[行号] [代码行]` 负向证据**。无证据的「看起来没问题」一律记为「未核查」，不得计入反证排除，也不得据此下调等级——否决造成的漏报用户不可见、不可恢复。

- **证据等级**（Bug 卡必填）：`静态可证` = 推导链完整且触发输入可静态构造；`需实测确认` = 依赖运行时输入规模、设备行为或环境差异。标 `需实测确认` 的条目**不得以「命中」名义出卡**，按观察项记录并附实测用例。
- **Agent 误判记录**（Bug 卡必填）：本次被推翻的假设、推翻它的证据（`[文件]:[行号] [代码行]` 或实测输出）、判定标准是否随之修订；无推翻写「无」。
- **误判回流**：同类误判在 3 次检视中重复出现，登记至 `cases/misjudgments.jsonl`（字段见 `cases/README.md`），并在本模式判定标准中新增对应防线；守门 C19d 校验台账字段合法。

## 10. 能力边界与自检（v3.8）

### 能力边界

- **静态可证**：清单里能在源码内给出「`文件:行号` + 推导链」的部分，按第 7 节判据出卡。
- **需实测确认**：依赖运行时输入规模、设备行为或环境差异的结论，只能记观察项并附实测用例（证据等级见第 7 节）。
- **不覆盖**：本模式以外的机理（边界见第 0 节）与仓外框架侧行为；`TRIAGE.md` 只负责收敛候选，不构成判定依据。
- **找不到 ≠ 没有**：按清单未命中只说明「本轮未发现」，不得表述为「该算子无此缺陷」；抽样核查须在报告写明抽样口径。
