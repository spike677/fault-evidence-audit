关联 Issue

修复 #686

问题

FSDP2 训练使用 BaseRandomBatchSampler 且 shuffle=True 时，training.seed 已正确传入 sampler（trainer.py 中 seed=args.training.seed），但 sampler 内部 g.manual_seed(self.epoch) 只用 epoch 初始化，完全忽略 self.seed，导致不同 seed 产生完全相同的采样顺序（data_sharding 两种路径均如此）。

修复

两处 g.manual_seed(self.epoch) 改为 g.manual_seed(self.seed + self.epoch)，与本文件既有约定一致（VariableVideoBatchSampler :729、AESampler :939/get_bucket :835、LuminaMetaLenDistSampler :1022 均用 self.seed + self.epoch）。

同一缺陷也存在于非 FSDP 版的 BaseRandomBatchSampler.__iter__（sampler.py :455/:466）及其子类 BucketBatchSampler（:644/:655）——同一文件、同样的手写 generator 模式，一并对齐修复，避免同类 issue 重复上报。

验证

运行 issue 最小复现脚本，修复前两条路径 same_order=True，修复后 same_order=False；epoch 递增仍会改变顺序（保留原 epoch 相关性）。

兼容性

种子语义从“仅 epoch”变为“seed+epoch”，顺序本身会变化（这正是 issue 期望的行为）；state_dict 格式不变。

变更摘要

本 PR 修复 BaseRandomBatchSampler 采样时忽略 seed、导致不同 seed 产生完全相同采样顺序的问题（关联 issue #686）。问题根源在于 sampler 内部 g.manual_seed(self.epoch) 仅用 epoch 初始化随机生成器，完全忽略已传入的 self.seed。修复方式是将两处文件中的 g.manual_seed(self.epoch) 统一改为 g.manual_seed(self.seed + self.epoch)，与本文件既有约定（VariableVideoBatchSampler、AESampler、LuminaMetaLenDistSampler 均使用 self.seed + self.epoch）保持一致，同时保留 epoch 递增仍会改变采样顺序的原相关性；种子语义从「仅 epoch」变为「seed + epoch」，采样顺序本身会随之变化，state_dict 格式不变。

主要改动

  • FSDP 版 BaseRandomBatchSampler 修复：在 mindspeed_mm/fsdp/data/dataloader/sampler.py 的 __iter__ 中，data_sharding 两条路径的 g.manual_seed(self.epoch) 均改为 g.manual_seed(self.seed + self.epoch)（:71/:82），使不同 seed 产生不同采样顺序。
  • 非 FSDP 版 BaseRandomBatchSampler.__iter__ 修复：在 mindspeed_mm/data/dataloader/sampler.py 中，bucket 与 full-bucket 两条 shuffle 路径的 g.manual_seed(self.epoch) 均改为 g.manual_seed(self.seed + self.epoch)（:452/:463），修复同类缺陷避免重复上报。
  • BucketBatchSampler 同步修复：其子类 BucketBatchSampler 中同样两处手写 generator 模式（:641/:652）一并改为 g.manual_seed(self.seed + self.epoch)，保证同一文件内行为一致。
