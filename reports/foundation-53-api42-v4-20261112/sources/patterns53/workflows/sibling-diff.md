# sibling-diff：兄弟实现对拍（同一逻辑、多条实现路径的漂移排查）

> `skills/` 回答「一条模式怎么查」，本 workflow 回答：**当同一份逻辑存在多个实现，如何用「一边对一边」把差异逼出来**。
>
> 适用前提：**你已经找到一处可疑点（或一处已修复点）**，要判断「它的兄弟实现有没有同样的病」。这是最高杠杆的举一反三方式——因为兄弟实现共享上游契约、共享测试资产、往往由同一个人前后脚写，缺陷会成组出现。
>
> 本 workflow 不替代模式检视：它**产出候选**，候选仍须回到对应 `skills/FP-X/*/SKILL.md` 第 7 节走正负证据判定。

## 0. 为什么需要它（本库原先的缺口）

52 条模式各自描述「一种机理」，但**同一算子内部**常有多条并列实现路径，它们之间的差异既不属于任何单条模式，也不在任何一张卡的映射点里。历史现网修复反复踩同一类坑：

| 兄弟对 | 漂移后果 | 归属模式 |
|---|---|---|
| rope `half` ↔ `interleaved` | 一侧置了布局标志、另一侧没复位 | FP-A21 |
| QuantMatmul `v4` ↔ `v5` | v4 漏处理 scale 连续性，v5 把「一维」当不用连续化 | FP-B11 / 新子型 |
| FA `fixed` ↔ `varlen` | 尾块记账只在一侧按奇数处理 | FP-B07 |
| forward ↔ grad | 同步后置条件只在正常迭代路径成立 | FP-G02 |
| A2 ↔ A3 ↔ 950 | tiling 容量系数只在一侧用对 A/B buffer | FP-A07 |
| `Inplace` ↔ 非 `Inplace` | 校验只加在一个入口 | FP-B04 |
| `arch22` ↔ `arch35` | 平台分支只 gate 一侧的空态处理 | FP-B06 |

**共同特征**：单看任一侧都「像没问题」，只有并排看才暴露不对称。这正是纯模式检视最容易漏的一类。

## 1. 输入

- 一处**已知锚点**：刚修复的缺陷、本轮命中点、或审查中觉得可疑的那一行；
- 该锚点所在的仓与 ref（须记录 `HEAD`）；
- 可选：该算子的历史 issue / PR 列表（用于判断哪一侧「后写的」）。

## 阶段

### Stage 0 — 锚点归一

1. 写出锚点的 `仓 / ref / HEAD / 文件:行号 / 函数名 / 实际执行通路（arch、dtype、layout、SoC）`。
2. **先判定它属于「哪一维度上的实现」**——这是后续找兄弟的依据，别急着搜相似代码。维度只有六类：

| 维度 | 兄弟判定依据 | 典型拆分点 |
|---|---|---|
| 布局 / format | layout 枚举、`isXxxLayout` 标志 | ND / NZ / TND / BNSD / BSND |
| 架构 / SoC | `arch22` / `arch32` / `arch35`、`__CCE_AICORE__`、SoC 条件编译 | A2 / A3 / 950 / 910B |
| dtype | `if constexpr (IsSameType<...>)`、`DT_*` 分派 | fp16 / bf16 / fp32 / int8 |
| 载体 / 接口层 | 目录语义 | `op_api` / `op_host` / `op_kernel` / AICPU / TBE |
| 语义变体 | 属性开关 | fixed / varlen、量化 / 非量化、inplace / 非 inplace、forward / backward |
| 形态变体 | 同族算子的独立目录 | `xxx_v3` / `xxx_v4`、`_grad` / 无后缀 |

3. **若六类都找不到兄弟** → 写「无兄弟实现（单路径算子）」，本 workflow 结束，回退到常规模式检视。**不要硬凑**——把不相关的算子当成兄弟，是这类排查最大的假阳性来源。

### Stage 1 — 结构化取兄弟

1. **同目录同族**：`ls` 锚点所在目录，按命名模式列出候选（`*_arch32*` / `*_varlen*` / `*_bn2*`）；
2. **跨目录同算子**：`grep -rn "<函数名或特征常量>" --include=*.h --include=*.cpp` 全仓搜，注意 `experimental/` 与正式目录**可能同名分叉**（见 §5 纪律）；
3. **跨仓同族**：同名算子在 `ops-nn` / `ops-math` / `ops-cv` / `ops-transformer` 之间迁移过的情况（迁移即 FP-B03 的高发场景）；
4. **版本前后**：`git log -L` 或 `git log -S"<特征串>"` 取引入 / 修改该行历史，判断哪一侧是「后补的」（后补的一侧通常更正确，先写的一侧更可能漏改）。

**产出**：兄弟清单表（`文件:行号 / 该侧实现 / 判定为兄弟的依据`），并明确标注**哪些只是相似、不是兄弟**（后者列入「不采信」并给理由）。

### Stage 2 — 逐维度对齐

对每一对兄弟，按下列**七个对齐面**逐项对表。每格填「一致 / 不一致 / 该侧不适用」，不一致即为候选：

| # | 对齐面 | 具体比对什么 | 漏掉会怎样 |
|---|---|---|---|
| 1 | **入参校验集合** | 同一组必选参数是否都被判空 / 校验；错误码是否一致 | FP-B04 / B11，一侧崩溃一侧正常返回 |
| 2 | **支持面声明** | 接受的 dtype / rank / format / 空态集合是否相同 | FP-B01 / B06，一侧误拒或误接 |
| 3 | **状态初始化与复位** | 类成员 / 文件作用域变量是否在**每条路径**都赋确定值 | FP-A21，跨调用污染 |
| 4 | **容量与资源公式** | UB/L1/workspace 的系数（`pbAL1` vs `pbBL1`）、单位（元素/字节/block）、取整方向 | FP-A07 / B07，等号边界漏降级 |
| 5 | **尾块与边界处理** | 奇数尾块、`B-1/B/B+1`、0 次迭代、`>=` vs `>` | FP-B07，越界或 NaN |
| 6 | **同步与后置条件** | Set/Wait 配对、零迭代分支是否也满足后置条件 | FP-G02，偶现错值 |
| 7 | **输出写所有权** | 谁写哪个输出、mask 门控是否覆盖全部写点 | FP-B04 子型②，core dump |

### Stage 3 — 差异定性（关键一步，不许跳）

对每处「不一致」，必须回答：

1. **这是缺陷还是有意差异？** 布局/架构/dtype 不同导致的**必然**差异（如 NZ 需要分形对齐）不算缺陷——须给出「为什么这一侧必须不同」的代码或文档依据。
2. **差异是否可达？** 该侧是否真会被调用（有没有被 tiling 拒绝、有没有被上层路由屏蔽）。
3. **差异的后果属于哪一档？** 崩溃 / 静默错算 / 性能 / 仅可观测性——对应 S 轴。
4. **能否构造单变量对照用例？** 同一份输入、只切换实现路径（layout / arch / dtype / 开关），两侧应给出相同结果。**做不到单变量的，降级为观察项**。

### Stage 4 — 产出

```markdown
# 兄弟实现对拍报告：<算子/接口名>（YYYY-MM-DD）
## 一、锚点与范围（仓 / ref / HEAD、锚点 文件:行号、归属维度、兄弟清单及判定依据、不采信清单）
## 二、对拍矩阵（七对齐面 × N 对兄弟；每格：一致 / 不一致 / 不适用）
## 三、不一致明细（每处：两侧 文件:行号、差异描述、是有意差异还是候选缺陷、可达性、S 档、对照用例）
## 四、单变量对照用例（路径 A/B、同一输入、期望两侧一致、实际结果）
## 五、回挂模式（每处不一致 → FP-XX / 子型号；无对应模式者单列「模式库缺口」）
## 六、结论（确认缺陷 X 处 / 有意差异 Y 处 / 待实测 Z 处 / 无兄弟实现）
```

**「模式库缺口」是本 workflow 的额外产出**：反复出现、但 52 张卡都装不下的差异类型，应回到库里加子型（走 `patterns/` + `fault_patterns_index.json` 的 `subtypes`）——这是库自我生长的入口。

## 3. 已验证的兄弟对速查（历史现网案例归纳，可直接当起手式）

| 兄弟对 | 优先比对的对齐面 | 依据案例 |
|---|---|---|
| rope `half` ↔ `interleaved` | ③ 状态复位（`isTndLayout` 是否无条件赋值） | 26-09 |
| QuantMatmul `v4` ↔ `v5` | ① 校验集合、② 非连续辅助输入 | 26-04 |
| FA `fixed` ↔ `varlen` | ⑤ 尾块、⑥ 同步后置条件 | 26-03 / 26-05 |
| FA forward ↔ grad | ⑥ 零迭代同步、⑦ 输出所有权 | 26-05 |
| ConvolutionBackward `dx` ↔ `dw` 路径 | ⑦ 输出写所有权（跨角色读 shape） | 26-02 |
| `matmul` 单核 ↔ 多核 SplitK | ④ 逻辑/对齐尺寸（`realK`/`realN`） | 26-06 |
| `foreach` 单 tensor ↔ tensor list | ④ 循环次数宽度、容量增长 | 26-08 |
| MaskedScatter `source` 空 ↔ 非空 | ② 空态支持面、早退语义 | 26-10 |
| `aclnnDiv` ↔ `aclnnDivs` ↔ TBE `real_div` | ① dtype promote 四层一致性 | 25-14 |
| `Conv3D` 普通 ↔ pointwise | ④ A/B buffer 系数（`pbAL1`/`pbBL1`） | 25-15 |
| `add_rms_norm` ↔ `layer_norm_grad` | ③ 初值确定性、⑥ 确定性 key | 25-10 |

## 4. 纪律

1. **兄弟必须能证明是兄弟**：给出「同一逻辑的两种实现」的依据（同名函数、同算子目录、同 tiling key 分支、或同一 PR 同时改动两者）。仅凭「代码长得像」不算。
2. **差异 ≠ 缺陷**：布局/架构差异是设计使然。**判缺陷前必须回答「这一侧为什么不能和另一侧一样」**。
3. **对拍要单变量**：同一输入只切实现路径。路径与 shape/dtype/options 同时变，得出的差异结论一律作废。
4. **`experimental/` 与正式目录可能同名分叉**，不是同一个算子；比对前先确认是否为软链或同源，计入「不采信」并写明。
5. **不做无锚点的全仓相似度扫描**：本 workflow 从一处已知锚点出发，**不**用来「找所有相似的代码」——那是 `scan_fp.py --only FP-XX` 的职责。
6. **结论克制**：未找到兄弟实现写「无兄弟实现」，不写「两侧均无缺陷」。

## 5. 停止条件

- 七对齐面全部填满且无「不一致」→ 结束，记「本轮对拍未发现不对称」；
- 同一对齐面连续 3 对兄弟均为「有意差异」→ 停止该面并记录（说明该维度天然有差异）；
- 兄弟数 > 8 时按维度分组，每组抽「最可能分叉的 2 对」（近期改动过的、新平台适配的），并在报告写明抽样口径。
