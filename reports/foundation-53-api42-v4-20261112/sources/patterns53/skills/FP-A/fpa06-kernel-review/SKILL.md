# FP-A06 aclnn 接口检视（fpa06-kernel-review）

对用户指定的 aclnn 接口（如 aclnnScatterNd）做 FP-A06 专项源码检视：先定位算子实现，再按清单逐项核查，每个结论给出**文件 + 行号 + 推导链**证据，命中即出 Bug 卡，输出检视报告。**本模式特殊纪律：① 缺陷特征是「开了确定性开关仍不固定」——同一用例连续两次运行结果 bitwise 不一致，或确定性二进制对比不通过；② 判据是**多轮 bitwise 一致性**，单轮数值断言（UT/golden）天然漏检本型；③ 「结果不固定」有多个随机性来源（未消除的 float 原子加、多核归约未定序、未清零缓冲区/padding 残留随机数、空地址取到随机数）——必须逐源排查，不得只核 `GetDeterministic` 分支就下结论；④ 触发签名 `AtomicAdd|SetAtomicAdd|Deterministic|GetDeterministic` 命中只表示「值得人工核」，无命中时仍须核查未清零缓冲等隐蔽来源。**

## 0. 与相邻模式的边界

| 相邻模式 | 分工 |
|---|---|
| FP-A02（归约/累加实现顺序与竞品不一致） | **最易混淆项**：A02 是**顺序固定但与标杆不一致**（同一实现多轮结果一致、与标杆有稳定偏差）；A06 是**顺序本身不定**（两次运行结果不同）。判据：同输入连续多轮是否 bitwise 一致 |
| FP-C05（确定性场景性能大幅劣于非确定性） | **功能 vs 性能**二分：C05 是确定性**开启后性能劣化**（结果正确但慢）；A06 是确定性**开启后结果仍不固定**（正确性面）——同一算子可两者并存，报告双向关联 |
| FP-A05（脏数据/数据踩踏） | **机理 vs 后果**二分：A05 管 workspace/缓冲未清零的**脏数据机理**；A06 管该脏数据在**确定性场景**下表现为「随机数残留」的后果（卡片明确关联：A05 的 workspace 未清零在此型表现为随机数残留）——按主导视角归属并双向关联 |
| FP-A04（功能问题演变为精度静默故障） | A04 是**本应报错却静默输出错值**；A06 是**结果随运行变化**（随机性）——按「是否有错误被吞」与「是否随机」分 |
| FP-A08（切块粒度差异致离群点精度问题） | A08 是尾块/padding 引入的**确定性**偏差；A06 是**未清零 padding 残留随机数**导致的不确定性——padding 值本身错归 A08，padding 未清零引入随机归 A06 |
| FP-E01（golden/UT 期望值失配） | 单轮 golden/UT 断言**天然漏检本型**——必须多轮 bitwise 一致性用例 |

**症状反查定位**：开启确定性开关后同一用例两次结果不一致 → 原子加/多核归约未定序面（清单①②③）；确定性二进制对比不通过、输出 mask 的 padding 部分非确定 → 未清零缓冲/padding 面（清单④）；某场景（如 LSE 不返回）框架侧传空地址后 ttk 确定性测试哈希不一致 → 空地址取随机数面（清单⑤）；关确定性正常、开确定性仍波动 → 确定性分支未真正生效面（清单①）。

## 1. FP-A06 模式卡摘要（检视依据，源自本库 `patterns/FP-A/FP-A06.md`，v3.1）

- **编号 / 名称**：FP-A06 确定性开关下结果不固定 ｜ **类别**：精度 ｜ **风险**：高（S3×O3=9）｜ **状态**：活跃
- **适用声明头**（照抄卡片）：仓 All ｜ 侧别 Kernel ｜ 载体 Kernel源码 ｜ 触发 AtomicAdd|SetAtomicAdd|Deterministic|GetDeterministic ｜ 默认启用 true
- **skill 核查面**：侧别 Kernel——skill 落地为 `op_kernel/` 中原子加、归约定序、缓冲区/padding 初始化与确定性分支的实现（含 arch35 / regbase / SIMT 等架构变体）；延伸至 `op_host` 侧确定性配置的传递链（tiling/attr 到 kernel 的确定性开关传导）与 `op_api` 的确定性分支
- **故障机理**：确定性分支未真正生效；多核归约顺序不定、原子加（float）路径未消除。
- **触发条件**：开启确定性计算开关，多核/多卡场景。
- **典型表现**：网络精度波动、精度差异。
- **源码审查映射点**：确定性分支是否真正生效；多核归约顺序不定、原子加（float）路径。
- **检测签名**（命中即候选缺陷点位）：`AtomicAdd|SetAtomicAdd|Deterministic|GetDeterministic`（确定性相关实现定位点）。
- **测试拦截建议**：同输入连续多轮 bitwise 级一致性用例（开确定性开关）。
- **实证案例**：ops-nn **#3728** ScatterNd 开启确定性计算后同一用例两次结果不一致（950PR，master 与 9.1.0 分支均复现）；**#1694 / #1559** ScatterNd 开启确定性后仍存在精度问题（#1559 早于 #1694，同根因两次记录）；**#2818** indexadd 确定性异常；ops-math **#2223** DropOutV3 输出 mask 的 padding 部分未清零、**保留随机数**，确定性二进制对比不通过；ops-transformer **#4700** MQSMLA/SML 在 LSE 不返回场景框架侧传空地址，ttk 确定性测试取到随机数致重复测试哈希不一致。**共性特征：确定性开关开启后仍有未消除的随机性来源（未清零缓冲区 / 未排序的原子加 / 未初始化的 padding）。**
- **关联**：FP-A02、FP-C05、FP-A05（A05 的 workspace 未清零在此型中表现为「随机数残留」）。

## 2. 检视输入与算子定位

**输入**：aclnn 接口名（必填，如 `aclnnScatterNd`）；可选 ref（默认 master）、指定仓（默认自动定位）；可选现象描述（是否开确定性开关 / 两次结果差异 / 平台与分支——用于直接定位随机性来源）；可选复现条件（arch + dtype + 场景开关，如 LSE 是否返回）。

**接口名 → 算子目录换算**：去 `aclnn` 前缀 + 驼峰转下划线小写：
`aclnnScatterNd → scatter_nd`、`aclnnIndexAdd → index_add`、`aclnnDropOutV3 → dropout_v3`。

**仓定位顺序**（GitCode `cann` 组织，逐仓用目录列表确认）：`ops-nn`（index/scatter/embedding 类——实证集中地）→ `ops-math`（math/random 类）→ `ops-transformer`（attention/moe 类）→ `ops-cv`。**类目名不总与直觉一致**，以目录列表为准。FP-A06 高发面：含 scatter/index_add 等**原子累加**的算子、多核并行归约实现、带 mask/padding 输出的算子（DropOut 类）、有随机数/空地址旁路的算子（attention 的 LSE 类可选输出）、带确定性分支开关的算子。

**算子目录结构约定**（以实证算子为例，具体布局以目录列表为准）：

```text
{类别}/{op_name}/
├── op_kernel/                # kernel 头文件——主检视面（原子加/定序/清零）
│   └── arch35/ regbase/ ...  # 架构变体
├── op_host/                  # def / infershape / tiling——确定性开关传导面
│   └── op_api/               # aclnn_*.cpp（确定性分支与空地址处理）

```

## 4. 检视清单（每点：查什么 → 何处 → 命中判据）

对算子的 `op_kernel/`（含架构变体）全部相关文件逐点核查，`op_host` 确定性开关传导与 `op_api` 确定性分支/空地址处理同步核对，**每点先查命中面、再做反证排除**；已消除随机性的实现要记录为防护面证据。

### ① 确定性分支是否真正生效
- 查什么：`GetDeterministic` / 确定性开关从 attr → tiling → kernel 的**传递链是否闭合**——kernel 是否真的读到该开关并改变执行路径；分支内的实现是否确实消除了随机性（而非只改了变量名/只打日志）；开关的默认值与框架侧约定是否一致。
- 何处：`op_api` 的确定性分支、`op_host` tiling 的开关传导、`op_kernel` 的确定性路径。
- 命中判据：开关未传到 kernel / 分支内未实际消除随机性 / 分支与注释意图不符 ⇒ 命中候选。

### ② float 原子加路径是否消除或定序
- 查什么：`SetAtomicAdd` / `AtomicAdd`（float）路径在确定性模式下是否被**消除**（改走确定性模板）或**定序**（排序后累加）；非确定性模板与确定性模板的分派条件是否正确；原子加的核间竞争顺序是否受分核方案影响（实证 #3728/#1694/#1559 ScatterNd 确定性后仍不一致）。
- 何处：kernel 的原子累加路径、tiling 的确定性模板分派、`SetAtomicAdd` 调用点。
- 命中判据：确定性模式下仍存在 float 原子加且无定序 ⇒ 命中候选。

### ③ 多核归约顺序确定性
- 查什么：多核部分和的**汇总顺序**是否固定（核号/块号索引是否稳定）；确定性模式下是否避免依赖核完成时序（如 `SyncAll` 后按固定次序汇总）；分核数变化是否改变结果。
- 何处：kernel 跨核汇总段、workspace 读写次序。
- 命中判据：汇总顺序依赖核完成时序 / 未固定 ⇒ 命中候选。

### ④ 缓冲区与 padding 清零（与 A05 交界）
- 查什么：输出 mask / padding 部分是否**显式清零**（实证 #2223：DropOutV3 输出 mask 的 padding 部分未清零、保留随机数，确定性二进制对比不通过）；workspace 与临时缓冲在确定性模式下是否自清零；未写满的尾块是否残留上一轮/随机数据。
- 何处：kernel 输出写入段、padding 处理段、workspace 初始化处。
- 命中判据：存在「padding/未写满区域未清零 → 残留随机数进入输出或对比」的路径 ⇒ 命中候选（机理侧同步关联 A05）。

### ⑤ 空地址 / 可选输出旁路取随机数
- 查什么：可选输出（如 attention 的 LSE）在**不返回场景**下框架侧是否传空地址、算子是否仍读该地址（实证 #4700：MQSMLA/SML 在 LSE 不返回场景框架侧传空地址，ttk 确定性测试取到随机数致重复测试哈希不一致）；可选输入的默认值与空指针处理是否确定。
- 何处：`op_api` 可选参数处理、kernel 对可选输出地址的读写路径。
- 命中判据：存在「空地址/未初始化可选输出被读取」的路径 ⇒ 命中候选。

### ⑥ 多轮 bitwise 一致性测试覆盖
- 查什么：`tests/` 是否有**开启确定性开关**的同输入连续多轮 bitwise 级一致性用例；确定性二进制对比用例是否覆盖 padding/mask 全区域；单轮数值断言不足以拦截本型。
- 何处：`tests/` 的确定性用例与对比口径。
- 命中判据：无多轮 bitwise 用例 / 只比数值不比二进制 ⇒ 记观察项（测试面缺口）。

## 5. 检视流程

1. **定界**：换算 op 目录、确认所在仓与 ref；确认架构变体布局；记录用户现象（是否开确定性 / 两次差异 / 平台与场景开关）。
2. **枚举**：目录列表列出 `op_kernel/`（含架构子目录）与 `op_host` / `op_api` 相关文件、`tests/`，产出文件清单。
3. **触发词扫描**：按 `AtomicAdd|SetAtomicAdd|Deterministic|GetDeterministic`、`Init|Duplicate|zeros|padding|mask`、可选输出/空地址处理定位风险面（本地仓用 grep；API 模式逐文件拉取后检查）。**触发为关键词：签名零命中时清单仍须逐项核查完毕**（未清零缓冲等来源可无签名）。
4. **逐点核查**：按第 4 节 ①~⑥ 记录命中面与防护面证据（文件:行号）；对每个随机性来源给出「开关是否覆盖该来源」的推导。
5. **反证排除**：确定性分支传导闭合且真正消除随机性、float 原子加已消除或定序、汇总顺序固定、padding/workspace 显式清零、可选输出空地址有防护 → 明确写出反证理由。
6. **判定**：按第 7 节标准给出 命中 / 观察项 / 反证排除。
7. **GitCode 查重**（仅命中项）：issues API 按接口名 + `确定性|deterministic|不一致|随机|bitwise` 检索，逐条比对是否同机理；无同机理才立卡。
8. **业务可达性核查**（仅命中项）：判 B 等级、定业务影响类型、给处置建议；默认保守（无法证明不可达即记 B3），降档须附证据；B 不改 S×O 档位。
9. **出报告**：按第 8 节模板落盘；所有结论标注「静态推演，需开确定性开关的多轮 bitwise 实测确认」并附实测方案。

## 6. 风险定级（S×O）与业务影响评估（B 轴）

- **S**：S3（确定性失效致结果不固定 / 网络精度波动——结果错但可运行）；S2（仅特定平台/分支复现的不确定性）；S1（不影响最终结果的不确定中间量）。
- **O**：O3 = ≥2 条独立实证；O2 = 1 条独立实证；O1 = 仅静态扫描命中或团队笔记（实证 = 确认对应的 issue / PR，或经跨仓、跨分支核验确认的缺陷记录，同权计入）。静态推演命中且无实证默认 **O1**；升档须在报告中给出实证依据。
- **风险 = S×O**：≥6 高；3/4 中；1/2 低。FP-A06 基准：模式卡整体 S3×O3=9（高）；纯静态命中 S3×O1=3（中，暂定，实测后复评）。

### B 轴：业务影响评估（与 S×O 正交；报告层新增，不改卡片定级）

S×O 回答"多严重、多常见"，**不回答"真实业务能不能碰到"**。B 轴补这一问，只决定**修复优先级建议**，**不参与 S/O 取值、不改 S×O 档位与卡片元数据**。

**业务可达性（B）**——触发条件在真实负载中的可达程度：

| 等级 | 判据 | 证据要求 |
|---|---|---|
| B3 现实可达 | 主流框架/公开模型默认路径即可命中（如 PTA/torch_npu、vLLM、MindIE 常规调用） | 调用方或公开负载来源 |
| B2 条件可达 | 需特定 attr/dtype/shape 组合，业务中存在但非默认 | 该组合的业务来源 |
| B1 边界/不可达 | 需极端、超规格或非法参数（超出接口合理上限的 shape、退化/非法输入） | "为何不可达"的说明 |

- **默认保守**：无法证明不可达 → 记 **B3**；降为 B1/B2 必须附证据，**不得仅凭"业务应该不会这么用"**。
- 超规格参数是否算 B1 取决于**接口契约**：契约允许但业务不用 → B1；契约不允许（本应报错）→ 属校验缺失（FP-B04/B05 类），另行归属。

**业务影响类型**（命中后对用户可见结果的后果，用业务语言表述）：静默精度损失（模型效果下降 / loss 不收敛 / 偶发 NaN）｜ 任务失败中断（报错 / 崩溃 / 挂死）｜ 性能退化 ｜ 仅可观测性（日志 / 错误码 / 文档，不影响结果）。

**处置建议**（由两轴推导的报告结论，非新档位）：

| S×O \ B | B3 现实可达 | B2 条件可达 | B1 边界/不可达 |
|---|---|---|---|
| 高（≥6） | 尽快修 | 尽快修 | 排期修 |
| 中（3/4） | 尽快修 | 排期修 | 记录（业务难以触达） |
| 低（1/2） | 排期修 | 记录 | 记录 |

## 7. 判定标准与反误报原则

- **签名 / 触发词命中 ≠ 成立**：`AtomicAdd`/`Deterministic` 在 kernel 中普遍存在——命中只是定位提示，必须证明「确定性模式下该随机性来源**未被覆盖**」；确定性分支存在但真消除了随机性即反证排除。
- **三种判定**：
  - **命中**（可静态证缺陷路径）：「确定性开关下仍存在未消除随机性来源（原子加/汇总时序/未清零 padding/空地址）」的推导链完整 → 立 Bug 卡（档级按实测证据定）；
  - **观察项**：随机性来源存在但确定性模式下是否被覆盖依赖运行时确认、或仅测试面缺口 → 记录并附实测方案，按 S3×O1 暂定；
  - **反证排除**：确定性传导闭合、原子加已消除/定序、缓冲区与 padding 清零、空地址有防护 → 明确写出反证理由（防护面证据）。
- **「关确定性正常」不是反证**：本型只在开确定性时暴露，须在确定性模式下核对。
- **「单轮 UT 通过」不是反证**：单轮数值断言天然漏检不确定性，必须多轮 bitwise 一致性。
- **「同轮结果一致」需与 A02 区分**：若多轮 bitwise 一致但均与标杆有稳定偏差 → 转 A02（顺序固定但与标杆不一致）。
- **不臆造行号**：每条证据必须是实际读到的 文件:行号；引用实证样板时同样给出路径与行号，issue 时点行号与本仓 HEAD 漂移时注明。

### 判定纪律补充（v3.6）：非对称增减、证据等级与误判记录

**增减不对称**：允许追加候选（有据即可，错了可由用户排除）；**撤销或否决候选必须附 `[文件]:[行号] [代码行]` 负向证据**。无证据的「看起来没问题」一律记为「未核查」，不得计入反证排除，也不得据此下调等级——否决造成的漏报用户不可见、不可恢复。

- **证据等级**（Bug 卡必填）：`静态可证` = 推导链完整且触发输入可静态构造；`需实测确认` = 依赖运行时输入规模、设备行为或环境差异。标 `需实测确认` 的条目**不得以「命中」名义出卡**，按观察项记录并附实测用例。
- **Agent 误判记录**（Bug 卡必填）：本次被推翻的假设、推翻它的证据（`[文件]:[行号] [代码行]` 或实测输出）、判定标准是否随之修订；无推翻写「无」。
- **误判回流**：同类误判在 3 次检视中重复出现，登记至 `cases/misjudgments.jsonl`（字段见 `cases/README.md`），并在本模式判定标准中新增对应防线；守门 C19d 校验台账字段合法。

## 9. 示例速览：aclnnScatterNd

- **定位**：`cann/ops-nn` → `index/scatter_nd/`（index/scatter 类；类别与目录布局以目录列表确认为准；op_kernel 为原子加与定序的主检视面，op_host 含 def / tiling / 确定性模板分派）。同批实证样板：`cann/ops-nn` `index_add`（#2818）、`cann/ops-math` `dropout_v3`（mask padding 未清零，#2223）、`cann/ops-transformer` MQSMLA/SML（LSE 不返回场景空地址，#4700）。
- **检视面提示**（引导，不预设结论，仍须逐点核查；行号以本地 HEAD 为准）：
  - 清单①②：`scatter_nd` kernel 的 `SetAtomicAdd` / 原子累加路径与 tiling 的确定性模板分派——核查确定性模式下是否消除或定序 float 原子加；实证 #3728（950PR，master 与 9.1.0 分支均复现）、#1694 / #1559 同根因两次记录——本地若已消除，记录为防护面证据；
  - 清单④：`dropout_v3` 输出 mask 的 padding 部分是否显式清零（实证 #2223 保留随机数致确定性二进制对比不通过）；
  - 清单⑤：attention 类算子可选输出（LSE）不返回场景的空地址处理（实证 #4700）；
  - 清单①③⑥：确定性开关从 attr → tiling → kernel 的传导链、跨核汇总顺序、`tests/` 多轮 bitwise 用例覆盖。
- 任何一点的最终判定以第 4/5/7 节口径为准，禁止凭算子类型直接下结论。

## 10. 能力边界与自检（v3.8）

### 能力边界

- **静态可证**：清单里能在源码内给出「`文件:行号` + 推导链」的部分，按第 7 节判据出卡。
- **需实测确认**：依赖运行时输入规模、设备行为或环境差异的结论，只能记观察项并附实测用例（证据等级见第 7 节）。
- **不覆盖**：本模式以外的机理（边界见第 0 节）与仓外框架侧行为；`TRIAGE.md` 只负责收敛候选，不构成判定依据。
- **找不到 ≠ 没有**：按清单未命中只说明「本轮未发现」，不得表述为「该算子无此缺陷」；抽样核查须在报告写明抽样口径。

### 自检


### 工作量与抽样（v4.0）
