修复 FlashAttentionScore TND 缺失序列长度时的 Host tiling 未定义行为

TND 布局使用 actual_seq_qlen 和 actual_seq_kvlen 描述 batch 边界。当前 Arch35 Host tiling 将缺省或零元素长度表视为成功，随后解引用空 vector 的 std::max_element 结果，可能导致未定义行为。
在读取长度数据前校验输入存在、为一维且非空，并补充缺省输入和零元素输入的 Host tiling 回归用例。单个 batch 的序列长度仍可为 0，需通过非空累计长度数组表示。

关联 Issue: https://gitcode.com/cann/ops-transformer/issues/7450

变更摘要

本 PR 针对 FlashAttentionScore 在 TND 布局下缺失或为空的序列长度输入所导致的 Host tiling 未定义行为进行修复。arch35 的 FlashAttentionScoreTilingRegbase::GetActualSeqLenData 此前把空指针、非一维形状、空数据等异常情况当作成功返回，从而继续对空的长度数组执行 std::max_element 等操作。变更将该函数改为在读取长度数据前做严格校验并返回失败，同时更新算子原型中 actual_seq_qlen、actual_seq_kvlen 的接口说明，明确 TND 场景下两者必须同时提供且为非空一维张量。

主要改动

  • GetActualSeqLenData 校验失败即返回错误: 将输入张量缺失、数据指针为空这两类情况的处理从告警后继续返回 true 改为通过 OP_LOGE_FOR_INVALID_ARGUMENT_WITH_REASON 报错并返回 false，阻断后续对无效数据的解引用。
  • 新增非空一维形状校验: 在获取 actual_seqLenShape.GetDim(0) 后校验 seqLen <= 0，使空长度表不再被视为合法输入，错误提示统一为必须是非空一维张量。
  • 错误日志改为带输入名定位: 引入 inputName，根据 inputIdx 是否为 ACTUAL_SEQ_LENGTH_INPUT_INDEX 区分 actual_seq_qlen 与 actual_seq_kvlen，报错信息中直接指明具体输入。
  • 算子原型文档补充接口约束: 在 flash_attention_score_proto.h 中修改 actual_seq_qlen、actual_seq_kvlen 的注释，说明 TND 布局下二者需配合使用，累计长度必须为非空一维张量。
  • 错误信息语义表述: 错误原因说明会提示 TND 布局要求两个 actual sequence length 输入同时提供，对应 PR 描述中“缺失序列长度即判定失败”的行为约定。
