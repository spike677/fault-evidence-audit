# FP-C06 aclnn 接口检视（fpc06-soc-generation-perf-review）

对用户指定的 aclnn 接口（如 aclnnAdaptiveMaxPool3dBackward、aclnnConvolutionBackward）做 FP-C06 专项性能源码检视：先定位算子实现，再按清单逐项核查，每个结论给出**文件 + 行号 + 推导链**证据，命中即出 Bug 卡，输出检视报告。**本模式特殊纪律：① 结果对、只是新代际卡上变慢——静态检视只能产出「嫌疑点」，任何「劣化 N 倍」的量化结论必须以基线差分实测为准；② 判据是「同版本、同 shape、仅 SOC 代际不同（A5 vs A2/A3）的耗时对比」，缺代际对比轴即不成立；③ 缺陷形态是「新 SOC 适配不完整的性能路径」——代际分支遗漏/未分流，既可能让新代际走未优化的通用路径，也可能反向伤及旧代际（实证 #2876）。**

## 0. 与相邻模式的边界

| 相邻模式 | 分工 |
|---|---|
| FP-B02（代际/型号分支遗漏，功能面） | **同一处 `GetSocVersion|SOC_VERSION` 分支的两个后果面**：B02 漏分支致**功能/结果错**；C06 漏分支致**性能回退**（新代际走通用路径）。实证 #2876 indexputv2 **未区分 A5 芯片**、反向影响 A3 性能——分支缺失同时伤及旧代际，性能面归本条，功能面归 B02，须同核 |
| FP-A17（A1 与 A2 硬件代际精度差异） | **代际家族三面**：A17 精度面、B02 功能面、C06 性能面——同一 `socVersion` 分支须三面同核；硬件代际精度规格差异致结果不一致归 A17，致耗时变长归本条 |
| FP-C04（A2 B2 机器性能劣于 A2 B3） | **对比轴不同**：C06 是**跨 SOC 代际**（A5 vs A2/A3）；C04 是**同芯片不同板型**（A2 B2 vs A2 B3）。同一份「性能劣于」现象先确认轴 |
| FP-C01（端到端耗时占比高） | 跨版本回归归 C01 子型③；C06 判据须「同版本、仅 SOC 不同」 |
| FP-C05（确定性场景性能劣化） | 开关轴；若代际差异仅在确定性开关下显现，勿把开关轴误记为代际轴 |

**症状反查定位**：**新代际芯片（A5/950 系）上性能不升反降**、精度与功能全对 → C06；若同时伴随结果错 → 同步按 B02 核功能面、按 A17 核精度面；跨版本同 SOC 回退 → C01 子型③；同 SOC 仅板型不同 → C04；仅确定性开关下劣化 → C05。**首发适配期特征：新代际尚未完成性能路径迁移，出现「新卡跑不过旧卡」。**

## 1. FP-C06 模式卡摘要（检视依据，源自本库 `patterns/FP-C/FP-C06.md`，v3.1）

- **编号 / 名称**：FP-C06 A5 性能劣于 A2 ｜ **类别**：性能 ｜ **风险**：高（S2×O3=6）｜ **状态**：活跃
- **适用声明头**（照抄卡片）：仓 All ｜ 侧别 All ｜ 载体 Tiling源码,Kernel源码 ｜ 触发 GetSocVersion|SOC_VERSION ｜ 默认启用 true
- **skill 核查面**：侧别 All——skill 落地为 op_host tiling / infershape 的 SOC 代际分流（`GetSocVersion` / `SOC_VERSION` / `socVersion` 读取点）与 `config/<soc>/` 的按代际配置，以及 op_kernel 的按代际模板实例化与指令特化；op_api 的实现选择点（代际决定走哪套实现）
- **故障机理**：**新 SOC 适配不完整的性能路径**——新代际首发适配期，性能路径未完整迁移/未按代际分流：① 代际分支遗漏，新代际落入**通用（未优化）路径**；② 旧代际的优化分支被改动后**未按代际隔离**，反向伤及旧代际性能（实证 #2876：`indexputv2` 未区分 A5 芯片，影响 A3 性能）；③ tiling 阈值/分核、kernel 模板/指令特化未按代际实例化。
- **触发条件**：新代际芯片首发适配期；跨代芯片（A5 vs A2/A3）部署同一算子、同版本同 shape。
- **典型表现**：**新代际性能不升反降**；精度全对、功能全对、无报错，仅耗时变长；单看新代际绝对值可能仍「合格」，只有跨代际对比才暴露；首发适配期的高发期。
- **源码审查映射点**：新 SOC 适配中的性能路径完整性。
- **检测签名**（命中即候选缺陷点位）：`GetSocVersion|SOC_VERSION|socVersion` 与分支语句（`if` / `switch` / 三元）同现；代际常量（`ASCEND910|ASCEND950|arch35` 类）；`config/<soc>/` 目录的覆盖度；kernel 模板的按代际实例化清单；代际分支内**仅列出部分代际**且缺 default/fallback。
- **审查关键词**（命中只表示值得人工审）：`GetSocVersion` 分支的**完整性**（新代际是否被枚举、default 落点是否为未优化路径）；旧代际分支是否被新代际改动波及（缺代际隔离）；`binary.json` 是否按代际分别维护；tiling 阈值/分核是否随代际变化。
- **测试拦截建议**：跨代际性能基线对比（同版本、同 shape，A5 vs A2/A3）；把 SOC 代际作为固定评测维度记录；新代际首发适配期加强跨代看护。
- **实证案例**：ops-nn **#3724** aclnnAdaptiveMaxPool3dBackward 存在用例 **A5 性能劣化于 A2/A3**；ops-nn **#3677 / #3822** convolution_backward 接口典型 case 在 A5 上性能劣于 A3；ops-nn **#4509** aclnnAdaptiveMaxPool3d 接口典型 case 在 A5 上性能劣于 A3；ops-nn **#5786** LSTM 算子精度、性能相对 A2 存在劣化；ops-nn **#2876** aclnn 接口调用 indexputv2 **未区分 A5 芯片**，导致影响了 A3 的性能（**反向问题：代际分支缺失同时伤及旧代际**）；ops-math **#2148** A5 polar 算子性能达不到预期（Vector 算力 bound 场景仅 0.3x，对标 950DT 486T vs H100 989T）；ops-transformer **#5213** MhcPresinkhorn 正向 A5 性能优化。**共性特征：新代际首发适配期，性能路径未完整迁移/未按代际分流，出现「新卡跑不过旧卡」。**
- **关联**：FP-A17（代际精度面）、FP-B02（代际/型号分支遗漏的功能面）、FP-C04（同芯片板型轴）。

## 2. 检视输入与算子定位

**输入**：aclnn 接口名（必填，如 `aclnnAdaptiveMaxPool3dBackward`）；可选 ref（默认 master）、指定仓（默认自动定位）；可选现象描述（跨代际耗时数据——用于反查优先清单点）；可选复现条件（两个对比代际 + shape + 版本——性能结论的可比性要素）。

**接口名 → 算子目录换算**：去 `aclnn` 前缀 + 驼峰转下划线小写：
`aclnnAdaptiveMaxPool3dBackward → adaptive_max_pool3d_backward`、`aclnnConvolutionBackward → convolution_backward`、`aclnnLSTM → lstm`、`aclnnIndexPutV2 → index_put_v2`。

**仓定位顺序**（GitCode `cann` 组织，逐仓用目录列表确认）：`ops-nn`（pool/convolution/norm/rnn/index 类）→ `ops-math`（math/conversion 类）→ `ops-cv`（image/vision 类）→ `ops-transformer`（attention/moe 类）。**类目名不总与直觉一致**，以目录列表为准。FP-C06 高发面：带多代际分支（`GetSocVersion` 判定）的 tiling、按代际实例化的 kernel 模板族（`arch35` 类子目录）、`config/<soc>/` 目录族、新代际首发适配期改动过的算子（含反向/梯度算子与 RNN 类）。

**算子目录结构约定**（已验证示例 `cann/ops-nn` → `pool/adaptive_max_pool3d_backward/`）：

```text
{类别}/{op_name}/
├── op_host/
│   ├── *_tiling*.cpp      # GetSocVersion/SOC_VERSION 代际分流——主检视面
│   ├── *_infershape.cpp
│   └── config/<soc>/      # *_binary.json（按代际的分核/派发配置——覆盖度检视面）
├── op_kernel/             # 按代际实例化的模板与指令特化（arch35 等子目录）
├── op_api/（或 op_host/op_api/）  # 代际决定的实现选择点
├── op_graph/  tests/  docs/  examples/
└── CMakeLists.txt
```

**aclnn 出口位置提示**：多数算子的 aclnn 出口在 `op_host/op_api/` 或顶层 `op_api/`（`aclnn_*.cpp`），以目录列表与 `docs/aclnn*.md` 确认。

## 4. SOC 代际路径检视清单（每点：查什么 → 何处 → 命中判据）

对算子的 op_host tiling / infershape（代际分流 + config）/ op_kernel（按代际模板与指令）/ op_api（实现选择）全部相关文件逐点核查，**每点先查命中面、再做反证排除**，防护面（已完整分流、已按代际隔离）也要记录。

### ① 代际分支枚举完整性与 default 落点
- 查什么：`GetSocVersion|SOC_VERSION|socVersion` 分支是否**枚举全部需支持代际**（新代际是否在内）；`switch`/`if` 链的 **default / fallback 落点**是否为未优化的通用路径（新代际落入 fallback 即性能回退的直接成因）。
- 何处：op_host tiling / infershape 的代际判定分支、op_api 的实现选择点。
- 命中判据：可给出「代际 → 走哪条路径」对表，且新代际落在 fallback / 通用路径 ⇒ 命中（实证族：#3724 / #3677 / #3822 / #4509 / #2148）。

### ② 新代际性能路径迁移完整性
- 查什么：新代际是否拥有**专属优化路径**（专属 tiling 参数、专属 kernel 模板、指令特化），还是复用旧代际/通用实现；旧代际的优化（向量化、合并搬运、专用指令）是否已迁移到新代际。
- 何处：op_kernel 的按代际模板实例化（`arch35` 类子目录）、tiling 中按代际的阈值/分核推导。
- 命中判据：新代际无专属实现 / 优化未迁移且可指认 ⇒ 命中（实证族：#3724 AdaptiveMaxPool3dBackward、#4509 AdaptiveMaxPool3d、#2148 polar 的 Vector 算力 bound 场景 0.3x）。

### ③ 旧代际误伤（反向问题）
- 查什么：新增/改动代际分支时，旧代际分支是否被**未隔离的共用改动**波及——如公共路径按新代际假设修改后旧代际一并受影响（实证 #2876：indexputv2 **未区分 A5 芯片**，影响 A3 性能）。
- 何处：代际分支之外的共用实现、被两代际共享的 tiling/kernel 公共路径。
- 命中判据：可指认「共用改动按新代际假设进行，旧代际路径随之变化」⇒ 命中（反向问题，须单独记录）。

### ④ 配置与派发的代际覆盖度
- 查什么：`config/<soc>/` 是否覆盖全部需支持代际（新代际是否有独立 `binary.json`）；tilingkey / 分核配置是否按代际分别维护，还是新代际复用旧代际配置。
- 何处：`config/<soc>/` 目录结构与配置项、tilingkey 计算。
- 命中判据：新代际缺独立配置而沿用旧代际配置 ⇒ 记录为嫌疑点（配置面）。

### ⑤ kernel 模板与指令的代际特化
- 查什么：kernel 模板是否按代际实例化；新代际可用的更优指令（如更高吞吐的向量/矩阵指令）是否被采用，还是沿用旧代际指令集实现。
- 何处：op_kernel 模板清单与 `arch*` 子目录、指令使用点。
- 命中判据：新代际可用更优指令而未使用（对照同仓已按代际特化的算子样板）⇒ 命中（实证族：#5213 MhcPresinkhorn 正向 A5 性能优化即此类）。

### ⑥ 代际家族三面同核（与 A17/B02 联动）
- 查什么：同一 `socVersion` 分支改动处，是否同时存在**精度面**（A17：代际指令精度规格差异）与**功能面**（B02：分支遗漏致结果错）风险；实证 #5786 LSTM 即「精度、性能相对 A2 存在劣化」并存。
- 何处：代际分支内的精度相关硬编码、功能条件分支。
- 命中判据：同处存在精度/功能风险 ⇒ 在报告中交叉标注，性能结论归本条、精度归 A17、功能归 B02。

### ⑦ 反证排除（防误报）
- 查什么：新代际是否**本就不支持**该算子的优化路径（客观能力差异）且属已知规划；现象是否实际由**跨版本**或**同芯片板型**差异造成（应转 C01 子型③ 或 C04）；差异是否源于评测环境/基线口径。
- 何处：算子支持矩阵、评测配置、基线定义。
- 命中判据：属客观能力差异且已规划 / 对比轴实为版本或板型 / 基线口径不一致 ⇒ 反证排除（写明理由）。

### ⑧ 测试拦截面（跨代际基线）
- 查什么：tests / 评测脚本是否具备**跨代际性能基线对比**；SOC 代际是否作为固定评测维度记录。
- 何处：tests/ut、examples、评测配置。
- 命中判据：无代际维度可静态确认 ⇒ 记录为拦截缺口。

## 5. 检视流程

1. **定界**：换算 op 目录、确认所在仓与 ref/HEAD；**确认对比轴为 SOC 代际**（若为跨版本转 FP-C01 子型③，若为同芯片板型转 FP-C04，若为确定性开关转 FP-C05）；核对可比性要素（两代际、shape、版本）是否齐备。
2. **枚举**：目录列表列出 op_host（tiling + infershape + config）/ op_kernel（含 arch 子目录）/ op_api 全部相关文件，产出文件清单。
3. **触发词扫描**：按 `GetSocVersion|SOC_VERSION|socVersion`、代际常量（`ASCEND910|ASCEND950|arch35` 类）、`binary.json` 定位风险面（本地仓用 grep；API 模式逐文件拉取后检查）。
4. **代际分叉表构建**：以第 4 节 ① 建立「代际 → 实现/配置/模板 → 是否专属优化」对表——后续所有清单点都在此表上比对。
5. **清单逐项核查**：每点记录命中面与防护面证据（文件:行号）；同步按 ⑥ 交叉标注精度/功能风险。
6. **反证排除**：代际分流完整、新代际有专属优化、无共用改动波及旧代际、对比轴无误 → 明确写出反证理由。
7. **判定**：按第 7 节标准给出 命中 / 观察项 / 反证排除。
8. **GitCode 查重**（仅命中项）：issues API 按接口名 + `A5|代际|SOC|性能|劣化` 检索，逐条比对是否同机理；无同机理才立卡。
9. **业务可达性核查**（仅命中项）：判 B 等级、定业务影响类型、给处置建议；默认保守（无法证明不可达即记 B3），降档须附证据；B 不改 S×O 档位。
10. **出报告**：按第 8 节模板落盘；静态推演结论一律标注「需基线差分实测确认」，并附跨代际对比方案。

## 6. 风险定级（S×O）与业务影响评估（B 轴）

- **S**：S2（性能不达标 / 交付受限——新代际性能不升反降，影响新卡交付）；S1（轻度资源浪费——未采用更优指令）。性能类缺陷不涉 S3/S4（结果仍正确）；若同处并存精度/功能风险，按 A17/B02 各自定级，不并入本条。
- **O**：O3 = ≥2 条独立实证；O2 = 1 条独立实证；O1 = 仅静态扫描命中或团队笔记（实证 = 确认对应的 issue / PR，或经跨仓、跨分支核验确认的缺陷记录，同权计入）。静态推演命中且无实证默认 **O1**；升档须在报告中给出实证依据。
- **风险 = S×O**：≥6 高；3/4 中；1/2 低。FP-C06 基准：模式卡整体 S2×O3=6（高）；纯静态命中 **S2×O1=2（低，暂定，量化劣化待基线差分实测后复评）**。

### B 轴：业务影响评估（与 S×O 正交；报告层新增，不改卡片定级）

S×O 回答"多严重、多常见"，**不回答"真实业务能不能碰到"**。B 轴补这一问，只决定**修复优先级建议**，**不参与 S/O 取值、不改 S×O 档位与卡片元数据**。

**业务可达性（B）**——触发条件在真实负载中的可达程度：

| 等级 | 判据 | 证据要求 |
|---|---|---|
| B3 现实可达 | 主流框架/公开模型默认路径即可命中（如 PTA/torch_npu、vLLM、MindIE 常规调用） | 调用方或公开负载来源 |
| B2 条件可达 | 需特定 attr/dtype/shape 组合，业务中存在但非默认 | 该组合的业务来源 |
| B1 边界/不可达 | 需极端、超规格或非法参数（超出接口合理上限的 shape、退化/非法输入） | "为何不可达"的说明 |

- **默认保守**：无法证明不可达 → 记 **B3**；降为 B1/B2 必须附证据，**不得仅凭"业务应该不会这么用"**。
- 超规格参数是否算 B1 取决于**接口契约**：契约允许但业务不用 → B1；契约不允许（本应报错）→ 属校验缺失（FP-B04/B05 类），另行归属。

**业务影响类型**（命中后对用户可见结果的后果，用业务语言表述）：静默精度损失（模型效果下降 / loss 不收敛 / 偶发 NaN）｜ 任务失败中断（报错 / 崩溃 / 挂死）｜ 性能退化 ｜ 仅可观测性（日志 / 错误码 / 文档，不影响结果）。

**处置建议**（由两轴推导的报告结论，非新档位）：

| S×O \ B | B3 现实可达 | B2 条件可达 | B1 边界/不可达 |
|---|---|---|---|
| 高（≥6） | 尽快修 | 尽快修 | 排期修 |
| 中（3/4） | 尽快修 | 排期修 | 记录（业务难以触达） |
| 低（1/2） | 排期修 | 记录 | 记录 |

## 7. 判定标准与反误报原则

- **性能类特殊纪律（务必贯彻）**：静态检视只能立「嫌疑点 / 优化项」——「代际分支遗漏/未分流」可静态证；但任何「劣化 N 倍」的量化结论**必须以基线差分实测为准**（同版本、同 shape、仅 SOC 不同），不可用代码审查替代性能基线看护。引用实证 #2148 的「Vector 算力 bound 场景仅 0.3x」等数据时须标注其为 issue 原文数据。
- **三种判定**：
  - **命中**（可静态证路径缺失）：代际分叉表显示新代际落在 fallback/通用路径、无专属优化、或旧代际被共用改动波及（#2876 反向问题）→ 立 Bug 卡；
  - **观察项**：分支缺失存在但降级代价需实测（无跨代际耗时数据即只能为观察项）→ 记录并附跨代际基线方案，按 S2×O1 暂定；
  - **反证排除**：代际分流完整、新代际有专属优化、无旧代际误伤、对比轴实为版本/板型 → 明确写出反证理由与防护面证据。
- **对比轴必须先确认**：跨版本 → C01 子型③；同芯片板型 → C04；确定性开关 → C05；SOC 代际 → 本条。轴错则整份结论作废。
- **代际家族三面同核**：同一 `socVersion` 分支处须同时核精度面（A17）与功能面（B02）；实证 #5786 LSTM 即精度与性能劣化并存——报告中交叉标注，勿把精度问题混入本条。
- **反向问题须单独记录**：#2876 表明代际分支缺失可能**伤及旧代际**（新代际未区分 → A3 性能受影响），检视不可只看新代际。
- **不臆造行号**：每条证据必须是实际读到的 文件:行号；引用实证样板时同样给出路径与行号，issue 时点行号与本仓 HEAD 漂移时注明。

### 判定纪律补充（v3.6）：非对称增减、证据等级与误判记录

**增减不对称**：允许追加候选（有据即可，错了可由用户排除）；**撤销或否决候选必须附 `[文件]:[行号] [代码行]` 负向证据**。无证据的「看起来没问题」一律记为「未核查」，不得计入反证排除，也不得据此下调等级——否决造成的漏报用户不可见、不可恢复。

- **证据等级**（Bug 卡必填）：`静态可证` = 推导链完整且触发输入可静态构造；`需实测确认` = 依赖运行时输入规模、设备行为或环境差异。标 `需实测确认` 的条目**不得以「命中」名义出卡**，按观察项记录并附实测用例。
- **Agent 误判记录**（Bug 卡必填）：本次被推翻的假设、推翻它的证据（`[文件]:[行号] [代码行]` 或实测输出）、判定标准是否随之修订；无推翻写「无」。
- **误判回流**：同类误判在 3 次检视中重复出现，登记至 `cases/misjudgments.jsonl`（字段见 `cases/README.md`），并在本模式判定标准中新增对应防线；守门 C19d 校验台账字段合法。

## 10. 能力边界与自检（v3.8）

### 能力边界

- **静态可证**：清单里能在源码内给出「`文件:行号` + 推导链」的部分，按第 7 节判据出卡。
- **需实测确认**：依赖运行时输入规模、设备行为或环境差异的结论，只能记观察项并附实测用例（证据等级见第 7 节）。
- **不覆盖**：本模式以外的机理（边界见第 0 节）与仓外框架侧行为；`TRIAGE.md` 只负责收敛候选，不构成判定依据。
- **找不到 ≠ 没有**：按清单未命中只说明「本轮未发现」，不得表述为「该算子无此缺陷」；抽样核查须在报告写明抽样口径。
