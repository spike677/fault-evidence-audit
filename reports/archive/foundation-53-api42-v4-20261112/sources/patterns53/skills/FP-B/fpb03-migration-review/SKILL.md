# FP-B03 aclnn 接口检视（fpb03-migration-review）

对用户指定的 aclnn 接口（如 aclnnPadDepthwiseConv2dFusion）做 FP-B03 专项源码检视：先定位算子实现，再按清单逐项核查，每个结论给出**文件 + 行号 + 推导链**证据，命中即出 Bug 卡，输出检视报告。**本模式特殊纪律：① 判定核心是「防御逻辑被移除/绕过」这一机理，两种移除方式——**漏迁**（迁移时只迁功能主体、防御分支没跟过来）与**显式跳过**（`skipCheck` 类开关、`SKIP_*_CHECK` 宏、注释掉校验后忘记恢复）——都要立卡；② 必须做**迁移前后拦截逻辑清单比对**：单看迁移后代码无法判断「少了一段校验」，须以源仓/迁移前版本为基准做差集；③ 显式跳过类缺陷常伪装成「调试遗留」，`if (skipCheck) return SUCCESS;` 在发布版本里是静默放行；④ 「应拦截场景未被拦截」的后果（错误结果静默产出）常与 FP-A04 复合放大，报告双向关联。**

## 0. 与相邻模式的边界

| 相邻模式 | 分工 |
|---|---|
| FP-A04（静默错误） | **最易复合项**：本型后果是「应拦未拦 → 错误结果静默产出」，该后果面归 A04；**成因**（防御被漏迁/被跳过）归本条——报告双向关联，不重复计缺陷 |
| FP-B01（支持面校验过严误拦截） | **方向相反的镜像**：B01 是「不该拦却拦」；本条是「该拦不拦」的迁移/跳过成因。二者同属校验面与输入面不一致 |
| FP-B05（入参校验覆盖度参差） | 同为「该拦不拦」族：B05 是**同仓内文件级**范差（有无校验骨架）；本条是**跨仓迁移**导致的防御缺失，且含显式跳过形态 |
| FP-B06（空 tensor 分支缺失） | 同为「该拦不拦」族：B06 是 `numel==0` 单一语义；本条不限输入形态，聚焦防御分支的来源（迁移/跳过） |
| FP-F04（交付面缺失） | 若「防御代码根本没随产物交付」（如模块未合入），属交付面：交付缺失归 F04，代码在但分支被删/被跳过归本条 |

**症状反查定位**：动态 shape 模型推理结果错误、静态 shape 正常 → 首查迁移进来的融合 Pass / 算子是否丢失动态 shape 拦截；某 Pass/算子在某次重构或跨仓迁移后开始出错 → 比对迁移 diff 中被删除的 `OP_CHECK` / `CheckNotNull` / `GRAPH_FAILED` 分支；搜索到 `skipCheck` / `SKIP_[A-Z_]*CHECK` / `enableCheck=false` → 校验被显式跳过；校验函数体内出现无条件 `return true` / `return GRAPH_SUCCESS` → 无条件放行；调试/性能优化期「临时关闭校验」的开关进入发布版本 → 显式跳过型。**注意：本型与 B01 方向相反，误拦截与漏拦截不要互相挂错标签。**

## 1. FP-B03 模式卡摘要（检视依据，源自本库 `patterns/FP-B/FP-B03.md`，v3.1 含 v2.16 增补）

- **编号 / 名称**：FP-B03 跨仓迁移丢失防御/拦截逻辑 ｜ **类别**：功能/兼容 ｜ **风险**：高（S3×O2=6）｜ **状态**：活跃
- **适用声明头**（照抄卡片）：仓 All ｜ 侧别 All ｜ 载体 Tiling源码,IR与图配置 ｜ 触发 skipCheck|SKIP_[A-Z_]*CHECK|OP_CHECK ｜ 默认启用 true
- **skill 核查面**：与卡片载体一致——主检视面为迁移进来的算子/融合 Pass 源码（tiling 校验分支、图 Pass 的 `CanFuseNodes` / 拦截分支、IR 与图配置）与**迁移类提交 diff**；延伸至同族未迁移算子作为「拦截行为对照样板」
- **故障机理**：算子/融合 Pass 从其它仓库（如 canndev）迁移时只迁功能主体，防御性代码（动态 shape 拦截、合法性校验分支）被漏掉；**同类后果的另一成因（v2.16 增补）：防御逻辑被「显式跳过」而非被删除**——以 `if (skipCheck) return SUCCESS;`、`SKIP_INDEX_CHECK` 类开关、或调试/性能优化期注释掉校验后忘记恢复等形式，使非法输入绕过校验直接进入执行。二者同属「**防御逻辑被移除 / 绕过**」这一机理，区别仅在移除方式（**漏迁** vs **显式跳过**）。
- **触发条件**：跨仓迁移、Pass 融合迁移场景；**调试 / 性能优化期临时跳过校验的开关被带入发布版本**（v2.16 增补）。
- **典型表现**：动态 shape 等应拦截场景未拦截，错误结果静默产出（常与 FP-A04 复合放大）。
- **源码审查映射点**：迁移类提交 diff 审查——被删除的防御分支；迁移前后拦截逻辑清单比对。
- **检测签名（v2.16 增补）**：迁移类提交 diff 中**被删除**的校验/拦截分支（`-.*(OP_CHECK|CheckNotNull|GRAPH_FAILED)`）；`skip[A-Za-z]*Check|SKIP_[A-Z_]*CHECK|enableCheck\s*=\s*false`（校验被显式跳过）；`if\s*\([^)]*\)\s*return\s+(?:true|ge::GRAPH_SUCCESS)\s*;` 出现在校验函数体内（无条件放行）。
- **测试拦截建议**：迁移类合入必附「迁移前后拦截行为对齐」清单；动态 shape 负向用例集。
- **实证案例**：ops-nn **#5522 / PR #9728** PadDepthwiseConv2dFusion 融合 Pass 自 canndev 迁移时丢失动态 shape 拦截逻辑，动态 shape 模型错误融合致推理结果错误；补回拦截分支根因级修复。
- **关联**：FP-A04、FP-B01、**FP-B05/FP-B06（同为「该拦不拦」族，按机理分工，见 FP-B01 关联字段）**。

## 2. 检视输入与算子定位

**输入**：aclnn 接口名 / 算子名（必填，如 `aclnnPadDepthwiseConv2dFusion` 或融合 Pass 名）；可选 ref（默认 master）、指定仓（默认自动定位）；可选迁移来源（源仓，如 canndev——比对基准）；可选现象描述（动态 shape 错误结果 / 某次迁移后出错——用于症状反查）。

**接口名 → 算子目录换算**：去 `aclnn` 前缀 + 驼峰转下划线小写：
`aclnnPadDepthwiseConv2dFusion → pad_depthwise_conv2d_fusion`。**注意融合 Pass 常不挂在同名算子目录下**，而是挂在主算子目录的 `op_graph/fusion_pass/` 下（如 PadDepthwiseConv2dFusion 的 Pass 位于 conv2d_v2 算子目录），**必须用目录列表与文件名检索确认**。

**仓定位顺序**（GitCode `cann` 组织，逐仓用目录列表确认）：`ops-nn`（conv/norm/matmul 类，融合 Pass 高发）→ `ops-math` → `ops-cv` → `ops-transformer`（attention/moe 类）。FP-B03 高发面：从 canndev 等仓迁移进来的算子与融合 Pass、带动态 shape 语义的 Pass、`op_graph/fusion_pass/` 下的 Pass 实现、迁移类提交触及的 tiling 校验段、含 `skipCheck` / `SKIP_*_CHECK` 类开关的代码。

**算子目录结构约定**（已验证示例 `cann/ops-nn` → `conv/conv2d_v2/`，融合 Pass 在 `op_graph/fusion_pass/` 下）：

```text
{类别}/{op_name}/
├── op_graph/
│   ├── fusion_pass/          # *_fusion_pass.cpp / .h——融合 Pass 的拦截分支主检视面
│   └── *_proto.h
├── op_host/                  # *_tiling*.cpp / *_infershape.cpp——迁移时被删的校验分支检视面
├── op_api/（或 op_host/op_api/）  # aclnn_*.cpp
├── framework/                # onnx 插件 / 图适配（视算子而定）
├── tests/ut/op_graph/        # Pass 的 UT（拦截行为对齐的现存证据）
└── docs/ examples/ CMakeLists.txt
```

## 3. 取数方式（Important）

公开网页端点被拦截，**必须走 API**（均需带 `User-Agent`；失败重试 2 次、间隔 5 秒）：

| 用途 | 端点 |
|---|---|
| 目录列表 | `GET https://api.gitcode.com/api/v5/repos/cann/{repo}/contents/{path}?ref={ref}` |
| 单文件内容 | `GET https://api.gitcode.com/api/v5/repos/cann/{repo}/raw/{path}?ref={ref}` |
| Issue 查重 | `GET https://api.gitcode.com/api/v5/repos/cann/{repo}/issues?q={关键词}` |

**已实测不可用（截至 2026-09 实测）**：`https://gitcode.com/{repo}/raw/{sha}/{path}`、`https://raw.gitcode.com/...` → 403 或拦截页；端点策略如有变化可复测。若本地已有算子仓克隆，优先直接读本地文件，行号证据以本地 HEAD 为准并记录 commit。**本模式特有取数限制**：本型判定依赖**迁移前后差集**——须同时取得迁移后代码与**迁移前/源仓版本**（历史提交 diff 或源仓对应文件）作为比对基准；只有迁移后代码无法判定「少了一段校验」。静态检视产出「防御分支缺失/被跳过」的候选点位与对齐清单，错误结果是否实际产出须用例复现验证。

## 4. 迁移/跳过检视清单（每点：查什么 → 何处 → 命中判据）

对迁移进来的算子与融合 Pass 的 op_graph / op_host / framework / tests 逐点核查，**每点先查命中面、再做反证排除**，已有的拦截分支与开关也要记录（防护面证据）。

### ① 迁移 diff 中被删除的防御分支
- 查什么：迁移类提交的 diff 中**被删除**的校验/拦截分支——`-.*(OP_CHECK|CheckNotNull|GRAPH_FAILED)`；迁移是否只带了功能主体而丢掉拦截逻辑（实证 #5522：动态 shape 拦截被漏）。
- 何处：迁移类提交的 diff；迁移后代码中「本应有拦截但为空」的位置（对照源仓/迁移前版本）。
- 命中判据：能写出「源仓/迁移前有某拦截分支 → 迁移后该分支不存在 → 对应非法输入可进入执行」的差集推导链 ⇒ 命中。

### ② 校验被显式跳过
- 查什么：`skip[A-Za-z]*Check|SKIP_[A-Z_]*CHECK|enableCheck\s*=\s*false` 类开关；`if (skipCheck) return SUCCESS;` / `if (skipCheck) return true;`；调试或性能优化期注释掉的校验；开关是否可被外部/配置置真而进入发布路径。
- 何处：校验函数入口、Pass 的 `CanFuseNodes` / 拦截判断前、图配置解析处。
- 命中判据：存在「开关置真即绕过校验」且该开关在发布配置下可开启 ⇒ 命中（显式跳过型）。

### ③ 校验函数体内的无条件放行
- 查什么：`if\s*\([^)]*\)\s*return\s+(?:true|ge::GRAPH_SUCCESS)\s*;` 出现在**校验函数体内**——条件成立即无条件放行（含恒真条件、被注释掉主体只留 return 的形态）。
- 何处：全部 `Check*` / `Verify*` / `CanFuse*` 类函数体。
- 命中判据：校验函数存在无条件放行分支（或恒真条件放行）⇒ 命中。

### ④ 迁移前后拦截逻辑清单比对
- 查什么：把源仓/迁移前版本的**全部拦截分支**列成清单，逐条在迁移后代码中确认存在性与语义等价性——不只比对「有无」，还比对条件、返回码、覆盖范围是否一致（漏 1 条即命中）。
- 何处：迁移后 Pass/算子文件的全部拦截点；源仓对应文件。
- 命中判据：清单中存在迁移后缺失或语义弱化的条目 ⇒ 命中（给出「清单条目 → 源仓行号 → 迁移后行号/缺失」对表）。

### ⑤ 动态 shape 语义拦截（本型最高发后果面）
- 查什么：融合 Pass / 算子对动态 shape 的拦截是否在位——`IsUnknownShape` / `GetShape().IsUnknownShape()` / `UNKNOWN_*` 判定；动态 shape 下是否被错误融合（实证 #5522 的后果）。
- 何处：融合 Pass 的 `CanFuseNodes` / `Check*Shape*` 类函数；tiling 的 shape 校验段。
- 命中判据：动态 shape 输入可绕过拦截进入融合/执行 ⇒ 命中（后果面与 FP-A04 关联）。

### ⑥ 测试对齐与负向用例（建设面）
- 查什么：迁移类合入是否附「迁移前后拦截行为对齐」清单；是否有动态 shape 负向用例集；Pass 的 `tests/ut/op_graph/` 是否覆盖动态 shape 拦截。
- 何处：`tests/ut/op_graph/` 用例、迁移提交说明。
- 命中判据：无动态 shape 负向用例（或迁移未附对齐清单）⇒ 记观察项（测试建设项）。

## 5. 检视流程

1. **定界**：换算/检索出算子与融合 Pass 的实际文件位置、确认所在仓与 ref；确定迁移来源仓与迁移前版本作为比对基准；按用户现象（动态 shape 错误结果）反查优先清单点。
2. **枚举**：目录列表 + 文件名检索列出 op_graph（含 fusion_pass）/ op_host / framework / tests 全部相关文件，产出文件清单。
3. **触发词扫描**：按 `skip[A-Za-z]*Check|SKIP_[A-Z_]*CHECK|enableCheck\s*=\s*false`、`return\s+(true|ge::GRAPH_SUCCESS)`（校验函数内）、`OP_CHECK|CheckNotNull|GRAPH_FAILED`、`IsUnknownShape` 定位风险面（本地仓用 grep；API 模式逐文件拉取后检查）。
4. **迁移 diff 审查**：取迁移类提交 diff，筛出被删除的校验/拦截行（`-.*(OP_CHECK|CheckNotNull|GRAPH_FAILED)`），逐条判断是否为防御分支。
5. **清单逐项核查 + 前后比对**：按第 4 节 ①~⑥ 逐点记录命中面与防护面证据（文件:行号）；对 ④ 做**迁移前后拦截清单对表**。
6. **反证排除**：迁移前后拦截清单逐条对齐、无跳过开关、校验函数无无条件放行、动态 shape 拦截在位 → 明确写出反证理由（防护面证据）。
7. **判定**：按第 7 节标准给出 命中 / 观察项 / 反证排除。
8. **GitCode 查重**（仅命中项）：issues API 按算子/Pass 名 + `迁移|动态shape|融合|未拦截|skipCheck` 检索，逐条比对是否同机理；无同机理才立卡。
9. **业务可达性核查**（仅命中项）：判 B 等级、定业务影响类型、给处置建议；默认保守（无法证明不可达即记 B3），降档须附证据；B 不改 S×O 档位。
10. **出报告**：按第 8 节模板落盘；静态结论一律附**迁移前后拦截行为对齐清单 + 动态 shape 负向用例集**方案。

## 6. 风险定级（S×O）与业务影响评估（B 轴）

- **S**：S3（应拦截未拦截致错误结果静默产出——动态 shape 模型推理结果错误）；S2（拦截弱化但后果受限，或跳过开关需特定配置才生效）；S1（仅缺对齐清单/负向用例等建设面）。
- **O**：O3 = ≥2 条独立实证；O2 = 1 条独立实证；O1 = 仅静态扫描命中或团队笔记（实证 = 确认对应的 issue / PR，或经跨仓、跨分支核验确认的缺陷记录，同权计入）。静态推演命中且无实证默认 **O1**；升档须在报告中给出实证依据。
- **风险 = S×O**：≥6 高；3/4 中；1/2 低。FP-B03 基准：模式卡整体 S3×O2=6（高）；纯静态命中 S3×O1=3（中，暂定，负向用例复现后复评）。

### B 轴：业务影响评估（与 S×O 正交；报告层新增，不改卡片定级）

S×O 回答"多严重、多常见"，**不回答"真实业务能不能碰到"**。B 轴补这一问，只决定**修复优先级建议**，**不参与 S/O 取值、不改 S×O 档位与卡片元数据**。

**业务可达性（B）**——触发条件在真实负载中的可达程度：

| 等级 | 判据 | 证据要求 |
|---|---|---|
| B3 现实可达 | 主流框架/公开模型默认路径即可命中（如 PTA/torch_npu、vLLM、MindIE 常规调用） | 调用方或公开负载来源 |
| B2 条件可达 | 需特定 attr/dtype/shape 组合，业务中存在但非默认 | 该组合的业务来源 |
| B1 边界/不可达 | 需极端、超规格或非法参数（超出接口合理上限的 shape、退化/非法输入） | "为何不可达"的说明 |

- **默认保守**：无法证明不可达 → 记 **B3**；降为 B1/B2 必须附证据，**不得仅凭"业务应该不会这么用"**。
- 超规格参数是否算 B1 取决于**接口契约**：契约允许但业务不用 → B1；契约不允许（本应报错）→ 属校验缺失（FP-B04/B05 类），另行归属。

**业务影响类型**（命中后对用户可见结果的后果，用业务语言表述）：静默精度损失（模型效果下降 / loss 不收敛 / 偶发 NaN）｜ 任务失败中断（报错 / 崩溃 / 挂死）｜ 性能退化 ｜ 仅可观测性（日志 / 错误码 / 文档，不影响结果）。

**处置建议**（由两轴推导的报告结论，非新档位）：

| S×O \ B | B3 现实可达 | B2 条件可达 | B1 边界/不可达 |
|---|---|---|---|
| 高（≥6） | 尽快修 | 尽快修 | 排期修 |
| 中（3/4） | 尽快修 | 排期修 | 记录（业务难以触达） |
| 低（1/2） | 排期修 | 记录 | 记录 |

## 7. 判定标准与反误报原则

- **「代码里没有某校验」不等于「漏迁」**：必须与源仓/迁移前版本比对出「曾经有、迁移后没有」的差集才立卡；无基准时降级为观察项。
- **三种判定**：
  - **命中**（可静态证缺陷路径）：「迁移 diff 删除防御分支」「显式跳过开关可置真」「校验函数无条件放行」「动态 shape 可绕过拦截」的完整推导链 → 立 Bug 卡；
  - **观察项**：跳过开关存在但不可达、拦截语义弱化但后果需用例确证、缺对齐清单/负向用例 → 记录并附复核方案；
  - **反证排除**：迁移前后拦截清单逐条对齐、无跳过开关、无无条件放行、动态 shape 拦截在位 → 写出防护面证据。
- **方向不许挂错**：本型是「该拦不拦」（漏拦族）；「不该拦却拦」归 FP-B01。误拦截与漏拦截结论必须分开写。
- **后果面与成因面分开**：错误结果静默产出的**后果**归 FP-A04，防御被删/被跳过的**成因**归本条，双向关联不重复计缺陷。
- **不臆造行号**：每条证据必须是实际读到的 文件:行号；引用实证样板（#5522 / PR #9728）时给出其在本仓的位置，迁移前后行号差异时注明基准版本。

### 判定纪律补充（v3.6）：非对称增减、证据等级与误判记录

**增减不对称**：允许追加候选（有据即可，错了可由用户排除）；**撤销或否决候选必须附 `[文件]:[行号] [代码行]` 负向证据**。无证据的「看起来没问题」一律记为「未核查」，不得计入反证排除，也不得据此下调等级——否决造成的漏报用户不可见、不可恢复。

- **证据等级**（Bug 卡必填）：`静态可证` = 推导链完整且触发输入可静态构造；`需实测确认` = 依赖运行时输入规模、设备行为或环境差异。标 `需实测确认` 的条目**不得以「命中」名义出卡**，按观察项记录并附实测用例。
- **Agent 误判记录**（Bug 卡必填）：本次被推翻的假设、推翻它的证据（`[文件]:[行号] [代码行]` 或实测输出）、判定标准是否随之修订；无推翻写「无」。
- **误判回流**：同类误判在 3 次检视中重复出现，登记至 `cases/misjudgments.jsonl`（字段见 `cases/README.md`），并在本模式判定标准中新增对应防线；守门 C19d 校验台账字段合法。

## 10. 能力边界与自检（v3.8）

### 能力边界

- **静态可证**：清单里能在源码内给出「`文件:行号` + 推导链」的部分，按第 7 节判据出卡。
- **需实测确认**：依赖运行时输入规模、设备行为或环境差异的结论，只能记观察项并附实测用例（证据等级见第 7 节）。
- **不覆盖**：本模式以外的机理（边界见第 0 节）与仓外框架侧行为；`TRIAGE.md` 只负责收敛候选，不构成判定依据。
- **找不到 ≠ 没有**：按清单未命中只说明「本轮未发现」，不得表述为「该算子无此缺陷」；抽样核查须在报告写明抽样口径。
