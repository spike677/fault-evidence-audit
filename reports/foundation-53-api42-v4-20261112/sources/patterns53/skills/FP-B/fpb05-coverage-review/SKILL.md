# FP-B05 aclnn 接口检视（fpb05-coverage-review）

对用户指定的 aclnn 接口或整个算子仓做 FP-B05 专项源码检视：先定位 `op_api/aclnn_*.cpp` 文件，再按清单逐项核查，每个结论给出**文件 + 行号 + 推导链**证据，命中即出 Bug 卡，输出检视报告。**本模式特殊纪律：① 判定粒度是「文件级 / 仓级」——本型缺陷不是某个接口算错，而是同一仓内**校验范式参差**：一部分文件有统一 `CheckNotNull` 骨架 + `CheckParams` 聚合入口，另一部分完全没有、只靠零散 `OP_CHECK_NULL`；② 因此检视方法是**跨文件横向比对**（横向统计「无骨架文件」占比并列出清单），而非单接口逐参数细查（后者是 FP-B04 的活）；③ 落于「无骨架文件」内的算子，其具体空指针后果按 FP-B04 立卡，本条负责定位短板文件与仓内范式漂移；④ 实证数据（无骨架文件数/占比）是**时点快照**，引用必须注明扫描时点与 ref。**

## 0. 与相邻模式的边界

| 相邻模式 | 分工 |
|---|---|
| FP-B04（aclnn 必选入参空指针校验缺失） | **最紧密项**：B05 是**文件级**范差（有无校验骨架）；B04 聚焦**单接口内**「校验存在但漏参数 / 晚 / 不生效」。落于无骨架文件内的算子即 B04 的受害者——本条负责**定位并列出无骨架文件清单**，B04 负责在该文件内逐参数立证 |
| FP-B03（跨仓迁移丢失防御/拦截逻辑） | **同族成因**：跨仓迁移（只迁功能主体、丢防御分支）易致仓内范式参差；迁移导致的防御缺失归 B03，长期并存/新增未对齐导致的**范差不齐**归本条 |

**症状反查定位**：同一仓内「部分算子对 `nullptr` 有完整拦截、另一部分任一必选入参置空即崩溃」→ 本型；单点抽检（只测一个算子）未发现空指针问题、换一个算子就崩 → 参差被抽检掩盖；新增算子合入后未对齐仓内既有校验范式 → 本型触发条件；仓内缺乏生成模板/范式约束、算子由不同开发者/不同时期合入 → 本型诱因。**分流口径**：判定「漏拦」类问题时先问机理——迁移丢失 → FP-B03；指针缺失 → FP-B04；**文件级覆盖度参差 → 本条**；空输入语义 → FP-B06。报告须给出「无骨架文件清单」作为定向补测依据，而非泛泛「校验不足」。

## 1. FP-B05 模式卡摘要（检视依据，源自本库 `patterns/FP-B/FP-B05.md`，v3.1）

- **编号 / 名称**：FP-B05 入参校验覆盖度参差（同仓内文件级） ｜ **类别**：功能/兼容 ｜ **风险**：低（S2×O1=2）｜ **状态**：活跃
- **适用声明头**（照抄卡片）：仓 All ｜ 侧别 Host ｜ 载体 aclnn源码 ｜ 触发 CheckNotNull|CheckParams|aclnn ｜ 默认启用 true
- **skill 核查面**：与卡片载体一致——核查面为仓内全部 `op_api/aclnn_*.cpp`（含 `op_host/op_api/` 变体位置）的**校验范式一致性**：`CheckNotNull` / `CheckNull` 函数骨架存在性、`CheckParams` 聚合入口存在性、校验宏是聚合调用还是散点 `OP_CHECK_NULL`；不逐参数细查（那是 FP-B04）
- **故障机理**：同一仓内 aclnn 接口文件的校验完备度严重不均——部分文件具备统一的 `CheckNotNull` 骨架 + `CheckParams` 聚合入口，另一部分**完全没有**，其入参校验仅依赖零散 `OP_CHECK_NULL` 散点，**无聚合入口则校验完整性与顺序皆无从保证**。
- **触发条件**：新增算子未对齐仓内既有校验范式；算子由不同开发者/不同时期合入；仓内缺乏生成模板或范式约束。
- **典型表现**：同一仓内部分算子对 `nullptr` 具备完整拦截，另一部分任一必选入参置空即崩溃——**缺陷分布呈文件级参差**，单点抽检易漏。落于无骨架文件内的算子即落入 FP-B04。
- **源码审查映射点**：文件是否存在 `CheckNotNull` 函数骨架与 `CheckParams` 聚合入口；校验宏是否聚合调用而非散点；仓内校验范式一致性（可作跨文件横向比对）。
- **检测签名**：静态扫描——逐 aclnn 实现文件检查 `CheckNotNull` / `CheckNull` 骨架存在性；统计「无骨架文件」占比定位短板仓。
- **测试拦截建议**：按「仓内无骨架文件清单」定向补探针用例，而非全量随机抽检；新增算子合入时强制对齐仓内校验范式（建议纳入 CI 静态检查）。
- **实证案例**：四仓 master 分支静态扫描（**2026-09-12 时点，990 个 `op_api/aclnn_*.cpp`**）——**ops-transformer 236 个文件中 136 个（57.6%）无 `CheckNotNull` 骨架**，为四仓唯一大面积缺失者；ops-nn 356 个中 30 个（8.4%）、ops-math 351 个中 28 个（8.0%）属零散遗漏；**ops-cv 47 个文件 0 缺失**，可作正向参照。
- **关联**：FP-B04（无骨架文件内的算子即 B04 的受害者）、FP-B03（跨仓迁移易致范式参差）。

## 2. 检视输入与算子定位

**输入**：仓名（必填，如 `ops-transformer`）；可选 aclnn 接口名（指定单接口时聚焦其所在文件，并仍做仓内横向比对以判断该文件是否属短板）；可选 ref（默认 master）；可选现象描述（某算子置空即崩 / 抽检漏检——用于症状反查）。

**接口名 → 算子目录换算**：去 `aclnn` 前缀 + 驼峰转下划线小写：
`aclnnInplaceMaskedScatter → masked_scatter`（`Inplace` 中缀去掉，以目录列表为准）、`aclnnRmsNorm → rms_norm`、`aclnnAdd → add`。

**仓定位顺序**（GitCode `cann` 组织，逐仓用目录列表确认）：`ops-transformer`（实测短板仓，236 文件中 136 无骨架）→ `ops-nn`（356 中 30）→ `ops-math`（351 中 28）→ `ops-cv`（47 中 0，**正向参照仓**）。FP-B05 高发面：新增算子/新合入算子、由不同时期/开发者合入的文件、仓内无统一模板或范式约束的仓。

**文件定位约定**（`op_api` 位置随算子而异——masked_scatter 在顶层 `op_api/`，fused_quant_mat_mul 在 `op_host/op_api/`，以目录列表为准）：

```text
{类别}/{op_name}/
├── op_api/（或 op_host/op_api/）  # aclnn_*.cpp——CheckNotNull 骨架与 CheckParams 聚合入口的检视单元
├── op_host/                  # def / infershape / tiling
├── docs/                     # aclnn*.md——必选性约束（判「骨架是否覆盖全部必选参数」的参照）
└── tests/ examples/
```

## 4. 校验覆盖度检视清单（每点：查什么 → 何处 → 命中判据）

对目标仓（或指定接口所在文件 + 仓内横向样本）逐文件核查，**每点先查命中面、再做反证排除**，已有的骨架与聚合入口也要记录（防护面证据）。

### ① `CheckNotNull` / `CheckNull` 函数骨架存在性（文件级）
- 查什么：每个 `aclnn_*.cpp` 是否存在统一的 `CheckNotNull` / `CheckNull` 类函数骨架——即把该接口全部必选入参的判空集中在一处；无骨架的文件即本型命中单元。
- 何处：`op_api/` 与 `op_host/op_api/` 下的全部 `aclnn_*.cpp`。
- 命中判据：文件内不存在 `CheckNotNull|CheckNull` 函数定义 ⇒ 该文件计入「无骨架文件清单」（给出文件路径；命中数为清单条目）。

### ② `CheckParams` 聚合入口存在性
- 查什么：是否存在 `CheckParams` 类**聚合入口**（统一调用判空/类型/shape 校验）；无聚合入口时校验完整性与**执行顺序**无从保证（散点校验易漏、易「先用后校验」）。
- 何处：`aclnn_*.cpp` 的 `GetWorkspaceSize` 内校验调用段。
- 命中判据：无 `CheckParams` 聚合入口且校验以散点 `OP_CHECK_NULL` 形式散布 ⇒ 命中（记入无聚合入口清单）。

### ③ 校验宏聚合调用 vs 散点
- 查什么：判空是**通过骨架/聚合函数统一调用**，还是 `OP_CHECK_NULL(...)` 散落各处；散点数量与必选参数数量是否匹配（散点 < 必选参数 ⇒ 覆盖不全嫌疑）。
- 何处：文件内全部 `OP_CHECK_NULL|CHECK_RET|OP_CHECK` 出现点。
- 命中判据：散点校验数与必选参数数不匹配（存在未覆盖参数）⇒ 命中（与 FP-B04 的逐参数对表衔接）。

### ④ 仓内范式一致性（跨文件横向比对）
- 查什么：把仓内全部 `aclnn_*.cpp` 的「有/无骨架」结果汇总，统计无骨架文件数与占比，定位**短板仓**与**短板文件簇**（同一类别/同一时期合入的文件更可能同缺）；与正向参照仓（ops-cv 形态：47 文件 0 缺失）对比。
- 何处：全仓 `aclnn_*.cpp` 清单。
- 命中判据：无骨架占比显著高于参照仓（如 ops-transformer 57.6% vs ops-cv 0%）⇒ 命中（仓级短板），输出无骨架文件清单。

### ⑤ 新增算子是否对齐范式
- 查什么：新增/近期合入算子的文件是否带骨架与聚合入口——新增算子未对齐仓内既有范式是本型触发条件；是否有生成模板/CI 静态检查约束范式。
- 何处：新增算子文件、仓级模板/CI 静态检查配置。
- 命中判据：新增算子文件无骨架且仓内既有范式存在 ⇒ 命中（增量缺陷）；无范式约束机制 ⇒ 记观察项（治理面）。

### ⑥ 骨架覆盖度与必选性自洽
- 查什么：已有骨架的文件中，`CheckNotNull` 是否覆盖**全部**必选参数（对照接口签名 + `docs/aclnn*.md` 必选性约束）——有骨架但漏参数属「骨架覆盖不全」，与无骨架同族但程度较轻。
- 何处：骨架函数体、接口签名、docs 必选性约束。
- 命中判据：骨架覆盖的必选参数数 < 必选参数总数 ⇒ 命中（程度较轻，可与 FP-B04 衔接）。

## 5. 检视流程

1. **定界**：确定目标仓与 ref（或指定接口所在文件）；若给了接口名，同时确定其所在文件与仓内横向比对范围。
2. **枚举**：目录列表 + 文件名检索枚举仓内**全部** `aclnn_*.cpp`（覆盖 `op_api/` 与 `op_host/op_api/` 两种位置），产出文件清单（记录总文件数）。
3. **触发词扫描**：逐文件检查 `CheckNotNull|CheckNull` 骨架存在性、`CheckParams` 聚合入口、`OP_CHECK_NULL|CHECK_RET` 散点分布（本地仓用 grep；API 模式逐文件拉取后检查）。
4. **清单逐项核查**：按第 4 节 ①~⑥ 逐点记录命中面与防护面证据（文件:行号）；汇总产出**无骨架文件清单**与占比统计。
5. **横向比对**：与正向参照仓（ops-cv 形态）对比范式一致性；对指定接口所在文件判定其是否属短板文件。
6. **反证排除**：文件均有骨架 + 有聚合入口 + 散点与必选参数匹配 + 新增算子已对齐 → 明确写出反证理由（防护面证据）。
7. **判定**：按第 7 节标准给出 命中 / 观察项 / 反证排除；命中对象是**文件清单**而非单个接口。
8. **GitCode 查重**（仅命中项）：issues API 按仓名/接口名 + `校验|CheckNotNull|空指针|nullptr|覆盖` 检索，逐条比对是否同机理；无同机理才立卡。
9. **业务可达性核查**（仅命中项）：判 B 等级、定业务影响类型、给处置建议；默认保守（无法证明不可达即记 B3），降档须附证据；B 不改 S×O 档位。
10. **出报告**：按第 8 节模板落盘；静态结论一律附**定向探针方案**（按无骨架文件清单补 `nullptr` 用例，而非全量随机抽检）。

## 6. 风险定级（S×O）与业务影响评估（B 轴）

- **S**：S2（无骨架文件内算子任一必选入参置空即崩溃——单个接口必现崩溃，但缺陷按文件分布、非全仓）；S1（仅缺聚合入口/范式约束、骨架覆盖不全但散点尚能兜住等治理面）。
- **O**：O3 = ≥2 条独立实证；O2 = 1 条独立实证；O1 = 仅静态扫描命中或团队笔记（实证 = 确认对应的 issue / PR，或经跨仓、跨分支核验确认的缺陷记录，同权计入）。静态推演命中且无实证默认 **O1**；升档须在报告中给出实证依据。本型**分布广 ≠ 触发概率高**：无单点实证一律 O1；若指定接口已被实证崩溃，则与该接口的 FP-B04 实证联动计档。
- **风险 = S×O**：≥6 高；3/4 中；1/2 低。FP-B05 基准：模式卡整体 S2×O1=2（低）；若指定文件内已确证某接口 `nullptr` 崩溃，按该接口的 FP-B04 定级（S2×O1=2 起）。

### B 轴：业务影响评估（与 S×O 正交；报告层新增，不改卡片定级）

S×O 回答"多严重、多常见"，**不回答"真实业务能不能碰到"**。B 轴补这一问，只决定**修复优先级建议**，**不参与 S/O 取值、不改 S×O 档位与卡片元数据**。

**业务可达性（B）**——触发条件在真实负载中的可达程度：

| 等级 | 判据 | 证据要求 |
|---|---|---|
| B3 现实可达 | 主流框架/公开模型默认路径即可命中（如 PTA/torch_npu、vLLM、MindIE 常规调用） | 调用方或公开负载来源 |
| B2 条件可达 | 需特定 attr/dtype/shape 组合，业务中存在但非默认 | 该组合的业务来源 |
| B1 边界/不可达 | 需极端、超规格或非法参数（超出接口合理上限的 shape、退化/非法输入） | "为何不可达"的说明 |

- **默认保守**：无法证明不可达 → 记 **B3**；降为 B1/B2 必须附证据，**不得仅凭"业务应该不会这么用"**。
- 超规格参数是否算 B1 取决于**接口契约**：契约允许但业务不用 → B1；契约不允许（本应报错）→ 属校验缺失（FP-B04/B05 类），另行归属。

**业务影响类型**（命中后对用户可见结果的后果，用业务语言表述）：静默精度损失（模型效果下降 / loss 不收敛 / 偶发 NaN）｜ 任务失败中断（报错 / 崩溃 / 挂死）｜ 性能退化 ｜ 仅可观测性（日志 / 错误码 / 文档，不影响结果）。

**处置建议**（由两轴推导的报告结论，非新档位）：

| S×O \ B | B3 现实可达 | B2 条件可达 | B1 边界/不可达 |
|---|---|---|---|
| 高（≥6） | 尽快修 | 尽快修 | 排期修 |
| 中（3/4） | 尽快修 | 排期修 | 记录（业务难以触达） |
| 低（1/2） | 排期修 | 记录 | 记录 |

## 7. 判定标准与反误报原则

- **「无骨架」不等于「无校验」**：无骨架文件仍可能有零散 `OP_CHECK_NULL` 散点——本型命中的是**范式缺失/参差**，后果严重度须看散点是否覆盖全部必选参数；判定时区分「无骨架且散点不全」（重）与「无骨架但散点齐全」（轻，记观察项）。
- **三种判定**：
  - **命中**（可静态证缺陷路径）：文件无骨架 + 无聚合入口 + 散点 < 必选参数（或仓级无骨架占比显著高于参照仓）→ 立 Bug 卡（对象为文件清单）；
  - **观察项**：无骨架但散点齐全、缺范式约束机制、骨架覆盖不全但可兜住 → 记录并附复核方案；
  - **反证排除**：骨架与聚合入口齐备、散点与必选参数匹配、新增算子已对齐 → 写出防护面证据。
- **计数须带时点**：四仓计数（136/30/28/0，990 文件）是 **2026-09-12 master 快照**，引用必须注明时点与 ref；不得表述为当前实时状态。
- **本型不逐参数细查**：单接口内的「漏参数/先用后校验/错误码」立证归 FP-B04，本条只输出文件级清单与范式判定，避免与 B04 重复计缺陷。
- **不臆造行号**：每条证据必须是实际读到的 文件:行号；仓级统计须给出可复算的口径（枚举到的文件总数、无骨架文件数）。

### 判定纪律补充（v3.6）：非对称增减、证据等级与误判记录

**增减不对称**：允许追加候选（有据即可，错了可由用户排除）；**撤销或否决候选必须附 `[文件]:[行号] [代码行]` 负向证据**。无证据的「看起来没问题」一律记为「未核查」，不得计入反证排除，也不得据此下调等级——否决造成的漏报用户不可见、不可恢复。

- **证据等级**（Bug 卡必填）：`静态可证` = 推导链完整且触发输入可静态构造；`需实测确认` = 依赖运行时输入规模、设备行为或环境差异。标 `需实测确认` 的条目**不得以「命中」名义出卡**，按观察项记录并附实测用例。
- **Agent 误判记录**（Bug 卡必填）：本次被推翻的假设、推翻它的证据（`[文件]:[行号] [代码行]` 或实测输出）、判定标准是否随之修订；无推翻写「无」。
- **误判回流**：同类误判在 3 次检视中重复出现，登记至 `cases/misjudgments.jsonl`（字段见 `cases/README.md`），并在本模式判定标准中新增对应防线；守门 C19d 校验台账字段合法。

## 9. 示例速览：跨文件横向比对（`op_api/aclnn_*.cpp` 骨架存在性）

- **定位**：以 `cann/ops-transformer` 为**短板仓**（实证 236 个 `aclnn_*.cpp` 中 136 个无 `CheckNotNull` 骨架，57.6%），以 `cann/ops-nn` 作**同族对照仓**（356 个中 30 个，8.4%），以 `cann/ops-cv` 作**正向参照仓**（47 个 0 缺失）。检视单元为各算子目录下的 `op_api/aclnn_*.cpp`（部分算子在 `op_host/op_api/`，以目录列表为准）。
- **检视面提示**（引导，不预设结论，仍须逐点核查；行号与计数以本地 HEAD 为准，卡片计数为 2026-09-12 master 快照）：
  - 清单点①：逐个 `aclnn_*.cpp` 检查是否存在 `CheckNotNull` / `CheckNull` 函数定义——无定义即计入清单；给出文件路径清单（这是本条的**主产出**）；
  - 清单点②③：对无骨架文件进一步看是否退化为散点 `OP_CHECK_NULL|CHECK_RET`，散点数与接口必选参数数对表（散点 < 必选参数 = 覆盖不全，衔接 FP-B04 逐参数立证）；
  - 清单点④：把 ops-transformer / ops-nn / ops-math / ops-cv 四仓的「无骨架占比」并列比对，说明 ops-cv 的 0 缺失范式作为正向样板（骨架形态可作对齐目标）；
  - 清单点⑤：对指定接口，核对其所在文件是否属无骨架清单，以及该算子是否为近期新增（增量未对齐范式）；
  - 清单点⑥：对**有骨架**的文件，核对 `CheckNotNull` 是否覆盖全部必选参数（对照接口签名与 `docs/aclnn*.md`）——有骨架但漏参数同样计入；
  - 衔接：清单内的具体算子空指针后果按 FP-B04 立卡（如共享校验函数不自校验、校验命中不 return），本条只出文件级清单与范式判定。
- 任何一点的最终判定以第 4/5/7 节口径为准，禁止凭算子类型直接下结论。

## 10. 能力边界与自检（v3.8）

### 能力边界

- **静态可证**：清单里能在源码内给出「`文件:行号` + 推导链」的部分，按第 7 节判据出卡。
- **需实测确认**：依赖运行时输入规模、设备行为或环境差异的结论，只能记观察项并附实测用例（证据等级见第 7 节）。
- **不覆盖**：本模式以外的机理（边界见第 0 节）与仓外框架侧行为；`TRIAGE.md` 只负责收敛候选，不构成判定依据。
- **找不到 ≠ 没有**：按清单未命中只说明「本轮未发现」，不得表述为「该算子无此缺陷」；抽样核查须在报告写明抽样口径。

### 自检

```bash
python3 scripts/gen_triage.py --check                          # 分诊表与映射一致

python3 scripts/verify_lines.py <报告.md> --root <被检仓>        # 行号校验
python3 check_fault_patterns.py                                # 全库守门
```

### 工作量与抽样（v4.0）

- **深度档：宽浅**（索引 `depth` 字段）——只跑签名定位 + 每类抽 3 例；报告必须写「抽样，非全量」，不得表述为全量检视。
- **报告必填**：抽样口径（全量 / 每点前 N 处 / 每类 N 例）+ 停止点记录；未写口径视为未完成。

## 11. 子型对照、量化基线与探针矩阵

### 子型对照

| # | 子型 / 检查面 | 检视落点 | 命中判据 |
|---|---|---|---|
| ① | 无校验骨架 | 文件内无 `CheckNotNull` 函数 | 入参判空仅靠零散 `OP_CHECK_NULL` |
| ② | 有骨架未聚合 | 有 `CheckNotNull` 但无 `CheckParams` 聚合入口 | 校验顺序与完整性无从保证 |
| ③ | 聚合但漏项 | `CheckParams` 内未覆盖全部必选参数 | 逐参数对照表出现空缺 |

### 量化基线（数字来自卡片实证，引用须注明来源）

- 四仓 master 静态扫描 **990 个** `op_api/aclnn_*.cpp`：ops-transformer 236 个中 **136 个（57.6%）无 `CheckNotNull` 骨架**；ops-nn 356 个中 30 个（8.4%）；ops-math 351 个中 28 个（8.0%）。
- 本型是**文件级参差**，不是单点缺陷：判定要给「无骨架文件清单」，而非抽检个例。

### 探针矩阵（最小可执行集）

| 探针 | 构造 | 期望 / 判据 |
|---|---|---|
| 骨架扫描 | 按仓统计 `CheckNotNull` 命中文件占比 | 得到无骨架文件清单（定向补测用） |
| 聚合入口 | 检查 `CheckParams` 是否被 init 调用 | 存在且覆盖全部必选参数 |
| 散点计数 | 统计文件内 `OP_CHECK_NULL` 出现次数 | 散点 ≥1 但无骨架 → 属高风险文件 |
| 范式对比 | 同目录同族文件横向比对 | 同族差异即参差证据 |
