- **故障机理**（**实质是内存安全正确性问题，不是容量问题**）：缓冲区未初始化、workspace 未清零、**算子申请 CKE 内存后未做初始化**、原地写覆盖输入、越界写引入未定义数据。
- **触发条件**：空张量/退化 shape、workspace 复用、inplace 路径、尾块覆盖不完整。
- **典型表现**：精度计算有误、网络 loss 不收敛、偶发 NaN。
- **源码审查映射点**：缓冲区初始化、workspace 清零、原地写覆盖输入、越界写。
- **控制变量（v6.30）**：**必须固定**——除被测张量内容外的其余输入全部固定（shape / dtype / 属性 / 调用序列），只让**一个**张量携带脏值；被测张量的脏值来源也固定为单一类型（未初始化 / 前次残留 / 越界写覆盖） ｜ **允许变动**——单个张量的内容 ｜ **多变量同变的典型误判**——一次性把所有输入填脏、或同时换 workspace 复用顺序 → 脏源不可归因；实测有人一次全填 NaN 得 47 例「kernel 崩溃」，改单缓冲定点注入后 47 例全部不复现
- **测试拦截建议**：空张量/零元素用例；workspace 复用下连续两次调用结果一致性；mssanitizer/memcheck 类内存检测。
- **实证案例**：ops-nn #5560 RmsNormGrad 空张量 dgamma 输出 NaN、Split-D 尾元素未覆盖，GM 清零 + bodyPart×2 修复（PR !9873）。
- **测试集失败语料补充（v2.13，2026-09-19，具体 issue 编号待核）**：日常测试集失败报告中「内存检测 / 内存安全」类 422 条，按机理逐项拆解后归属如下——**内存未初始化 / CKE 内存申请后未初始化 → 本条**；地址未对齐致错位 → FP-B07 成因 ④；内存检测（memcheck / mssanitizer）报错 → **属检测信号、不属机理**（本条与 FP-B07 的拦截建议已分别列出该手段）；aclGraph 条件算子 OOM → FP-D01。故该批差异**不在本条新增编号**，仅补充上述机理表述与定位口径。
