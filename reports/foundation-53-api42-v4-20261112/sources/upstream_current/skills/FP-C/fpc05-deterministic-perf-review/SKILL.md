# FP-C05 aclnn 接口检视（fpc05-deterministic-perf-review）

对用户指定的 aclnn 接口（如 aclnnScatterNd、aclnnConvolutionBackward）做 FP-C05 专项性能源码检视：先定位算子实现，再按清单逐项核查，每个结论给出**文件 + 行号 + 推导链**证据，命中即出 Bug 卡，输出检视报告。**本模式特殊纪律：① 结果对（且结果固定）、只是开了确定性开关后变慢——静态检视只能产出「嫌疑点」，任何「劣化 N 倍」的量化结论必须以基线差分实测为准；② 判据是「同 shape、同硬件、同版本下确定性开 vs 关的耗时对比」，缺开关对比轴即不成立；③ 缺陷形态是「确定性路径实现低效」——以串行化、禁用必要并行、排序/去重代价换取结果固定，代价远超必要。**

## 0. 与相邻模式的边界

| 相邻模式 | 分工 |
|---|---|
| FP-A06（确定性开关下结果不固定） | **同一开关的两面**：A06 是「**开了不生效**」——确定性分支未真正消除随机性来源，结果仍不固定（精度面）；C05 是「**生效了但代价过大**」——结果已固定、性能骤降（性能面）。两者审查同一处 `Deterministic|AtomicAdd` 分支，**必须同时判两面**：只核性能不核是否生效，会把 A06 误判为 C05 的「实现正常」 |
| FP-C01（端到端耗时占比高） | C01 不看开关轴；C05 必须给出「同 shape 同硬件下确定性开/关对比」才成立；确定性路径的串行化循环若上界写错多算，按 C01 子型② 核 |
| FP-G01（挂死/超时） | 确定性路径常引入串行化/排序循环——须按 G01 成因① 核「循环体是否含推进变量更新 + 不推进退出」；C05 是「慢但能完成」，G01 是「根本没完成」 |
| FP-C02 / FP-C03 / FP-C04 / FP-C06（dtype/板型/代际特化型） | 同属**同版本内跨维度对比**家族，但维度不同（dtype / 板型 / 代际）；C05 的维度是 **确定性开关**，勿合并；若性能差异仅在确定性开关下显现，勿把开关轴误记为 dtype/板型/代际轴 |
| FP-A05（workspace 未清零） | 确定性路径为消除随机性可能引入额外清零/初始化，其副作用面按 A05（残留随机数）与 C05（额外代价）分别核 |

**症状反查定位**：开启确定性开关后**性能骤降**（同 shape 同硬件、结果已固定）→ C05；开了开关结果仍不固定 → A06（精度面）；与开关无关的绝对耗时高或跨版本回归 → C01；确定性路径的循环若「完全无进展」→ G01。**高发算子族：Scatter / Histogram / 卷积反向等含原子累加或乱序写的算子**——这些正是确定性路径需要串行化/排序代价最高的形态。

## 1. FP-C05 模式卡摘要（检视依据，源自本库 `patterns/FP-C/FP-C05.md`，v3.1）

- **编号 / 名称**：FP-C05 确定性场景性能大幅劣于非确定性 ｜ **类别**：性能 ｜ **风险**：高（S2×O3=6）｜ **状态**：活跃
- **适用声明头**（照抄卡片）：仓 All ｜ 侧别 Kernel ｜ 载体 Kernel源码 ｜ 触发 Deterministic|AtomicAdd ｜ 默认启用 true
- **skill 核查面**：侧别 Kernel——skill 落地为 op_kernel 的确定性分支（`Deterministic` / `AtomicAdd` / `SetAtomicAdd` 命中点）、串行化实现、排序/去重逻辑、原子累加消除路径；延伸至 op_host tiling 的确定性分流（确定性开关是否改变分核 / 派发路径）
- **故障机理**：**确定性路径实现低效**——为消除乱序写/原子累加带来的不确定性，确定性路径采用串行化、禁用必要并行、全量排序/去重、串行累加等手段，代价远超必要（结果固定但性能骤降）。
- **触发条件**：开启确定性计算开关；多核/多卡场景；含原子累加或乱序写的算子族（Scatter / Histogram / 卷积反向）。
- **典型表现**：**开确定性开关性能骤降**；结果正确且固定（与 A06 的区别）；精度全对、功能全对、无报错，仅耗时变长；非确定性基线（如 71 版本口径）对比才暴露。
- **源码审查映射点**：确定性路径实现效率（串行化、禁用必要并行）。
- **检测签名**（命中即候选缺陷点位）：`Deterministic|GetDeterministic`、`AtomicAdd|SetAtomicAdd` 与确定性分支同现；确定性分支内的**单核/串行化**形态（核数被置 1、并行度被强制降低）；`Sort|sort|Gather|Unique` 类排序/去重调用与确定性分支同现；确定性分支内新增的 `SyncAll` / 屏障。
- **审查关键词**（命中只表示值得人工审）：`Deterministic` 分支与非确定性分支**是否共用同一低效实现**（未分流的开关形同虚设，性能差异无从优化）；原子累加消除方式（退化为串行累加 vs 保留并行 + 确定性归约）；额外清零/初始化（与 FP-A05 交叠）。
- **测试拦截建议**：确定性开/关性能对比基线（同 shape、同硬件、同版本）；与 FP-A06 的 bitwise 一致性用例成对执行（确认「生效」与「代价」两面）。
- **实证案例**：ops-nn **#946** convolutionbackward 开启确定性计算性能劣化严重（同一用例 **200us → 3000us，劣化 15 倍**，A2/A3）；ops-nn **#3178** ScatterNd 开启确定性后在给定 shape 下性能相较 910b 存在**数倍差距**；ops-nn **#3234 / #966** ScatterNdAdd 小 case 确定性计算性能需优化；ops-nn **#3237 / #1759** ScatterNdUpdate 部分 case 与 David 确定性模板性能优化；ops-nn **#3332** uss 确定性性能相对 71（非确定性基线）不达标；ops-math **#2957** Hist V2 确定性路径性能不达标（open）；ops-transformer **#473** FAG 确定性性能劣化。**共性特征：集中在 Scatter/Histogram/卷积反向等**含原子累加或乱序写**的算子族——这些正是确定性路径需要串行化/排序代价最高的形态。**
- **关联**：FP-A06（同一开关的两面：A06 是开了不生效，C05 是生效了但代价过大）、FP-C01（性能总类）。

## 2. 检视输入与算子定位

**输入**：aclnn 接口名（必填，如 `aclnnScatterNd`）；可选 ref（默认 master）、指定仓（默认自动定位）；可选现象描述（确定性开/关耗时数据——用于反查优先清单点）；可选复现条件（SOC/板型 + shape + 开关状态——性能结论的可比性要素）。

**接口名 → 算子目录换算**：去 `aclnn` 前缀 + 驼峰转下划线小写：
`aclnnScatterNd → scatter_nd`、`aclnnScatterNdAdd → scatter_nd_add`、`aclnnConvolutionBackward → convolution_backward`、`aclnnHistV2 → hist_v2`。

**仓定位顺序**（GitCode `cann` 组织，逐仓用目录列表确认）：`ops-nn`（index/scatter/convolution 类）→ `ops-math`（math/histogram 类）→ `ops-cv`（image/vision 类）→ `ops-transformer`（attention/moe 类）。**类目名不总与直觉一致**，以目录列表为准。FP-C05 高发面：含**原子累加**的 Scatter 族（ScatterNd / ScatterNdAdd / ScatterNdUpdate / IndexAdd）、**直方图**族（Hist 系列）、**卷积反向**族（convolutionbackward / FAG 类反向注意力）、小 case 与大 case 表现分化明显的确定性模板。

**算子目录结构约定**（通用形态，以目录列表为准）：

```text
{类别}/{op_name}/
├── op_kernel/             # kernel 模板：确定性分支 / 原子累加消除 / 排序去重——主检视面
│   └── arch*/             # 各代际/架构变体（确定性模板可能按架构分别实现）
├── op_host/
│   ├── *_tiling*.cpp      # 确定性开关是否改变分核/派发
│   └── config/<soc>/      # *_binary.json（确定性模板的派发配置）
├── op_api/（或 op_host/op_api/）
├── op_graph/  tests/  docs/  examples/
└── CMakeLists.txt
```

**aclnn 出口位置提示**：多数算子的 aclnn 出口在 `op_host/op_api/` 或顶层 `op_api/`（`aclnn_*.cpp`），以目录列表与 `docs/aclnn*.md` 确认。

## 4. 确定性路径检视清单（每点：查什么 → 何处 → 命中判据）

对算子的 op_kernel（确定性分支 / 排序去重 / 原子累加路径）/ op_host tiling（确定性分流）全部相关文件逐点核查，**每点先查命中面、再做反证排除**，防护面（已保留并行的确定性归约）也要记录。

### ① 确定性分支定位与开关分流
- 查什么：确定性开关的读取点（`Deterministic` / `GetDeterministic`）与后续分流——确定性分支与非确定性分支**是否真的分叉**；若共用同一实现（开关形同虚设），则「开/关性能一致」且性能问题属 C01 而非 C05。
- 何处：op_kernel 的开关读取与分支、op_host tiling 的确定性分流。
- 命中判据：可给出「开关状态 → 走哪条路径」的对表；若两态共用实现 ⇒ 记录（并转核 FP-A06 的「开关是否生效」）。

### ② 串行化与并行度禁用
- 查什么：确定性分支是否以**单核/串行**替代多核并行（核数被置 1、`blockDim` 被强制降低、循环按全量串行遍历）；被禁用的并行是否**必要**（为消除乱序写所必需）还是**过度**（可保留并行 + 确定性归约）。
- 何处：确定性分支的分核设置、主循环结构。
- 命中判据：可指认「并行度被降至 1 而理论上可保留并行」⇒ 命中（实证族：#946 卷积反向、#3178 ScatterNd 数倍差距）。

### ③ 排序 / 去重代价
- 查什么：确定性分支是否引入**全量排序 / 去重**（`Sort` / `Unique` / 重排索引）以获得确定顺序；排序是否为该算子消除乱序写的**唯一手段**（可替代性）；小 case 与大 case 的代价分化。
- 何处：确定性分支的排序/去重调用点、索引重排逻辑。
- 命中判据：排序/去重存在且可指认更优替代（如按确定性归约顺序分核）⇒ 命中（实证族：#3234/#966 ScatterNdAdd 小 case、#3237/#1759 ScatterNdUpdate、#2957 Hist V2）。

### ④ 原子累加消除方式
- 查什么：非确定性路径的 `AtomicAdd` / `SetAtomicAdd` 在确定性分支中如何被消除——是退化为**串行累加**（代价大），还是保留并行并改用**确定性归约/分段累加**（代价小）；归约是否引入不必要的全量同步。
- 何处：`AtomicAdd|SetAtomicAdd` 命中点及其确定性替代实现。
- 命中判据：确定性替代实现为串行累加且可指认并行归约替代方案 ⇒ 命中。

### ⑤ 冗余同步与额外清零
- 查什么：确定性分支是否新增冗余 `SyncAll` / 屏障、额外清零或初始化（与 FP-A05 交叠——为消除随机数残留而多做的初始化其代价归本条，残留问题归 A05）。
- 何处：确定性分支内的同步调用与初始化段。
- 命中判据：同步/清零可指认冗余（不影响确定性结果）⇒ 命中。

### ⑥ 反证排除（防误报）
- 查什么：串行化/排序是否为**确定性语义所必需**（消除乱序写的唯一可行手段，无更优替代）；性能差异是否实际由**非确定性基线口径不一致**（如实证 #3332 中「71 非确定性基线」口径）造成，而非确定性路径本身低效。
- 何处：确定性实现的语义说明、基线口径定义。
- 命中判据：串行化/排序为语义必须且无更优替代 / 差异源于基线口径 ⇒ 反证排除（写明理由）。

### ⑦ 测试拦截面（开关对比基线）
- 查什么：tests / 评测脚本是否具备**确定性开/关性能对比基线**；是否与 FP-A06 的 bitwise 一致性用例成对执行。
- 何处：tests/ut、examples、评测配置。
- 命中判据：无开关对比项可静态确认 ⇒ 记录为拦截缺口。

## 5. 检视流程

1. **定界**：换算 op 目录、确认所在仓与 ref/HEAD；确认对比轴为确定性开关（非 dtype / 板型 / 代际 / 版本）；核对可比性要素（SOC、shape、版本、开关状态）是否齐备；确认算子是否属 Scatter/Histogram/卷积反向高发族。
2. **枚举**：目录列表列出 op_kernel（含 arch 子目录）/ op_host（tiling + config）全部相关文件，产出文件清单。
3. **触发词扫描**：按 `Deterministic|GetDeterministic`、`AtomicAdd|SetAtomicAdd`、`Sort|Unique|Gather`、`SyncAll`、`blockDim|usedCoreNum` 定位风险面（本地仓用 grep；API 模式逐文件拉取后检查）。
4. **开关分叉表构建**：以第 4 节 ① 建立「开关状态 → 路径 → 关键实现（串行/排序/原子消除）」对表——后续所有清单点都在此表上比对。
5. **清单逐项核查**：每点记录命中面与防护面证据（文件:行号）；同步按 FP-A06 核「确定性是否真正生效」（两面同核）。
6. **反证排除**：串行化/排序为语义必须且无更优替代、差异源于基线口径不一致 → 明确写出反证理由。
7. **判定**：按第 7 节标准给出 命中 / 观察项 / 反证排除。
8. **GitCode 查重**（仅命中项）：issues API 按接口名 + `确定性|deterministic|性能|劣化` 检索，逐条比对是否同机理；无同机理才立卡。
9. **业务可达性核查**（仅命中项）：判 B 等级、定业务影响类型、给处置建议；默认保守（无法证明不可达即记 B3），降档须附证据；B 不改 S×O 档位。
10. **出报告**：按第 8 节模板落盘；静态推演结论一律标注「需基线差分实测确认」，并附开关对比方案。

## 6. 风险定级（S×O）与业务影响评估（B 轴）

- **S**：S2（性能不达标 / 交付受限——开确定性开关后性能骤降）；S1（轻度资源浪费——冗余同步/清零）。性能类缺陷不涉 S3/S4（结果仍正确）。
- **O**：O3 = ≥2 条独立实证；O2 = 1 条独立实证；O1 = 仅静态扫描命中或团队笔记（实证 = 确认对应的 issue / PR，或经跨仓、跨分支核验确认的缺陷记录，同权计入）。静态推演命中且无实证默认 **O1**；升档须在报告中给出实证依据。
- **风险 = S×O**：≥6 高；3/4 中；1/2 低。FP-C05 基准：模式卡整体 S2×O3=6（高）；纯静态命中 **S2×O1=2（低，暂定，量化劣化待基线差分实测后复评）**。

### B 轴：业务影响评估（与 S×O 正交；报告层新增，不改卡片定级）

S×O 回答"多严重、多常见"，**不回答"真实业务能不能碰到"**。B 轴补这一问，只决定**修复优先级建议**，**不参与 S/O 取值、不改 S×O 档位与卡片元数据**。

**业务可达性（B）**——触发条件在真实负载中的可达程度：

| 等级 | 判据 | 证据要求 |
|---|---|---|
| B3 现实可达 | 主流框架/公开模型默认路径即可命中（如 PTA/torch_npu、vLLM、MindIE 常规调用） | 调用方或公开负载来源 |
| B2 条件可达 | 需特定 attr/dtype/shape 组合，业务中存在但非默认 | 该组合的业务来源 |
| B1 边界/不可达 | 需极端、超规格或非法参数（超出接口合理上限的 shape、退化/非法输入） | "为何不可达"的说明 |

- **默认保守**：无法证明不可达 → 记 **B3**；降为 B1/B2 必须附证据，**不得仅凭"业务应该不会这么用"**。
- 超规格参数是否算 B1 取决于**接口契约**：契约允许但业务不用 → B1；契约不允许（本应报错）→ 属校验缺失（FP-B04/B05 类），另行归属。

**业务影响类型**（命中后对用户可见结果的后果，用业务语言表述）：静默精度损失（模型效果下降 / loss 不收敛 / 偶发 NaN）｜ 任务失败中断（报错 / 崩溃 / 挂死）｜ 性能退化 ｜ 仅可观测性（日志 / 错误码 / 文档，不影响结果）。

**处置建议**（由两轴推导的报告结论，非新档位）：

| S×O \ B | B3 现实可达 | B2 条件可达 | B1 边界/不可达 |

## 7. 判定标准与反误报原则

- **性能类特殊纪律（务必贯彻）**：静态检视只能立「嫌疑点 / 优化项」——「确定性路径串行化/排序代价大」可静态证；但任何「劣化 N 倍」的量化结论**必须以基线差分实测为准**（同 shape、同硬件、同版本、确定性开 vs 关），不可用代码审查替代性能基线看护。引用实证 #946 的「200us → 3000us，15 倍」时须标注其为 issue 原文数据。
- **三种判定**：
  - **命中**（可静态证低效）：确定性分支存在「并行度被降至 1 而可保留并行」「全量排序/去重而存在更优替代」「原子累加退化为串行累加」中任一，且反证排除失败 → 立 Bug 卡；
  - **观察项**：串行化/排序存在但最优替代方案需实测评估（无开/关耗时数据即只能为观察项）→ 记录并附开关对比方案，按 S2×O1 暂定；
  - **反证排除**：串行化/排序为确定性语义所必需且无更优替代、差异源于基线口径不一致 → 明确写出反证理由与防护面证据。
- **必须与 A06 两面同核**：确定性开关的审查不可只看性能——须同时确认「开关是否真正生效」（A06 精度面）；若开关未分流（两态共用实现），性能问题不属本条。
- **基线口径必须一致**：非确定性基线的口径差异（实证 #3332 中「71 非确定性基线」）会被误读为确定性劣化；判定前先核对基线的版本与开关口径。
- **确定性路径的循环按 G01 核**：串行化/排序循环须核「推进变量更新 + 不推进退出」，空转归 FP-G01。
- **不臆造行号**：每条证据必须是实际读到的 文件:行号；引用实证样板时同样给出路径与行号，issue 时点行号与本仓 HEAD 漂移时注明。

### 判定纪律补充（v3.6）：非对称增减、证据等级与误判记录

**增减不对称**：允许追加候选（有据即可，错了可由用户排除）；**撤销或否决候选必须附 `[文件]:[行号] [代码行]` 负向证据**。无证据的「看起来没问题」一律记为「未核查」，不得计入反证排除，也不得据此下调等级——否决造成的漏报用户不可见、不可恢复。

- **证据等级**（Bug 卡必填）：`静态可证` = 推导链完整且触发输入可静态构造；`需实测确认` = 依赖运行时输入规模、设备行为或环境差异。标 `需实测确认` 的条目**不得以「命中」名义出卡**，按观察项记录并附实测用例。
- **Agent 误判记录**（Bug 卡必填）：本次被推翻的假设、推翻它的证据（`[文件]:[行号] [代码行]` 或实测输出）、判定标准是否随之修订；无推翻写「无」。
- **误判回流**：同类误判在 3 次检视中重复出现，登记至 `cases/misjudgments.jsonl`（字段见 `cases/README.md`），并在本模式判定标准中新增对应防线；守门 C19d 校验台账字段合法。

## 9. 示例速览：aclnnScatterNd

- **定位**：`cann/ops-nn` → `index/scatter_nd/`（op_kernel 含确定性分支与原子累加消除路径；op_host 含 tiling 的确定性分流与 config/<soc>/；docs/aclnnScatterNd.md）。同族样板：ScatterNdAdd / ScatterNdUpdate（同目录族）、`convolution/convolution_backward/`（实证 #946）、`cann/ops-math` Hist V2（实证 #2957）、`cann/ops-transformer` FAG（实证 #473）。
- **检视面提示**（引导，不预设结论，仍须逐点核查；行号以本地 HEAD 为准）：
  - 清单点 ①：定位 `Deterministic|GetDeterministic` 读取点与后续分流，建立「开关状态 → 路径」对表；同步按 FP-A06 核开关是否真正生效（两面同核）。

  - 清单点 ⑤：额外清零/初始化与冗余同步——与 FP-A05 交叠，分别记录代价面与残留面。
  - 清单点 ⑥：反证面——若串行化/排序为确定性语义所必需且无更优替代，或差异源于非确定性基线口径不一致（对照实证 #3332 中「71 非确定性基线」口径），写出反证理由。

## 10. 能力边界与自检（v3.8）

### 能力边界

- **静态可证**：清单里能在源码内给出「`文件:行号` + 推导链」的部分，按第 7 节判据出卡。
- **需实测确认**：依赖运行时输入规模、设备行为或环境差异的结论，只能记观察项并附实测用例（证据等级见第 7 节）。
- **不覆盖**：本模式以外的机理（边界见第 0 节）与仓外框架侧行为；`TRIAGE.md` 只负责收敛候选，不构成判定依据。
- **找不到 ≠ 没有**：按清单未命中只说明「本轮未发现」，不得表述为「该算子无此缺陷」；抽样核查须在报告写明抽样口径。

### 自检

```bash
python3 scripts/gen_triage.py --check                          # 分诊表与映射一致

python3 check_fault_patterns.py                                # 全库守门
```

### 工作量与抽样（v4.0）
