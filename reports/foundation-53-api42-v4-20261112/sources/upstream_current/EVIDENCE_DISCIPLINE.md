# 证据纪律（Evidence Discipline）—— 本轮 aclnn×52FP 专项沉淀

> 来源：2026-11-06 专项一（A5 / CANN 9.3.0，20748 格矩阵、12 条 issue）。
> 每条都附本轮真实反例——不是抽象教条，是踩出来的。
> 适用：任何"静态分析 + 真机验证"混合的缺陷挖掘。

---

## D1. T1 只能来自「该接口自身」的实测

**规则**：`T1` = 本接口有真机实测；同判据族（同 tiling / 同分支 / 同 opdir / 同 kernel 模板）的实测**只能支撑 T2**。

**反例**：C05 的 FAG 族 9 格，想借 `aclnnAddmm` 的实测（`det=2` 时 `workspaceSize` 7,340,544→512）升 T1。但 ADDMM 与 FAG 是不同算子，且 FAG 本体在 A5 的可达性从未验证。被判据持有人顶回，最终 `cand/T2`。

**自检问句**：这个证据是在**这个接口**上测出来的吗？

---

## D2. 阴性证据同样不许跨接口借用

**规则**：对照 shape 下的实测阴性（如 BNR `det=0/1` 两档 workspaceSize 相同），只能支撑该接口该 shape 记 `uncovered`，**不能外推成"该族无劣化"**。

**反例**：若把 BNR 的阴性推广到其余 22 个确定性实现接口，会直接产出 22 个错误结论（它们根本没上板）。
同源反例在文档面：把「同算子 README 说算子支持」当成「该接口支持」，会让 38 格虚胖成立。

---

## D3. 观测不到 ≠ 阴性

**规则**：当静态证据与实测观测点**不在同一层**时，观测不到只能记「当前工具链不可观测」，既不改写成"无问题"，也不升级为 found。

**反例**：C05 的 FAG 两腿 `workspaceSize` 完全相同（23,399,424 / 25,758,720），但确定性代价发生在 **kernel 侧**（S2 分块部分和落 GM），而 `workspaceSize` 是 **tiling 侧**观测量——两路可能按同一上界统一申请。所以这组数据既不证实也不证伪静态结构证据。

---

## D4. 阴性结果必须先证明「你测到了那个形态」

**规则**：任何"跨核/写冲突"类用例，开跑前必须验证前提成立：
```
① 核数 > 1 —— 从 host tiling 推导 usedCoreNum / SetBlockDim 的实际值（不要只看"有没有分核变量"）
② 切分维确实落在会产生重叠（同一输出元素被多次写）的维度上
③ （推荐）记录 tilingKey 与分核依据
```
不满足 ①② 的用例，其阴性结果只能记 `BASELINE_UNVERIFIED`，**不得记 uncovered，更不得记 clean**。

**反例（本轮最典型）**：`aclnnUnfoldGrad` 用 `gradOut=[1,5,8,4]`、`dim=1` 测跨核写冲突，跑出 20 轮 × 两腿逐字节一致。看着像"该算子确定性很好"，实际
`unfold_grad_tiling.cpp:343 useCoreNum = CeilDiv(batchNum, CeilDiv(batchNum, totalCoreNum))`、`:276-278 batchNum = ∏ gradOutShape[0..dim-1]`
⇒ `batchNum=1` ⇒ **useCoreNum=1，结构性单核**——"跨核竞争"这个前提根本没被构造出来，阴性毫无信息量。
正确形态是 `gradOut=[8,8,5,4] / dim=2`（batchNum=64）。

> D2 与 D4 是一对：D2 说"阴性不能外推"，D4 说"阴性本身要先有资格算数"。

---

## D5. 判 clean 的两条充分条件（跨核/写冲突类）

```
① 静态可证「无跨核同元素累加」（每核写互斥区间 / 核数 = f(tile 数) 而非 f(归约维)）
   或
② 「C1 成立的 shape」与「对照 shape」都 20 轮 × 两腿逐字节一致
```
**只有对照 shape 的阴性 → 只能记 `uncovered`**。

**静态反证三件套**（GMMA / UnfoldGrad 都用它判了 clean）：
```
a. 核数 = f(tile 数) 还是 f(归约维)？      看 usedCoreNum_ / SetBlockDim 的表达式
b. 归约维块大小（baseK/baseN…）是单核内循环，还是跨核下标？
c. kernel 输出地址是否形如 base + blockIdx * 互斥步长？原子加作用域是核内还是跨核？
```
- GMMA：`usedCoreNum_ = min(mCnt*nCnt*groupNum_, aicNum)` + `yRefGm + blockIdx*baseM*baseN`
- UnfoldGrad：`useCoreNum = CeilDiv(batchNum, …)` + `gradInBlockOffset = batchNumPerCore*blockIdx*outputNumPerCore`

## D6. 主张必须区分「算子级」与「接口级」声明面

**规则**：`README.md` 产品表是**算子级**，`docs/aclnnXxx.md` 是**接口级**。同算子下 V1/V2/V4 支持 P 而 V3 不支持 P 是**合法设计**。

**三层强度**：
| 层 | 主张 | 强度 |
|---|---|---|
| **L1** | 同 opdir 内两份**接口级**资料对同一产品结论相反（且共用同一份 `*_def.cpp`） | 最强（不依赖 README、不依赖实测） |
| **L2** | 接口级资料 vs OpDef 注册面（`AddConfig` / `AddConfigByArch`），且同 opdir 其余接口都支持 | 中（可被"注册≠宣称"驳回） |
| **L3** | 接口级资料 vs README 产品表 | 弱，**单独不提** |

**反例**：43 格 F03 里，只有 4 组满足 L1 并成功提单；5 组是 DUPLICATE/SIBLING；**5 组只剩 L3 不提**。

---

## D7. 「期望」要写成"无论对方怎么答都成立"的形式

**四级写法**：`选边（错） < 条件式（可） < 硬锚点（最强） < 硬锚点 + 条件式（最稳）`

**反例**：三条文档 issue 提交后被打回重写，原因是"期望"写成"资料应改为支持"——维护方一句「该产品未适配」即可推翻。改成"若已适配→改资料；若未适配→撤 README 声明，**无论哪一方对，当前都有一方需修正**"后无法关单。

**另记**：`AddConfig` 属编译注册面，**不等同发布宣称**，只能当佐证。

---

## D8. 全量回加自检：任何一列 `sum(状态) == 接口总数`

**规则**：矩阵是全量口径，任何一列的分状态之和必须等于接口总数，否则必有漏记/重复记。

**反例**：汇总时把 C05 的 `uncovered 26` 写成 23，`3+9+23+361=396≠399`，靠回加才发现。

**建议**：做成常驻自检 `for fp: assert sum(Counter(state)) == N`，进 CI。

---

## D9. 标量属性值域校验是可枚举的缺陷面

**规则**：`eps`/`momentum`/`clamp` 等**标量属性**的值域校验缺失，可以静态枚举后再用真机三组对比确认。

**本轮实证**：`scan_attr_validation.py` 扫 399 接口 → 339 个有标量形参、**282 个（83.2%）存在"未见图省校验"形参**、**54 个 `eps/epsilon` 未校验**。真机三组对比（`合法值` / `负值+Var>1` / `负值+Var<1`）做成 6 个，**4 found**（LayerNorm/FastLayerNorm/BatchNorm/WithImplMode）+ 2 clean 正例。

**注**：`training=true/false` 会改变失败形态（`1/0=inf` vs `sqrt(负数)=NaN`），BN 类接口必须两腿都看。

---

## D12. 精度判定必须用 `golden.py` 的 `aclnn` 入口，`kernel` 入口不得用于 aclnn 层

**规则**：仓内 `tests/assets/golden.py` 的 `__golden__` 注册表通常有三个键——`kernel` / `aclnn` / `e2e`，
而**很多算子只有 `kernel` 键**。拿 `kernel` 入口的参考去判 `aclnn` 层的输出，会把
**层间差异**（dtype 转换、参数校验、内存布局、可选输出占位）当成算子缺陷。

**实测（`ops-nn` @ `b27fda2`，全仓 `tests/assets/golden.py`）**：

| 指标 | 数量 |
|---|---:|
| `golden.py` 总数 | **362** |
| 含 `aclnn` 键 | **80（22.1%）** |
| 仅 `kernel` 键 | **228** |

即**近八成算子根本不存在 aclnn 层参考**。此时正确动作是记「判据不成立」，而不是「未覆盖」，
更不是拿 `kernel` 参考硬判。

**前置条件（三条，缺一不可）**：
① 该算子 `golden.py` 存在且 `__golden__["aclnn"]` 有同名注册；
② 输入可**精确重构**（示例的造数逻辑能被独立复现，而不是只有示例自己知道）；
③ 输出**全量导出**——官方示例通常只打印 `result[0..7]`，而 `aclnnRmsNorm` 有 32 个输出元素，
只比前 8 个等于只测了 1/4（见 D13）。

**本轮实测漏斗（四模式 A01/A14/A08/A22 下 248 个未覆盖接口）**：
`golden.py` 存在 56~73 → 其中 `aclnn` 段有同名注册 **12** → 输入可精确重构 11 → **真正完成判定 4**。

## D13. 精度比对必须全量导出，不能只看示例打印的 `result[]`

**规则**：若示例只打印前 N 个元素，必须在 `memcpy` D2H 处拦截并把**全量**数据落盘
（如 `DEV_DUMP_DIR`），否则比对范围小于输出规模，漏判概率极高。

**实测**：`aclnnRmsNorm` 输出 32 个元素，示例只打印 8 个——按示例输出比对只覆盖 25%。

**踩坑补充**：`aclCreateTensor` 只保存 dims/strides **指针**（见 pitfalls K1363），
shim 里若把 dims 放在局部数组，后续访问会 SIGSEGV，并被误读成「算子崩溃」。

---

## D11. 索引类输出的比对前提：并列时结果不唯一，不得用于任何 bit 比对

**规则**：当被测输出是 **TopK 索引 / ArgMax 下标 / 排序置换**等**离散选择**，且输入存在并列
（含「全为同一常数」这种极端并列）时，选择结果**不唯一**。此时**不得**把该输出用于：
① 跨代 / 跨版本 bit 比对（A17）；② 多轮 bit 一致性判定（A02）；③ 精度对标杆（A01/A14）。

**必要前置**：构造**严格无并列**的输入——按索引位加扰动（如 `+1e-3 × i`），并断言「并列数为 1」。

**本轮反例（两次，方向都是「误判成缺陷」）**：

| 接口 | 当时判定 | 实际 | 根因 |
|---|---|---|---|
| `aclnnBSASelectBlockMask` | 跨代 bit 不同 → 疑似 A17 | 用例 q/k 全为 `0.1f`，score 完全并列，两代选不同索引 | 资料只承诺「取 top-k 个最大值对应的索引」，未规定并列选哪个 |
| `aclnnNsaCompressAttention` | 10 轮签名不同 → 疑似 A02 | 用例全为常数 `1.0`，差异全部落在 `topkIndicesOut` | 同上 |

**为什么这条要单独列为一条纪律，而不是塞进 A01/A02/A17 卡片**：
它是**输出语义层**的前提，不是某一条模式的参数。塞进卡片就得写三遍，而写三遍必然漂移
（本库已经吃过「兄弟对拍结论写反」的亏，见 `cases/false-upper-bounds.md`）。
放在这里，四张卡各引一句即可。

**落地动作**：测试设计阶段填一个「输入是否可能有并列」的是/否；填「是」则必须在用例 `note`
里写明「已加扰动、并列数=1」，否则该输出不参与任何 bit 比对。

## D10. 真机扩面用「签名聚类 + 同构复用」

**规则**：不要按算子族扫，按**签名形状**聚类，找每类里基线已跑通的代表接口，同类内直接套 spec 只改名。

**实证**：通用生成器跑 25 个 norm 接口，前 11 个全部 `BASELINE_FAIL`（量化族三层约束串联）；
而按签名聚类后 `aclnnFastLayerNorm` 与已验证的 `aclnnLayerNorm` **签名逐字相同**，1 次命中。

**推论**：量化族（`*Quant` / `*DynamicQuant` / `*MxQuant`）各自成类且无代表 → 标 `BASELINE_UNVERIFIED`，不硬啃。

---

## D14. 两段式接口第二段返回 0 ≠ 执行成功，必须检查 `aclrtSynchronizeStream`

**规则**：`aclnnXxx` 第二段只是**下发**，返回 0 仅表示入队成功。判「静默成功但输出未写」之前，必须同时打印 `aclrtSynchronizeStream` 的返回码；sync 非 0 时，未写的输出是**设备侧拒绝**的结果，不是 B12 类缺陷。

**反例（2026-11-07，差点误报）**：`aclnnIndexSelect` 传越界 `index=7`（`dim0=4`），两段返回 `0/0`、输出保持预填值，第一版据此写成「返回成功但输出未写」。补打 sync 后发现 `aclrtSynchronizeStream = 507035`，kernel 已在 `gather_v3_base.h:137` 的 `CheckIdxValue` 断言处终止——实现**正确地拒绝了**越界索引，只是拒绝发生在设备侧。

**自检问句**：这个「返回 0」是同步结论，还是仅仅表示命令入队？（同理适用于 `aclrtStreamSynchronize` / 带同步的 `aclrtMemcpy`。）
