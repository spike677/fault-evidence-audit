# FP-A01 aclnn 接口检视（fpa01-kernel-review）

对用户指定的 aclnn 接口（如 aclnnCdistGrad）做 FP-A01 专项源码检视：先定位算子实现，再按清单逐项核查，每个结论给出**文件 + 行号 + 推导链**证据，命中即出 Bug 卡，输出检视报告。**本模式特殊纪律：① 缺陷不是「算错」而是「精度规格低于竞品」——单算子功能正确、UT 可能恰好卡在阈值内侧，须以「与 GPU/CPU 标杆逐元素 utol 对比」为判据，而非以能否跑通判据；② 触发签名 `Exp|Log1p|Rsqrt|Tanh|Power(` 在 kernel 中普遍存在，命中只表示「值得人工核」，不表示成立——必须给出「误差量级劣化倍数 + 标杆实现差异」的量化推导链；③ 精度劣化是**静态可推导但需实测确认**的结论——静态只能立「近似路径 + 无补偿」的候选点位与实测方案，不可直接表述为「UT 必然不过」。**

## 0. 与相邻模式的边界

| 相邻模式 | 分工 |
|---|---|
| FP-A14（FFMA 与 MMAD 硬件指令差异） | **同族按指令类别分工**：A01 管**超越函数类**近似指令（exp/log/rsqrt/tanh/power 及其组合）的精度规格；A14 管**乘加与矩阵乘类**指令（FFMA/MMAD）的配置差异。同一算子可两者并存，报告双向关联 |
| FP-A17（A1 与 A2 硬件代际精度差异） | A17 是**同一实现跨硬件代际**的精度差（A1 vs A2）；A01 是**同一代内所选指令规格低于竞品标杆**——若「换代际」是因、「换指令」是果，按主导机理归属，不重复立卡 |
| FP-A03（竞品高精度中间计算，NPU 直接低精度） | **位宽 vs 指令**二分：A03 是**中间变量位宽**不足（该 fp32 累加却用 fp16/bf16）；A01 是**指令本身**的精度规格不足（近似超越函数/低精度乘加）。位宽归 A03，指令选型归 A01 |
| FP-A13（输入尾数截断才能通过精度标准） | A13 是**输入预处理阶段**的尾数截断；A01 是**计算阶段**的指令选型——按「截断 vs 指令」分，可同算子共现 |
| FP-A15（inf/nan 特殊值行为差异） | A15 管特殊值语义（inf/nan 传播与处理）；A01 管有限值区间的精度量级差异——特殊值用例失败先查 A15 |
| FP-A04（功能问题演变为精度静默故障） | A04 是**本应报错却静默输出错值**；A01 是**正常路径精度不达标**（无错误、无静默降级语义）——按「是否有错误被吞」分 |

**症状反查定位**：与 GPU/CPU 标杆逐元素比对，误差稳定落在 **2~4 ULP** 或均方根误差明显劣化（如劣化 4.65 倍）→ 近似指令选型面（清单①）；`exp`/`log` 组合被用来近似 `pow` → 组合近似替代路径面（清单②）；输入落在数值稳定敏感区（如 Softplus 的 x≈-16.6、Bessel 的 |x| 偏大）时输出与标杆符号或量级不符 → 补偿缺失面（清单③④）；单算子 UT 通过但网络级 E2E 精度波动 → 基线看护面（清单⑤）。

## 1. FP-A01 模式卡摘要（检视依据，源自本库 `patterns/FP-A/FP-A01.md`，v3.1）

- **编号 / 名称**：FP-A01 硬件指令精度不足，未与竞品对齐 ｜ **类别**：精度 ｜ **风险**：高（S3×O3=9）｜ **状态**：活跃
- **适用声明头**（照抄卡片）：仓 All ｜ 侧别 Kernel ｜ 载体 Kernel源码 ｜ 触发 Exp|Log1p|Rsqrt|Tanh|Power\( ｜ 默认启用 true
- **skill 核查面**：侧别 Kernel——skill 落地为 `op_kernel/` 中超越函数与近似指令的实现文件（含 arch35 / regbase / SIMT 等架构变体）；延伸至 `op_host` 侧与精度对齐相关的属性/精度模式选择（如 DOUBLE_FLOAT_TECH 类高精度模式开关）与 docs 中的精度说明
- **故障机理**：所选硬件指令（近似超越函数、低精度乘加等）的精度规格低于竞品同类指令，且未做软件补偿。
- **触发条件**：依赖特定指令路径的算子（exp/sin/cos/rsqrt 等近似指令实现）。
- **典型表现**：精度差异、网络精度波动。
- **源码审查映射点**：指令选型与精度对齐逻辑；降精度路径是否有补偿。
- **检测签名**（命中即候选缺陷点位）：`Exp\s*\(\s*Muls\s*\(\s*Log`（exp/log 组合近似 pow）；`log1p|Log1p`（数值稳定补偿缺失排查点）。
- **测试拦截建议**：含超越函数/近似指令的算子与 GPU 参考逐元素比对 utol；关键网络级 E2E 精度基线看护。
- **实证案例**：ops-math **#2110** cdist_grad 的 GENERAL(0<p<2)/LARGEP(p>2) 两条 DAG 用 `Exp(Muls(Log(ratio), p-1))` 近似 pow（误差 2-4 ULP），对标 `torch.ops.aten._cdist_backward` 的 `std::pow`（表驱动、内部扩展精度，<1 ULP）均方根误差劣化 **4.65 倍**（NPU fp32 3.91e-4 vs GPU A100 8.40e-5），ATK 双标杆精度不达标，修复改用高精度 `Vec::Power`（DOUBLE_FLOAT_TECH，约 1 ULP）与 torch 对齐；ops-math **#2271** bessel_i1e（arch35）`exp(-|x|/4)` 的 Taylor 级数仅 9 项截断误差大 + 有理多项式系数有效位不足，最大误差 2.6e-6 远超 fp32 精度预期，修复将 Taylor 扩至 13 项、提升系数精度并分段 Horner 规避编译器限制，误差降至 6.1e-10（约 4000 倍，PR #4131）；ops-nn **#3589** SoftplusV2 直接 `log(1+exp(x))` 无数值稳定补偿，输入 -16.619（exp≈6e-8，fp32 下 1+x 舍入为 1）NPU 输出 0 而 torch CPU 非 0。**共性特征：近似/低精度实现路径的精度规格低于标杆（GPU/CPU 库）且未做软件补偿，修复方式均为换用高精度指令、扩展级数项数或改用数值稳定实现。**
- **关联**：FP-A14、FP-A17。

## 2. 检视输入与算子定位

**输入**：aclnn 接口名（必填，如 `aclnnCdistGrad`）；可选 ref（默认 master）、指定仓（默认自动定位）；可选现象描述（实测误差量级 / 劣化倍数 / 失败输入取值——用于直接定位近似路径与敏感区）；可选标杆实现（GPU/CPU 参考库，如 `torch.ops.aten.*`）。

**接口名 → 算子目录换算**：去 `aclnn` 前缀 + 驼峰转下划线小写：
`aclnnCdistGrad → cdist_grad`、`aclnnBesselI1e → bessel_i1e`、`aclnnSoftplusV2 → softplus_v2`。

**仓定位顺序**（GitCode `cann` 组织，逐仓用目录列表确认）：`ops-math`（math 类——超越函数/特殊函数实证集中地）→ `ops-nn`（activation/loss 类）→ `ops-cv`（image 类）→ `ops-transformer`（attention/moe 类）。**类目名不总与直觉一致**，以目录列表为准。FP-A01 高发面：含 exp/log/rsqrt/tanh/power 近似实现或组合近似的算子、特殊函数（bessel 类、erf 类）的级数/多项式实现、activation 类的数值稳定实现、arch35 等新架构上的近似指令路径。

**算子目录结构约定**（以实证算子为例，具体布局以目录列表为准）：

```text
{类别}/{op_name}/
├── op_kernel/                # kernel 头文件——主检视面（近似指令与级数实现）
│   └── arch35/ regbase/ ...  # 架构变体（近似指令实现可能逐架构不同）
├── op_host/                  # def / infershape / tiling——精度模式与属性选择面
│   └── op_api/               # aclnn_*.cpp（若存在）
├── op_graph/  tests/  docs/  examples/   # 视算子而定
```

## 4. 检视清单（每点：查什么 → 何处 → 命中判据）

对算子的 `op_kernel/`（含架构变体）全部相关文件逐点核查，`op_host` 精度模式选择与 docs 精度说明同步核对，**每点先查命中面、再做反证排除**；已换用高精度指令或已做补偿的实现要记录为防护面证据。

### ① 超越函数近似指令选型与精度对齐
- 查什么：exp/log/rsqrt/tanh/power 等的实现是走**近似指令**还是**高精度模式**（如 `Vec::Power` + `DOUBLE_FLOAT_TECH`）；是否有与竞品（GPU/CPU 库）对齐的选型说明；降精度路径是否有补偿。实证 #2110：GENERAL/LARGEP 两条 DAG 用近似组合替代高精度 `Vec::Power`，精度劣化 4.65 倍。
- 何处：kernel 中超越函数调用点、指令封装函数（`Vec::` / `Reg::` 类）、架构变体文件。
- 命中判据：能写出「近似指令误差量级（2~4 ULP）→ 与标杆（<1 ULP）对齐失败」的推导链，且该路径为算子主路径 ⇒ 命中候选（须附实测方案）。

### ② pow 类组合近似的替代路径
- 查什么：是否存在 `Exp(Muls(Log(x), p))` 这类「以 exp/log 组合近似 pow」的写法（检测签名 `Exp\s*\(\s*Muls\s*\(\s*Log`）——组合近似在 p 非整数、x 跨数量级时误差放大；是否应改用原生 `Power` 指令。
- 何处：kernel 中 pow/幂运算的实现段（CDIST 类、norm 类、量化反量化路径高发）。
- 命中判据：存在组合近似写法且无误差补偿、对标库使用原生 pow ⇒ 命中候选。

### ③ 降精度路径的软件补偿（log1p / 数值稳定实现）
- 查什么：`log(1+x)` 类写法是否用了数值稳定的 `log1p`（检测签名 `log1p|Log1p`）或等价补偿；Softplus 类 `log(1+exp(x))` 在 x 为负大数时 `1+exp(x)` 是否被舍入为 1 导致输出恒 0（实证 #3589：x=-16.619 输出 0 而 torch CPU 非 0）；是否存在分段/恒等变形补偿（如 `max(x,0)+log1p(exp(-|x|))`）。
- 何处：activation 类算子的 kernel 主计算段、数学恒等变形处。
- 命中判据：存在「无稳定补偿的 log(1+exp) / log(1+x) 写法」且触发输入区间可构造 ⇒ 命中候选。

### ④ 级数截断与多项式系数精度
- 查什么：特殊函数（bessel/erf/gamma 类）的 Taylor / 有理多项式实现——**截断项数是否与目标精度匹配**、**系数有效位是否足够**、Horner 求值是否受编译器常量折叠限制（实证 #2271：Taylor 仅 9 项 + 系数有效位不足，最大误差 2.6e-6，扩至 13 项 + 分段 Horner 后降至 6.1e-10）。
- 何处：kernel 中特殊函数的级数展开与多项式求值段。
- 命中判据：能给出「截断余项量级 > fp32 精度预期（~1e-7 量级）」或「系数有效位不足以支撑目标精度」的静态推导 ⇒ 命中候选。

### ⑤ 数值稳定敏感区与标杆对齐基线
- 查什么：算子是否标注了与标杆（torch / TF / GPU 库）的精度对齐目标（utol 阈值）；`docs/` 中是否有精度说明；关键网络级 E2E 精度基线是否在测试矩阵中看护；ATK 双标杆（NPU vs GPU vs CPU）是否覆盖。
- 何处：`tests/` 的精度用例、`docs/`、算子精度配置。
- 命中判据：无对齐基线 / 敏感区无专项用例 ⇒ 记观察项（测试面缺口），不单独定缺陷。

## 5. 检视流程

1. **定界**：换算 op 目录、确认所在仓与 ref；确认架构变体布局；记录用户现象（误差量级 / 失败输入取值 / 标杆库）。
2. **枚举**：目录列表列出 `op_kernel/`（含架构子目录）与 `op_host` 相关文件、`docs/`、`tests/`，产出文件清单。
3. **触发词扫描**：按 `Exp\s*\(\s*Muls\s*\(\s*Log`、`log1p|Log1p`、`Exp\(|Log\(|Rsqrt\(|Tanh\(|Power\(` 定位风险面（本地仓用 grep；API 模式逐文件拉取后检查）。**触发为关键词：签名零命中时清单仍须逐项核查完毕**（如纯多项式实现无 exp 签名仍核 ④）。
4. **逐点核查**：按第 4 节 ①~⑤ 记录命中面与防护面证据（文件:行号）；对近似路径给出「误差量级 vs 标杆」的推导链。
5. **反证排除**：已换用高精度指令（`Vec::Power` + DOUBLE_FLOAT_TECH 类）、已有数值稳定补偿（log1p / 分段恒等变形）、级数项数与系数精度满足目标、无组合近似写法 → 明确写出反证理由。
6. **判定**：按第 7 节标准给出 命中 / 观察项 / 反证排除。
7. **GitCode 查重**（仅命中项）：issues API 按接口名 + `精度|ULP|误差|对标|utol` 检索，逐条比对是否同机理；无同机理才立卡。
8. **业务可达性核查**（仅命中项）：判 B 等级、定业务影响类型、给处置建议；默认保守（无法证明不可达即记 B3），降档须附证据；B 不改 S×O 档位。
9. **出报告**：按第 8 节模板落盘；所有精度结论标注「静态推演，需与标杆逐元素 utol 实测确认」并附实测方案。

## 6. 风险定级（S×O）与业务影响评估（B 轴）

- **S**：S3（精度差异 / 网络精度波动——结果错但可运行）；S2（仅影响非关键路径的轻微劣化）；S1（精度达标但实现非最优）。
- **O**：O3 = ≥2 条独立实证；O2 = 1 条独立实证；O1 = 仅静态扫描命中或团队笔记（实证 = 确认对应的 issue / PR，或经跨仓、跨分支核验确认的缺陷记录，同权计入）。静态推演命中且无实证默认 **O1**；升档须在报告中给出实证依据。
- **风险 = S×O**：≥6 高；3/4 中；1/2 低。FP-A01 基准：模式卡整体 S3×O3=9（高）；纯静态命中 S3×O1=3（中，暂定，实测后复评）。

### B 轴：业务影响评估（与 S×O 正交；报告层新增，不改卡片定级）

S×O 回答"多严重、多常见"，**不回答"真实业务能不能碰到"**。B 轴补这一问，只决定**修复优先级建议**，**不参与 S/O 取值、不改 S×O 档位与卡片元数据**。

**业务可达性（B）**——触发条件在真实负载中的可达程度：

| 等级 | 判据 | 证据要求 |
|---|---|---|
| B3 现实可达 | 主流框架/公开模型默认路径即可命中（如 PTA/torch_npu、vLLM、MindIE 常规调用） | 调用方或公开负载来源 |
| B2 条件可达 | 需特定 attr/dtype/shape 组合，业务中存在但非默认 | 该组合的业务来源 |
| B1 边界/不可达 | 需极端、超规格或非法参数（超出接口合理上限的 shape、退化/非法输入） | "为何不可达"的说明 |

- **默认保守**：无法证明不可达 → 记 **B3**；降为 B1/B2 必须附证据，**不得仅凭"业务应该不会这么用"**。
- 超规格参数是否算 B1 取决于**接口契约**：契约允许但业务不用 → B1；契约不允许（本应报错）→ 属校验缺失（FP-B04/B05 类），另行归属。

**业务影响类型**（命中后对用户可见结果的后果，用业务语言表述）：静默精度损失（模型效果下降 / loss 不收敛 / 偶发 NaN）｜ 任务失败中断（报错 / 崩溃 / 挂死）｜ 性能退化 ｜ 仅可观测性（日志 / 错误码 / 文档，不影响结果）。

**处置建议**（由两轴推导的报告结论，非新档位）：

| S×O \ B | B3 现实可达 | B2 条件可达 | B1 边界/不可达 |
|---|---|---|---|
| 高（≥6） | 尽快修 | 尽快修 | 排期修 |
| 中（3/4） | 尽快修 | 排期修 | 记录（业务难以触达） |
| 低（1/2） | 排期修 | 记录 | 记录 |

## 7. 判定标准与反误报原则

- **签名 / 触发词命中 ≠ 成立**：`Exp(`/`Log(`/`Rsqrt(` 在 kernel 中普遍存在且绝大多数正常——命中只是定位提示，必须给出「该路径精度规格低于标杆」的量化推导链（误差量级、劣化倍数、标杆实现差异）。
- **三种判定**：
  - **命中**（可静态证缺陷路径）：存在「近似指令/组合近似/级数截断 → 精度规格低于标杆且无补偿」的完整推导链 + 触发输入可构造 → 立 Bug 卡（档级按实测证据定）；
  - **观察项**：近似路径存在但误差是否超标依赖实测（多数情形）、或仅测试面基线缺口 → 记录并附实测方案，按 S3×O1 暂定；
  - **反证排除**：已用高精度指令 / 已有数值稳定补偿 / 级数项数与系数满足目标 → 明确写出反证理由（防护面证据）。
- **「UT 通过」不是反证**：单算子 UT 阈值可能恰好卡在劣化内侧；须以与**标杆实现**（GPU/CPU 库）逐元素 utol 对比为准，网络级 E2E 基线另行看护。
- **精度劣化不静态断言「必然不过」**：静态只能立「候选点位 + 实测方案」，实测前不升级为「已确认」。
- **不臆造行号**：每条证据必须是实际读到的 文件:行号；引用实证样板时同样给出路径与行号，issue 时点行号与本仓 HEAD 漂移时注明。

### 判定纪律补充（v3.6）：非对称增减、证据等级与误判记录

**增减不对称**：允许追加候选（有据即可，错了可由用户排除）；**撤销或否决候选必须附 `[文件]:[行号] [代码行]` 负向证据**。无证据的「看起来没问题」一律记为「未核查」，不得计入反证排除，也不得据此下调等级——否决造成的漏报用户不可见、不可恢复。

- **证据等级**（Bug 卡必填）：`静态可证` = 推导链完整且触发输入可静态构造；`需实测确认` = 依赖运行时输入规模、设备行为或环境差异。标 `需实测确认` 的条目**不得以「命中」名义出卡**，按观察项记录并附实测用例。
- **Agent 误判记录**（Bug 卡必填）：本次被推翻的假设、推翻它的证据（`[文件]:[行号] [代码行]` 或实测输出）、判定标准是否随之修订；无推翻写「无」。
- **误判回流**：同类误判在 3 次检视中重复出现，登记至 `cases/misjudgments.jsonl`（字段见 `cases/README.md`），并在本模式判定标准中新增对应防线；守门 C19d 校验台账字段合法。

## 11. 已知缺陷案例库：触发条件 / 根因 / 修复范式 / 针对性深挖（v5.1）

> 本节把本型**已确认缺陷**拆到「触发条件 → 根因（具体路径）→ 修复范式（✅ 正确代码）→ 针对性发现步骤 → 最小复现锚」的代码级颗粒度。
> 修复范式为**正确形态示意**；路径引用取自卡片实证，行号以被检仓本地 HEAD 为准，**不得臆造**。

### 案例 1｜exp/log 组合近似替代原生幂，精度劣化 —— #2110（cdist_grad）

- **触发条件**：cdist 反向 grad 的 pow 路径（GENERAL 0<p<2 / LARGEP p>2 两条 DAG），ratio 跨数量级或 p 非整数时命中。
- **根因（具体路径）**：GENERAL/LARGEP DAG 将 `pow(ratio, p-1)` 写成 `Exp(Muls(Log(ratio), p-1))` 组合近似（误差 2~4 ULP）→ 对标 `torch.ops.aten._cdist_backward` 的 `std::pow`（表驱动、内部扩展精度 <1 ULP）→ 均方根误差劣化 **4.65 倍**（NPU fp32 3.91e-4 vs GPU A100 8.40e-5）→ ATK 双标杆精度不达标。
- **修复范式（✅，示意）**：

```cpp
// ❌ 组合近似：误差 2~4 ULP、跨数量级放大
// out = Exp(Muls(Log(ratio), p - 1.0f));
// ✅ 高精度原生幂（DOUBLE_FLOAT_TECH，约 1 ULP）
// out = Vec::Power(ratio, p - 1.0f, /*DOUBLE_FLOAT_TECH*/);
```

- **针对性发现（可执行）**：① 签名 `Exp\s*\(\s*Muls\s*\(\s*Log` 定位组合近似段；② 核是否已有 `Vec::Power` + DOUBLE_FLOAT_TECH 路径（有则记防护面）；③ 对照标杆 pow 的精度口径（表驱动 / 扩展精度）。
- **最小复现锚**：构造 ratio 跨数量级、p∈(1,2) 与 p>2 输入，与 GPU `_cdist_backward` 逐元素 utol，看误差是否稳定落在 2~4 ULP / 均方根劣化。
- **实证**：ops-math **#2110**。

### 案例 2｜Taylor 级数截断 + 系数有效位不足 —— #2271（bessel_i1e，arch35）

- **触发条件**：arch35 上 bessel_i1e 的 `exp(-|x|/4)` Taylor 级数实现，|x| 偏大输入。
- **根因（具体路径）**：Taylor 级数仅 **9 项**截断 + 有理多项式**系数有效位不足** → 最大误差 **2.6e-6** 远超 fp32 精度预期 → 修复将 Taylor 扩至 **13 项**、提升系数精度并**分段 Horner** 规避编译器常量折叠限制 → 误差降至 **6.1e-10**（约 4000 倍）。
- **修复范式（✅，示意）**：

```cpp
// ❌ 固定 9 项 + 低有效位系数
// t = poly9(x);
// ✅ 扩至 13 项 + 分段 Horner（规避编译器常量折叠）
// if (x < seg) t = horner_lo(x); else t = horner_hi(x);
```

- **针对性发现（可执行）**：① grep `Taylor|taylor|Horner`；② 数截断项数与目标精度匹配性；③ 核系数有效位；④ 看是否分段 Horner。
- **最小复现锚**：|x| 扫描到较大值，与 CPU 参考 bessel_i1e 逐点比对最大误差量级。
- **实证**：ops-math **#2271**（PR **#4131**）。

### 案例 3｜log(1+exp) 无数值稳定补偿，负大数输出恒 0 —— #3589（softplus_v2）

- **触发条件**：SoftplusV2 输入为负大数（实证 x=**-16.619**），`exp(x)≈6e-8`，fp32 下 `1+exp(x)` 被舍入为 1。
- **根因（具体路径）**：直接 `log(1+exp(x))` 无 log1p / 分段恒等变形补偿 → x=-16.619 时 NPU 输出 **0** 而 torch CPU 非 0 → 静默精度损失。
- **修复范式（✅，示意）**：

```cpp
// ❌ 负大数下 1+exp(x) 舍入为 1
// y = Log(Add(Exp(x), 1.0f));
// ✅ 数值稳定分段恒等变形
// y = Max(x, 0.0f) + Log1p(Exp(-Abs(x)));
```

- **针对性发现（可执行）**：① 签名 `log1p|Log1p` 定位补偿面；② 找 `Log(Add(Exp(` 无补偿写法；③ 核是否分段恒等变形。
- **最小复现锚**：输入 x=-16.619 及相邻负大数，与 torch CPU softplus 比对，看 NPU 是否恒 0。
- **实证**：ops-nn **#3589**。

### 案例 4｜候选型：组合近似 / 补偿缺失的泛化深挖（无独立实证）

- **触发条件**：quant/dequant、norm 缩放类算子以 `Exp(Muls(Log(...)))` 近似幂/缩放；或 log(1+x) 类写法未用 log1p，ratio / x 跨数量级。
- **根因（候选）**：检测签名 `Exp\s*\(\s*Muls\s*\(\s*Log` 或 `log1p|Log1p` 命中，且未用原生 `Power`（DOUBLE_FLOAT_TECH）/ 无稳定补偿、位于算子主路径。
- **修复范式（✅，示意）**：改用 `Vec::Power`（DOUBLE_FLOAT_TECH 类）或数值稳定实现（log1p / 分段恒等变形）。
- **针对性发现（可执行）**：① 全仓 grep 两枚检测签名；② 仅对「组合近似 + 无补偿 + 主路径」记候选，并按第 7 节给量化推导链。
- **最小复现锚**：见下方语料基线 scan 命令 + 与标杆逐元素 utol。
- **实证**：无（检测签名候选，须实测确认后升档）。
