Subject: [PATCH] fix(inductor): populate template fusion metadata before
 render

NPUTritonScheduling.codegen_template reimplements the template codegen path
but never called _compute_fusion_metadata, so store_output always saw
has_epilogue_fusion as False and skipped the fp32 -> output dtype truncation
cast for fused epilogues.

Call it before render() so fused template GEMMs with fp16/bf16 outputs round
the accumulator at the same point as the unfused path.

Also align codegen_template with upstream's parameter order (prologue_nodes
third, only_gen_src_code keyword-only) and reject prologue fusion explicitly.
This path only implements epilogue fusion, and the old signature let a
non-empty prologue list bind to only_gen_src_code.
