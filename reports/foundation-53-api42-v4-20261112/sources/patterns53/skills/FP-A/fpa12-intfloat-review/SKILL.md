# FP-A12 aclnn 接口检视（fpa12-intfloat-review）

对用户指定的 aclnn 接口做 FP-A12 专项源码检视：先定位算子实现，再按清单逐项核查，每个结论给出**文件 + 行号 + 推导链**证据，命中即出 Bug 卡，输出检视报告。**本模式特殊纪律：① 缺陷表征是「大数值才偏、小数值全过」——常规小 shape 用例天然漏检，必须做**可达上界反推**（该量在大 shape 下能否超 2^24）才能立卡；② 卡片触发为关键词（`static_cast<float>|static_cast<double>`）——该签名在大型仓命中量极大且绝大多数正常（普通整型转浮点、常量定义），命中只作定位提示，不可按命中数下结论；③ 本模式卡片**无确认 issue 级实证**（仅跨仓静态扫描 58 处同源风险点，具体 issue 归属待逐点复核）——静态命中一律按 O1 定档，禁止把扫描命中数表述为「已确认缺陷」；④ 转换点若用于**比较**而非计算，移交 FP-A18 口径，不得重复立卡。**

## 0. 与相邻模式的边界

| 相邻模式 | 分工 |
|---|---|
| FP-A18（int32 边界值转 float 舍入致比较语义偏差） | **最易混淆项（卡片关联直指）**：同源不同焦点——A12 管**数值计算损失**（转换后参与乘加 / 求和，结果整体偏差），A18 管**比较语义偏差**（转换后用于比较 / 索引 / 阈值判断，分支走错）。同一转换点可两面并存，此时两卡连打，并在 Bug 卡内标注用途对表 |
| FP-A15（inf/nan 特殊值行为差异） | 转换链上若因 float 上溢引入 inf（大整数转 float 超 float 上界），有限值的尾数截断归 A12，非有限值的传播与比较归 A15 |
| FP-A04（功能问题演变为精度静默故障） | A12 的典型表现「大数值场景结果偏差」常无任何报错，是静默数值流出的一个来源：转换语义本身归 A12，错误分支吞掉错误状态归 A04 |
| FP-A08（切块粒度差异致离群点精度问题） | 大 shape 是 A12 的触发面（计数 / 求和超 2^24）：尾块覆盖不完整 / 离群点归 A08，数值在转换点失真归 A12 |
| FP-B07（索引 / 偏移计算错误致越界） | 同属 int 承载主题：索引 / 偏移在整型域溢出回绕致越界归 B07，索引 / 计数转 float 后回算致偏差归 A12 |
| FP-A03（竞品高精度中间计算，NPU 直接低精度） | A03 是中间计算整体精度档位低于竞品（口径面）；A12 是单点转换的尾数不足（实现面）——档位设计问题归 A03 |

**症状反查定位**：大 shape / 大计数 / 大求和场景结果偏差且**无任何报错** → 首查该值路径上的 int→float 转换点；同一算式改写转换次序（先乘后转 vs 先转后乘）后结果变化 → 转换次序问题；小数值用例全过、仅含 2^24±1 或 INT32_MAX/MIN 的边界用例失败 → 尾数 24 位上界；网络 loss 不收敛且输入含大数值 → 计算链上的转换点；偏差量级与「大数 × 1 ulp」吻合 → 尾数截断。转换点同时参与比较时同步核 FP-A18。

## 1. FP-A12 模式卡摘要（检视依据，源自本库 `patterns/FP-A/FP-A12.md`，v3.1）

- **编号 / 名称**：FP-A12 大整数转 fp32 计算精度损失 ｜ **类别**：精度 ｜ **风险**：中（S3×O1=3）｜ **状态**：活跃 ｜ **来源**：团队笔记 + 跨仓扫描
- **适用声明头**（照抄卡片）：仓 All ｜ 侧别 All ｜ 载体 Tiling源码,Kernel源码 ｜ 触发 static_cast<float>|static_cast<double> ｜ 默认启用 true
- **skill 核查面**：侧别 All——skill 落地为 `op_host` 的 tiling / infershape（shape 乘积、元素数、分核参数、缩放系数转 float 的 host 面）、`op_kernel` 的搬运 / 归约 / 乘加路径（索引、循环计数、累加量转 float 的设备侧）；`op_api` 校验段中的整型→浮点转换一并纳入
- **故障机理**：int64/int32 数值超出 float 24 位尾数精确表示范围（|x| > 2^24）时，转换后尾数被截断 / 舍入，参与计算产生偏差；**先转后乘与先乘后转的结果不同**——转换发生在乘法之前会把中间量的精度损失放大到整条算式。
- **触发条件**：大数值索引 / 计数 / 求和后转 float 参与计算（元素数、shape 乘积、循环计数、累加量超 2^24）。
- **典型表现**：大数值场景结果偏差；小数值用例全过、仅大数值 / 边界值用例偏。
- **源码审查映射点 / 检测签名**：映射点 = int64→fp32、int32→fp32 转换点、乘法前未升位（先乘后转 vs 先转后乘）；检测签名 = `static_cast<(float|double)>\([^)]*\bint(32|64)`、`numeric_limits<int` 邻近的 float 赋值（极值转换点）。
- **测试拦截建议**：含 2^24±1、INT32_MAX/MIN 边界值的数值用例。
- **实证案例**：2026-09-05 跨仓追溯扫描 P1 命中 **58 处** int→float 截断同源风险点（ops-nn 37 / ops-transformer 14 / ops-math 7），其中部分属本型，**具体 issue 归属待逐点复核**——即本模式暂无确认的 issue 级实证算子，检视结论一律按静态口径定档（详见第 9 节）。
- **关联**：FP-A18（同源不同焦点：A12 关注数值计算损失，A18 关注比较语义偏差）、FP-A15、FP-A04、FP-A08、FP-B07。

## 2. 检视输入与算子定位

**输入**：aclnn 接口名（必填）；可选 ref（默认 master）、指定仓（默认自动定位）；可选现象描述（偏差出现的数值量级 / shape 规模 / 是否仅大数值失败——用于直接反推可达上界）；可选复现输入（大 shape 取值、边界值取值）。

**接口名 → 算子目录换算**：去 `aclnn` 前缀 + 驼峰转下划线小写：
`aclnnRmsNorm → rms_norm`、`aclnnReduceSum → reduce_sum`、`aclnnEmbeddingDenseGradV2 → embedding_dense_grad_v2`。

**仓定位顺序**（GitCode `cann` 组织，逐仓用目录列表确认）：`ops-nn`（norm / loss / activation / matmul 类）→ `ops-math`（math / conversion 类）→ `ops-cv`（image / vision 类）→ `ops-transformer`（attention / moe 类）。**类目名不总与直觉一致**（如 diag_v2 在 `conversion/`），以目录列表为准。FP-A12 高发面：大 shape 归约 / 累加类算子（`reduce_*` / `*norm*` / `*loss*`）、含 shape 乘积与元素数换算的 tiling、带缩放 / 归一化系数的 kernel、含计数器（`count` / `total` / `numel`）转 float 的路径。

**算子目录结构约定**（已验证示例 `cann/ops-math` → `math/add/`）：

```text
{类别}/{op_name}/
├── op_host/           # *_def.cpp、*_infershape.cpp、*_tiling*.cpp（shape 乘积/元素数/分核参数转 float 的 host 面）
│   └── op_api/（或顶层 op_api/）  # aclnn_*.cpp（校验段内的整型→浮点转换）
├── op_kernel/         # kernel 头文件（含 arch35 / regbase / SIMT 等架构变体）——索引/计数/累加量转 float 的设备侧
├── op_graph/  tests/  docs/  examples/   # 视算子而定
```

## 4. 三类检视清单（每点：查什么 → 何处 → 命中判据）

对算子 `op_host`（tiling + infershape）/ `op_kernel` / `op_api` 全部相关文件逐点核查，**每点先查命中面、再做反证排除**，防护面（已有的整型域累乘、显式 `int64_t` 提升、双精度中间量）也要记录（作为反证依据）。

### ① 整型→float 转换点枚举与可达上界反推
- 查什么：全部 `static_cast<float>` / `static_cast<double>` 的整型操作数，尤其 `int64` / `int32` 的 shape 乘积、元素数、索引、循环计数、累加量——逐个反推该量在**合法输入范围内的可达上界**是否可能 > 2^24；是否在乘法之后才转换（先乘后转）而中间乘积已在整型域回绕 / 超出（后者同步核 FP-B07）。
- 何处：`op_host` tiling / infershape 的 shape 与分核计算段、`op_kernel` 的搬运 / 归约 / 乘加路径、`op_api` 校验段。
- 命中判据：能给出「该量在大 shape 下可达 > 2^24 → 转 float 后尾数不足 → 参与计算偏差」的完整推导链 ⇒ 命中候选；反推上界 < 2^24（或该量仅作位数/对齐计算，与结果无关）⇒ 反证排除并写明理由。

### ② 转换次序（先转后乘 vs 先乘后转）
- 查什么：同一算式中转换与乘法的相对次序；是否存在「先转 float 再累乘 / 累加」而改用整型域累乘后一次转换即可保精度的写法。
- 何处：kernel 的乘加 / 归约表达式、tiling 的缩放系数与分块因子计算。
- 命中判据：给出两种次序的代数对比、证明原次序损失更大且可达 ⇒ 命中候选；次序不影响结果或量级远小于容差 ⇒ 反证排除。

### ③ 极值转换点（numeric_limits）与用途分流
- 查什么：`std::numeric_limits<int32_t/int64_t>::min()/max()` 被 `static_cast<float>/<double>` 的位置及其**用途**——用于**计算**（本型）还是用于**比较 / 索引 / 阈值判断**（归 FP-A18）；`constexpr float ...Min/Max...AsFloat` 类常量同理。
- 何处：tiling 常量定义、kernel 哨兵值 / 阈值初始化。
- 命中判据：极值转 float 后参与算术运算且差值可达 ULP 级 ⇒ 命中候选（本型）；仅用于比较 ⇒ 移交 FP-A18 口径，在本报告标注「已移交」。

### 横切面：边界值测试覆盖
- 查什么：卡片拦截建议的边界值用例（2^24±1、INT32_MAX/MIN）是否存在于用例集；纯小 shape 用例集天然漏检本型。
- 何处：`tests/` 用例与输入生成脚本、golden 资产。
- 命中判据：无边界值用例 + 存在静态命中的转换点 ⇒ 记观察项（测试建设缺口），不计入缺陷。

## 5. 检视流程

1. **定界**：换算 op 目录、确认所在仓与 ref；按用户现象（大数值才偏 / 无报错偏差）反查优先清单点；收集大 shape 规模与边界值取值。
2. **枚举**：目录列表列出 `op_host`（tiling + infershape）/ `op_kernel`（含架构子目录）/ `op_api` / `tests` 全部相关文件，产出文件清单。
3. **触发词扫描**：按 `static_cast<(float|double)>` 与 `int32|int64` 同现、`numeric_limits<int` 邻近 float 赋值定位风险面（本地仓用 grep；API 模式逐文件拉取后检查）。**签名零命中时清单仍须逐项核查**（隐式转换、函数返回整型再赋 float 同样命中面）。
4. **逐点核查**：每点记录命中面与防护面证据（文件:行号）；对每个转换点写出「量 → 声明类型 → 可达上界 → 与 2^24 关系 → 参与计算方式 → 用途（计算 / 比较）」六项对表。
5. **反证排除**：上界 < 2^24、仅作对齐 / 位数计算、整型域累乘后一次转换、显式 `int64_t` 提升或双精度中间量、用途属比较（移交 A18）→ 明确写出反证理由。
6. **判定**：按第 7 节标准给出 命中 / 观察项 / 反证排除。
7. **GitCode 查重**（仅命中项）：issues API 按接口名 + `精度|偏差|截断|float` 检索，逐条比对是否同机理；无同机理才立卡（本模式历史查重多为空结果，属预期）。
8. **业务可达性核查**（仅命中项）：判 B 等级、定业务影响类型、给处置建议；默认保守（无法证明不可达即记 B3），降档须附证据；B 不改 S×O 档位。
9. **出报告**：按第 8 节模板落盘；所有数值后果标注「静态推演，需 NPU 实测确认」，并附边界值用例建议。

## 6. 风险定级（S×O）与业务影响评估（B 轴）

- **S**：S3（大数值场景结果偏差——结果错但可运行）；S2（偏差量级小、仅极端输入才显）；S1（仅静态转换点存在、可达上界不可达）。
- **O**：O3 = ≥2 条独立实证；O2 = 1 条独立实证；O1 = 仅静态扫描命中或团队笔记（实证 = 确认对应的 issue / PR，或经跨仓、跨分支核验确认的缺陷记录，同权计入）。静态推演命中且无实证默认 **O1**；升档须在报告中给出实证依据。
- **风险 = S×O**：≥6 高；3/4 中；1/2 低。FP-A12 基准：模式卡整体 **S3×O1=3（中）**；纯静态命中一律 S3×O1=3（中，暂定），实测偏差后复评。

### B 轴：业务影响评估（与 S×O 正交；报告层新增，不改卡片定级）

S×O 回答"多严重、多常见"，**不回答"真实业务能不能碰到"**。B 轴补这一问，只决定**修复优先级建议**，**不参与 S/O 取值、不改 S×O 档位与卡片元数据**。

**业务可达性（B）**——触发条件在真实负载中的可达程度：

| 等级 | 判据 | 证据要求 |
|---|---|---|
| B3 现实可达 | 主流框架/公开模型默认路径即可命中（如 PTA/torch_npu、vLLM、MindIE 常规调用） | 调用方或公开负载来源 |
| B2 条件可达 | 需特定 attr/dtype/shape 组合，业务中存在但非默认 | 该组合的业务来源 |
| B1 边界/不可达 | 需极端、超规格或非法参数（超出接口合理上限的 shape、退化/非法输入） | "为何不可达"的说明 |

- **默认保守**：无法证明不可达 → 记 **B3**；降为 B1/B2 必须附证据，**不得仅凭"业务应该不会这么用"**。
- 超规格参数是否算 B1 取决于**接口契约**：契约允许但业务不用 → B1；契约不允许（本应报错）→ 属校验缺失（FP-B04/B05 类），另行归属。

**业务影响类型**（命中后对用户可见结果的后果，用业务语言表述）：静默精度损失（模型效果下降 / loss 不收敛 / 偶发 NaN）｜ 任务失败中断（报错 / 崩溃 / 挂死）｜ 性能退化 ｜ 仅可观测性（日志 / 错误码 / 文档，不影响结果）。

**处置建议**（由两轴推导的报告结论，非新档位）：

| S×O \ B | B3 现实可达 | B2 条件可达 | B1 边界/不可达 |
|---|---|---|---|
| 高（≥6） | 尽快修 | 尽快修 | 排期修 |
| 中（3/4） | 尽快修 | 排期修 | 记录（业务难以触达） |
| 低（1/2） | 排期修 | 记录 | 记录 |

## 7. 判定标准与反误报原则

- **签名 / 触发词命中 ≠ 成立**：`static_cast<float>` 在大型仓命中量极大且绝大多数正常——必须过「可达上界反推 + 转换次序代数对比 + 用途分流」三关；命中数大只说明核查工作量大。
- **三种判定**：
  - **命中**（可静态证缺陷路径）：可达上界 > 2^24 的推导链完整 + 该量确实参与计算 + 反证排除失败 ⇒ 立 Bug 卡；
  - **观察项**：上界依赖具体运行时输入规模、或偏差量级无法静态界定 ⇒ 记录并附边界值实测方案，按 S3×O1 暂定；
  - **反证排除**：上界 < 2^24、仅作对齐 / 位数计算、整型域累乘后一次转换、显式提升到 64 位整型 / 双精度 → 写出防护面证据与反证理由。
- **不把扫描命中数当证据**：卡片实证仅为跨仓静态扫描的风险点计数，**不得**表述为「已确认 N 处缺陷」；每处候选必须有独立推导链。
- **用途决定归属**：转换点用于比较 → 归 FP-A18；同一转换点两用 → 两卡连打并标注。
- **不臆造行号**：每条证据必须是实际读到的 文件:行号；无实证算子时不写算子名与行号（见第 9 节）。
- **静态推演声明**：无 NPU 环境时，所有运行时行为结论必须标注「静态推演，需 NPU 实测确认」。

### 判定纪律补充（v3.6）：非对称增减、证据等级与误判记录

**增减不对称**：允许追加候选（有据即可，错了可由用户排除）；**撤销或否决候选必须附 `[文件]:[行号] [代码行]` 负向证据**。无证据的「看起来没问题」一律记为「未核查」，不得计入反证排除，也不得据此下调等级——否决造成的漏报用户不可见、不可恢复。

- **证据等级**（Bug 卡必填）：`静态可证` = 推导链完整且触发输入可静态构造；`需实测确认` = 依赖运行时输入规模、设备行为或环境差异。标 `需实测确认` 的条目**不得以「命中」名义出卡**，按观察项记录并附实测用例。
- **Agent 误判记录**（Bug 卡必填）：本次被推翻的假设、推翻它的证据（`[文件]:[行号] [代码行]` 或实测输出）、判定标准是否随之修订；无推翻写「无」。
- **误判回流**：同类误判在 3 次检视中重复出现，登记至 `cases/misjudgments.jsonl`（字段见 `cases/README.md`），并在本模式判定标准中新增对应防线；守门 C19d 校验台账字段合法。

## 9. 示例速览：本模式暂无确认实证算子

卡片「实证案例」仅记录 2026-09-05 跨仓追溯扫描的 **58 处** int→float 截断同源风险点（ops-nn 37 / ops-transformer 14 / ops-math 7，P1），**具体 issue 归属待逐点复核**——即本模式尚无确认的实证算子与行号。故本节不给具体算子与行号，改为给**签名 / 触发词起点速览**（**严禁虚构算子名或行号**）：

- **检索起点**（按第 2 节换算 op 目录后，在 `op_host`（tiling/infershape）+ `op_kernel`（含架构子目录）+ `op_api` 全量 grep）：
  - `static_cast<float>(` / `static_cast<double>(` 与 `int32` / `int64` / `size_t` 同现处；
  - `numeric_limits<int32_t>::max()` / `numeric_limits<int64_t>::max()` / `numeric_limits<int32_t>::min()` 邻近的 float / double 赋值；
  - host 侧 shape 各维乘积（`GetShapeSize()` 类调用）与其后的浮点换算；
  - kernel 侧 `sum` / `acc` / `count` / `total` / `numel` 类变量的类型声明与转换点；
  - `constexpr float|double \w*(Min|Max)\w*As(Float|Double)` 类常量定义。
- **核查方式**：逐点写出「量 → 声明类型 → 可达上界 → 与 2^24 关系 → 参与计算方式 → 用途（计算 / 比较）」六项对表，用途属比较者移交 FP-A18。
- **纪律**：不得据扫描命中数直接下结论、不得虚构算子名或行号；每条候选必须附可达上界反推与边界值用例方案；无实测证据时档级一律 S3×O1（中，暂定）。
- 任何一点的最终判定以第 4/5/7 节口径为准，禁止凭算子类型直接下结论。

## 10. 能力边界与自检（v3.8）

### 能力边界

- **静态可证**：清单里能在源码内给出「`文件:行号` + 推导链」的部分，按第 7 节判据出卡。
- **需实测确认**：依赖运行时输入规模、设备行为或环境差异的结论，只能记观察项并附实测用例（证据等级见第 7 节）。

- **找不到 ≠ 没有**：按清单未命中只说明「本轮未发现」，不得表述为「该算子无此缺陷」；抽样核查须在报告写明抽样口径。
