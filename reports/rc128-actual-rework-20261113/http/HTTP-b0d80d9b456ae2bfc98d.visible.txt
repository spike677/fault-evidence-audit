Subject: [PATCH] fix(inductor): exclude NPU dropout ops from fx_graph_cse

npu._npu_dropout takes no seed and uses an internal RNG, so it is not
deterministic. torch._functorch.compile_utils.fx_graph_cse only skips ops
listed in rand_ops; aten.native_dropout is listed but npu._npu_dropout is
not. When torch._inductor.config.fallback_random is True, native_dropout is
lowered to npu._npu_dropout, and CSE merges two structurally identical
dropout calls so they share the same output/mask and consume RNG only once.

Extend rand_ops with the NPU dropout random ops so CSE keeps them.

Verified on npu-triton and npu-ascendc: with fallback_random=True and
training, two identical dropout calls now yield different results.
