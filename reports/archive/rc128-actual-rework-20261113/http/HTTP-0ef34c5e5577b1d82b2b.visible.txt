问题描述
npu._npu_dropout
没有 seed 入参、内部使用 RNG，不是确定性算子。但
torch._functorch.compile_utils.fx_graph_cse
只跳过
rand_ops
名单中的算子：
aten.native_dropout
在名单内，
npu._npu_dropout
不在。
当
torch._inductor.config.fallback_random=True
时，
native_dropout
会下沉为
npu._npu_dropout
。训练路径会经过 AOTAutograd min-cut 分区并调用
fx_graph_cse
，此时两个结构完全相同的 dropout 调用会被合并成一个，导致：
两次 dropout 共用同一 mask/output，随机性丢失、分支强相关；
复现步骤
import
torch, torch_npu
import
torch.nn.functional
as
F
import
torch._inductor.config
as
icfg
icfg.fallback_random =
True
class
M
(torch.nn.Module):
def
__init__
(
self
):
super
().__init__()
self
.w = torch.nn.Parameter(torch.ones(
64
,
1024
))
def
forward
(
self, x
):
        a = F.dropout(x,
0.5
, training=
True
)
        b = F.dropout(x,
0.5
, training=
True
)
return
(a *
self
.w).
sum
() + (b *
self
.w).
sum
(), a, b

x = torch.randn(
64
,
1024
, device=
"npu"
)
m = M().npu()
f = torch.
compile
(m, options={
"npu_backend"
:
"default"
})
# 或 "ascendc"
loss, a, b = f(x)
loss.backward()
print
(torch.equal(a, b))
# 打补丁前为 True（被 CSE 合并）
期望结果
两次独立 dropout 应采样不同 mask，
torch.equal(a, b) == False
。
实际结果
打补丁前
torch.equal(a, b) == True
，两个 dropout 被合并。
影响后端
npu-triton 与 npu-ascendc 均可复现（CSE 在 AOTAutograd 阶段，与后端无关）。纯推理路径和
fallback_random=False
默认路径不受影响。
修复
已在 PR #49092（
https://gitcode.com/Ascend/pytorch/merge_requests/49092）中修复：在
torch_npu 侧把
_npu_dropout
、
npu_dropout_gen_mask
、
npu_dropout_do_mask
、
npu_dropout_with_add_softmax
补充进
rand_ops
，使 CSE 不再合并。
环境
torch 2.10.0 / torch_npu 2.10.0.post7.dev20261016
设备：Ascend910_9362（A3，soc_version=255）
后端：npu-triton / npu-ascendc
