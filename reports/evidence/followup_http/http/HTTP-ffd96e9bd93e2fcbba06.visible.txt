现象
aclnnLightningIndexerGrad
（Atlas A2 / 910B3）在
inputLayout=BSND ∧ sparseMode=3（滑窗裁剪）∧ S1>S2（存在 realTopk==0 的"死行"）且 N1(groupNum) 取值使奇偶分裂后每核零化元素数不满足 16 元素倍数
时，死行的
dweights 输出未被零化，残留全局内存脏值
。接口正常返回 0（无任何报错）；dq / dk 两个输出不受影响：
1000 用例精度测试（4 轮）的 50 个精度失败用例中
29 例由此缺陷引起
（其余 21 例为 bf16 舍入级 dq/dk 残差，与本缺陷无关）。29 例全部为 BSND + mode=3 + S1>S2，N1 ∈ {1,2,5,7,16,63}，19 bf16 + 10 fp16——缺陷与具体 dtype 无关（两者同为 2 字节）。
死行 dweights 脏值量级
0.63 → 1.18e+37
（跨 6 个数量级，未初始化内存特征）；同 case 的 dq / dk 全部干净（max ≤ 0.03125；10 个 fp16 case 在紧 3 倍的 rtol 0.00146484 门限下仍全过）。
N1=64 的死行用例从不失败
（3/3 PASS，死行全为精确 0——该取值下每核零化 32 元素 = 64B，恰好满足 32B GM 粒度）。
非确定性
：同一输入两次独立运行结果可以不同——case 9 一次通过（死行恰为 0）、一次失败（死行 0.632812）；case 203 三次运行死行脏值元素数各不相同（3873 / 3842 / 3860）。这是输出缓冲未初始化的直接证据。

期望
死行输出应被显式零化：
数学契约
：sparseMode=3 滑窗使部分 query 行的 realTopk==0（S1>S2 时必然出现）——这些行不与任何 key 发生计算，其 dweights、dq 梯度恒为 0。CPU 参考实现在死行处返回精确 0。
确定性
：算子输出应是输入的确定性函数。当前同一输入两次运行通过/失败翻转，训练不可复现。

机制：
dweights 每行仅 groupNum（=N1）个元素；奇偶分裂后每核零化元素数 =
groupNum/2
（偶核）或
(groupNum+1)/2
（奇核）。2 字节 dtype（bf16/fp16）的 GM DataCopy 要求
32 字节粒度（16 元素倍数）
：
groupNum==1
→ 偶核 count=0（
一个元素都不写
）、奇核 count=1（2 字节）；
groupNum ∈ {2,5,7,16,63}
→ count 非 16 倍数 → 零化不足/未生效，死行 dweights 残留 GM 旧值；
groupNum==64
→ 32/32 元素（64B）恒对齐——与"N1=64 全过、N1∈{1,2,5,7,16,63} 失败"的观测一一对应；
dq 零化长度 =
blockGroupNum × headDim
（headDim=128）恒对齐 → 29 例 dq 全部干净（含 fp16 紧门限）——精确解释"dweights 脏 / dq 干净"；
数值行为吻合未初始化输出：同 case 两次运行垃圾元素数不同、通过/失败翻转、干净 GM 上返回精确 0、脏值均为该 dtype 可表示数且量级无界。
证据链：
case 203 确定性失败
：生产 3873/4064 死行脏值；独立设备复现 2/2 次失败（3842、3860 个死行脏值，数值如 0.3125/−0.265625/0.734375，均为 bf16 可表示值）；
case 9 通过/失败翻转
：生产失败（死行 1.023）→ 复现 A 通过（死行恰为 0）→ 复现 A2 失败（0.632812）；
case 623（N1=64）对照组
：3/3 全过，死行 dweights 全部精确 0；
N1 相关性
：死行 shape 用例 acc FALSE 按 N1 分布 {1:19, 2:4, 5:1, 7:2, 16:2, 63:1}，与"count 非 16 元素倍数"的取值集合一一对应（N1=3/32 无死行样本）。
诚实性注记：DataCopy 在不足 32B 粒度时未生效的结论由代码 + 数值行为推断（无 NPU 硬件 trace 直接证明）；活行走 ReluGrad 的 copyout 同样使用奇偶分裂，但活行值来自计算、不受零化对齐影响（观测一致）。

影响
触发条件是常态而非边角
：mode-3（滑窗稀疏注意力）+ S1>S2（query 段长于 key 段）在变长序列训练（actualSeq 各异）中真实存在；N1∈{1,2,5,7,16,63} 均为真实头数/GQA 分组配置。

：接口正常返回，无任何报错；脏值进入 dweights 后参与梯度更新，量级无界（实测 1.18e+37），可直接污染训练。
非确定性
：同一输入两次运行结果可翻转，训练不可复现、问题难以稳定复现定位。
dq/dk 不受影响（零化长度恒对齐）。
建议
dweights 零化 count 向上对齐到 16 元素倍数（
AlignUp(blockGroupNum, 16)
，2 字节 dtype → 32B）；
或整行由单核零化（取消奇偶分裂）；
或改用
SetAtomicZero
类原子清零原语；
v9.1.0 与 master 需同步修复
（两版函数语义相同）；
回归门禁：mini_a（case 203 必须转为死行全 0 + case 623 对照保持 PASS + case 0 锚点），并建议将 mode=3 + S1>S2 + N1∈{2,3,5,8,16,31,32,33,63} 的死行扫描加入 CI——当前官方 utest 唯一用例（S1<S2 且 groupNum=64）测不到本缺陷。
