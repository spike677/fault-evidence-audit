[BugFix][Quantization] Fix ModelSlim DeepSeek-V4 wo_a grouped MXFP8 layout
### What this PR does / why we need it?

ModelSlim DeepSeek-V4 checkpoints can quantize `wo_a` as `W8A8_MXFP8` even when the checkpoint is otherwise W4A4. The generic MXFP8 loader leaves its weight as a 2D matrix, while attention calls `npu_transpose_quant_batchmatmul` with `perm_x2=(0, 1, 2)`. A `[4096, 16384]` weight consequently raises `IndexError: Dimension out of range (expected to be in range of [-2, 1], but got 2)`.

Prepare grouped weights and MX scales before allocating persistent inference buffers, retain ND storage for this BMM, and restore checkpoint layouts for reloads while preserving captured buffer addresses. Identify grouped `wo_a` by the configured `o_lora_rank` and layer suffix without requiring a particular `model_type`. Other projections and models without this configuration retain their ordinary linear layouts.

Grouped `wo_a` output shards are gathered along dimension 0 (groups) during weight switching; ordinary transposed linear output shards keep dimension 1. Select this per layer so grouped processing cannot change another layer's gather axis. Share one checkpoint-row conversion helper across ModelSlim MXFP8, native FP8, and BF16 loading/reloading, deriving local groups from the loaded shard and avoiding intermediate transpose copies.

### Does this PR introduce _any_ user-facing change?

Fixes ModelSlim grouped `wo_a` loading and its output-sharded weight-switch layout. No new serving arguments or environment variables.

### How was this patch tested?

- **21 targeted tests passed** remotely using the exact candidate helper and quantization classes with installed Ascend image dependencies in an isolated process; serving packages were not replaced. This is not the full repository test suite.
- The pre-review implementation fails the new gather-axis assertions for simulated world sizes 2 and 4. The candidate reconstructs exact full weight/scale contents and switches back to the original local shards twice; ordinary output layers retain dimension 1 on the same scheme.
- Coverage includes loading without a DeepSeek-specific model type, BF16 row mapping, native FP8 shard layout, local groups 1/2/16, skipped NZ conversion, checkpoint restoration, graph buffer address stability, other projections, and incomplete output groups.
- Earlier PR revision: actual checkpoint layer-0 tensors passed 4 eager/ACL-graph numerical cases on Ascend (batch sizes 1 and 6, explicitly dequantized FP32 reference, `atol=0.02`, `rtol=0.02`); original 2D error independently reproduced. Those operator cases were not rerun for this review update.
- `ruff check`, `ruff format --check`, Python syntax checks, and `git diff --check` passed. Local `bash format.sh ci` could not run because Bash is unavailable on the Windows host; the repository pre-commit workflow will validate the new commits.
- Full-model PD/DeepSWE and live multi-rank CP/PCP communication have not been rerun with this revision; the gather regression uses a simulated collective.
