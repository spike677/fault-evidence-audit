- **适用**：仓 All ｜ 侧别 Tiling,Host ｜ 载体 Tiling源码,aclnn源码 ｜ 触发 TilingData|tilingKey|namespace ｜ 默认启用 true
- **故障机理**：tiling（以及 2026-10-21 扩展的 **aclnn/host 层**）里有一部分状态**语义上是 per-call 的**（本次输入的 layout、dtype、由 shape 推导出的切分参数、本次选定的 tilingKey、本次的阈值/可选输入开关），却被放进**per-process 的容器**——文件作用域或匿名 `namespace` 内的可变全局变量、全局 `XxxTilingData` 对象。两者**生命周期不匹配**，产生两类后果：**① 时序耦合（串行残留）**——前一次调用写入的值被后一次调用读到；若某条分支（如 4D 路径）压根没有写操作，该分支就永远读到上一次留下的值，不存在「该更新了所以自动复位」这回事；**② 数据竞争（并发串味）**——多线程并发 tiling 时各方在同一块内存上读改写，A 线程 `SaveToBuffer` 时可能把 B 线程刚写进去的字段一并写进自己的 tiling data。它不是「某一行写错了」，而是**「状态该归谁」的设计错误**：C++ 里静态存储期变量的复位只有两个时机——静态初始化（模块加载时一次）、或显式赋值语句真的被执行。 **两个子型（v6.33 机读化）**：**A21-1 时序耦合（串行残留）**——前一次调用写入的 per-call 状态被后一次调用读到；**A21-2 数据竞争（并发串味）**——多线程并发 tiling 在同一全局/静态状态上读改写。
- **触发条件**：tiling 源码或 aclnn/host 源码在匿名 `namespace` / 文件作用域声明了**非 `constexpr` 的可变全局**（`bool` 标志位、`uint64_t tilingKey/dtypeSize/seqLen/headDim/bufferSize`、`XxxTilingData tiling` 对象）；同一进程内**先后调用同一算子的不同 shape**（尤其「新增路径在前、旧路径在后」，如 3D TND → 4D BNSD/BSND）；**多线程 / 多流并发调用**同一算子（每线程独立 stream，host 侧 tiling 无锁进入）；图模式一次编译含多个该算子节点。**注意：单算子用例天然凑不齐「前导状态」，结构上无法复现序列型变体**——一进程一 shape，全局每次都是初值。
- **典型表现**：① **静默错算**——D 维取到原 S 维的值、batch/head 互换，输出与 golden 偏差但无任何报错（最常见，最易被当成普通精度问题排查）；② **tiling failed**——污染后落入 `else` 分支返回 `GRAPH_FAILED`，报 `xxx do tiling failed`（只有少数形状会走到）；③ **偶发精度失败**——并发下时对时错，单跑通过、压测失败、复跑轮换；④ **越界**——`tilingKey` 与 `dtypeSize` 是两个独立全局，可组合出「key=fp16 但 dtypeSize=4」这种真实 dtype 永不产生的错配，kernel 按错误 stride 访问 buffer，或切分参数串味导致 UB 搬运越界（`aicore does not support it` / device 侧非法地址）。**关键识别特征：缺陷随「调用顺序」或「并发度」变化，与 shape 本身无因果关系。**
- **源码审查映射点**：① 文件作用域 / 匿名 `namespace` 内是否存在**非 `constexpr` 的可变变量**（`constexpr` 与 `static const` 安全，唯独「可变」不安全）；② 这些变量是否**在每条路径上都被赋值**——只要有一个分支不写，该分支就读到上一次的值（`isTndLayout` 旧代码的 4D 分支正是这种情况）；③ `TilingData` 对象是**全局**还是**类成员**；全局则 `set_*` 与 `SaveToBuffer` 之间的空隙越大越易串写；④ 声明位置——匿名 `namespace` 内是内链接（每 TU 一份，仍进程常驻），`namespace optiling` 内是**外链接**（更暴露）；⑤ 同一算子的**前向 / 反向 / 镜像实现**是否复制了同一写法（本型成簇传播，查一个必须连带查其成对实现）；⑥ **载体下沉到 aclnn/host 层**——`op_api/aclnn_*.cpp` 顶层匿名 `namespace` 的 `float/bool/std::string` 标量（如 `thresholdVal_`）在 `GetWorkspaceSize` 里写入、在 `GetDtypeSupportList()` / l0op 选择处读取，窗口跨函数且无锁。判据同 ②：写点是否在每条路径上执行、并发进入 `GetWorkspaceSize` 时是否互踩。
- **检测签名**：`(?m)^[A-Za-z_][\w:]*TilingData\s+tiling\s*;`（顶层 TilingData 对象）；`(?m)^bool\s+\w*(?:[Ff]lag|[Ll]ayout)\w*\s*=\s*false\s*;`（顶层可变布尔标志）；`(?m)^(?:uint64_t|int64_t|uint32_t|int32_t)\s+(?:tilingKey|dtypeSize|seqFrontLen|seqTailLen|wholeBufferNum|maxElementNum|alignHeadDim)\s*;`（顶层切分参数 / tilingKey）。三条均以**行首无缩进**为锚：`scripts/scan_fp.py` 逐行匹配，因此**顶层定义（列 0）命中，函数内局部变量与类成员（有缩进）自动排除**——实测 `posembedding` 500 个文件得 **11 候选全部真阳**，与 `rope_half_grad_tiling.cpp:56/57`、`rope_interleaved_grad_tiling.cpp:80/106` 及 6 个切分标量一一对应；同目录 4 个 `rope_*` 算子的 `TilingData tiling;` 写在函数内或作类成员，被正确排除（反证：`rope_rotate_half_tiling.cpp:131-136` 全部在 class body 内）。**负向排除**：`constexpr` / `const` / `static const` 修饰；`thread_local`；类成员（`isTndLayout_` 这类带下划线后缀且在 class body 内）；UT fixture 的 `CompileInfo` 全局（无跨调用语义）。**注意签名必须单行**——`scan_fp.py` 按行 `search`，含 `[\s\S]` 的跨行签名永不命中。

- **Host/aclnn 层补充（v6.13，暂无机器签名）**：人工 grep `^(?:bool|int|float|double|uint64_t|int64_t|uint32_t|std::string)\s+\w+_\s*(?:=|;)`（行首无缩进锚，排除类成员），再按映射点 ⑥ 核查写点覆盖与并发窗口。实证 `aclnn_threshold_backward.cpp:33` 的 `float thresholdVal_ = 0.0;`。
- **审查关键词**：`全局变量|静态变量|文件作用域`；`状态残留|跨调用|顺序依赖|串味|污染`；`可重入|reentrant|线程安全|thread.?safe`；`匿名 namespace`；`tilingKey.*串|dtypeSize.*串`；`SaveToBuffer`；`ubLoopGap|seqFrontLen|wholeBufferNum`；`静态初始化|static storage duration`；`aclnn 层可变全局|GetWorkspaceSize 共享状态`；`thresholdVal_|optionalUbNum|BENCHMARK_TILING_KEY`。
- **测试拦截建议**：① **序列化用例**（比并发易落地，且必须做）——同一个 `main` 内连续调用，覆盖「3D→4D」「带可选输入 x → 不带 x」「fp16→fp32」「新路径→旧路径」四种顺序，断言每次输出与单独跑一致；② **UT 顺序检查**——`--gtest_shuffle --gtest_repeat=50` 打乱既有用例顺序，撞到「新增路径在前」的组合即红（既有用例按「4D 在前 3D 在后」声明序编写，天然掩盖缺陷，全绿不代表覆盖）；③ **并发压测**——多线程、每线程独立 stream，只调 aclnn 第一段 `GetWorkspaceSize`（它就是 tiling 入口，host 侧同步，无需跑 kernel），交替不同 layout/dtype，判据取「返回码异常」与「输出与串行参考不一致」；④ **打桩自证**——`DoOpTiling` 首尾加 `atomic` 进入计数，`peak > 1` 才能证明并发真的发生，否则「未复现」的结论无效；⑤ **静态扫描**——扫匿名 `namespace` 内可变全局 + 全局 TilingData，命中即列入审查清单（候选 ≠ 缺陷）；⑥ **aclnn/host 层并发压测**——多线程只调 `aclnnXxxGetWorkspaceSize`，交替不同 `threshold` / 可选输入开关，判据为返回码异常、崩溃或输出与串行参考不一致（#7007/#7026 即此形态）。
