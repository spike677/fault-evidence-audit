Subject: [PATCH] fix(dequant_swiglu_quant): fix dynamic scale garbage when
 UbFactorDimy < 64 and Brcb overwriting scaleOut

Two bugs in DynamicQuant (DSK group-index path, dynamic quant mode):

1. WholeReduceMax mask was hardcoded to 64. When UbFactorDimy < 64
   (e.g. H=64 -> UbFactorDimy=32), each repeat reads across two rows
   and out of bounds, producing garbage scale values (observed
   INT_MAX-like row max on tail blocks).
   Fix: mask = min(UbFactorDimy, 64).

2. Row-scale broadcast used Brcb(outLocal, scaleOut) + Copy via
   outLocal as scratch. Brcb writes outLocal[0, blockCount*64) floats
   while scaleOut lives at outLocal[UbSingleOutSize_/4]; when
   UbSingleOutSize_/4 < blockCount*64 (e.g. UbFactorDimx=1,
   outDimy=160 -> offset 40 < 64), Brcb overwrites scaleOut itself
   before CopyOut, so the final scale output is garbage.
   Fix: replace Brcb+Copy with a single BroadCast instruction
   (same as the official dynamic_quant operator), which broadcasts
   scaleOut to tmpUbF32Gate directly without touching outLocal.

Verified on Atlas A2 (910b): error_case.json case7 (x[15,64], 9
groups) and case27 (x[1,320], 9 groups) now Pass; regression
dwq.json / dwq_mode0.json / network_mode0.json all still Pass.
