[CRCR][Bug]: 上游 pytorch #195787 将标量索引赋值分发到 index_fill_ 后，aclnnInplaceIndexFill 不支持 DT_INT8 导致 test_binary_ufuncs 4 例失败 #5067

问题现象

forward CI（上游 pytorch PR 转发测试）中，test/test_binary_ufuncs.py 的 4 个 int8 参考数值用例失败（4/16560，其余全部通过）：

  • 首次发现流水线：Ascend/pytorch run 35842185432（"PyTorch CI Trigger PR - PR 189538"，2026-09-23 09:18 UTC）
失败用例（nodeid） 状态
TestBinaryUfuncsDevicePRIVATEUSE1::test_reference_numerics_floor_divide_npu_int8 failed
...::test_reference_numerics_fmod_npu_int8 failed
...::test_reference_numerics__refs_floor_divide_npu_int8 failed
...::test_reference_numerics__refs_fmod_npu_int8 failed

报错信息：

RuntimeError: index_fill_:third_party/op-plugin/op_plugin/ops/opapi/IndexFillKernelNpuOpApi.cpp:109
NPU function error: call aclnnInplaceIndexFill failed, error code is 161002
[PID: 31409] AclNN_Parameter_Error(EZ1001): Tensor self not implemented for DT_INT8,
should be in dtype support list [DT_INT32,DT_FLOAT16,DT_FLOAT,DT_INT64,DT_BOOL,DT_BFLOAT16,].

根因分析

触发链路（失败点在测试数据构造阶段，尚未执行到被测算子）：

  1. fmod/floor_divide 的 OpInfo 配置了 rhs_make_tensor_kwargs={'exclude_zero': True}（rhs 不允许为 0，避免除零）；
  2. generate_elementwise_binary_tensors 逐 shape 调 make_tensor(exclude_zero=True) 生成 int8 rhs，内部执行 result[result == 0] = 1（torch/testing/_creation.py:269）；
  3. 当 shape 为 0 维标量 () 时（shape 列表第 3 项），0 维 bool 掩码在 C++ setitem 路径中被 boolToIndexingTensor 转换为 kLong 索引张量；
  4. pytorch master 新增的 try_dispatch_index_fill_ 快速路径命中（单个 kLong 索引 + 标量值 → 直接调 index_fill_，绕过 index_put_）；
  5. torch_npu index_fill_ → CANN aclnnInplaceIndexFill，该算子不支持 DT_INT8 → 161002 报错。

根本原因：上游 pytorch setitem 分发路径变更 + CANN 算子 dtype 覆盖缺口

  • 触发变更：pytorch/pytorch#195787（"Dispatch index_put_ to index_fill_.Scalar when possible"，commit 4f2fcf1b42cc）于 CI 运行前 24 分钟（2026-09-23 08:54 UTC）合入 master。CI 基线 e96c318a57e3 已包含该提交（ahead_by=2, behind_by=0）；
  • 暴露的缺口：原路径 aclnnIndexPutImpl 支持 int8，新路径 aclnnInplaceIndexFill 不支持（dtype 支持列表仅 [DT_INT32, DT_FLOAT16, DT_FLOAT, DT_INT64, DT_BOOL, DT_BFLOAT16]），分发切换后踩中空缺；
  • op-plugin IndexFillKernelNpuOpApi.cpp 的 DO_COMPATIBILITY 仅做符号存在性检查，不做 dtype 感知回退，错误直接抛出。

交叉验证证据：

  • 同一运行中同测试的 int32/int64/float16/float32 变体全部通过——精确匹配 aclnnInplaceIndexFill 的 dtype 支持列表；bfloat16 变体被 skip；
  • small_values 变体通过（其生成器 generate_elementwise_binary_small_value_tensors 用 Python list 构造张量，不走 result[result == 0]=1 路径）；
  • CANN plog 确认失败算子为 aclnnInplaceIndexFill 的 CheckDtypeValid(DT_INT8)。

复现步骤

# 环境：torch_npu master (acc54de9beee) + op-plugin 09fca6f6 +
# pytorch >= 4f2fcf1b42cc（含 #195787）
python -c "
import torch, torch_npu
t = torch.randint(-9, 10, (), dtype=torch.int8, device='npu')
t[t == 0] = 1   # RuntimeError: index_fill_ ... aclnnInplaceIndexFill ... DT_INT8
"

# 或直接跑失败用例（pytorch 源码目录）：
python test/test_binary_ufuncs.py \
  TestBinaryUfuncsDevicePRIVATEUSE1.test_reference_numerics_fmod_npu_int8

影响

  • pytorch #195787 合入（2026-09-23）后，所有跑 NPU 全量测试的上游 PR forward CI / nightly 都会命中这 4 个用例失败，不限于 PR 189538；
  • 0 维张量 t[t == 0] = scalar（int8/int16/uint8 dtype）这一用户侧常见写法在新分发路径下会直接抛错（int16/uint8 同样不在 aclnn 支持列表，只是现有测试未覆盖到）。

期望

  • 方案 A（op-plugin 侧，推荐）：IndexFillKernelNpuOpApi.cpp 的 index_fill_ 对 aclnn 不支持的 dtype（int8/int16/uint8）增加 dtype 感知回退——降级到 aclop 版 index_fill_（aclop 实现基于 float 辅助矩阵，dtype 覆盖更广）或回退 index_put_；
  • 方案 B（CANN 侧）：aclnnInplaceIndexFill/aclnnIndexFill 补齐 int8（及 int16/uint8）dtype 支持；
  • 验收：上述 4 个用例 FAIL→PASS，且 t[t==0]=1（int8 0 维）不再报错。

关联
