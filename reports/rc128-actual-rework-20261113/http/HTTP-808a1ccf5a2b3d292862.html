变更摘要

本 PR 修复调频 plugin（csrc/plugin/frequency_regulator.cpp）异步执行时的资源管理问题（Fixes #328）。核心改动是移除手写的 workspace/executor/ACL Tensor 生命周期管理代码（AclTensorDeleter、AclWorkspaceDeleter、HugeMemSession、HugeMemReleaseGuard 等自定义结构体及 aclrtMalloc/aclDestroyTensor 手工调用），改用统一的 EXEC_NPU_CMD<FREQUENCY_REGULATOR_OP_NAME> 框架调用 aclnnFrequencyRegulator，将 workspace、executor 和 ACL Tensor 的生命周期交由公共插件框架统一管理，同时去掉手工流同步与 D2H/H2D 状态拷贝，保持算子异步执行，使该实现与 MindIE-SD 其他 PyTorch plugin 的方式保持一致。

主要改动

  • 改用统一的 EXEC_NPU_CMD 调用框架: 删除全部自定义删除器、HugeMemSession/HugeMemReleaseGuard 及 AllocateFrequencyRegulatorWorkspace 等资源管理辅助结构，改为 EXEC_NPU_CMD<FREQUENCY_REGULATOR_OP_NAME>(frequency, output_wrapper) 一行调用，由公共框架统一管理 workspace、executor 和 ACL Tensor 生命周期。
  • 移除手工流同步与状态拷贝: 删除 aclrtSynchronizeStream 同步以及 CopyFrequencyRegulatorStatusToHost（D2H）、CreateFrequencyRegulatorResultTensor（H2D）等 aclrtMemcpy 拷贝逻辑，算子保持异步执行。
  • 状态类型改用 ACL_UINT32 并转换为 int64: 用 TensorWrapper{output, ACL_UINT32} 包装输出张量直接接收算子状态，返回时通过 output.to(c10::ScalarType::Long) 转换为接口约定的 int64 Tensor，替代原先的 CreateFrequencyRegulatorOutAclTensor 校验与 ACL_UINT32 手动建张量逻辑。
  • 精简输出张量创建: 输出张量由 empty_with_format({1}, options, ACL_FORMAT_ND) 直接创建（Int 类型），删除了原先的 FREQUENCY_REGULATOR_OUTPUT_NUMEL 常量与 frequency_regulator_impl_npu 内的多步组装逻辑，代码量从 132 行缩减至 11 行新增。
