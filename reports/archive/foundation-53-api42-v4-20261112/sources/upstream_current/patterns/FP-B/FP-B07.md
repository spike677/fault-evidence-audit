# FP-B07 索引/偏移计算错误致越界

- **故障机理**：索引/偏移量在 host（tiling / infershape / aclnn）或 kernel 内计算错误，导致越界读/写或取到错误数据。**七种**典型成因：① **整型宽度不足**——用 `int32_t` 承载元素数/地址（元素数 > 2^31 即溢出，单核偏移相乘更易溢出）；② **符号/方向翻转**——`idxOffset`、`startOffset` 等正负号或方向取反；③ **边界条件写错**——`>=`/`>` 混用、末块/尾块偏移计算漏 1、`CeilDiv/FloorDiv` 取整方向错；④ **对齐与分核偏移**——`DataCopy/DataCopyPad` 的 32B 对齐、多核分核偏移叠加未对齐；⑤ **检查次序颠倒**——先按连续性/对齐算偏移，后做维度值校验，非法值先参与偏移运算；⑥ **GM 偏移 / 长度 32 位计算域溢出（v2.17 增补）**——合法大 shape 下线性元素位置达 **`2^32`**（**uint32 域回绕**，与成因① 的 int32 溢出是不同档位），或 GM 起始地址 / 下标 / 搬运长度 / `SetGlobalBuffer` 的 **size 参数**中 **≥2 个 32 位因子相乘**。**隐蔽特征是最终变量已声明为 `int64_t` / `uint64_t`，但右侧乘法仍全在 32 位域完成**——赋值时回绕已发生，再提升也无效。表现常为**后段输出全 0 的静默错误**（无 `aic error`、无 coredump），与成因① 的 aic error 型不同（实证 ops-nn #4494）。 ⑦ **分组/列表索引负值未校验（v6.33）**：`groupList` / `indices` / `slot` 等分组或索引值取负时未拦截，直接参与前缀和/寻址，导致 AI Core 越界（507015）或静默错位；与 ② 的区别是 ② 是偏移算式符号翻转，本条是**入参值域本身为负**。
```cpp
// ❌ 错误 1：最终变量是 int64_t / uint64_t，但右侧操作数全是 uint32_t —— 先回绕再赋值
int64_t offset = batchIdx * numHeads * seqLen * headDim;
uint64_t gmBias = i_o * rowFactor * numCol;
xGm.SetGlobalBuffer((__gm__ T*)x + blockIdx_ * blockFactor * numCol, rowWork * numCol);
// ❌ 错误 2：GM 偏移 / 搬运长度变量直接用 32 位类型承载
uint32_t gmBias = i_o * rowFactor * numCol;
int32_t blockOffset = mIdx * numCol;
// ✅ 正确：第一次乘法前显式提升到 64 位计算域
int64_t offset = static_cast<int64_t>(batchIdx) * numHeads * seqLen * headDim;
uint64_t gmBias = static_cast<uint64_t>(i_o) * rowFactor * numCol;
xGm.SetGlobalBuffer((__gm__ T*)x + static_cast<uint64_t>(blockIdx_) * blockFactor * numCol,
                    static_cast<uint64_t>(rowWork) * numCol);
```
- **触发条件**：大 shape（元素数跨 2^31、单核偏移超 int32）；indices/offsets 取**边界值、负值、重复值**；末维/尾块非对齐（如 31/32/33）；分核数与 shape 不整除；模板分支（全载/切分/单核）切换处的偏移语义不同；dav3510x 等多平台分支的检查次序差异；**合法大 shape 且 GM 偏移链路存在多因子乘法**（batch×heads×seqLen×headDim 量级可达数十 GB，见成因⑥）。
- **典型表现**：`aic error` / `AIC Error` 报错；coredump；结果**错位**（部分位置取到相邻元素）而非整体偏差；偶发性（依赖分核与 shape，同一算子部分 case 才复现）；有时先被当成"部分用例精度不对"，掩盖越界根因。
- **源码审查映射点**：地址/偏移变量的**声明类型**（`int32_t` vs `int64_t`）与元素数上界是否匹配；`idxOffset`/`startOffset`/`coefArr`/`*Stride` 的符号与方向；索引算式中的 `+1/-1`、除法与取模的取整方向；`DataCopy`/`DataCopyPad` 的 blockLen 与 32B 对齐；`GetShapeSize()` 与 `INT32_MAX` 比较处是否已溢出（比较本身在溢出之后即无效）；host 侧 shape 各维相乘是否可能超 int32；连续性/对齐检查与维度值检查的**先后次序**；`cubeMathType` 等枚举数组下标取值。
- **检测签名**：`int32_t[^\n]{0,40}(idx|Idx|offset|Offset|addr|Addr)`；`idxOffset|startOffset|offsetIndex|coefArr`；`CeilDiv\([^;]{0,60}(idx|offset)`；`DataCopy(Pad)?\([^;]{0,60}(offset|Offset)`；`GetShapeSize\(\)\s*[<>]=?\s*INT32_MAX`；`cubeMathType\s*\[`；**成因⑥ 增补（v2.17）**：`SetGlobalBuffer\s*\([^;]{0,80}\*`（GM 偏移含乘法）；`(int32_t|uint32_t)\s+\w*(?i:gmBias|gm_bias|blockOffset|block_offset|progress)`（GM 偏移变量落在 32 位域）；**成因⑥ 类型感知检测器（v6.12）**：`scripts/scan_uint64_mul.py`——正则签名只能覆盖 `SetGlobalBuffer(...*...)` 这类形状，普通赋值形态（`uint64_t x = a * b * c;`）需类型推断，见下条。
- **机器辅助（成因⑥，v6.12）**：`python3 scripts/scan_uint64_mul.py <仓根> [--json out.json] [--baseline b.json]`——**类型感知**检测器：解析 `struct` 字段 / 局部变量 / 函数形参 / `constexpr` 常量的声明类型，只对「左值 64 位 + 右侧乘法操作数全 ≤32 位」报 HIGH，类型未知单列 UNKNOWN；退出码 1 = 存在未豁免 HIGH。实测四仓 10,389 个 kernel 文件：ops-transformer 722 / ops-nn 117 / ops-math 35 / ops-cv 13 条 HIGH，人工复核确认 22 处；并据此**回退 9 处误判**（`numCol`、`outputLastDimValue_` 在部分算子里是 `uint64_t`/`int64_t`，乘法已提升）。局限：不做值域分析、混合 64 位加数的表达式（`a*b*c + 2*xBaseOffset`）可能漏报，HIGH 仍须按本卡判定标准复核。
- **审查关键词（`keywords` 字段；命中只表示该处值得按上文映射点人工审，**不是缺陷候选**）**：`\w*[Ss]tride\w*`（stride 类变量参与偏移计算，如 `blockTablesStride` / `srcStride` / `strideW`——⚠️ **高频词，正常代码里大量出现，按 v2.15 判据不得作判别性指纹**，只作定位提示）；`SetGlobalBuffer`（**对照锚点**：命中 = 存在 GM 偏移注册点，真正要看的是其第二个 size 参数的**计算域**）。
- **专属检视方法（成因⑥；v2.17 新增，来源 `cann/cannbot-skills` `ascendc-code-review` 红线条例 9）**：① **枚举**所有 GM 起始地址、GM 下标、GM 搬运长度表达式——`SetGlobalBuffer((__gm__ T*)ptr + expr, size)`（**第二个 size 参数同样要查**）、`GlobalTensor[expr]` / `xGm[gmBias]` / `yGm[progress]`、`CopyIn(gmBias)` / `CopyOut(progress)` / `DataCopy*(gm[expr], ...)`，以及名称含 `gmBias` / `gm_bias` / `offset` / `progress` / `blockOffset` 与 stride 类变量（`\w*[Ss]tride\w*`）的表达式；② 对每个表达式**同时看声明类型与右侧计算域**：若存在 `blockIdx` / `indexOuter` / `i_o` / `mIdx` 与 `blockFactor` / `rowFactor` / `numCol` / `tiling->n` / stride 等多因子相乘，**必须在第一次乘法之前**显式提升到 `int64_t` / `uint64_t`；③ **不能只看最终变量类型**——`uint64_t gmBias = i_o * rowFactor * numCol;` 中右侧操作数全为 32 位时仍先回绕后赋值，**判 FAIL**；④ **反推最大可能值**：若合法 shape 或 tiling 可使线性元素位置达到或超过 `2^32`，且乘法前未进入 64 位计算域 → **FAIL**；无法确认上界但表达式用于 GM 偏移且全为 32 位操作数 → 至少 **SUSPICIOUS**。
- **控制变量（v6.30）**：**必须固定**——shape / dtype / 属性固定，只把**一处** index / offset 推到边界值（最后一个合法值、第一个越界值）；每次只动一个下标 ｜ **允许变动**——单个索引 / 偏移值 ｜ **多变量同变的典型误判**——同时改 shape 与索引 → 越界位置说不清是 shape 算错还是索引算错；实测 40 个抽样里索引边界注入只对 7 个生效（其余无整型输入），按「全支持」统计会虚高
- **测试拦截建议**：构造四类探针——「元素数跨 2^31」「indices 取边界/负值/重复」「非对齐尾块（末维 31/32/33，尾块非整除）」「分核数 = 1 / 2 / 实际核数 ± 1」；对索引敏感算子跑 `mssanitizer`（内存越界检测）而非只比数值；比对时同时看「是否 aic error / 是否 coredump / 数值是否错位」三类症状，避免只报"精度不一致"；大 shape 用例需与 tiling 阈值（分核/全载切换点）两侧成对构造。
- **检测工具误报判据（v6.49，守卫区复核强制）**：`mssanitizer --tool memcheck` 报 `WARNING: out of bounds of size N at 0xADDR on GM when writing data` 时**不得直接作缺陷证据**，必须先用「前置 + 后置守卫区 canary」复核。A2(910B2) + CANN 9.3.0 实测两例误报：① 官方 example `aclnnMlaProlog`（nq / pq 两个用例）报 1024B/128B 与 512B/64B 两条，地址**恰好等于 `kvCache` / `krCache` 的张量基址**；把张量基址后移 4096B 重跑，告警地址同步后移到 `base+0x1000`，而前置 4KB 与后置 1MB 守卫区（预填 0x7F）**零改动** ⇒ 工具在张量首址上的边界记账偏差，不是写越界。② `aclnnMsaIndexScore` 报 88 条 64B 告警，地址以 `scoreStride*4 = 1088B` 为步长落在**逐行行首**；40 个用例各加 1MB 后置守卫区 → 全部 `guard_bad = 0`。判据三条：告警地址是否随张量基址平移、步长是否等于行 stride、守卫区是否被改动；三条同时成立即判**工具误报**，不得提交 issue。**反向纪律**：也不能只看关键词 `illegal` 就判「全绿」——`out of bounds` 是独立消息类（`ERROR: illegal read/write of size` 之外的另一族），漏看会把真越界当无异常。
- **实证案例**：ops-nn **#1029** `EmbeddingDenseGradV2` idx 越界导致 aic 问题；**#1182** 同算子 `idxOffset` **翻转**导致 indices 取值越界致 aic（**同根因两连发**）；**#1359** `MatMulUnAlignedSingleCoreSplitKKernelGmToL1` 模板 `DataCopy` 指令读越界；**#1608** 32B `DataCopy` 越界；**#1483** `cubeMathType` 数组越界引发 coredump；另有 #1928 index_fill 数据量超 int32 触发地址越界风险（与 FP-A18 交叠）。语料统计（2026-09-14，四仓缺陷类）：该机理命中 **125 条**。**成因⑥ 实证增补（v2.17）**：ops-nn **#4494**（910B2）`rms_norm` 在**合法大 shape** 下从元素位置 `4294969344`（紧贴 `2^32`）附近开始输出**全 0**——**无 `aic error`、无 coredump、无其他报错**，是成因⑥ 的**静默型**表现（与该卡主症状「aic error / 结果错位」不同，须并看 FP-A04）；修复把 `blockIdx_ * blockFactor * numCol`、`gmBias`、`CopyIn/CopyOut` 的 GM 偏移链路改为 `uint64_t` 并在乘法前显式 `static_cast<uint64_t>`。该案例由 `cann/cannbot-skills` `ops/ascendc-code-review` 红线条例 9 收录，本库 v2.17 据此补录。 **现网复盘增补（v2.19）**：ops-transformer PR **#69068**（现网 25-09，`ScatterAddWithSort`）——UB 容量比较用 `>` 而非 `>=`，`updatesAlign * inputSize` **恰好等于** `max_ub` 时漏入降级分支，scratch 预留不执行致越界；修复后 `scatter_add_with_sorted_tiling.cpp:219` 改 `>=`。ops-transformer PR **#2466**（现网 26-03，`FlashAttentionScore`）——BMM2 搬运因子固定 `ndNum = 2`，奇数尾块只剩 1 个 ND 单元时仍按 2 搬运，同时 `blockCount`/`cacheSize` 一并按 2 记账；修复后 `flash_attention_score_s1s2_bn2gs1_sab.h:2353` 改为 `ndNum = aColNum - curK == 1 ? 1 : 2`。**注**：两条均为仅 PR 无 issue 的现网单，PR 号在此登记以固定溯源。 **2026-11 批次（v6.33 反哺）**：本簇 31 条；代表 ops-transformer#6571（slotMapping 上界）、#6576（blockId 越界）、#6543/#6605（groupList 负值）、ops-cv#1437（4*C*(H*W-1) 超 int32）。
