[Bug-Report|缺陷报告]: 910B 上 DS V4.1 W4A8 预填充 DSA 压缩器 FP32 Linear(matmul) 触发 507035 向量核异常 #8342

6 days ago Create

环境

  • 硬件：Atlas 800I A2（Ascend 910B）
  • 部署：MindIE-Motor 3.2 + Mooncake PD 分离，TP=8 / EP=8，4p4d
  • 模型：deepseek-v4.1-flash-w4a8（quantization=ascend）
  • 现象：4 个 prefill（P）节点全部重启，decode 节点正常

崩溃栈

崩溃发生在 DSA C2 ring compressor 的 gate 线性层，输入为 FP32：

File ".../vllm_ascend/attention/dsa_v41.py", line 531, in _write_compressed_source
    score = compressor.wgate(hidden_states_fp32)   # hidden_states.float()
File ".../torch/nn/modules/linear.py", line 134, in forward
    return F.linear(input, self.weight, self.bias)
RuntimeError: The Inner error is reported as above ... current working operator name is aclnnIndex.

对应算子为 vllm_ascend/models/deepseek_v41/compressor.py 中的 FP32 nn.Linear（bias=False）：

self.wkv   = nn.Linear(dim, self.width, bias=False, dtype=torch.float32)  # ratio==2
self.wgate = nn.Linear(dim, self.width, bias=False, dtype=torch.float32)

该 FP32 Linear 在 NPU 上映射为 aclnn matmul 算子：aclnnMatmul（ops-nn matmul/mat_mul_v3，MatMulV3，A2 支持）。

设备侧错误

主故障设备（device 2）先向量核超时，随后同步报向量核异常：

retCode=0x30, [vector core timeout]     → rtsLaunchKernelWithHostArgs execution failed
retCode=0x31, [vector core exception]   → aclrtLaunchKernelWithHostArgs failed: 507035
[Error]: The vector core execution is abnormal.

其余 rank（5/6/7）随后在各自下一次同步点级联报 507035（如 aclnnRmsNorm）。

关于 "aclnnIndex"

HCCL watchdog 报的 "current working operator name is aclnnIndex" 疑似异步执行下的陈旧归因：

  • ops-nn index/index 的 aclnnIndex 仅编译了 ascend950/350/960dt/960pr（SUPPORT_COMPUTE_UNIT 无 910B），910B 上无对应 kernel；
  • 崩溃栈最上层 Python 帧明确指向 compressor.wgate 的 FP32 Linear（matmul）。

因此实际故障算子更可能是压缩器的 FP32 matmul（或其附近向量核算子），而非 aclnnIndex。已设置 ASCEND_LAUNCH_BLOCKING=1 复现，后续可提供精确归因。

期望

请 CANN 侧协助确认：910B 上 FP32 matmul（aclnnMatmul，MatMulV3）在 DSA 压缩器该场景下为何触发向量核超时/异常（507035），是否为算子缺陷。
