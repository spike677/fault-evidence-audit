# FP-F04 算子接口交付面缺失（符号未导出 / 原型未注册 / 未纳入商分）

> [← 库索引](../../README.md) ｜ [变更记录](../../CHANGELOG.md) ｜ 类别：工程/交付 ｜ 风险：高（S2×O3=6） ｜ 状态：活跃

- **元数据**：类别 工程/交付 ｜ 风险 高（S2×O3=6）｜ 状态 活跃 ｜ 来源 gitcode CANN + Ascend 组织 issue 检索（2026-09-19，6 条确认对应，覆盖 3 仓）
- **适用**：仓 All ｜ 侧别 All ｜ 载体 构建配置与日志,aclnn源码,IR与图配置 ｜ 触发 undefined symbol|dlsym|AddConfig ｜ 默认启用 true
- **故障机理**：算子的**实现已经完成**，但在「把接口交付到用户手里」的清单上漏项，使接口在用户侧不可用、或被**静默降级**。五种独立成因：① **`.so` 符号未导出**——`libopapi.so` / `liboptiling.so` 中缺少 aclnn 接口或 typeinfo 符号，框架侧 `dlsym` 返回 `nullptr`；② **公开算子名未注册**——PTA / 框架侧公开名（如 `cann_ops_transformer::compressor`）未注册，`torch.ops.<ns>.<op>` 不可用；③ **派发表未同步注册**——算子跨版本复用兄弟实现（v4 复用 v3 的 tiling/kernel）时，上游新增的 tilingkey 未同步适配，走到该模板即报「未注册 tilingkey」；④ **适配层注册缺失致静默降级**——算子未在 torch_npu 注册，dynamo 时**静默 fall back 到 CPU**（不报错，仅性能与行为变化）；⑤ **商分清单未合入**——代码已进社区主干但未进商业发行分支，表现为能力缺失或用例挂死；⑥ **接口/源码未同步至开源仓、文档跳转缺失（发布面遗漏，v2.16 增补）**——接口本体只存在于内部 dev 仓、未随发布同步到开源仓，或资料中的「跳转源码」链接指向不存在的路径，用户按文档接入时找不到实现。**与 FP-B03 的边界**：B03 是「迁移时把**防御代码**漏掉」（机理 = 防御逻辑漏迁），本成因是「**接口本体**没迁、或跳转没配」（机理 = 交付清单漏项），二者不同源。**共同特征：交付面缺失，而构建 / 调用链不报错、或只打 `ERROR` 日志仍返回成功。**
- **触发条件**：新增算子或新增接口后未同步更新导出符号表 / 公开名注册 / `binary.json` / apt 派发表；算子跨版本复用且上游新增 tilingkey；**选择性打包**（sanitizer、商分裁剪、形态裁剪）；跨 toolkit 版本发布；框架侧适配层（torch_npu）未同步算子清单；**接口从内部 dev 仓向开源仓同步时遗漏**、文档「跳转源码」链接未随仓迁移更新（v2.16 增补）。
- **典型表现**：`undefined symbol: ...`（如加载 `liboptiling.so` 失败）而**构建退出码仍为 0**、target 显示 `Done` / `Built target`、且继续产出 `.o` / `.json` 产物；`dlsym` 返回 `nullptr`（`EXEC_NPU_CMD` 查不到 aclnn API）；`torch.ops.<ns>.<op>` 不存在；「未注册 tilingkey」报错；dynamo 静默 fallback 到 CPU；同一算子族的多个 mode 稳定报同一错（同根因）。按文档「跳转源码」链接点进去**路径不存在或指向兄弟算子**；开源仓接口清单与内部清单不一致（内网能调通、开源包内找不到该接口）（v2.16 增补）。**仅检查顶层构建退出码无法发现本型。**
- **源码审查映射点**：导出符号表（version script / `*_symbol.txt`）与 aclnn 接口清单的**双向差集**；PTA / 框架侧公开名注册表与算子清单差集；`op_host/config/<soc>/*_binary.json` 与 `.def` `AddConfig` 的差集（**与 FP-F01 共用同一门禁但关注面不同**：F01 看配置是否**一致**，本条看导出/注册清单是否**覆盖**）；apt / 派发表中复用兄弟版本的 tilingkey 清单是否覆盖上游新增项；torch_npu 适配层映射表覆盖率；商分裁剪清单与社区算子清单差集；`asc_opc` 类编译工具在符号解析失败时是否仍返回成功；**内部 dev 仓接口清单 × 开源仓同名接口清单的双向差集**、**文档跳转链接 × 目标仓实际路径的存在性校验**（v2.16 增补）。
- **检测签名**：`undefined symbol`（**构建日志中出现即应判失败，不得只查退出码**）；`dlsym` 返回值是否有 `nullptr` 校验；`libopapi\.so|liboptiling\.so` 加载失败日志；导出符号清单（`*_symbol\.txt` / version script）与 `aclnn[A-Za-z]+` 接口名的差集；公开名注册（`m\.def\(|TORCH_LIBRARY|register_op`）与算子清单差集；`未注册\s*tilingkey|tilingkey.*not\s*register`；`fall\s*back|fallback.*cpu`（静默降级的观测点）；**接口清单差集扫描**（内部仓 vs 开源仓的同名 aclnn 接口）；**文档跳转链接存在性扫描**（`docs/**/*.md` 中的仓内跳转路径是否真实存在）。
- **测试拦截建议**：① **构建门禁必须解析日志而非退出码**——实证证明「退出码 0 + `Built target` + 日志若干行 ERROR」是常态，CI 需对构建日志做 `undefined symbol` 与 `lib*\.so` 加载失败的正则断言；② **接口可用性冒烟**——每个 aclnn 接口发布前跑一次 `dlsym`（或直接调用），断言符号可解析；③ **框架侧注册矩阵**——对每个算子断言 `torch.ops.<ns>.<op>` 可访问**且不回退**（在 `torch._dynamo` 下检查图是否被打断）；④ **商分与社区算子清单差集**纳入发布门禁；⑤ **选择性打包 / 裁剪场景单测**（sanitizer、商分、跨 toolkit）；⑥ 本型与 FP-F01 的 binary.json 门禁可合并实现，但**断言方向相反**（F01 断言「注册了就必须有产物」、本条断言「产物里必须有符号」）。
- **实证案例**：ops-transformer **#4967**（closed）在 `master` 分支执行 Ascend 950 sanitizer 多算子选择性打包时，构建命令**最终返回 0**、相关 target 显示 `Done` / `Built target`，但完整日志中存在 `asc_opc` 加载 `liboptiling.so` 失败的错误——`liboptiling.so: undefined symbol: _ZTIN8optiling24GroupedQmmBasicApiTilingE`（解码为 `typeinfo for optiling::GroupedQmmBasicApiTiling`），共 4 行 `[ERROR]`，对应 `lightning_indexer_v2_ascend950_0` / `_1` 两个编译任务各重复打印同一错误，**错误发生后 `asc_opc` 仍返回成功并继续生成 `.o` 与 `.json` 产物，因此仅检查顶层构建退出码无法发现**（CANN 9.2.0 / Linux x86_64 Docker）——**「交付面缺失 + 静默成功」的教科书案例**；ops-transformer **#5434**（closed）`compressor` 的 **PTA 公开算子名 `cann_ops_transformer::compressor` 未注册**，`torch.ops.cann_ops_transformer.compressor` 不可用（Ascend950 / CANN 9.2.0 / Python 3.10；同 issue 另含 VF reduce 非整除精度问题）——**量化算子接口未注册的原型案例**；Ascend/op-plugin **#242**（closed）在 NPU 上跑上游 `test/test_ops.py` 的 scatter_reduce 用例时，运行时通过 `EXEC_NPU_CMD(aclnnScatterReduce, ...)` 走 `dlsym` 查找 `aclnnScatterReduce` / `aclnnScatterReduceGetWorkspaceSize` 时**返回 `nullptr`**，即**当前 CANN 发布的 `libopapi.so` 并未导出 ScatterReduce 家族的 aclnn API**——3 个失败 test 命中 sum / amax / amin 三种 reduction mode 但根路径完全一致（**同一家族多入口同根因**）；Ascend/op-plugin **#416**（closed）`aclnnRepeatInterleaveTensor` 算子**未注册 pta**，导致 dynamo 时 **fall back 到 CPU**（静默降级，无报错）；ops-transformer **#5104**（closed）`moe_init_routing_v4` 复用 v3 的 tiling 与 kernel，v3 新增 tilingkey 而 **v4 的 apt 未适配**，走到该模板时 v4 报**未注册 tilingkey**（ascend950 / cann9.2.0）；ops-transformer **#5337**（closed）MoeInitRoutingV4 部分用例超时挂死，备注明确指出「**商分未合入**」（挂死后果见 FP-G01）。**测试集失败语料补充（v2.16，2026-09-19，具体 issue 编号待核）**：一批归类中「算子接口仓迁移 / 发布遗漏」**18 条**（询问"aclnn 接口是否有遗漏跳转源码至 ops-math 仓""接口从 dev 仓迁移到开源仓"）——即本成因 ⑥ 的语料支撑。**共性特征：实现已完成，缺的只是"把接口交付出去"那一步；且失败多为静默（退出码 0 / 不报错 / 静默回退）。**
