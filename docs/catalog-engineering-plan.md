# 从手工整理到模式库草案工具

实施更新：0.1.9 已增加 `catalog-draft prepare / validate / export`，具体能力和文件往返见[操作说明](catalog-draft.md)。下面保留最初的设计与验收边界；正式采用、Excel 回导及自动模型执行尚未实现。

日期：2026-11-06。代码基线为 `c9e9c6b`，基于 0.1.8 的调查工具开发分支。本文是后续实现方案；本次交付仅新增 XLSX、说明和本方案，不新增执行命令，不修改现场状态或正式库。

## 目标与现状

把本次“读资料、对照原故障、比较原库、抽象模式、保留缺口、合并导出”的工作做成可复核流程。先实现小型模式草案层，复用取证链路，不重新建设网站客户端、模型客户端或自动事件合并系统。

当前已有来源台账、证据计划、快照与独立摘要、`work_id` 事实对照、原库映射、模型文件桥接、输入预算、策略失效及报告导出。`investigation-plan` 能生成只读调查输入和带引文的六列资料摘要卡片；它不会自动执行采集、判断或正式入库。

本次 XLSX 是手工审查交付物。它能作为实现时的对照样本，不能据此宣称自动整理链路已完成。

## 数据流

```text
原表 / 旧表 + 冻结原库
  → evidence_plan：全部已有引用优先整理、控制新增搜索
  → 外部 Agent 采集：正文 / 讨论 / 必要 issue 与修复 Diff
  → 独立资料摘要：快照、子问题、事实、精确引文
  → work_id 事实对照：原记录与资料逐项比较，执行有限自检
  → investigation_plan + 当前有效库映射
  → CatalogProposal：覆盖比较、抽象模式、具体根因、未知项
  → 程序校验：15 列、来源、版本、枚举与选定新增集合
  → 只读合并预览：旧库原值 + 明确选定的新增草案
  → JSON / 差异清单 / XLSX
```

已有原始、旧表及确认关联的引用全部保留并安排必要整理。同 URL 在同批只采集一次，同快照共享独立摘要；不同子问题范围分别处理，`work_id` 贯穿任务和结果。

默认一份适用证据即可停止新增搜索。停止搜索不取消其他原始引用的整理，也不等于全部技术字段已证实。登录失败、部分采集或来源冲突分别记录，不转换成“没有证据”后自动扩搜。未知修复版本、缺失字段不触发补齐所有资料类型的搜索。

## 最小新增数据结构

建议新增独立 `CatalogProposal`，不把 15 列草案塞入现有 `CatalogItem` 或故障判断中。首版可让 Agent 按 JSON 合同提交草案，程序验收，不必先增加模型任务种类。

| 内容 | 最小字段或约束 |
| --- | --- |
| 身份与版本 | `proposal_id`、修订号、基线库 identity/hash、规则版本及输入指纹 |
| 处理建议 | `ADD / REFINE / APPEND_CASE / NO_CHANGE`、可选目标模式 ID、覆盖理由 |
| 产品内容 | 完整 15 列；抽象模式名和具体根因分开 |
| 适用范围 | 原 case IDs、work IDs、子问题范围、实现归属 `implementation_owner` |
| 字段依据 | 对每个事实字段记录原单元格或 snapshot/fact IDs、精确引文、支持程度 |
| 证据属性 | 区分原文事实、代码推断、作者验证、当地复现及未知；提案不改变原判断 |
| 建议与缺口 | 检查/处理/注入建议、未执行状态、未知项、冲突及修订来源 |

结构化 JSON 与证据记录作为后续工具的真源，XLSX 是展示与交付物。若支持人工修改 XLSX，应通过显式校验导入形成新修订；不得静默覆盖事实或继承人工 `ACCEPT`。该回导能力可放在后续阶段，不阻塞首版。

客户事件身份、通用技术模式和库覆盖是不同判断。公开 PR 可以支持一种实现机制，但客户事件关联、具体版本和产品归属仍须分别保留依据。其他事件资料不能确认原故障根因；未确认客户关联也不能把公开代码变更写成该客户已经验证的修复。

## 程序、Agent 与人工的分工

| 执行者 | 职责 |
| --- | --- |
| 程序 | 检查引文存在、来源链、哈希与当前有效性、固定分类、必需字段、选定集合、唯一 ID、无损合并和导出；已有任务与失效机制继续复用。 |
| Agent | 读正文和必要 Diff，对照数值含义、术语、场景、机制和修复；比较原库，提出抽象模式与合并建议，并检查反证、子问题串用和推断越界。 |
| 人工 | 处理无法消解的冲突、范围和分组争议；明确决定正式库是否采用草案。正常来源整理不增加逐条确认，系统处理不冒充人工 ACCEPT。 |

程序能验证引文和结构，不能单靠关键词或枚举证明根因成立。相同数字必须含义和条件相同；字节、元素数、TP 与块尺寸不得互换，算子名称相似也不证明同事件。

## 复用接口与最小实现步骤

现有 `investigation_plan(store, run_id)` 提供当前资料卡片、事实与根因候选；`import_catalog(..., scope, expected_count)` 提供冻结原库与数量约束；`export_report → workbook_data → scripts/export_xlsx.mjs` 提供表格导出基础。先复用这些接口，不建设第二份采集或判断台账。

1. **草案合同与纯校验。** 在 `contracts.py` 定义 `CatalogProposal`，在独立小模块实现字段和来源校验。三级只允许“计算算子、通信算子、图引擎”；四级只允许“算子计算、算子接口、数据切分、图融合优化”。建议字段明确未验证，缺失事实保持未知。用合成数据测试；本次手工 XLSX 作为本机对照资料，不把客户原文复制成自动化测试夹具。
2. **只读合并预览与导出。** 建议增加 `catalog-draft validate`、`catalog-draft export` 两个命令（尚未实现）。输入冻结原库和草案 JSON，输出校验、差异及新工作簿。核对基线哈希、唯一 ID 与明确选定的提案集合；重复执行不重复追加。语义合并由 Agent 提建议，程序不能按名称相似自动覆盖旧条目。首版不回写原库或现场 state。
3. **接入 Agent 文件任务。** 沿用 OpenCode/Codex 的请求和提交协议，让 OpenChamber/OpenCode 或 Codex 执行摘要、对照及草案填写。新模块、规则和模板必须进入策略指纹或任务输入哈希；证据、基线、Prompt、预算或规则变化使旧草案失效，历史响应和人工记录保留。正式采用时形成明确的新库版本，不原地改变本轮冻结库。

若最终模型请求超过现有预算，明确 `BLOCKED / INPUT_TOO_LARGE`；不删减原文、事实或库条目后声称完整成功。本机试行已出现摘要成功而比较请求超限的情况，首版允许保持阻塞，不以新增复杂聚合算法作为前置条件。

## 本次三条的验收边界

| 草案 | 必须保留的限制 |
| --- | --- |
| WB-010：缓存复用条件不完整 | 缓存未区分布局/连续性这一机制与具体 key 字段分开；未取得的修复代码不能由 golden 测试改动代替。 |
| WB-034：量化参数读取错误 | 只写已提供的 V scale 读取错误；未知索引、stride、地址计算细节保持未知，其他 AllReduce 资料不能作其正证。 |
| WB-036：分块数据处理错误 | 分开说明归约步长和量化临时区调整；不把 64 字节换成 64 元素，不推断未知 tiling 参数；保留 vllm-ascend 自定义算子的实现归属。 |

三条检查与注入方法均为建议，未执行注入；不得生成“已复现”结论。

回归至少验证：

- 本轮选择集合只新增 WB-010、WB-034、WB-036 对应的 3 条，不能把额外公开 PR 自动扩成新增模式。
- 原库 30 条的模式名、原因、影响保持原值，新增 3 条完整对应 15 列；旧条目缺少的检查或注入字段不造值。输出明确标为“新增 3 条 + 30/33 条共有字段核对”。
- 同一模式可保留多个案例和引文；重复运行不重复新增，不因多份引文重复计数。
- 多子问题不串用；不同事件、不匹配、过期或人工拒绝结果不能支持原故障根因。
- 已有证据满足搜索目标时停止扩搜，仍整理已有引用；单份读取失败不阻止其他资料正常处理。
- 基线、证据、输入或策略变化后旧草案不能作为当前结果；旧记录保留，不自动转移 ACCEPT。
- 超限明确阻塞，导出保留未知、冲突、建议与验证状态，不把草案直接计入正式覆盖率。
