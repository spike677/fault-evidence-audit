Describe the current behavior / 问题描述 (Mandatory / 必填)

InsV2AllGatherSequenceExecutor3Level::PrepareResForTemplate() 裸调用三个返回 HcclResult 的 GetRes()，随后立即用返回的 slaveThreadNum 对 threads_ 构造范围：

tempAlgLevel0.GetRes(Level0TempRequest);
tempAlgLevel1.GetRes(Level1TempRequest);
tempAlgLevel2.GetRes(Level2TempRequest);

levels_[0].threads.assign(threads_.begin(), threads_.begin() + Level0TempRequest.slaveThreadNum + 1);
levels_[1].threads.assign(threads_.begin(), threads_.begin() + Level1TempRequest.slaveThreadNum + 1);
levels_[2].threads.assign(threads_.begin(), threads_.begin() + Level2TempRequest.slaveThreadNum + 1);

GetRes() 是 HcclResult 虚接口，基类实现明确返回 HCCL_E_INTERNAL。当前实现不传播任一模板资源错误，也没有验证 threads_.size() 是否覆盖三个 count；无效资源请求或线程不足时会产生越界迭代器。后续 GenTempResource() 复用 levels_[idx].threads，故问题会进入模板 KernelRun，而不是在资源准备阶段确定失败。

Environment / 环境信息 (Mandatory / 必填)

  • 仓库：cann/hccl，分支：master
  • 审计基线：fbc2661c2ec82760220f3874cf04a72e20197841
  • 文件：src/ops/all_gather/executor/ins_v2_all_gather_sequence_executor_3level.cc
  • 位置：PrepareResForTemplate 约 145-158 行；注册算法约 325-331 行
  • 注册路径：InsAllGatherSequenceNHRNHRMesh1D
  • 相关接口：src/ops/op_common/template/common_alg_template_base.h:29；alg_v2_template_base.cc:74-79
  • Ubuntu 24.04 x86_64；静态源码/控制流核验；无昇腾设备
  • 团队：XDU；成员：Mr_lee226688

Steps to reproduce the issue / 重现步骤 (Mandatory / 必填)

可在定向 UT/stub 中复现，无需设备：

  1. 构造注册为 InsAllGatherSequenceNHRNHRMesh1D 的三层 executor。
  2. 让任一 level 模板的 GetRes() 返回 HCCL_E_INTERNAL。
  3. 调用 PrepareResForTemplate() 或其上层 Orchestrate()。
  4. 当前代码忽略错误，继续读取对应 AlgResourceRequest。
  5. 令 threads_ 长度小于任一 slaveThreadNum + 1；当前 assign 的第二个迭代器越过 end()，构成未定义行为。

Describe the expected behavior / 预期结果 (Mandatory / 必填)

  • 三次 GetRes() 均用 CHK_RET 或等效方式传播首错。
  • 每次 threads_ 切分前验证请求数不超过 threads_.size()；失败返回 HCCL_E_PARA。
  • 资源准备失败后不得写入 levels_ 或进入 GenTempResource/KernelRun。
  • 增加三组 GetRes 失败注入、三组线程不足和一组全成功路径 UT。

Related log / screenshot / 日志 / 截图 (Mandatory / 必填)

确定性控制流：

level 模板 GetRes 失败
→ 返回值丢弃
→ slaveThreadNum 未保证有效
→ begin() + slaveThreadNum + 1
→ 可能越过 threads_.end()
→ 资源错误丢失或后续模板异常

当前无硬件日志；结论来自固定基线源码。
