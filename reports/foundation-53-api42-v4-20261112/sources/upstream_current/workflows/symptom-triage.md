# symptom-triage：现象驱动定位

> 用于**只知道现象、不知道根因**的场景：从 `TRIAGE.md` 收敛候选，再单点深挖、交叉反证，最后输出定位结论。
> 与 operator-admission 的区别：不做全量体检，只回答「这次到底是什么问题」。

## 输入

- 现象描述（必填）：卡死 / 超差 / 报错码 / 结果不稳 / 变慢 / OOM / 测试全绿但线上异常；
- 复现条件（可选但尽量给）：shape、dtype、芯片、开关（确定性、图模式）、频率；
- 已排除项（可选）：换机器/换版本是否复现、是否单算子可复现。

## 阶段

### Stage 0 — 收敛候选（≤6）

1. 打开 [TRIAGE.md](../TRIAGE.md)，按「后果」找入口（T1~T7），不要先想模式名；
2. 取入口内 2~6 条候选，逐条核「适用」声明；不匹配 → 降权或剔除并记理由；
3. 候选 >2 条时，先问一个**区分性问题**再继续（如「日志是否推进」「是否只在开关打开时出现」「是否特定 shape」）。

### Stage 1 — 单点深挖（先 1 ~ 2 条，不要并行铺开）

1. 打开候选 skill，按第 2 节定位实现、第 3 节取数、第 4 节清单逐条核查；
2. 每条清单点记录：命中面（`文件:行号`）/ 防护面 / 反证；
3. 命中即按 Bug 卡流程出卡（证据等级 + B 轴）；`需实测确认` 只记观察项并给实测用例。

### Stage 2 — 交叉反证（强制）

- 对**最像的相邻模式**（skill 第 0 节边界表的第一行）跑一次负向验证：找出「若它是 Y 则必然存在的现象 / 代码形态」，确认不存在或存在；
- 负向证据必须写成 `[文件]:[行号] [代码行]`，没有就记「未核查」；
- 两条模式都强命中 → 按「多机理叠加」合并报告，不强行二选一。

### Stage 3 — 未命中回退

按顺序执行，每一步都要在报告留痕：

1. 换同入口的下一条候选；
2. 扩到 TRIAGE 相邻入口（如 T3 精度 → T4 稳定性）；
3. 若现象无法定界到单算子（整网 / 环境 / 用法），输出 **`verdict: OUT_OF_SCOPE`** 并说明缺什么信息；
4. 仍无线索 → 输出「本轮未定界」，附已排除路径与建议补测项，**不得硬套一条模式**。

### Stage 4 — 报告

```markdown
# {现象} 定位报告（YYYY-MM-DD）
## 一、现象与口径（输入 / 复现条件 / 已排除项）
## 二、候选收敛过程（TRIAGE 入口 → 候选 → 区分性问题 → 保留/剔除理由）
## 三、深挖结果（命中卡 / 观察项 / 证据等级）
## 四、交叉反证（相邻模式 / 负向证据 / 结论）
## 五、定位结论（verdict: FP-XX / OUT_OF_SCOPE / 未定界）+ 下一步
```

## 停止条件与边界

- 同一候选连续两轮清单核查无新增证据 → 换候选，不做第三次；
- 定位报告**不是**体检报告：只覆盖候选相关映射点，不得表述为「全量检视」；
- 若用户要的是「准入体检」，改用 [operator-admission](operator-admission.md)。
