# 观察项台账（`observations.jsonl`）

**定位**：收纳「有现象、无根因」的线索。这是库结构里原本的空档 ——
`AGENTS.md:48` 规定了观察项的表格式（清单项 | 文件:行号 | 存疑点 | 复现方案），
`INVARIANTS.md` 纪律 2 也说「答不出本身就是产出（= 观察项）」，
但 `cases/` 下只有 `misjudgments.jsonl`（专收**改变了结论**的误判，
`cases/README.md` 明确写「台账不是垃圾桶」）。

结果是一批「跑出来了、但证据不够进库」的线索无处沉淀，只能散落在各次报告里，
下一次检视从头再来。

## 与 `misjudgments.jsonl` 的分工

| | `misjudgments.jsonl` | `observations.jsonl`（本文件） |
|---|---|---|
| 收什么 | **改变了结论**的误判 | **有现象、证据不足以定论**的线索 |
| 判据 | 已登记误判类型（7 类） | 至少有可复现的现象（不是猜测） |
| 目的 | 防止同类误判复发 | 防止线索流失；为下次复检留锚点 |
| 出口 | 升级为防线 / 改档 | 补足证据 → 提正式 issue 或进卡；或标「已排除」 |

**不进本台账的**：纯静态推测、无现象、无复现方案的猜测。
本台账也要守「不是垃圾桶」这条。

## 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | `OB-YYYYMMDD-NN`，全局唯一 |
| `date` | 是 | 登记日期 |
| `op` | 是 | 算子名（snake_case） |
| `repo` | 是 | 所在仓（ops-nn / ops-math / ops-transformer / ops-cv） |
| `symptom` | 是 | 观测到的现象，含具体数值（错误条数、size、地址特征） |
| `probe` | 是 | **参数从哪来**（哪个 example、什么 shape）—— 没有就不登记 |
| `suspect` | 否 | 初步怀疑的机理，可空（空就是「还不知道」） |
| `related_fp` | 否 | 可能归属的 FP 卡（可空，空表示「现有卡都不覆盖」） |
| `missing` | 是 | **还缺什么证据**才能定论（具体到「补哨兵」「查 tiling」「对 golden」） |
| `status` | 是 | `open` / `probing` / `promoted`（已提 issue）/ `dismissed`（已排除，须写理由） |
| `note` | 否 | 补充说明 |

## 准入判据（三条全满足才登记）

1. **有可复现的现象** —— 能写出具体的错误条数 / size / 地址特征，不是「感觉不对」。
2. **写得出参数来源** —— 哪个 example、什么 shape。写不出说明连输入都不确定，先别登。
3. **写得出还缺什么** —— `missing` 不能是「需要进一步分析」这种空话。

## 与 FP-B07 误报判据的关系（重要）

memcheck 报 OOB **不等于**算子越界。`patterns/FP-B/FP-B07.md:31` 的
「检测工具误报判据（v6.49）」给了三条：① 告警地址是否随张量基址平移；
② 步长是否等于行 stride；③ 守卫区是否被改动。
三条同时成立即判**工具误报**，不得提交 issue。

`aclnn-bug-hunt/references/pitfalls/40-memory.md` 的 K427 是同一判据的另一个版本
（判据：① 报错地址 == 自己申请的缓冲起始地址；② 块对齐用例同样全块报错）。

**登记观察项时，若还没做这两条排除，必须在 `missing` 里写明「未做 K427 排除」。**
本次 12 条里至少 2 条（`sim_thread_exponential` / `apply_adam_w_quant`）的报错地址
恰好落在缓冲基址，高度疑似 shadow 假象 —— 这类**不应该**按「越界」登记，应按
「待排除工具误报」登记。
