# FP-B13 host 侧 int64→int32 窄化 / 乘积溢出（参数值静默改变）

> [← 库索引](../../README.md) ｜ [变更记录](../../CHANGELOG.md) ｜ 类别：功能/兼容 ｜ 风险：高（S3×O3=9） ｜ 状态：活跃

- **元数据**：类别 功能/兼容 ｜ 风险 高（S3×O3=9）｜ 状态 活跃 ｜ 来源 ops-cv 全量 issue 语料（2026-10-17，本簇 **5 条**）
- **适用**：仓 All ｜ 侧别 Host ｜ 载体 aclnn源码,Tiling源码 ｜ 触发 static_cast<int32_t> ｜ 默认启用 true
- **故障机理**：proto 里属性/维度是 **int64 语义**（`ListInt`/`ListInt64`/shape），host 实现却用 `int32_t` 承接或在 32 位域完成乘积：`static_cast<int32_t>(attr)` 无范围判断，或 `H*W`、`offsets+size`、`totalPairs` 这类表达式的操作数全为 32 位。超界即回绕，**参数值被静默改写**（`2^32+1` 变成 `1`、`2^31` 变成负数），随后参与 shape 推导、约束判定与 tiling data 填充——参数、推导出的 shape、tiling 三者互相不一致。与 [FP-B07](FP-B07.md) 的区别：B07 错在**索引/偏移算式**（后果是越界读写），本条错在**参数值本身**（后果是形状/配置错误）；与 [FP-A12](../FP-A/FP-A12.md) 的区别：A12 是 int→float 的**精度**损失，本条是整型**回绕**。
- **触发条件**：`ListInt` 属性值接近或超过 `INT32_MAX`（`stride`/`rate`/`pad`/`output_size`/`pooled_size`）；shape 维度乘积超 int32（`H*W`、`N*C*H*W`、`output_shape` 各维相乘）；`int64` 偏移相加（`offsets + size`）；`size_t` 在空/rank-0 输入下下溢（`rank-0` 取 `size()-1`）。CV 算子里这类"极大属性"多来自 fuzz/边界测试或图上的常量折叠结果，业务侧较少但**一旦发生就是静默错误**。
- **典型表现**：**按文档/常规输入的对照组全 PASS，只有超大值输入出错**；错误表现为输出 shape 与调用方给的 `output_size` 不一致、tiling 参数被改成小值、或直接生成非法 shape；日志无报错、返回码为 SUCCESS。特征信号：问题只在 `2^31` / `2^32` 附近出现，且**改小值后现象消失**（与 FP-B11 的"非法输入"不同，这里是**合法但极大**的输入）。
- **源码审查映射点**：host 侧检索所有 `static_cast<int32_t>(`（尤其作用于 attr / `ListInt` 元素 / shape 维度）；`ListInt` 读取处是否直接赋给 `int32_t` 变量；shape 乘积链条（`H*W`、`D*H*W`、`N*C*H*W`）中是否有操作数为 `int32_t`；`offsets + size` 类相加是否先转 int64；`size_t` 与有符号数混用处的下溢（`rank-0` 输入）；tiling data 字段类型是否与 proto 声明的 int64 语义一致（int32 字段本身就是窄化点）。
- **检测签名**：静态扫描 `(?:int32_t|int)\s+\w+\s*=\s*(?:static_cast<int32_t>\()?[^;]*(?:attr|Attr|size|Size|shape|Shape|dim|Dim)` ⇒ 候选；再对每个候选反推可达上界（属性契约上限、shape 上限），可达 `INT32_MAX` 即成立。配套扫描：`\([A-Za-z_]\w*\s*\*\s*[A-Za-z_]\w*\)\s*\*\s*[A-Za-z_]\w*` 形式的连续乘积。ops-cv 基线：**5 个算子**命中（`Dilation2DBackpropInput`、`RoiAlignV2`、`ImageProjectiveTransform`、`Crop`、`NMSWithMask`）。
- **测试拦截建议**：属性/维度边界矩阵 = `INT32_MAX-1 / INT32_MAX / INT32_MAX+1 / 2^32 / 2^32+1 / 2^63-1`，每例断言"第一段接口返回 161002（参数非法）**或**按 int64 语义正确推导"，绝不允许"返回 SUCCESS 且值被改写"；对乘积类参数额外构造 `H=65536, W=65536`（`H*W=2^32`）；把上述静态扫描纳入 CI，新增 `static_cast<int32_t>` 作用于 attr 即告警。
- **实证案例**：ops-cv 五例：**#950** `Dilation2DBackpropInput` 将 `strides`/`rates`/`pads` 直接从 `int64_t` 转 `int32_t`，`2^32+1` 被当成 `1`，大 stride 使本应 1×1 的 VALID 输出被按 3×3 接受；**#937** `RoiAlignV2` Host InferShape 将超 int32 的正 `pooled_size` 窄化为错误 shape；**#995** `ImageProjectiveTransform` 极大 `output_shape` 乘积溢出后仍返回成功（`op_host/arch35/image_projective_transform_tiling.cpp`）；**#1009** `Crop` Host InferShape 未防护 `offsets + size` 的 int64 溢出；**#933** `NMSWithMask` Host InferShape 对 rank-0 输入执行 `size_t` 下溢（`experimental/image/nms_with_mask/op_host/nms_with_mask_infershape.cpp`）。
